# AI化组织 V3.1｜复制按钮强制规范

适用：所有需要持久化和跨页面恢复的任务，保留已冻结V2/V3的DSH、ECC、节点版本机制。

任务开头展示完整定位码 TASK_ID/N000/V1，编号在左、超大复制按钮在右。按钮要有大字号、足够大点击区域，保证深色模式可读。

默认白底黑色粗体「复制」。每次点击都复制完整编号。第一次点击变为整块绿色、白色「已复制」；再次点击仍复制，同时恢复白底黑色「复制」；以后每次交替。不得极短瞬闪或依赖自动定时恢复。该已验收交互替代之前的650ms自动复原版。

新页面只有真正通过授权接口查询并核对任务索引才可宣称恢复；显示编号与复制成功不等于业务完成。

## 线上写入故障修复经验（2026-10-24）

当Windows执行调用触发安全检查或本地git命令不能执行，不得将其直接判定为GitHub不可写。先通过已授权的GitHub官方连接器确认仓库push权限；按确切路径fetch_file读取内容和blob SHA；仅对需要变更的文件使用update_file（传入该SHA），新文件使用create_file；成功后再次fetch_file核对实际内容。若该文件路径404，应先核对任务根索引中的真实位置，不能把路径错误解释成权限故障。仍被策略阻止则停止该途径，不通过改写命令规避安全策略；保留C盘已确认副本并登记待同步。只宣布真实回读成功的写入，保持V2/V3冻结内容不变。
