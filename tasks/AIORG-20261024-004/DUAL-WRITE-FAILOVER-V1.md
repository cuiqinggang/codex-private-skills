# 双通道故障接管规则 V1.1｜先自查调用，再官方纠错
日期：2026-10-24。线上共同工作区 GitHub 优先，C:\AI\AIORG-Shared 为备用共同工作区；任务不因可恢复的单通道故障停止。

## 拒绝／安全检查后强制诊断
默认先将拒绝归类为“原因待查”，不得直接断言操作本身被永久禁止，也不得把一次工具失败当成任务不可完成。
1. SELF_CHECK：回查本次工具选型、API 契约、路径、参数、文件格式、权限范围、调用顺序、历史成功操作及报错原文；首先检验自己是否调用错误。
2. OFFICIAL_REUSE：优先改用官方文档允许、符合当前授权的正常功能入口（如 GitHub Contents API 文件创建/更新+SHA，Windows 原生文件读写）；只做必要调整，记录成功或失败证据。
3. FAILOVER：GitHub 普通故障时 C 盘原生写入并回读，保持任务 OPEN 并继续不依赖故障端的业务，恢复后对账补同步。反之亦然，保留权威版本判断。
4. EVIDENCE_GATE：仅在确认属于真实、适用于当前操作的安全/权限边界，或官方允许的可行路径确实不可用时，停止该受限操作并记录可复核原因；不尝试绕过明确限制。停止某个受限操作不等于结束其他可执行的任务步骤。
5. CONTINUATION：已完成成果不重做，未知外部副作用先对账；每次拒绝后必须确定下一个合法可执行动作。只有完整QA及T_VALID通过才能标记TASK_COMPLETE。跨会话无人值守需要真实持久执行器ACK；规则本身不提供后台持续运行。

## 验收
分别注入线上普通不可用、C盘普通不可用与错误调用三类条件；验证自查修正、备用写入、恢复同步、未完成任务保持 OPEN；不可用文字声明冒充真实演练。
