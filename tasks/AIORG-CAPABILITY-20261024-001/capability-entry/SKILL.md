# AI 化组织 · 统一能力入口
入口版本：1.0.0（2026-10-24）。方法基线：AIORG V3.1.2 候选；不代表原系统升级为成熟版。把技能、工具、环境、授权和验收组合成可执行能力；不要把入口文档称作新执行器。

## 目标与继承
- 以商业质量合同、完整交付、可靠性、成本和当前授权为约束，最小化完整有效时间 T*=min(T_VALID)。这是优化目标；不得宣称已证明全局最优或承诺无依据的倍数。
- 从收到可执行任务至最终验收交付计墙钟；计入检索、连接、加载、排队、生成、审核、返工、恢复和交付。历史局部耗时只用于估计。失败方案记 NOT_VALID；未完整计时记 NOT_MEASURED；不得重置失败时间美化结果。
- 先加载现有 dsh-extreme-effective-time，执行成熟基线→至多三条可行候选→比较融合→攻击迭代→虚拟成熟→STOP_GATE→Freeze→一次整体 Reality。单纯直达任务采用一个候选；不要为凑方案引入额外执行成本。
- 继承三人行 V5、轻量状态 V3、Windows 执行桥 V12.0.1、原 DSH/ECC 与节点恢复。按需要读取原规则，不一次加载全库。冻结 V2/V3 不改；当前用户指令及系统规则优先。

## 接单即执行
1. 确认最小合同：目标、输入、可审查的成品、必要商业质量、预算/权限/约束及验收。已有上下文足够则直接推进；不要让用户选择可自行裁决的工具。
2. 持续任务创建唯一 TASK_ID/N000，持久记录合同、当前节点、已提交产物、未完成项和下一动作。用户提交既有编号时，先查线上 N000 和节点回执，线上不可用再查 C 盘；核对后直接继续未完成业务，不重复已提交节点。
3. 根据 [能力路由](references/capability-routes.md) 只读取相关技能。以当前工具目录、原生技能加载及授权环境为准，使用现有成熟模板/工作流/接口；缺项先查现有连接器和案例，再决定是否建设，避免从零重造。
4. 针对本次调用检查最少前置条件：技能入口、执行工具、所需模型/服务或登录、输入可读、输出可保存、验收可执行。历史成功不代替当前可用性；不要每次全面重装、扫描环境或重跑已确认测试。
5. 虚拟成熟覆盖完整输入→执行→产物→验收→故障→恢复路径，排除不匹配的画质、错误业务语义、隐藏人工步骤、过期接口、输出丢失和 UNKNOWN 副作用；仅对选定路径做必要无副作用探针。冻结后实际执行，普通故障自主修复并继续。
6. 读回实际产物并验收。功能、外观、持久化、并发、许可和维护交付只检查合同相关部分。复杂判断按净收益采用独立只读审核；确定性条件优先用确定性验证。
7. 最后交付成品、验收证据和完整 T_VALID；记录可复用修正。只有规则/索引的任务可以文档验收收尾；真实业务任务不能以路由方案或状态报告收尾。

## 能力与执行边界
- 整体能力包含云端工具和授权本机技能；不能因为本页缺少原生视频按钮就断言不能做视频。也不能因为目录存在就承诺能生成指定质量成片。
- 区分 PRESENT（文件存在）、DISCOVERABLE（可找到）、INVOCABLE（已加载且调用链明确）、EXECUTABLE（真实运行成功）、ACCEPTED（本次合同验收通过）。为每个结论保留范围、时间和产物证据；这些标签不是另一套调度状态机。
- Windows 首次调用前加载 gpt-windows-execution-bridge，动态发现 A=Remote Desktop Commander 在线设备并探针；A 成功继续 A。只有按桥规则重新发现、复验失败并对账后才逐级 B→C。业务错误不等于通道故障；不改代理、FlClash或其他任务配置。
- 连接器优先；工具不足时按其规则使用正式浏览器。调用前核对当前授权；支付、发消息等外部行为遵守具体任务授权。技能不赋予账号、支付或后台调度权限。
- 长任务复用现有 n8n/受支持的持久执行器，只有真实接单回执才算移交；无接单不得宣称后台继续。不得自造调度器、锁、状态机或浏览器控制器。
- 副作用 UNKNOWN 先查账；CONFIRMED_COMMITTED 继承，CONFIRMED_NOT_EXECUTED 才能重试。不可自行解决的硬阻断保存状态、证据及解除条件。

## 已知未验收边界
V3.1.2 的 N004 全业务恢复、真实 GPT 新页面交接、无人值守持续性及完整 T_VALID 不因本入口发布变为 PASS。参考权威来源 [继承与状态](references/inheritance.md)，恢复旧业务时读取最新回执覆盖历史快照。
