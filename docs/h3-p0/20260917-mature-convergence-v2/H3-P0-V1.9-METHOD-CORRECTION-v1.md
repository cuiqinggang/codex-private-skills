# H3-P0 v1.9 方法修正与当前路线收口

状态：`MICRO_REPLAN_LOOP_STOPPED=YES / E2M_CANCELLED=YES / CLOSED_BATCH_REQUIRED=YES`

## 1. 为什么修正

H3-P0 在 E1 Star7 取得巨大 KEEP 后，v1.8 的“每个结果 RETURN_TO_GPT”执行语义把原本已经完整设计的铁路拆成：

```text
E1 -> GPT -> E2R -> GPT -> E2P -> GPT -> E2M ...
```

E2R/E2P 本身提供了真实信息，但继续沿该模式会重新形成历史 V1→V11 式工程循环，与“实际执行前完整 Virtual-99”初衷冲突。

## 2. 根因

v1.8 同时要求：

1. GPT 在执行前把当前批次完整 Virtual-99 条件铁路一次写完；
2. Codex 每个 stage 后 STOP / RETURN GPT。

这两个要求会制造不必要的微重规划。

## 3. v1.9 修正

当前项目后续采用：

```text
CANONICAL_SKILL=first-principles-physical-limit-convergence v1.9.0
PREAUTHORIZED_BATCH_EXECUTION=YES
NO_FREE_EXPLORATION=YES
NO_REPLAN_ON_MAGNITUDE_SURPRISE=YES
NO_OPEN_ENDED_PREFLIGHT_CHAIN=YES
RETURN_TO_GPT_AT_BATCH_BOUNDARY=YES
```

v1.9 不给 Codex 新的实验设计权，只允许它在 GPT 已经完整定义的 batch 内沿预定义 PASS/FAIL/NOT_APPLICABLE 分支连续执行。

## 4. 当前项目事实不回滚

保留：

```text
E1 Star7 = KEEP
E1 Total P50 = 10.562 s
E1 Total P95 = 14.510 s
E1 fast valid sample = 6.484 s
E2R = ATTRIBUTION_INCONCLUSIVE
E2P = FALLBACK_SUPPORTED / W4A8_CANDIDATE_MATURE=NO / COMPATIBILITY_INCONCLUSIVE
```

E2R/E2P 作为证据保留，但不再成为继续拆分 preflight 的理由。

## 5. E2M 取消

```text
E2M_REMOTE_METADATA_PREFLIGHT=CANONICALLY_CANCELLED_FOR_CURRENT_RUN
```

理由：

- W4A8 已经是 Virtual-99 原始 mature candidate；
- 同卡公开路线证明它有潜在价值；
- 当前本机源码存在 SM75 eager fallback；
- 真正的 loader/metadata/性能兼容性最终仍需实际 bounded run 才能裁决；
- 继续拆分 metadata preflight 会继续微循环，而无法代替 real A/B。

因此不再单独执行 E2M。

## 6. 剩余候选 ROI 压缩

### W4A8

当前唯一仍值得一次 bounded real A/B 的剩余 mature candidate。

理由：从当前约 20.97GB diffusion 降到约 12.5GB，可能改变 residency/tail；当前 P50 10.562s，fast valid 6.484s，现实可稳定收益上限约数秒，仍可能占 Total 的数十个百分点。

只允许一次 A/B。load fail / metadata incompatibility / mechanism inactive 直接按预定义 FAIL/NOT_APPLICABLE 收口，不再追版本/kernel。

### Conditioning / TE

E2R 无法证明 formal conditioning rerun/cache 状态；当前无机制级 >=10% 可归因块。继续需要新 instrumentation 或新研究链，当前判：

```text
DEFERRED_PORTFOLIO_ROI_INSUFFICIENT
```

### INT8 VAE

E1 后 Path P50 约 3.43s，且同卡公开存在 black/NaN 风险，当前无可归因 VAE 大块：

```text
DEFERRED_HIGH_RISK_LOW_REMAINING_HEADROOM
```

### host-sync targeted patch

Generation P50 已约 3.10s，处于此前现实 2–5s 带；慢尾无法归因，继续需要新 instrumentation：

```text
DEFERRED_NO_ATTRIBUTED_MATERIAL_BLOCK
```

## 7. 当前最短完成路径

```text
INSTALL/VERIFY v1.9.0 runtime
-> W4A8 ONE BOUNDED PAIRED A/B
-> KEEP / ROLLBACK / NOT_APPLICABLE
-> NO NEW RESEARCH BRANCH
-> FINAL 10-RUN CERTIFICATION ON WINNER
-> REPORT / PUSH / REMOTE VERIFY
-> FREEZE OR RETURN GPT ONLY IF FINAL CERTIFICATION FAILS
```

这条路线既继承原始命令包的 mature candidate 验证，又终止 E2R/E2P/E2M 式微循环。
