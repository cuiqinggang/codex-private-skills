## 执行要求与停止条件

1. 先沿实际 ARO 正文和报告核对缺口，不把 MOA 更新 PASS 当作 ARO 全面 PASS。如发现之前综合测试仅完成预检或存在未运行 L 项，读取原定义逐条纳入覆盖；不得凭名称编造其含义。
2. 不重装整套系统、不创建第二套资源调度、浏览器或审核平台。仅扩展方法参考和必要触发规则；原路由有具体失败证据时才最小修复受影响适配。
3. 使用已有成熟测试框架/夹具。失败注入只限隔离测试和任务级受支持入口，不改系统网络、不停用户服务、不消耗真实额度制造耗尽。取消/恢复测试只操作本任务拥有的任务与测试文件。
4. 原权限拒绝需定位层级；不能切 Yolo、修改全局信任/ACL 或通过其他工具绕过安全拒绝。能合法采用“分析资源返回计划、Codex 在自身授权范围执行”的原分工时分别记证据，不能改写 Reasonix 写入状态。只有强制阻断且无合法替代时才问一个最小必要问题；其余自动继续。
5. 编写本命令之外新的独立执行命令，按既有门禁由编写端审核一次；已审同版不重审。本命令正文和引用的已审专项不再次评分；运行时新事实核对不叫重新审核。
6. 观察记录复用原任务状态，保持简短进度。用户问时展示已填四列表和成果指标；不用空表占位。用户改要求时更新目标与受影响验收，不默认取消原任务。
7. 合成测试文件和产物保存在本任务隔离目录；原始用户文件、账户信息及敏感回执不得自动提交远端。必要诊断脱敏，不泄露 tokens/cookies/密钥。
8. 修改候选先做结构核对和方法行为测试，再按已有正式技能发布流程保存；遵循现有技能 git 同步规则，只提交本次已审范围内的技能/脱敏报告，不夹带其他改动。运行验收未过的规则标 candidate/限制，不写成成熟能力。
9. 如果仓库同步受阻，保留本地成果并分别报告 LOCAL_DEPLOY 和 SOURCE_SYNC；不得把远端发布失败写成已保存，也不为同步修改权限或凭据。
10. 在已确认的 ARO 验收根下创建本编号加时间戳目录。保存一份 ACCEPTANCE.md（含四列分析、能力映射、实际结果与证据路径）、FINAL-STATUS.json、必要原始回执和实际产物。旧 ARO/MOA 报告只引用不覆盖。知识索引有现成入口则结束时同步一次；同步成功不是功能通过。
11. 最终给用户一张“能力 / 已完成 / 仍缺 / 证据 / 状态”表，明确还不能自动完成的任务类型。列出实际修改文件和版本、测试覆盖分子/分母及统计口径、新调用/重试/费用、配置意外变化、实际可打开产物和唯一最小下一动作。未读取原始证据的历史结论注明来源。
12. 到达停止条件时保存检查点和准确缺口；不能以继续写说明、重评分、重复同步或重复同一失败调用代替修复。没有本机实际结果前，禁止宣称“全自动已成熟、全面测试全部通过”。
