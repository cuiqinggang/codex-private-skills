## 验收

本轮只做四个工作包W1—W4。工作包可以有部分成果；每个判定需注明证据和实际覆盖范围。缺口不能靠取消原标准变成通过。

W1 模型与力度证据收尾：
- 从既有允许访问的Reasonix任务结果、受支持会话诊断、官方已有脱敏请求摘要或等价运行记录，关联task/session/request ID、requested_model、resolved_request_model、requested_effort、sent_effort。
- 优先复用旧两模型调用及Flash两力度调用。确实缺证据时，先验证现成接口能产生需要的记录，再补最少短调用；不能再次只调用然后继续得到相同UNKNOWN。
- CLI参数、界面勾选只证明选择意图；程序实际发送记录才证明请求参数。模型自述、输出风格、token数量、耗时均不是模型/力度证据。
- 两个不同可用模型和同一模型两个受支持力度均有可关联请求证据时REQUEST_CONTROL=PASS。服务端不回报内部模型仍可记UNKNOWN，不能因此否定正确发送证据，也不能宣称证实了内部模型。
- 对已被自动审批拒绝的Codex受保护会话目录不再尝试，不换壳、换工具、拷贝路径或扩权读取。不新造日志填写预期值自证。找不到允许的请求证据入口时REQUEST_CONTROL=PARTIAL并明确限制；W2—W4继续。
- 原分派证据能与原记录对应则补R07对应字段，不必再分派同样数量的智能体；无法对应仍保留未验证字段。

W2 合法写入与自动交付：
- 从原拒绝回执确定是操作系统权限、宿主安全策略、工具授权、工作目录范围，还是工具本身不具备写入；不能仅凭“写入被拒”改系统。
- 只使用既有接口和当前真实允许的任务目录/工具作用域。若读取原配置证明上一任务传错了已授权目录或会话参数，可以最小修正本任务参数后试一次；不得修改ACL、全局信任、权限模式、Yolo、代理或系统设置来消除拒绝。
- 若拒绝来自强制安全策略，遵守拒绝，不通过另一工具代做被禁止的动作。若Reasonix只是无写工具，而Codex本来具有独立、已授权的执行交付职责，则可用原调度的“Reasonix分析—Codex执行”分工完成业务任务，必须把两个主体及动作分别记录。
- 最小写入成果可以复用CSV去重：输入A,12/B,18/A,12/C,7，保留首次id，输出顺序A/B/C、值12/18/7，summary含4→3和total=37。必须重新解析实际产物，不只读取“37”字符串。
- Reasonix发起真实工具写入并成功，REASONIX_WRITE=PASS；合法分工交付成功，WORKFLOW_DELIVERY=PASS。只有后者成功时旧R05保持BLOCKED/未通过，旧R06补记新的业务路线证据，不能改写旧运行事实。
- 无合法写入路线则准确记录受阻操作，保留分析成果，不声称完成交付。

W3 图片完整闭环：
- 用现有成熟测试素材生成工具制作一张小型无敏感信息PNG测试卡：高对比几何图形、清晰位置关系、随机短码和一个小型数值表。随机短码与表中数值由控制端产生并保留，任务提示词、文件名、描述及其他元数据不透露答案；不把被测答案先写给接收智能体。
- 控制端先用现有工具打开并核对文件可读。测试素材属于合成数据，不上传用户账户、患者资料、真实工作文档或当前Reasonix截图。
- 原调度按附件能力选择可接收图像的智能体/具体模型，使用已有专用浏览器上传或成熟API附件入口真实发送原图，并交付用户目标、限制和任务编号。发送本地C盘路径不等于对方收到文件；收到缩略图不默认等于收到原图。
- 接收端需正确返回仅凭图像可得的随机短码、指定位置图形/颜色与表格合计，形成analysis.json；至少一项不能由文件名或文本提示猜出。原文件送达、内容理解分别验收。
- 让原流程完成一个可确定的图像处理任务：用现有成熟图像工具/技能生成精确二倍宽高的PNG副本，并把成品返回控制端可访问的输出目录。此处是测试图像处理交付，不代表艺术制图/图像生成质量通过；不临时接入新收费制图服务。
- 验证原图尺寸与输出尺寸比例、PNG可解码、内容对应输入，独立核对analysis.json数值与图形。如果外部智能体仅分析、Codex处理，则明确采用此合法分工；不能说外部模型直接生成图片。
- 真实附件送达、盲测理解正确、处理成果回传且独立可打开，IMAGE_E2E=PASS。只有接收文本描述或控制端先OCR再把答案传给对方，不能记原图理解通过。

W4 视频完整闭环：
- 用已有成熟视频工具（如当前已安装的FFmpeg）生成6—10秒、体积小的合成视频：三段明确不同视觉事件，每段含不同随机短码/位置变化，含可校验的音轨事件。可用两段频率明显不同的短音，分别在固定时间播放；验证频率/时间而非要求理解虚构对白。不为了本测试下载大模型或安装整套媒体平台。
- 输入视频、时间轴和音轨先由控制端现有工具核对。保留期望事件、短码、音调先后和时间范围，提示词与文件名不泄露答案。没有可用音轨生成工具时可先完成静音视频分项，但AUDIO_SCOPE=UNTESTED；不能把静音通过扩大为音视频全覆盖。
- 调度先检查接收方和现有入口支持的文件类型、大小/时长限制，以及视频与音频是否都能处理。上传整个文件，经已有完成/处理状态确认后再开始分析，不只确认点击了上传。
- 支持原视频的路线：交接原文件及任务要求，接收方返回三个视觉事件顺序、至少两个短码、事件时间（误差不超过0.5秒），以及两段音调顺序与出现时间（误差不超过0.5秒）；与独立期望比较。平台是否实际逐帧解码无法观察时不猜测，但明确按所测输入完成内容任务。
- 不支持原视频时，优先复用成熟抽帧/音频提取技能分派给支持对应资料的智能体。记录派生资料来自哪个原文件、实际帧时间、音轨覆盖范围；原文件由执行端保留并作为来源关联。派生资料不得直接夹带控制端答案；真实分析结果再由调度汇总。
- 派生路线可以证明任务经适配完成，记VIDEO_DERIVED_E2E；不能记VIDEO_NATIVE_E2E，也不能宣称原视频已传给不支持它的接收方。向同一用户界面只显示一个来源并不证明各子智能体能打开原片。
- 让原流程用已有视频处理技能截取中间完整一段视觉事件，保留该段应有音轨，输出一个可解码MP4及analysis.json，并交回控制端。截取参数必须由实际分析结果和任务要求得出；控制端只用预设期望验收，不替被测分析端填写结果。
- 检查输出时长、目标事件与短码、音轨是否存在且对应区间，用现有解码工具实读；ffprobe头信息、文件存在或“完成”文本单独不够。容差不超过0.5秒或一个必要编码帧误差，采用较宽者并记录理由。
- 原片送达与真实理解、处理产物回传均通过才记VIDEO_NATIVE_E2E=PASS；派生路线按自身覆盖单列。声音未处理或未测必须明确，视频文件能上传不等于音轨已分析。

W3/W4共同交接标准：
