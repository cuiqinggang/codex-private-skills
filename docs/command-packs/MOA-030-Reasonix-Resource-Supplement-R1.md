## 验收

以下R01—R08为本补充的必需测试；保留原C01—C12结论，不用本补充重置旧结果。每项记录实际类型、期望、发送参数、回执和结果。不能因缺少接口而删项改成通过。

| 编号 | 实际测试和通过标准 |
|---|---|
| R01 资源发现与控制入口 | 读取现有总调度和Reasonix相关技能/帮助，取得当前agent/profile、provider/model目录、各模型支持力度、工具及真实分派入口。用会话或实际支持接口读取至少两个候选模型。菜单存在只算发现；CLI与桌面profile/目录能否对应要实测，不推定相同。 |
| R02 具体模型选择 | 经原调度适配入口在两个隔离Reasonix任务中明确选择两个不同可用模型，各完成一次短任务；优先核对截图flash/pro。记录requested_model及实际请求resolved_request_model，必须与选择一致；若确有文档支持别名映射，明确记录映射。只返回“我是某模型”不能通过。 |
| R03 同模型力度切换 | 在一个实际支持多档力度的模型上，设置两个不同有效档位，各执行一次真实短任务，记录requested_effort及sent_effort。优先采用两个明确档位而非auto；不支持low/high就采用该模型实际支持的两档。可与R02复用一次调用。不能以不同模型各用一档证明同一模型切换；若全环境没有支持两档的模型，报告缺口而非伪造。 |
| R04 生效与桌面范围 | 用现成脱敏运行日志、会话结果或等价安全诊断证明R02/R03请求采用选定provider/model/effort。分开记录选择状态、发出参数和provider_reported_model。供应商不回报后者写UNKNOWN，不影响“正确参数已发送”的判定，也不能声称验证了其内部模型/思维强度。只测CLI/ACP则只能判该入口通过，桌面自动点击/同步单独标未测，不能混称。 |
| R05 Reasonix工具实际执行 | 至少一次Reasonix任务自主发起已有文件/终端/MCP工具调用，读取隔离输入并写出正确结果，保留其工具调用与执行回执；Codex独立读取验收。通过现成客户端代理执行的工具可以计入，但必须有Reasonix发起的调用链。仅由Reasonix输出建议、Codex自行代做不算。 |
| R06 按任务自动选择资源 | 交给现有总调度两个不同特征的任务，由其实际选择agent/provider/model/effort/工具并执行；保留简短选择依据与请求结果。可复用后述简单任务和约束任务。不能事先人工填死所有选择后称自动路由。两任务合理选择同一模型不自动判失败，但不据此宣称已验证模型切换或全局最优性价比。R02/R03仍需独立满足。 |
| R07 真实智能体分派 | 把两个可独立小工作包交现有调度，启动至少两个独立智能体上下文，分别返回可验收成果；至少一个通过Reasonix，另一可按调度选Codex或Reasonix。记录系统启动/会话ID、工作包、实际模型/力度及回执，主控汇总并核对。两个角色名或一段模拟对话不算；串行可验证分派，只有时间确实重叠才称并行通过。不为此强行跑完整ECC。 |
| R08 参数边界、会话隔离与复用 | 通过原入口的现成参数校验或隔离调用验证一个不存在的测试模型名或明确不支持的力度组合得到拒绝/明确换路记录，不产生静默默认请求。不能新造一个永远拒绝的验证函数冒充原入口。恢复已完成任务时复用原编号与产物，不重复提交；读取验证原用户会话、全局默认和权限模式未被测试改动。无法测的分项写UNTESTED，不能整体PASS。 |

推荐合成任务，允许现有成熟技能在同等范围内适配：
A：在测试目录读取CSV列id,amount，行A,12；B,18；A,12；C,7，按id保留首次，输出A/B/C对应12/18/7，以及before_count=4、after_count=3、total=37。R05要求由Reasonix发起工具执行；Codex用现有CSV解析独立核对字段、顺序、记录数和合计。
B：根据明确规则判断候选顺序是否满足“A在B前，C在B后，D必须最后”，输入ACBD、ABCD、BACD，输出false/true/false和违背的规则。它只是一项有约束的小任务，不预设必须用最大模型或max。
R07可把CSV去重工作包与B规则校验工作包分给两个上下文，分别输入所需数据；不让两个智能体写同一文件。输入、预期答案由主控预先固定，不让被测模型自定验收。

已有旧CSV任务只复用输入、预期及证据；为验证本轮模型/力度/工具而发生的新调用要新编号，不能把旧调用标成本轮参数生效。

## 智能体

Codex为主控，AI资源总调度2.0为调度，Reasonix为必需执行资源。
预计5—7次独立模型任务提交；硬上限8次，含子任务与重试。尽量让一次真实任务同时提供模型、力度和工具证据。
代理内部工具回合/API调用数另记可观察的实际值，不能将8次任务提交宣称为最多8次供应商API调用。单个测试任务使用少量工具步骤和简短输出，不启动开放式研究或长循环。预算内不能覆盖则如实部分完成。

## 时间上限

预计20—40分钟，总硬上限60分钟；达标即停。
某一步最多10分钟无有效进展即暂停受影响路线，独立测试继续。同一缺陷最多一次有依据的最小修正及复测，计入调用预算；不得反复原样重试。
