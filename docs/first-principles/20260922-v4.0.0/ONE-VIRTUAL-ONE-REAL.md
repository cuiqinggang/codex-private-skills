# 一虚一实：最短闭环说明

只记一句话：

> **虚拟成熟负责把方案做对、做短；实际验证负责证明它在现实里真的对、真的短。**

## 最短循环

```text
虚拟成熟
  ↓
冻结一个唯一方案
  ↓
实际验证
  ↓
通过 -> 结束
失败 -> 把现实差异送回虚拟成熟
```

没有第三步。

## 两边的边界

### 虚
可以：
- 读 Reality Twin / 本地现实底座；
- 重新找新的成熟方案；
- 组合；
- 淘汰；
- 攻击；
- 修复；
- 比时间；
- 冻结。

不直接把“虚拟结果”冒充现实证明。

### 实
可以：
- 照冻结方案执行；
- 测时间；
- 判 VALID；
- 记录现实差异；
- 停止。

不可以：
- 自己想新办法；
- 现场修方案；
- 现场换路线。

## 唯一锚定

无论“虚”还是“实”，只问：

```text
这件事是否让 VALID 成立？
或者是否让 T_VALID 更短？
```

都不是，就删。

## 为什么不能再少一个物理步骤

可以把用户操作做成“一键”，但物理逻辑仍至少有：
1. 决定执行什么；
2. 在现实里证明一次。

纯虚拟无法永久证明物理现实，因此“一虚一实”是当前保持现实有效性的最小逻辑闭环。
