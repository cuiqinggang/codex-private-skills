# 整体闭环极限短时间引擎｜简明使用说明

## 它是什么？
> 在结果必须正确有效的前提下，把完成一件事情所需要的时间不断压到最短的方法。

不是单纯“做得快”。

`先定义什么叫有效 -> 在所有有效方案中寻找最快`

核心目标：`T* = 最小有效完成时间`

## 怎么使用？
只需要理解两个阶段：`虚`、`实`。

### 虚
执行之前把事情想成熟：
- 我要得到什么结果？
- 什么叫真正完成？
- 已知现实限制是什么？
- 有哪些成熟方法能复用？
- 哪些事实还不知道？
- 如果不知道，最低成本怎样搜索、测量或小实验获得？
- 在有效方案中哪条最快？
- 现实最可能在哪里失败？

然后冻结一套唯一方案和时间目标。

### 实
按照冻结方案现实执行，不一边执行一边临时重新设计。

成功：完成。

失败：`Reality Delta -> 回虚 -> 改进方案 -> 再现实验证`

## 已知问题
`找已有方案 -> 找差距 -> 最小修改 -> 执行`

## 未知问题
`不知道 -> 搜索/测量/小实验 -> 得到事实 -> 再形成方案`

## 它能做什么？
它不替代编程、研究、设计、商业等领域知识；它决定具体方法如何被选择、验证和改进。

适用于工程、研究、学习、自动化、软件、视频制作、商业项目、个人规划、工具选择、流程设计和复杂问题解决。

前提只有一个：**能够定义什么叫“有效完成”。**

因此它更接近“通用效率操作系统”，而不是某一种工作的技巧。
