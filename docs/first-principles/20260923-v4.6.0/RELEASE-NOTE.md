# 极限短时间引擎 v4.6.0 冻结说明

## 为什么从 v4.5.10 升到 v4.6.0

v4.5.x 是方法形成期，连续吸收了真实 Reality Delta。v4.6.0 不再继续堆补丁，而是把已经验证有价值的规则压缩为一个干净合同。

## 核心只剩这些

1. 只有一虚一实。
2. 唯一目标是整体闭环极限时间，不是局部 runner 时间。
3. Codex 保留为默认现实执行器，PowerShell/浏览器只是 Codex 内部工具。
4. 四定位固定；序号在同一 TASK_TIME_ID 下单调递增。
5. GPT 发布时、Codex 接手/结束时、GPT 最终验收时全部计时。
6. Reality Foundation 提前提供已知现实限制；已知同类错误应在虚阶段被拦截。
7. 虚完成必须同时把现实任务直接交付，禁止额外下载、搬运、第二次询问。
8. GitHub 是共同事实源，不是默认现实启动传输层。

## 51 分钟的正确解释

`>=00:51:07.109` 是 v4.5.x 首次开发/返工过程的历史有效工作时间下界。

它不是：
- v4.6.0 成熟运行时间；
- T*；
- 物理下界；
- 认证下限。

它的价值是证明：返工、错误门缺失、交接复杂度会显著增加整体任务时间。

对于 `T*=min(T_VALID_RUN)`，一个 51 分钟的有效历史样本最多提供“曾经完成过”的历史成本信息；真正成熟 T* 必须重新 clean run 测量。
