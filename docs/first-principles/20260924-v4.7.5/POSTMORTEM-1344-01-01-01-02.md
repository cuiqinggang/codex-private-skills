# v4.7.3 / v4.7.4 1344 双失败复盘

## 为什么虚拟验证通过

v4.7.4 的 8/8 自测只调用状态验证逻辑，并把 `PROCESS_SPAWN_PRECHECK=PASS` 作为事件字段输入；它没有真实创建 Windows 子进程。

因此 8/8 的真实含义是：

> 假设当前执行通道已经能创建子进程时，状态门逻辑能正确 ALLOW/BLOCK。

它不证明当前 Codex 通道本身具备进程启动能力。

## 为什么“已验证窄工作目录”仍失败

重新审计 mature-download-router REAL-TASK-04：合同允许窄目录仍 1344 时，再使用一次“已授权且曾成功的备用执行通道”。

REAL-RESULT-04 只记 `WORKDIR/PROCESS_SPAWN=PASS`，没有记录究竟哪个执行通道成功。

因此历史证据不足以支持“C:\AI\Mature-Download-Router-Real-Test 本身可消除 1344”。

当前 01-02 在同一目录再次 1344，现实证明：workdir（工作目录）不是充分条件。

## 新结构

状态机规则是上游控制规则，必须在 GPT↔Codex 控制层发送前验证；不应该让 Codex 先启动子进程来证明上游状态规则。

真正需要本地子进程的业务任务，另行绑定执行通道身份并做当前上下文现实能力认证。

连续两次相同 1344 且第二次已经针对目录做修正，属于结构性路径错误；按有限循环规则提前重组到 02-01，而不是继续 01-03。
