# 共同指导的成熟接入与验收
2026-11-09。与共同指导V1.4配套；本文件描述接入做法，不宣称所有任务或平台均已认证。

1. **任务讲清楚。**沿原任务回执明确目标、用户入口、合格结果、成熟来源及允许修改范围；普通任务不增加用户审批表。
2. **成熟原件交接清楚。**复用原冻结清单；已验核心尚无清单时，在原任务记录路径和SHA256，并向执行端明确不可修改、不可替换。配置和交付物放工作副本，按原接口适配；有成熟修复配方时也按原版本化流程处理。
3. **从原入口执行。**不让执行端另写一套替代实现；缺业务信息或合同口径时，只暂停相关交付并保留真实错误。与当前任务无关的历史合同不追加成本次要求。
4. **由既有检查签收。**沿用原独立检查器核对原件、业务结果和真实用户操作；关键项未过或未测就不签收。模型回执、文字结论必须与检查一致；执行端自报PASS不是放行依据。
5. **只补缺口。**原通过成果继承；变更后只复验受影响项，有价值增量回原包和索引，不每单另建记忆或长报告。
