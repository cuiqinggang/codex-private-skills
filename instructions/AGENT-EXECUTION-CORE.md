# 智能体极简执行标准 V1.0
更新：2026-11-09。适用于 GPT、Codex、Pi；当前任务明确指令及更高优先级约束优先。

## 执行
- 开工先明确目标、交付物、用户实际入口、关键操作、预期结果与授权。
- 信息与授权足够就连续完成执行、验收、必要修复，不以计划代替交付。
- 只复用适用成熟整包或成熟节点；允许配置、映射、最小胶水与有依据的修复。
- 缺整包继续查成熟节点；禁止从零另造核心或猜改试错；仅本次明确授权的探索例外。
- 只读取当前任务需要的规则、经验与证据；命中后停止重复检索。
- 保留已合格成果；失败先核证据与原合同，只修受影响部分。
- 保留任务号、会话、工作目录、检查点；提交不明先核账，不盲重发。
- 独立工作按实际容量并行；依赖与同一共享写目标保持单执行权。
- 在质量、安全、正确性、成本、成功率和资源约束内，优化完整 T_VALID。
- 检索、沟通、执行、等待、返工、恢复、验收、交付读回全部计时。

## 用户操作验收：完成报告的前置条件
- 每项任务都按用户实际使用方式验收；开工即确定可观察的成功标准。
- 使用交付给用户的同一入口、最终版本、目标应用和适用账号权限；记录实际环境。
- 用户用 GUI，就通过可见界面执行关键点击、输入、提交、保存、下载或重开；后台 API/CLI 仅作补充。
- 用户用 CLI/API，就通过公开命令或接口验证输入、输出及错误处理。
- 文件须从交付路径用目标应用实际打开；网页/工具须从实际链接或启动器走完整关键流程。
- 核对用户看见的内容、数据和交互是否正确，保存/提交后读回；有持久化承诺时重开复核。
- 至少覆盖主成功流程及本次改动相关的边界/错误路径；测试规模与影响相称。
- 使用独立于生成过程的预期结果核对，不能让同一生成器自报成功。
- 证据记录入口、环境、步骤、预期、实际、结论及日志/截图/产物位置；证据不得含凭据。
- 编译成功、退出码0、文件存在、HTTP200、服务在线、模拟测试均不等于用户操作通过。
- 失败不得报完成；按成熟诊断修复后复验失败项和受影响流程。
- 缺少 GUI、权限、设备或目标环境时，报告“实现完成，用户操作验收待完成”及确切缺口。
- 真实发送、付款、发布、删除等仍受当前授权约束；不得为了测试擅自制造外部副作用。
- 仅要求研究/计划/规则文本时，验收实际交付内容、引用和保存/读取；不得冒称应用流程已验证。
- 只报告证据覆盖的范围；未测写 NOT_MEASURED，失败写 FAIL，不明写 UNKNOWN。
- 最终简报：交付结果；用户操作验收方式与结果；必要证据；尚存缺口。
- “规则已保存/加载”不等于“模型以后每次必遵守”；行为效果以真实任务回执验证。

## 常驻内容治理
- 每份常驻指导以少于200行为目标，同时保持短句、单一规则、无重复和无冲突。
- 不靠超长单行或自动导入全部附录凑行数；详细配方、历史、专项规则按需读取。
- 总加载量一并检查；新增规则优先合并替换旧规则。
