61|# 3. 0 层：Router（问题分流模块）
62|
63|Router 是 v2.0 的核心新增模块。
64|
65|它的作用是判断某个用户问题属于：
66|

68|- **复杂题：使用完整 A/B/C/D 流程**

71|**保证简单的问题不走复杂流程，复杂问题绝不走简化流程。**

74|
75|## 3.1 判断标准（一般题 → D-Lite）
76|
77|当问题满足以下任意 **≥ 2 条**，即可走 D-Lite：
78|
79|- 问题逻辑链少于 3 层因果关系  
80|- 不涉及健康、金钱、工程、法律等高风险领域  
81|- 不需要证据交叉验证  
82|- 用户的错误答案不会造成严重后果  
83|- 关键事实均可直接查证  
84|- 单模型给出的答案高度一致，无明显冲突  
85|
86|若满足以上至少两项，则 Router 将该题标记为：
87|
88|**Route = D-Lite（一般题）**
89|
90|---
91|
92|## 3.2 判断标准（复杂题 → 完整 A/B/C/D）
93|
94|当问题满足以下任意 **≥ 3 条**，必须走完整流程：
95|
96|- 多因果链（≥ 3 层）  
97|- 涉及健康、金钱、工程、法律等高风险领域  
98|- 需要证据交叉验证  
99|- 需要达到 “几乎不出错” 的可靠性  
100|- 不同模型的答案不一致或互相矛盾  
101|- 需要深度推理或多维度综合判断  
102|
103|若满足三项或以上，则 Router 输出：
104|
105|**Route = Full（完整流程）**

198|（UF-GPT Restriction Check & Grok Fallback Router）

200|用途：仅检测本题 A_GPT 是否受限；若 FAIL → 本题全流程停用 GPT，由 Grok 完成融合与终审。
201|# UltraFusion Auto GPT Guard（GPT 受限检测与 Grok 兜底自动接管）
202|
203|Role（职责）：
204|1. 自动判断 GPT 生成是否受限（政策/版权/敏感/拒答/中断/过简）。
205|2. 一旦受限，自动摘除 GPT，不再参与本题任何后续生成。
206|3. 一旦判定 FAIL，本题后续所有融合与终审工作一律由 Grok 接管，生成最终 Ultra_Answer_Final。
207|
208|4. 若 GPT 正常则继续参与（不切换）。
209|
210|Rule（判断逻辑，机器自动执行）：
211|- Restricted signal（受限信号）包括但不限于：
212|  a. 模型主动声明不能回答/不能给出具体内容
213|  b. 以政策/版权/敏感为理由明确回避
214|  c. 生成中断/截断/停在句子中间
215|  d. 只复读原则，避开核心诉求细节
216|  e. 用户任务未完成或明显认真度不足
217|
218|Auto route（自动路由输出）：
219|- 仅输出一行结果：
220|  UF-Router: PASS
221|  或
222|  UF-Router: FAIL → GPT removed → Grok takeover ALL

225|若为 FAIL：
