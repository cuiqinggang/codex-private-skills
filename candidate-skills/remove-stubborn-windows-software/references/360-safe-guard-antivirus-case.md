# 360 安全卫士与 360 杀毒案例

此案例是验收压力测试，不是通用删除清单。

## 测试范围

- 在 disposable Windows VM 中同时安装 360 安全卫士和 360 杀毒。
- 安装包来源、版本、SHA-256、签名和获取日期必须记录。
- 先创建 baseline 与 pre-removal checkpoint。
- 通过各产品当时提供的官方卸载入口处理；如果 UI 要求关闭自保护，由人在 guest 内明确操作。
- 每次需要重启时，先保存跨重启 checkpoint，再由 VM 控制器重启 guest。
- 重启后重新 inventory，不沿用旧的进程、服务或文件结论。

## 通过条件

两个产品的卸载入口和活跃组件均不存在，或残留被准确分类并符合用户事先定义的成功条件。任何未知驱动、签名无效组件、重新出现的产品入口或仍运行的保护组件都使测试不通过。

不要硬编码网上流传的 GUID、服务名、驱动名和路径作为删除依据。版本变化会使它们失效，也可能误伤其他组件。

## 已知风险

安全软件会使用自保护、内核驱动和重启后清理。正常卸载后仍加载的厂商驱动可能是产品缺陷或待重启状态；记录文件哈希、签名、服务状态与 boot id，优先交给厂商修复或官方清理工具，不进行猜测式删除。
