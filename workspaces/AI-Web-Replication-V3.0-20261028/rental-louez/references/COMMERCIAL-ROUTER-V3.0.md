# V3.0 商业成熟能力优先路由（正式规则）
发布日期：2026-10-28；范围：网站、独立站、应用、商业交付方案选择。继承 V2.0.1 的真实业务证据，不改动原程序和在线数据。
## 不可违反的总原则
能力选择优先于自建，商业交付优先于技术偏好。用户选择的是合格业务成果，并非指定我方代码。本地复刻能力默认作为备份、特殊高保真定制和谈判退出保障，不享有优先选型权。只有同合同完整有效时间或约束成本明显优于成熟平台且证据充分时，才转为首选。
## 路由
0. DEFINE：明确客户交付合同（用途、视觉、功能、支付/数据、部署、维护、法律许可、预算、时限、性能、可靠性、源码/迁移）。
1. FACT：优先复用客户已经拥有的合规成熟服务和账号、既有认证配方；搜索官方文档、公开同类已成交案例及真实交付证据；区分营销宣称、独立数据与我方实测；不强迫重复测试已有成熟平台的常识能力。
2. COMPARE：最多筛三条满足完整合同的成熟路线；默认先筛市场现成产品/服务（如 Shopify、WordPress+WooCommerce、托管建站、预约/CRM 成熟产品）；再筛我方已认证配方；最后是自主开发。顺序是优先核验顺序而非强制优胜。
3. DECIDE：质量安全正确性成功率合规成本资源全部过硬门后，按最短 T_VALID_E2E 选优；预算/托管/维护按客户约束可接受范围筛选，存在时间成本冲突必须报告帕累托权衡。无法证实的时间不编造倍数。
## 计时与费用
T_VALID_E2E=需求到可交付成功的全部工作+平台开设/初始配置+素材+迁移+交互/业务/视觉QA+部署+修复重试+审批/人工接力+恢复。历史热复用、仅生成首页、单QA不得冒充完整交付。
C_TOTAL=平台订阅/域名/插件/交易费+执行/人工+托管+维护+失败重试+迁移/退出；以客户适用期限衡量。不能把免费代码称为免费交付。
公开样本单独登记（合同差异、时间起止点、人数、是否冷启动、成本来源和日期），仅可做范围或能力判断；未取得同口径的对照数据不产生伪精确排名。
## 实施边界
现成可配置绝不从零复制同类系统；已有认证组件先复用，补缺仅允许最小适配。指定像素级视觉、完全独立源码、强数据主权、平台限制或特殊功能时，现有复刻包可能优胜；须验收。严禁为比较临时创建付费商店、购买服务、改支付配置或客户生产数据。
各项业务输出：选中路线、放弃路线与原因、T_VALID证据类型、成本、剩余未知、可回退路线和客户交付验收。未出现真实订单/同合同验收时维持 NOT_VERIFIED，不借政策升级宣称加速。
