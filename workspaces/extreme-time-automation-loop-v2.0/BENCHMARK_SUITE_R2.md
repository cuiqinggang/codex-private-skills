# 标准测试体系 R2｜极限短时间自动化闭环 v2.0

## 当前唯一测试边界

本项目测量的不是“最终产品运行一次需要多久”，而是：

**从用户提出原始需求，到系统把任务真正做成成熟版并通过最终现实验收，整个闭环需要多久。**

唯一主指标：T*=min(T_VALID)。

T_VALID 包含：需求理解、完成条件定义、成熟方案搜索、方案比较与选择、成熟能力组合、虚拟成熟、现实执行、等待、失败、根因分析、修正或换路、重试、最终现实验收、成熟版完成。

产品成熟以后，日常运行一次要几秒，只属于产品运行性能，不是本项目核心时间。

## 为什么使用“已经完成的项目”做标准题

已完成项目只承担三种作用：
1. 证明这道题现实可解；
2. 提供隐藏参考答案；
3. 提供最终验收标准。

测试路径不得直接读取旧最终实现、最终修复答案或最终冻结结果。候选必须从原始需求开始，按照 v2.0 方法重新完成任务。

## 第一轮候选路径

- 路径A：GPT 原生路径；
- 路径B：GPT + Codex；
- 路径C：Manus 2.0，仅作成熟商业方案测试对照；
- 后续：其他成熟完整方案或成熟组合。

Codex 是测试对象，不是系统前提。

## “极限物理实际时间参考”

这里的“极限物理实际时间参考”是：**从需求接受到成熟版完成之间，当前现实环境中所有不可避免串行步骤能够压缩到的最短合理参考。**

它必须根据完整任务依赖结构、真实阶段耗时、已验证可并行关系、必要现实等待共同推导。不得用“成熟成品运行一次的耗时”替代。

## 第一轮结束后

完整真实数据出来后：分析时间损失 → 删除无收益步骤 → 搜索更成熟路径 → 组合 → 虚拟成熟 → 预测新的完整 T_VALID → Reality（现实执行）→ 与当前最短完整 T_VALID 对比 → 有收益则升级。
