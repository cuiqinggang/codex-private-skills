先测试最薄的 GPT 原生成熟路径，而不是先假设需要 Codex。

真实目标：

> 从共同私库恢复“极限短时间自动化闭环 v2.0”的当前状态，核验当前官方事实，形成一份可复用 Reality 结果，写回 GitHub main，并远端回读验证。

## 3. 默认路径

优先只使用 ChatGPT Work 当前原生能力：
- Project / context；
- connected apps / plugins；
- browser；
- 文件；
- 可用的本地桌面能力；
- GitHub connected capability；
- 自动结果回传。

不得因为历史习惯先加入 Codex。

## 4. Codex 加入条件

只有出现下列任一现实条件才允许进入同一任务的第二候选路径：

1. Work 无法完成明确技术 / 工程步骤；
2. Codex 可明显降低完整 T_VALID；
3. Codex 能消除需要用户手工完成的工程操作；
4. Work 的结果无法达到 FINAL_VALID，而 Codex 能补齐。

如果加入 Codex，必须把：
- 上下文传递；
- 等待；
- 切换；
- 结果回传；
- 验收
全部计入 `T_VALID_WORK_CODEX`。

## 6. FINAL_VALID

只有同时满足：
- GitHub main 真实存在目标文件；
- 写后远端重新读取；
- 不要求用户搬运中间消息；
- 普通失败自行恢复；
- 机器可验事实自动验收；
- 所有人工介入和失败如实记录。
