# 长期记忆超级虚拟人 v1.0

```ini
PROJECT=长期记忆超级虚拟人
VERSION=v1.0
STATE=10
VIRTUAL_MATURE=NO
PROJECT_FREEZE=NO
FINAL_VALID=NO

OBJECTIVE=T*=min(T_VALID)
PRIMARY_BRAIN=GPT
LONG_TERM_MEMORY=REQUIRED
PRIMARY_ROUTE_CERTIFIED=NO
STRONG_BACKUP_CERTIFIED=NO
```

## 1. 项目定义

“长期记忆超级虚拟人”不是单一助手，也不是单一执行器。

它是一个长期存在的个人智能核心：

```text
长期记忆
+
高智能综合判断
+
互联网与在线工具
+
本地电脑工具
+
按需调用 Codex / Reasonix / 浏览器 / 专用模型 / 其他成熟执行器
+
现实结果验证
+
故障恢复与换页续跑
```

GPT 当前作为首要超级大脑候选，但在 Reality 数据证明之前，不宣称它是唯一最优路线。

## 2. 三个独立基础资产

本项目调用但不合并以下资产：

1. `极限短时间智能体宪法 v0.3.1`
2. `极限短时间自动化闭环 v2.0`
3. `GPT直连Windows双路执行桥 v0.2.0`

三者分别负责：
- 判断原则；
- 极限 T_VALID 工作方法；
- Windows 现实连接与主备通道。

它们各自独立版本、独立 Reality、独立升级。

## 3. 默认主链候选

```text
用户现实目标
→ GPT 超级大脑
→ 全维度观察 / 搜索 / 组合判断
→ 选择当前最短有效工具
→ 网络 / Remote / Codex / Reasonix / Browser / 其他执行器
→ 现实执行
→ 机器可验证结果自动验收
→ FINAL_VALID
→ 经验写回
```

工具是能力，不默认与 GPT 平级。

需要并行时，GPT 可按任务拆出搜索、执行、审核、整合等子任务；只有能改善完整 T_VALID 时才保留并行层。

## 4. 两个当前必补核心能力

### A. GPT 连续性与换页恢复

必须解决：
- 上下文过长；
- 页面卡顿 / 不回答；
- 网络节点暂时故障；
- 长任务中途停止；
- 新页面丢失当前项目状态。

目标不是无限延长单一聊天，而是：

```text
工作会话
→ Checkpoint
→ 权威项目状态
→ 新会话恢复
→ 继续原任务
```

### B. GPT 本身不可用时的强备份

正式生产不能只依赖 GPT + Codex 同时健康。

必须存在一条独立成熟备份，使 GPT 服务、登录、配额或会话故障时仍可继续关键工作。

备份可较慢，但必须能达到同等现实 VALID。

## 5. 长期记忆结构

长期记忆不等于无限上下文。

至少分三层：

```text
个人长期记忆
→ 稳定偏好、权限边界、长期目标

项目权威状态
→ README / SUMMARY / Reality / 决策 / 证据

会话 Checkpoint
→ 当前任务、已完成、未完成、下一步、禁止重复路径
```

聊天页面只是工作内存，不是唯一事实库。

## 6. 权限边界

默认可充分使用已授权成熟能力。

长期硬边界：
- 不破坏 / 删除 Windows 系统；
- 不修改 FlClash / 网络代理；
- 高危、不可逆、账号安全、支付等动作按现实权限门处理；
- 其他普通执行尽量不要求用户充当消息中继。

## 7. 当前阶段

v1.0 先验证“GPT 超级大脑 + 直接工具”的最短主链。

不提前宣布成熟，不提前宣布 GPT 路线必然最快。

Reality 数据产生后再决定 v1.1 / v2.0 / v3.0 的真实升级内容。
