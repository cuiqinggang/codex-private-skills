# 长期记忆超级虚拟人｜三路线 Reality 对比 v1.0

## 原则

不用架构感觉证明“最快”。

同一批正式现实任务，从相同有效起点到同一 FINAL_VALID，比完整 T_VALID。

## 路线 A｜GPT 直接工具优先

```text
用户
→ GPT
→ 直接网络 / Plugin / Desktop Commander Remote / CLI / Browser
→ 必要时调用专项执行器
→ 验收
```

目标：验证减少中间层是否真正缩短完整 T_VALID。

## 路线 B｜GPT + Codex 强执行

```text
用户
→ GPT
→ Codex 为主要工程执行器
→ 工具 / 本地 / GitHub
→ 回传
→ GPT 验收
```

目标：验证大型编码、长工程任务中 Codex 是否降低返工和总时间。

## 路线 C｜旧式多层 Agent + 自动化编排

候选结构：
```text
总控
→ 搜索 / 执行 / 审核 / 汇总子智能体
→ 自动化编排
→ 现实执行器
```

当前允许状态：`NOT_READY`。

如果该路线尚未真正打通，不得伪造基准；先记录基础设施缺口。它同时可作为未来独立强备份候选。

## 每个正式任务统一记录

- TASK_ACCEPTED / FLOW_START；
- FINAL_VALID；
- 完整 T_VALID；
- 人工介入次数；
- 返工次数；
- 工具失败与恢复次数；
- 页面 / 会话迁移次数；
- 最终 Reality 证据。

后五项用于解释 T_VALID，不升级为第二优化目标。

## 首批任务要求

任务应覆盖至少：
- 本地文件/系统类；
- 编码/工具建设类；
- 网络研究 + 本地执行混合类；
- 长流程可恢复类。

第一批优先使用真实有价值任务，而不是为了 Benchmark 制造玩具任务。
