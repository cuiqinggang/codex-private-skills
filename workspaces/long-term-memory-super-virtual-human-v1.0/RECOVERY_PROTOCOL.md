# 长期记忆超级虚拟人｜恢复协议 v1.0

## 目标

GPT 页面、网络、工具或执行器发生暂时故障时，任务可以恢复，而不是重新开始。

## 恢复阶梯

```text
L0 正常执行
↓ 当前页异常
L1 同页最小重试
↓ 仍异常
L2 保存/读取 Checkpoint，换新 GPT 页面继续
↓ 本地直连异常
L3 Desktop Commander Remote → GitHub Windows runner
↓ 专项工具异常
L4 换成熟等价执行器（Codex / Reasonix / Browser / 其他）
↓ GPT 服务本身不可用
L5 独立强备份路线
↓ 全部不可用
BLOCKED：持久化当前状态，等待依赖恢复
```

## Checkpoint 最小内容

- 项目名 / 版本；
- 当前现实目标；
- FLOW_START；
- 当前 STATE；
- 已完成现实结果；
- 未完成事项；
- 当前工具和连接状态；
- 失败路径与根因；
- 下一步唯一动作；
- 必须继续遵守的安全边界；
- 关键文件、Commit、Run ID、Artifact ID。

## 页面切换原则

- 不追求无限长单页面；
- 页面只是工作内存；
- 权威状态必须写在项目工作区或长期记忆；
- 页面明显迟缓、上下文膨胀或反复遗漏时，Checkpoint 后换页；
- 换页恢复时间计入完整 T_VALID。

## 漂移纠正

高智能不能替代任务锚定。

每个长流程必须持续核对：
- 最终现实目标有没有变化；
- 当前动作是否仍直接服务 FINAL_VALID；
- 是否发生范围膨胀；
- 是否遗漏了已经承诺的子任务；
- 是否把局部完成误判成 FINAL_VALID。

发现偏移时，回到最近权威 Reality Contract / Checkpoint，而不是继续沿错误路线扩展。
