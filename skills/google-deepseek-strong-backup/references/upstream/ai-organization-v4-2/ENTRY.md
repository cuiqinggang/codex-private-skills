# AI 化组织 V4.2

方法版本：V4.2，2026-10-24 冻结。封装日期：2026-10-26；执行依赖补丁：2026-10-27，接入 Windows 执行桥 V12.0.4。组织方法仍为 V4.2，原冻结与业务验收证据保留。经验依赖接入：2026-10-27，reuse-experience-brain V1；见[经验接入与继承](references/memory-integration-20261027.md)。

## 核心合同

以固定质量、完整交付、可靠性、约定成本和授权为约束，最小化完整有效交付时间 T*=min(T_VALID)。从收到可执行任务至成品验收交付计墙钟，包含检索、接入、排队、配置、派发、审核、失败、返工和恢复。未验收记 NOT_VALID；未完整计时记 NOT_MEASURED；不得以局部耗时或推演宣称全局最优。

采用一套组织方法、一个统一入口、多个独立专业能力包。默认 GPT 直接完成小、中、大任务；仅在同合同完整 T_VALID 证据支持净收益且现有入口可用时，临时增加专业执行者或 CEO＋执行者双 GPT。双 GPT 不作为默认，候选最多三条，简单任务可只有一条。不另造调度器、锁、状态机或浏览器控制器。

## 连续执行

1. 定义最小合同：目标、真实输入、成品形态、质量底线、预算与约束、验收办法。信息足够直接做；仅询问影响结果的关键缺项，每轮最多三问，不为换页主动打断未完成任务。
2. 先复用成熟能力与已验证经验。相关任务先加载 reuse-experience-brain，实际读取共同工作区经验索引及最相关1—3张卡片，核对当前合同/版本后采用或拒绝；不能只加载专业技能而跳过匹配的旧解法。无命中直接继续，不全库注入。按 [能力路由](references/capability-routes.md) 加载本次相关原技能；必要时用 local-capability-index 查现有本机能力，再查外部成熟产品、官方接口和模板。不全库注入，不重复搭环境。
3. 涉及 Windows 时，在首次本机调用前原生加载 gpt-windows-execution-bridge 当前有效版本（本次 V12.0.4），先核验收费 A，并在派发前判断哪些步骤适合一次本地批量；不得被其他旧文档的 V12.0.1 引用覆盖。加载现有 dsh-extreme-effective-time；当前环境缺该技能时，按本入口和 [执行与恢复要点](references/operations.md) 执行，具体专业能力缺失须查清。比较成熟基线与至多三条可行路径，计入完整成本，不为组织层增加步骤。
4. 对输入→工具→成品→审核→故障→恢复→交付做虚拟成熟。核对关键依赖、数据语义、质量、授权、输出保存和副作用对账，以成熟处理覆盖主要反例。推演用于选路，不冒充实测。
5. 合同清楚、必需依赖可用、路径可执行、主要阻断有处理且继续搜索收益不足时，STOP_GATE→Freeze。冻结方案、配置和验收合同后，做一次整体 Reality。必要探针、分层检查和故障最小修复不算新的完整 Reality；不反复重跑已确认业务。
6. 普通故障自主修复并继续；实质换路线时记录依据并重新冻结受影响部分。长任务沿用 TASK_ID、N000/节点回执与检查点；已提交成果继承，未保存可重做部分作为沉没成本。不可逆外部动作结果 UNKNOWN 先只读核账，禁止盲重发。
7. 读回成品，优先确定性检查；复杂审核仅按净收益增派只读审核。交付成果、验收证据、完整时间及真实限制。旧经验确实影响行动时，在原任务回执记录经验ID/采用或拒绝/真实结果；交给原21点任务去重写回共同工作区，不另造记忆库。业务任务交付实际业务成果；只要求规则文档时可用文档一致性验收完成。

## 通道与专业能力

- Windows 的目录、文件、搜索、命令均先加载 gpt-windows-execution-bridge V12.0.4。严格 A=收费 Remote Desktop Commander → B=免费 GPT-Windows-MCP-Bridge → C=GitHub Actions Windows Runner，默认优先 A。动态发现 A 在线设备并无副作用探针，成功后继续 A。初测失败须重新发现并复验，保留两次失败证据且核清副作用才降级；B 同理。异步 running 按回执取结果，不视为失败；业务脚本报错不证明通道故障。
- A/B 共用安全本地批量：多文件纯读优先一次 read_multiple_files，本地读取→处理→校验闭环优先一次 start_process 复用成熟脚本；批量大小按依赖、授权、输出与恢复边界决定，不固定 5 项。逐项校验并汇总返回；RUNNING/PID 续读至真正结束，部分成功或 UNKNOWN 先核账，只续做确认未执行项。外部审批与不可逆提交按实际边界拆批；不新增执行层、调度器或连接池。细则以执行桥为准，见[执行桥依赖同步](references/bridge-integration-20261027.md)。
- 不改 FlClash、网络代理、凭据或其他任务配置；复用已授权专用浏览器与正式连接器，不独占浏览器或抢占其他任务资源。
- 网站/应用加载独立 V2.0 专业包；教育、视频、图片、文档等保留各自版本、合同和证据。只检查本次需要的条件，索引存在不等于已运行通过。
- 跨进程确有必要才复用现有 n8n 或受支持持久执行器，只有真实接单回执才称后台继续。保存文件不等于自动续跑。技能不赋予账号、发送、支付或后台调度权限。
