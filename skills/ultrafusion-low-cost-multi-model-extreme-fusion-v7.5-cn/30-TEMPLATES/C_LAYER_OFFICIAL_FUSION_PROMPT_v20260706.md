【新增：C 层“四维稠密融合”的刚性总约束（在后续各步骤中都必须贯彻）】

在执行后续 1.x / 2.x / 3.x 所有步骤时，必须额外同时满足以下刚性约束：

1. 必须显式识别并输出 3–5 条模型之间的关键分歧点
   （包括：矛盾结论、不同机制解释、不同适用范围 / 前提等）

2. 对每一条关键分歧，必须给出清晰的取舍理由：
   - 主要依据：
     - 事实稳健度（Fact robustness）
     - 逻辑密度与闭合程度（Logic density & closure）
     - 未来与长期价值（Long-term value）
     - 家庭 / 普通用户视角下的可执行性（Practical executability）

3. 对于仍无法在 C 层达成统一的观点，必须在结果中显式标记为：
   【不确定-Uncertain】
   并简要说明“不确定的来源”（例如：证据不足、模型分歧较大、超出当前资料范围等）。

4. 严禁把多份 B 稿“堆叠 / 拼盘式”罗列后就当作融合；
   所有保留内容必须经过实际的取舍决策与结构重组。

5. 最终融合稿 C_Fusion 必须体现“四维稠密”特征：
   -
 事实层：关键结论有可描述的证据类型支撑
   -
 逻辑层：重要结论都能追溯到清晰的因果链条或机制解释
   -
 价值层：相较任一单模型稿，有新增洞察 / 新视角 / 更高结构清晰度
   -
 执行层：对家庭 / 普通用户而言，有实际可操作的启发或路径，而非纯概念性描述

6. 如因系统截断导致输出未完成，必须严格遵守原模板“防截断规则”，在续写时补齐全部必需版块，不得用一句概括替代未展开内容。

【全局硬约束：证据与数据要求（领域通用）】


在下面执行所有步骤时，你必须同时遵守以下“证据与数据”硬规则（适用于任何领域）：

所有关键结论必须“有理有据”

可以接受的证据/依据类型包括但不限于：
• 本领域的权威指南、共识、标准、协议
• 系统综述、多篇文献交叉信息、技术报告
• 官方机构、政府部门、国际组织发布的信息或统计
• 主流教材、教科书、权威技术文档
• 官方统计数据、年报、白皮书、大型数据集
• 知名开源项目或产品的官方文档
• 在业界/学界被普遍采用的方法（需说明其普遍性与局限）

禁止捏造“看起来很专业”的具体数据

禁止无来源地编造：
• 精确百分比（例如：47.3%）
• 精确样本量（例如：n=1234）
• 具体期刊名 + 年份 + 卷期号组合
• 并不存在的标准号、法规号、文献编号等

如无法确认具体数值，只能使用：
“有资料提示”“部分文献/报告认为”“目前尚无一致定量结论”
并在合适处标注“需人工复核”。

关键事实必须尽量注明“证据来源类型”

对每条关键事实，尽量说明：
“依据本领域权威指南”“可在主流教科书中查证”“来源于官方统计数据”等来源类型，
而不是空口无依据。

不可验证内容必须降级处理

若某个信息目前不能通过公开权威资料或可靠来源验证：
必须标记为“不可验证/需人工复核”，不得当作确定事实强行使用。

对此类内容，只能作为假设或经验性建议呈现，并明确提醒存在不确定性。

一句话原则（务必遵守）

没有证据或来源类型说明，就没有充分说服力。

在后续 D 层中，凡是缺乏证据类型说明的关键句，都会显著拉低“准确性”评分。

一、B 层多通道综合评审 + 逻辑闭合性筛查

请你先对上述 3–4 份 B 层稿件进行系统评审，包含：

【1.1 内容维度评审（四维）】

对每份稿件分别评估：

准确性：
是否存在明显事实错误或严重“要证不证”的说法；

完备性：
是否覆盖本问题的关键方面，有无重要遗漏；

结构与清晰度：
是否条理清楚、层次合理、方便读者理解；

深度与洞察力：
是否给出了合理的机制分析、因果链、策略或启发。

请给出简洁的相对比较：

哪份在“准确性”上明显更稳？

哪份在“结构/可读性”上更好？

哪份在“深度/洞察力”上更有价值？

【1.2 逻辑闭合性筛查（C 层 v3.0 硬要求）】

对每份 B 稿，你必须检查并指出是否存在：

逻辑跳步：
直接从某个描述跳到结论，中间缺乏必要推理步骤或桥接论据；

逻辑断点：
推理链 A → B → C 中，某些中间环节在正文中未被说明或支撑；

循环论证：
结论 A 依赖于命题 B，而命题 B 又是通过命题 A 得出的；

前提不一致：
不同 B 稿对前提/假设的描述互相冲突，但各自给出相同结论且未解释差异；

结论冲突但无解释：
不同 B 稿对同一问题给出明显相反或不兼容结论，却未说明适用条件或背景差异。

你可以用简短列表形式，按稿件列出主要逻辑问题。

【1.3 反向一致性检查（Reverse Consistency Check）】

对于每份 B 稿中的关键结论，你需要回答两个问题（可以摘要呈现）：

若结论为真，哪些前提必须成立？

这些前提是否已经在稿件中被明确提出或有事实支撑？

若发现存在“隐含但未说明”的关键前提，你必须在评审报告中指出，并在后续 C_Fusion 中通过：

显式补写前提；

或者下调该结论的确定性/适用范围；
来修复这一问题。

【1.4 证据等级与结论强度匹配（Evidence Alignment Rule）】

你需要检查每份 B 稿中“证据类型”与“结论强度”是否匹配：

权威指南 / 标准 / 共识 → 可支持强结论；

系统综述 / 多篇可靠文献 → 可支持强或中等偏强结论；

单篇研究 / 案例报告 / 经验总结 → 通常只支持中等或偏弱结论；

数据或出处不明 / 无法验证 → 只能作为推测或可能性提出，不得写成确定性结论。

对于不匹配的地方（例如“弱证据却写成确定性结论”），你必须在后续 C_Fusion 中进行降级处理：

增加限定词（如“可能”“倾向于”“部分资料提示”）；

或明确标注“需人工复核”。

【1.5 输出：B 层综合评审报告】

请输出一份结构化的评审报告，至少包含：

各 B 稿在四个维度（准确性 / 完备性 / 结构 / 深度）上的相对表现概述；

各 B 稿在逻辑闭合性方面的主要问题清单（跳步、断点、循环论证、矛盾等）；

各 B 稿在证据等级与结论强度匹配上的明显问题；

当前综合表现最好的稿件（可以是某一份，也可以是“某稿为主干 + 某稿部分优点”的组合），并说明选择理由。

二、运行 V15 精神，生成融合极限稿 C_Fusion

在完成上述评审后，你需要在 V15 规范的约束下，以“融合优点、修复缺点”为目标，生成一个新的融合极限稿 C_Fusion。要求：

【2.1 融合策略（结构骨架 + 内容主干）】

以 结构最清晰、层次最合理 的 B 稿作为结构骨架；

以 事实最稳妥、证据来源类型最明确 的 B 稿作为内容主干；

从其它稿件中有选择地吸收：
• 更好的结构组织方式；
• 更有帮助的类比、示例、分层框架；
• 未被主干稿件覆盖但又重要的补充信息。

同时必须：

删除或修正所有存在事实错误、逻辑问题或证据等级不匹配的内容；

避免重复内容与啰嗦表述。

【2.2 C_Fusion 内部的“最小逻辑闭合单元”】

在 C_Fusion 中，每个关键结论，尽量具备一个“最小闭合单元”：

（已验证或可验证的事实）
→ （解释机制或推理步骤）
→ （适用范围/前提条件）
→ （结论表达）

如果任一环节缺失，该结论不得作为“强结论”呈现，必须：

降级为“可能”“倾向于”“部分资料提示”等；

或者明确写出“需人工复核”或“证据有限”。

【2.3 证据与结论强度一致】

在 C_Fusion 中，对于每个重要结论，应在文中用自然语言说明（可以嵌入句子，不必学术引用格式）：

这是基于何种证据类型（指南/标准/综述/官方文档/经验等）；

该证据类型大致支持的结论强度（强 / 中 / 弱）；

若证据有限，应明确提示不确定性。

【2.4 矛盾和差异的处理方式】

如果 B 稿之间存在相互矛盾的结论，你必须：

明确指出存在差异（可在 C_Fusion 中用一小段说明）；

尽可能基于证据质量选择更可靠的一侧；

说明选择的理由：
例如：某观点仅见于少数资料、缺乏支撑；另一观点有更多权威来源或更强逻辑支持；

或者，在证据确实不足以做出单一判断时，以“多个可能方案”的形式呈现，并标明各自局限与适用条件。

【2.5 输出：C_Fusion（融合极限稿）】

在上述原则下，生成一个结构清晰、逻辑基本闭合、证据与结论强度匹配、适合进入 D 层终检的融合极限稿，命名为：

C_Fusion
