# UltraFusion 6.1B 官网三模型极限答案工作台

日期：2026-07-02
版本：6.1B

## 1. 核心结论

UltraFusion 当前路线从 6.0 的：

```text
GPT 官网订阅版 + Kimi 官网会员版 + GLM-5.2 / GLM Coding Plan
```

修正为 6.1B 的：

```text
普通问题：GPT 直接回答
高价值 / 极限答案问题：GPT 官网 + DeepSeek 官网 + 千问/Qwen 官网
```

这次补充的重点是：不要把所有问题都复杂化。现在只保留两档路由。

## 2. 两档路由总规则

### 第一档：普通问题，GPT 直接回答

普通问题不是指问题一定很简单，而是指：

```text
GPT 本身已经能给出足够有价值的答案；
再调用 DeepSeek、千问/Qwen、V15、多模型融合，也不会显著增加答案质量。
```

这种问题直接由 GPT 回答即可。

不需要：

```text
DeepSeek
千问/Qwen
V15
A/B/C/D
三模型融合
复杂验收
```

### 第二档：高价值 / 极限答案问题，进入 UltraFusion

只有当额外工具能显著提升回答质量时，才进入 UltraFusion 流程。

触发条件：

```text
高价值问题；
复杂决策；
用户明确要求极限答案；
单 GPT 可能不够；
需要不同模型互审；
使用 DeepSeek / 千问 / V15 能显著提高答案质量；
需要写入技能包、知识库、命令包、长期规则或工程方案。
```

进入流程后使用：

```text
GPT 官网版 + DeepSeek 官网版 + 千问/Qwen 官网版
```

## 3. 模型定位

### GPT 官网版

```text
主脑 / 总控 / 直接回答入口 / 最终融合 / 最终验收 / 视觉多模态入口
```

GPT 是默认入口。普通问题直接结束在 GPT。

### DeepSeek 官网版

```text
低成本深度分析 / 反方审稿 / 高价值问题补深度
```

只在第二档中使用，只走官网，不走 API。

### 千问/Qwen 官网版

```text
第三视角 / 中文资料补充 / 搜索补充 / 多样性审稿
```

优先使用千问中文官网，模型优先 Qwen3.7-Max；必要时使用 Qwen 国际版。

### Kimi

```text
降级为备用，仅做少量高价值 Agent Swarm 标杆测试。
```

### GLM-5.2

```text
不进答案主链，仅作为工程执行、代码、技能包制作、文档结构化候选。
```

## 4. V15 边界

V15 不是默认必用。

```text
普通问题不用 V15。
只有高价值 / 极限答案 / 技能包 / 知识库 / 命令包 / 长期规则类任务，才使用 V15_FULL。
```

使用 V15 时不能只写“进入 V15 模式”，必须真实粘贴完整 V15_FULL。

标准结构：

```text
V15_Guard_Prefix
+ V15_FULL
+ 当前层模板
+ 用户问题 / 输入材料
+ 输出格式要求
```

## 5. 官网三模型的边界

官网三模型组合的定位是：

```text
极限答案工作台 / 高价值问题增强 / 模型互审 / 提示词评测台
```

不是：

```text
大规模自动化公共服务后端
```

未来公共服务需要单独工程化，包括入口、分级、缓存、低成本基础回答、高价值升级、合规 API 或私有化部署、风控和服务稳定性。

## 6. 验收规则

写入技能包、知识库或 GitHub 后，不直接标记 FINAL PASS。

需要：

```text
三轮实际测试 + 截图验证
```

没有截图验证，状态只能是：

```text
PENDING_THREE_ROUND_SCREENSHOT_VALIDATION
```

## 7. 最终一句话

```text
UltraFusion 6.1B 只保留两档：普通问题 GPT 直接回答；只有高价值或极限答案问题，并且额外模型/V15 能显著提升质量时，才进入 GPT + DeepSeek + 千问/Qwen 的 UltraFusion 流程。
```
