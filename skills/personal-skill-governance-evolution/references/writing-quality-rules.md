# 技能写作质量规则

仅在执行 `simplify`、`merge` 或修改 description/目录结构时读取。

1. 简洁不是目标本身；目标是在关键行为 100% 保留的前提下降低上下文和执行成本。
2. 删除重复规则、空泛解释、模型已知常识和失效历史。
3. description 优先保证路由准确，不设机械字数指标。
4. 区分用户显式入口、允许的自动触发和仅供内部使用的子流程。
5. 核心工作流留在 `SKILL.md`；变体、长清单和案例按需放入一层 `references/`。
6. 引用保持一层，不创建深层链式引用。
7. 同一规则只保留一个权威位置。
8. 每次删除或合并规则，都完成修改前后行为映射。
9. 每一步写清动作、检查和完成条件。
10. 一次优化只解决一个明确问题。
11. 自动整理不等于自动修改。
12. 不得仅为变短而删除门禁、排除条件、验证、证据或回滚。

完成条件：`behavior-map.tsv` 中所有 critical 规则均映射到候选位置且状态为 `covered`。
