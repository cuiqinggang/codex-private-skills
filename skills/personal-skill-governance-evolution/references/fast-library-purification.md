# 高速全库净化规则

仅在已有可信目录、活动视图和问题清单，且用户明确要求批量正式治理时使用。

## 分区与所有权

- 不重新全库盘点；从现成机器清单生成互斥分区。
- 权重：机械=1、一般结构=2、超长/触发重叠=3；系统、安全、退役、合并争议交总控。
- 一个技能在一次运行中只能有一个写入负责人；公共治理技能只由总控修改。

## 批次协议

1. 用显式 manifest 列出目标和确定性操作，禁止运行时模糊发现后直接改写。
2. 每批一个回滚根，每个技能保留独立 before 子目录和 SHA/行数/字符数。
3. 每项独立应用、验证和决定；失败只恢复该技能，继续后续项。
4. A 类全量静态检查并抽查10%；B 类全量行为合同并做代表性行为抽样；C 类每个重叠簇执行正向、反向、边界测试；D 类逐项完整验证。
5. 静态通过只证明结构正确，不得写成实际节省、成功率或业务收益。

## 可自动化与禁止边界

可自动化：精确字符串替换、已确认多余的 frontmatter 键、已确认备份/归档发现噪声迁出、候选文件复制、引用存在性与 quick_validate。

不得自动化：凭据读取/轮换、系统技能修改、用途不明的有效技能删除、语义不确定的合并/退役、依赖未冻结的高风险瘦身。

执行器：`scripts/fast_governance_batch.py`。它只处理显式 manifest，不扫描目标；每个技能先快照，失败后仅回滚该技能。
