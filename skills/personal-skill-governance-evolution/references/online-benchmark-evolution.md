# 联网对标增强净化

只在相关能力簇内增量运行；不得重新扫描整个技能库，也不得批量安装候选。

## 两批连续工作流

第一批：冻结本地基线，按实际任务聚类；一个能力簇做一次中英文系统搜索。优先官方规范、官方插件、原作者仓库和成熟开源项目，再看可追溯到原始项目的社区分享。每个候选记录原始来源、维护时间、真实示例、依赖、Windows/Codex 适配、API/付费/凭据、高风险命令、许可证和重复度。

对值得评估的候选使用同一任务集：正常任务、边界任务、失败恢复任务。每个任务同时记录本地、候选和增强方案的成功、质量、步骤、人工干预、时间、可取得的 Token、安全和可维护性。外部方案至少在一个重要指标上明确提升且不降低关键能力或安全性，才进入第二批。

第二批：优先吸收方法和组件，不整体照搬。先建批次回滚根和逐技能 before；只有总控可写公共治理技能。按显式 manifest 正式应用；单技能失败只恢复该技能并继续。增强后运行原有行为覆盖、正常/边界/失败恢复、误触发和依赖检查。

## 决策

- `ABSORB`：吸收已验证的局部优点。
- `COMPLEMENT`：外部能力独立且可作为可选补充，不并入默认链。
- `REPLACE_COMPONENT`：只替换内部组件，保留本地入口和门禁。
- `KEEP_LOCAL`：相同任务下本地更好或更适配。
- `REJECT`：无收益、不可追溯、许可证/安全/适配风险过高。
- `DEFER`：当前证据不足或无法做同任务验证。

许可证允许时保留 SPDX 标识、来源 URL 和必要通知；许可证未知或不允许复制时，只能独立实现方法。候选访问凭据、包含遥测或高风险命令时默认不执行；不能证明隔离方案则拒绝。

## 确定性门禁

将能力差异矩阵写成 JSON，运行 `python scripts\validate_online_benchmark.py <matrix.json> --summary <validation.json>`。验证器检查原始 HTTPS 来源、证据、许可证、安全缓解、三类同任务结果、六类决策，以及吸收项是否有可测提升且无安全回退。它不下载也不执行候选代码。

## 多智能体分区

总控先按实际能力形成互斥簇并登记唯一 owner。执行面只做搜索、核验和对标，不写公共技能；总控汇总候选、控制正式应用和单技能回滚。默认可用三面：长任务/编排/治理；浏览器/GitHub/知识/自动化；视频/设计/演示/图像/内容。按工作量调整簇，但禁止同一技能多 owner。

## 证据 2.0 硬门禁

- 候选必须标为 `EXECUTABLE`、`SERVICE` 或 `METHOD_OR_SPEC`。方法/规范不得伪装成可执行候选，服务不得在未授权、未实测时声称已验证。
- 每项指标必须带 `measurement_state`。只有 `MEASURED` 可以写数值，且必须同时提供运行 ID、UTC 起止时间、输入、输出、执行方式和状态；质量分还必须指向评分量表。
- 可执行候选进入 `ABSORB` 或 `REPLACE_COMPONENT` 前必须有隔离运行证据；方法候选必须在正常、边界、失败恢复三个任务上都有本地/增强 A/B 实测；服务候选必须另有明确授权和真实运行证据。
- 原始候选必须逐项归一化并闭账；重复来源可以合并为一个规范候选，但必须保留全部 raw ID，禁止用“去重”掩盖未处理候选。
- 每个能力簇必须保存中英文查询、UTC、来源类型和结果 ID；确实没有有效候选时写 `NO_VALID_CANDIDATE`，不得留空。
- 许可证 `VERIFIED` 必须指向直接许可证/条款地址并保存文件 SHA256 或官方引用；项目主页、Star、市场描述不能充当许可证证据。`UNKNOWN` 不得进入吸收。
- 新文件的 before 状态必须写 `ABSENT`，回滚动作必须是移动到可恢复隔离区；已有文件写 `PRESENT`、before SHA256 和恢复来源。禁止把“永久删除新增文件”写成默认回滚。
- 静态检查、导入成功和文字推演只能标为 `NOT_MEASURED`，不得换算成收益百分比、成功率、Token 或时间节省。

运行 `scripts/validate_online_benchmark.py` 后，只有校验为 `PASS` 且对应技能回归通过，才允许正式保留增强。单技能失败只恢复该技能，批次继续；最终由未参与实施的新审计智能体重新核对证据链。
