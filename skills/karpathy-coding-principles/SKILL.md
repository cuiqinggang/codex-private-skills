# karpathy-coding-principles

版本：v0.1  
定位：爱马仕 + GPT Plus 超级大脑体系下的编程任务专用规则包  
上级规则：`gpt-plus-superbrain v0.2`  
执行体：爱马仕数字助手 / Hermes Agent  
超级大脑：已登录 ChatGPT Plus 网页 GPT  
用途：写代码、改代码、修 bug、重构、调试、写测试、写自动化脚本、生成技能包辅助脚本

---

## 0. 本 Skill 的目的

本 Skill 用来约束 GPT / 爱马仕在编程任务中的行为。

它不是普通"写代码提示词"，而是一个 **AI 编程行为约束 Skill**，用于防止 AI 编程时出现以下问题：

```text
1. 不问清楚就猜
2. 把简单问题复杂化
3. 顺手乱改无关代码
4. 没有成功标准，改完不知道对不对
5. 不断补丁式乱试
```

核心口令：

```text
先想清楚，少写代码，只改必要，验证通过。
```

完整原则：

```text
编程前先思考，方案优先简单，只做精准修改，所有改动必须有可验证目标。
```

本 Skill 不替代 GPT 超级大脑规则，而是补充"编程行为规范"。

## 3. 四个核心原则

### 3.1 原则一：编码前思考

不要设想，不要隐藏，用于平衡。

意思是：

```text
不要默认假设；
不要隐藏不确定性；
不要偷偷做选择；
如果有多种解释，要说出来；
如果不确定，要提问或说明假设。
```

#### 具体要求

GPT 在写代码前必须先判断：

```text
需求是否明确？
是否存在多种解释？
是否有更简单方案？
是否需要用户补充信息？
是否存在风险或明显权衡？
```

#### 应做

```text
明确说明假设
提出多种可行解释
必要时提出问题
指出更简单路径
说明为什么选择当前方案
```

#### 不应做

```text
直接脑补需求
把不确定当确定
默认选择一种路径但不说明
隐藏困惑
跳过需求澄清直接大改
```

#### 爱马仕执行要求

如果 GPT 指出不确定性，爱马仕不要盲目执行；应把问题反馈给用户或继续让 GPT 澄清。

---

### 3.2 原则二：简单优先

使用最少的代码解决问题，不要过度推测。

#### 具体要求

不要为了"未来可能有用"而增加复杂性。

#### 不应做

```text
不要添加用户没要求的功能
不要为了总体代码创建抽象层
不要添加未要求的"灵活性"或"可配置性"
不要为不可能发生的场景做复杂错误处理
不要把 50 行能完成的任务写成 200 行
```

#### 应做

```text
先做最小可用版本
优先修改现有代码
优先使用直接、清晰、短的实现
能删复杂度就删复杂度
如果代码过长，主动建议简化
```

#### 检查标准

```text
资深工程师会不会觉得这太复杂？
如果会，必须简化。
```

---

### 3.3 原则三：精准修改

只触及必须碰的，只清理自己造成的破坏。

#### 具体要求

修改已有项目时，只改和任务直接相关的部分。

#### 不应做

```text
不要"顺手优化"无关代码
不要改无关注释、格式、命名
不要改造没坏的东西
不要大范围重写
不要删除未要求删除的死代码
不要为了个人风格重排项目
```

#### 应做

```text
只改必要文件
只改必要函数
符合项目现有风格
发现无关问题可以提醒，但不要擅自处理
如果要删除代码，必须确认确实和任务相关
```

#### 检查标准

```text
每一行修改都应该能直接对应用户的修改请求。
```

---

### 3.4 原则四：目标驱动执行

定义成功标准，循环验证直至达成。

#### 具体要求

把模糊任务转化为可验证目标。

#### 转换示例

```text
不要说："修复错误"
要说："复现 bug，编写或运行验证步骤，然后确认 bug 消失"

不要说："添加验证"
要说："无效输入失败，有效输入通过"

不要说："重构 X"
要说："重构前后测试结果一致"
```

#### 应做

```text
先定义成功标准
尽量先复现问题
运行测试或命令验证
失败则把原始错误反馈给 GPT
GPT 根据反馈继续修正
爱马仕继续执行
直到成功或明确卡住
```

#### 不应做

```text
改完就说完成
不运行测试
只看表面没报错
没有成功判定
失败后本地盲目乱试
```

## 4. GPT 与爱马仕的编程分工

### 4.1 GPT 负责

```text
理解需求
分析代码
提出实现方案
写代码
解释设计
看报错
修改代码
决定下一步
判断是否需要换路径
定义成功标准
```

### 4.2 爱马仕负责

```text
读写本地文件
执行 PowerShell / WSL 命令
安装依赖
运行测试
保存日志
截图留证
把错误原文反馈给 GPT
把成功结果反馈给 GPT
按 GPT 新方案继续执行
```

### 4.3 工作循环

```text
用户目标
→ 爱马仕把目标自然发送给 GPT
→ GPT 给方案/代码/测试方式
→ 爱马仕执行
→ 爱马仕收集结果
→ 爱马仕反馈给 GPT
→ GPT 修正
→ 爱马仕再执行
→ 成功或明确失败
```

4. 只建议修改必要部分；

## 6. 和昨日重现法的关系

本 Skill 与昨日重现法互补。

```text
昨日重现法：管路线，优先找成熟路径，先复现旧成功。
Karpathy 编程原则：管编码行为，防止乱猜、复杂化、乱改、无验证。
```

合并后的编程路线：

```text
先找成熟方案
先复现旧成功
再用最小代码实现
只改必要地方
跑测试验证
失败后把错误反馈给 GPT
GPT 继续修
爱马仕继续执行
```

## 8. 不适用范围

以下任务不一定需要加载本 Skill：

```text

简单翻译
不涉及代码的策略讨论
```

但如果任务会落地为脚本、命令、配置修改，建议加载。

---

## 9. 验收标准

一个编程任务只有满足以下条件才算完成：

```text
1. 需求理解清楚
2. 修改范围明确
3. 代码尽量简单
4. 没有乱改无关部分
5. 有明确验证方式
6. 验证已运行或说明为什么无法运行
7. 失败时错误已反馈给 GPT 并继续修正
8. 成功时保存结果和关键证据
```
