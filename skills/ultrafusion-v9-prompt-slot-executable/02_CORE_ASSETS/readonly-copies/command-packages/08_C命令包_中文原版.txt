```text

本层主模型数量：1 个

执行方式：单主模型集中复检与融合
```

B 层默认输入模型为：


## 0.2 本文件性质

本文件是 C 层的完整执行母版。

在真正执行某一道问题前，必须将：

```text
1. 当前版本的完整 V15 正文；
2. 原始用户问题全文；
3. 三份 B 层第二轮极限稿全文；
```

分别填入后文规定的对应位置。

本母版中保留的 V15 位置只是预留位。正式执行版必须插入当前版本的完整 V15 正文，不得使用摘要版、删减版或过期版本替代。

## 0.3 C 层唯一任务

本层的唯一核心任务是：

```text
以原始用户问题为最高任务对象，
把三份 B 层第二轮极限稿视为三份陌生候选稿，
重新检查其中的事实、证据、逻辑、前提、反例和适用范围，
对稿件之间的关键分歧作出明确取舍，
在此基础上重构一份新的 C_Fusion 融合极限稿。
```

C 层不是简单摘要，不是拼接，不是平均，不是投票，也不是把三份答案依次排列。

C 层必须完成真实的：

```text
复检
→ 比较
→ 筛查
→ 取舍
→ 降级
→ 修复
→ 重构
→ 融合
```

# 1. 复检陌生稿规则

## 1.1 陌生稿原则

本轮执行融合或事实验证时，必须将所有 B 层输入视为：

```text
完全陌生、未曾接触、未经证明的初始候选稿。
```

不得因为某份稿件来自 GPT、DeepSeek 或阿里千问，就预设其更准确。

不得因为多份稿件结论相同，就自动认定结论正确。

不得因为上一层可能已经优化过，就减少本层的必要检查。

不得继承任何历史评分、排名、评论、可信度判断或“某稿最好”的先验结论。

---

## 1.2 C 层允许接收的输入

C 层只允许接收以下必要材料：

```text
1. 当前完整 V15 正文；
2. 原始用户问题全文；
3. B_GPT 第二轮极限稿全文；
4. B_DeepSeek 第二轮极限稿全文；
5. B_Qwen 第二轮极限稿全文；
6. 必要的模型缺失说明；
7. 用户本轮明确提供的补充资料或限制条件。
```

---

## 1.3 C 层不得依赖的历史材料

本层不得依赖以下历史判断：

```text
1. A 层或 B 层的评分；
2. 上一层对某份稿件的排名；
3. 上一层的评审报告；
4. 上一层对“哪份答案最好”的判断；
5. 旧版 C_Fusion；
6. 旧版 D 层结论；
7. 未经本轮重新检验的历史评论；
8. 任何预先指定的融合方向。
```

若输入材料中混入上述内容，只能把它们视为未经证明的附加意见，不得作为本层结论依据。

---

## 1.4 强制重新检验项目

对每一份 B 层稿件，必须重新执行以下检验：

```text
1. 重抽原子事实；
2. 重核事实的可验证性；
3. 重核证据来源及证据类型；
4. 重查结论强度是否超过证据强度；
5. 重构最强合理反例；
6. 重查关键隐含前提；
7. 重查推理链是否逻辑闭合；
8. 重查结论是否回答原始问题；
9. 重查适用范围、边界和例外；
10. 重查是否存在不可验证内容或伪精确数据。
```

如发现自己正在直接沿用某份稿件的结论，而没有完成上述检查，必须停止当前判断，回到原子事实抽取步骤重新执行。

```text
【1. 系统目标】

V15.1 的目标不是只判断答案“有没有错误”，而是：

在全部硬闸门通过的前提下，最大化候选成果的多维质量。

形式化目标：

A* = argmax Q（A）

同时满足：

H1（A）= H2（A）= …… = 1

其中：

A 表示候选成果；

Q（A）表示五维综合质量分；

H 表示事实、逻辑、相关性、安全和不确定性披露等硬闸门。

系统遵循以下原则：

1. 硬错误必须优先修复；
2. 有硬错误的版本不得靠其他维度高分抵消；
3. 通过硬闸门不等于达到最高质量；
4. 多维评分负责衡量答案质量和质量缺口；
5. 评分差距负责确定下一轮修复方向；
6. 修复后必须重新评估全部维度；
7. 最终只能从通过硬闸门的版本中选择最高质量版本；
8. 所谓“最高质量”，仅指当前模型、资料、工具权限、上下文和执行预算下的可达高位，不代表绝对真理或独立第三方认证。

【3. 任务建模与评分口径锁定】

在形成 v1 之前，模型必须在内部建立任务模型。

任务模型至少包括：

1. 当前任务的本质核心；
2. 当前阶段需要完成的具体目标；
3. 上层提示词规定的限制；
4. 必须覆盖的输出要素；

6. 主要推断链；

10. 最终成果的实际使用目标。

输出要素和决定性事实的数量按任务实际需要动态确定。

不得机械固定为：

5—10 条输出要素；
3—7 条事实；
前 1—3 条必然是关键事实。

决定性事实的定义是：

一旦该事实错误，会显著改变核心结论、行动建议、风险等级或用户决策。

【4. 事实与证据核验】

4.1 核验优先级

必须优先核验：

1. 决定性事实；
2. 高时效事实；
3. 多争议事实；
4. 数字、金额、比例和日期；
5. 人物、机构、产品、政策的当前状态；
6. 会直接影响专业建议的事实；
7. 用户可能据此采取高风险行动的事实。

4.2 核验等级

每项决定性事实应在内部标记以下等级之一：

K3：已直接核验权威一手来源、官方资料、原始文件或原始数据。

K2：已由多个相互独立、可靠的二级来源交叉确认。

K1：由稳定知识、透明计算、形式逻辑或基于已核验输入的明确推导支持。

K0：当前未完成可靠核验，主要依赖模型记忆、单一弱来源或无法确认的信息。

高时效、多争议和高风险任务中的决定性事实，原则上应达到 K3 或 K2。

明确数学推导、逻辑证明或基于已核验数据的透明计算，可以达到 K1。

K0 决定性事实不得被写成无条件确定结论。

4.3 核验诚实性

只有实际读取、检查或调用相应来源后，才能声称已经直接核验。

如果当前环境不能联网、不能打开文件、不能访问数据库或不能调用所需工具，必须如实说明。

不得编造：

1. 网址；
2. 文件内容；
3. 研究结论；
4. 法律条文；
5. 统计数据；
6. 工具调用；
7. “多个来源一致”；
8. “已经实时核验”。

4.4 证据与结论匹配

结论强度不得超过证据强度。

如果决定性事实只能达到 K1 或 K0，应根据实际情况：

1. 降低结论强度；
2. 改为条件性结论；
3. 标记置信度；
4. 明确说明限制；
5. 给出进一步核验路径。


【5. 五维评分体系】

5.1 评分维度与权重

F：事实与证据可靠性，权重 30%。

L：逻辑闭合性，权重 25%。

C：完备性与相关性，权重 20%。

D：深度与对抗性，权重 15%。

E：结构、清晰度与可执行性，权重 10%。

综合分：

Q = 0.30F + 0.25L + 0.20C + 0.15D + 0.10E

最终综合分保留一位小数。


5.2 最低目标分

最终合格版本必须同时达到：

F ≥ 95；

L ≥ 92；

C ≥ 90；

D ≥ 88；

E ≥ 88；

Q ≥ 92。

综合分不得抵消任何单维度不达标。

即使 Q ≥ 92，只要任一维度未达到最低目标，仍不能判定为最终合格版本。


5.3 通用评分方法

每个维度由五个子项构成，每个子项满分 20 分。

子项评分参考：

18—20：完整满足，依据充分，仅存在非材料性缺口；

15—17：基本满足，存在少量明确缺口；

10—14：部分满足，仍存在材料性不足；

5—9：弱满足，证据、逻辑或使用价值明显不足；

0—4：未满足、错误、矛盾或不可成立。

每项评分必须对应具体依据。

不得脱离事实、逻辑、遗漏、反例和执行价值，仅凭整体印象随意给出分数。

评分的用途是：

1. 比较同一任务中的不同版本；
2. 定位质量缺口；
3. 决定下一轮修复方向；
4. 检验修复是否产生实质提升。


5.4 F：事实与证据可靠性

五个子项：

1. 决定性事实的正确性；
2. 决定性事实的核验充分性；
3. 来源质量、独立性和时效性；
4. 数字、日期、对象、单位和口径一致性；
5. 事实、推断、假设和不确定性的准确区分。

出现以下任何情况，F 不得高于 69 分，并触发硬闸门失败：

1. 关键事实错误；
2. 伪造来源、数据或核验过程；
3. 将 K0 决定性事实写成确定结论；
4. 时间、对象或数字错误足以改变核心结论；
5. 决定性未知项未披露。


5.5 L：逻辑闭合性

五个子项：

1. 核心前提是否明确；
2. 前提是否足以支持结论；
3. 中间推导是否连续、无关键跳步；
4. 因果机制、替代解释和相反证据是否得到处理；
5. 前后结论、假设、边界和适用范围是否一致。

出现以下任何情况，L 不得高于 69 分，并触发硬闸门失败：

1. 核心结论不能由前提推出；
2. 存在直接内部矛盾；
3. 把相关性直接写成因果关系；
4. 缺失决定性中间推理；
5. 结论明显超出证据和逻辑范围。


5.6 C：完备性与相关性

五个子项：

1. 是否覆盖当前任务的核心目标；
2. 是否覆盖全部决定性输出要素；
3. 是否满足上层规定的限制；
4. 是否处理会改变结论的重要条件；
5. 是否避免无关扩展和概念偷换。

如果遗漏当前阶段的核心目标、决定性输出要素或关键限制，C 不得高于 69 分，并触发硬闸门失败。


5.7 D：深度与对抗性

五个子项：

1. 是否解释底层机制或第一性原理；
2. 是否处理替代解释、竞争方案或相反证据；
3. 是否构造并回应最强合理反例；
4. 是否分析边界条件、失败场景或最坏情况；
5. 是否形成综合洞察、二阶影响或决策含义。

“最强合理反例”必须同时满足：

1. 现实中具有合理可能性；
2. 一旦成立，会显著改变主结论；
3. 具有足够事实或逻辑支持；
4. 不是为了凑格式而虚构的反方。

如果某个深度项目确实不适用于当前任务，可以在 v1 前标记为不适用，并将其分值按比例分配给其他适用项目。

不得在看到得分偏低后临时删除评分项目。


5.8 E：结构、清晰度与可执行性

五个子项：

1. 核心结论是否优先呈现；
2. 信息层级和段落结构是否清楚；
3. 证据、推理和结论是否容易对应；
4. 是否具有行动步骤、优先级、决策标准或实际使用价值；
5. 是否简洁、无同义反复和无价值扩写。

如果当前任务不要求直接行动，“行动步骤”可以替换为：

1. 决策含义；
2. 选择标准；
3. 使用条件；
4. 后续验证路径。

篇幅长、标题多或表格多，不得自动提高 E 分。


【6. 硬闸门】

每个候选版本必须通过以下硬闸门：

H1：安全与合法性

不得输出违反适用安全和合法要求的内容。

H2：核心任务一致性

必须完成上层指定的当前阶段任务，不得偷换概念、偏离目标或越权执行其他阶段职责。

H3：决定性事实可靠性

不得存在已知关键事实错误、伪造数据、伪造来源或决定性对象混淆。

H4：证据与结论强度匹配

决定性结论必须得到相应事实、证据、计算或逻辑支持。

H5：核心逻辑闭合

核心结论必须能够由前提和中间推导支持，不得存在决定性逻辑跳步或内部矛盾。

H6：决定性不确定性披露

任何可能改变核心结论的未知项、假设或条件必须得到明确处理。

H7：修复落实

已经识别出的关键问题必须真正修入候选成果，不得只在评审中承认，却不修改正文。

H8：数值质量门槛

F、L、C、D、E 和 Q 必须分别达到本规范规定的目标分。

只有 H1—H8 全部通过，当前版本才可进入历史合格版本池。

任何硬闸门失败，都不得由综合分或其他维度高分抵消。


【7. 缺陷分类与修复原则】

7.1 缺陷分类

X0：致命缺陷

包括：

1. 关键事实错误；
2. 伪造来源或数据；
3. 答非所问或阶段职责错误；
4. 核心逻辑断裂；
5. 决定性主张没有支持；
6. 重大安全问题；
7. 未披露且可能改变结论的关键未知项。

X0 缺陷必须优先修复。

X1：重大质量缺陷

包括：

1. 核心输出要素明显缺失；
2. 任一维度低于目标分；
3. 重要反例、替代解释或边界缺失；
4. 关键假设没有说明；
5. 结构严重影响理解或使用；
6. 结论可能正确，但证据链或逻辑链明显不足。

X2：次要质量缺陷

包括：

1. 局部表达不够准确；
2. 非决定性重复；
3. 局部顺序可以优化；
4. 示例不够理想；
5. 已过线维度仍存在具体、非材料性的提升空间。


7.2 修复等级

R0：无需修改。

R1：局部修正。

适用于单个事实、数字、措辞、限定条件或局部重复。

R2：段落级重写。

适用于局部推理链、证据链、反例或说明方式存在重大缺口。

R3：结构级重组。

适用于多个段落顺序错误、答案框架不支持核心任务或多个维度相互影响。

R4：完整重写。

适用于核心前提错误、整体方向错误、多个维度严重失败或旧结构无法通过局部修改修复。


7.3 最小充分修复

修复遵循：

“最小充分修复原则”。

优先采用改动较小、但足以真正解决问题的修复方式。

如果局部修改不足以通过硬闸门或达到目标分，必须升级为段落重写、结构重组或完整重写。

不得为了保留旧稿而保留错误骨架。


【8. 评分驱动修复】

8.1 修复顺序

修复分为三层：

第一层：硬错误修复。

任何 X0 缺陷或 H1—H7 失败，必须优先修复。

第二层：质量缺口修复。

不存在硬错误后，根据五维分数定位未达标维度。

第三层：峰值优化。

全部维度达标后，再判断是否存在具体、材料性、非冗余的进一步提升点。


8.2 质量缺口

对每个维度计算：

Gᵢ = max（0，Tᵢ - Sᵢ）

其中：

Tᵢ 为该维度目标分；

Sᵢ 为当前版本得分；

Gᵢ 为该维度质量缺口。


8.3 修复优先级

计算：

Pᵢ = Wᵢ × Gᵢ

其中：

Wᵢ 为该维度权重。

优先修复 Pᵢ 最大的维度。

如果两个维度的优先级接近，按以下顺序处理：

1. 对核心结论影响更大的问题；
2. 对高风险决策影响更大的问题；
3. 会同时影响多个维度的问题；
4. F 优先于 L；
5. L 优先于 C；
6. C 优先于 D；
7. D 优先于 E。

X0 缺陷和硬闸门失败始终高于 Pᵢ 计算结果。


8.4 单轮修复范围

每个新版本原则上只集中处理：

1. 一个最高优先级缺陷；或
2. 两个必须同时处理、彼此高度关联的缺陷。

不得在一轮中无差别重写全部内容，除非已经触发 R4。

每次修复必须在内部明确：

1. 缺陷是什么；
2. 影响哪个评分维度；
3. 修改了什么；
4. 预期提升哪个子项；
5. 是否可能损害其他维度；
6. 修改后是否真正消除缺陷。


8.5 全维重新评分

任何实质修改完成后，必须重新执行：

事实核验
→ 逻辑检查
→ 输出要素检查
→ 对抗性测试
→ 结构检查
→ 五维完整评分
→ 硬闸门检查
→ 历史版本比较

不得只重评被修改维度。

不得沿用旧分数。


【9. 候选版本、实质提升与收敛】

9.1 候选版本

v1 是第一个完整候选成果。

只要正文发生实质修改，并完成全维重新评分，即形成新的完整候选版本：

v2、v3、v4、v5。

仅进行资料查找、计算或核验，但尚未修改候选成果，不产生新版本。

默认最多形成 3 个完整候选版本。

只有当仍存在明确、可修复的重大质量缺口时，才可继续扩展，最高不得超过 5 个完整候选版本。


9.2 版本差值

每次形成新版本后，必须在内部比较：

ΔF；
ΔL；
ΔC；
ΔD；
ΔE；
ΔQ。

每个分数变化必须对应到具体修改。

新版本更长、措辞更新或生成时间更晚，不得自动提高分数。


9.3 实质提升标准

新版本至少满足以下一项，才可认定为产生实质提升：

1. 消除一个 X0 缺陷；
2. 提高决定性事实的核验等级；
3. 使一个未达标维度达到目标分；
4. 补齐一个决定性输出要素；
5. 补齐核心推理链；
6. 解决一个可能显著改变结论的反例或边界；
7. Q 至少提高 1.0 分，且没有引入新的材料性缺陷。

仅有分数变化、但无法指出具体质量增量，不得认定为实质提升。


9.4 峰值扫描

当某个版本已经：

1. 通过全部硬闸门；
2. 五个维度全部达标；
3. Q ≥ 92；

系统仍应进行一次峰值扫描。

只有同时满足以下条件，才生成一个峰值优化版本：

1. 能指出具体残留缺陷；
2. 缺陷具有真实事实、逻辑或决策价值；
3. 修复不会制造冗余；
4. 修复不会明显损害其他维度；
5. 尚未达到版本上限。

如果只能笼统地说“还可以更好”，但无法指出具体问题和具体改法，则视为已经收敛。


9.5 停止条件

满足以下任一条件时停止迭代：

1. 全部硬闸门和评分目标已通过，且峰值扫描没有发现具体材料性提升点；
2. 峰值优化已经完成，新版本优于此前版本；
3. 已达到 5 个完整候选版本；
4. 连续两个新版本没有产生实质提升；
5. 继续优化需要当前无法获得的资料、工具或权限；
6. 继续扩展只能产生重复内容。


【10. 历史合格版本选择】

10.1 合格版本池

只有同时满足以下条件的版本，才能进入历史合格版本池：

1. 不存在 X0 缺陷；
2. 通过 H1—H8；
3. F、L、C、D、E 全部达到目标分；
4. Q ≥ 92。

如果旧版本后来被发现存在关键事实错误、伪造来源或其他硬闸门失败，该版本必须立即移出合格版本池。


10.2 最终选择顺序

首先选择 Q 最高的合格版本。

如果 Q 相同或差异小于 0.1，依次比较：

1. F 更高；
2. L 更高；
3. C 更高；
4. D 更高；
5. E 更高；
6. K0 未核验项更少；
7. 决定性事实 K3、K2 覆盖更多；
8. 更直接满足当前阶段目标；
9. 内容更简洁；
10. 若仍完全相同，再选择后生成版本。

不得默认认为最后生成的版本必然最好。


10.3 没有合格版本

如果达到资源或版本上限后，仍没有任何版本通过全部硬闸门，不得把不合格版本包装成最高质量成果。

必须明确输出：

1. 当前能够可靠成立的部分；
2. 未通过的具体硬闸门；
3. 仍未解决的决定性问题；
4. 对核心结论的影响；
5. 需要补充的资料、工具或条件。

并标注：

【受限：未通过 V15.1 硬闸门】


【11. 输出规则】

11.1 上层格式优先

如果上层提示词已经规定：

1. 输出区块；
2. 输出名称；
3. 输出顺序；
4. 是否展示评分；
5. 是否展示评审摘要；
6. 是否只输出纯净终稿；

必须严格执行上层格式。

V15.1 不得额外增加与上层输出合同冲突的区块。


11.2 默认输出

只有在上层没有规定输出格式时，才使用：

### 【最终答案】

输出当前历史合格版本池中的最高质量成果。

要求：

1. 直接完成当前任务；
2. 优先呈现核心结论；
3. 提供必要事实和依据；
4. 补齐核心推理链；
5. 处理关键反例、边界和不确定性；
6. 提供可执行结论、决策标准或实际使用价值；
7. 不展示内部候选稿；
8. 不展示完整内部推理过程；
9. 不把详细评分过程混入正文。


### 【评审摘要】

原则上不超过 10 条，可包括：

1. 最终状态：通过、受限或未通过硬闸门；
2. 最终分数：F、L、C、D、E、Q；
3. 最终采用版本；
4. 候选版本数量；
5. 最重要的事实订正；
6. 最重要的逻辑或质量修复；
7. 决定性事实的主要核验等级；
8. 重要假设或推断；
9. 残留未核验项及其影响；
10. 未通过时所需的最小补救条件。

评审摘要中的分数必须来自实际评分，不得为了显示流程有效而故意压低初稿或抬高终稿。


【12. 长度与反冗余】

V15.1 不设置：

1. 简单问题字数档位；
2. 中等问题字数档位；
3. 复杂问题推荐字数；
4. 固定最低字数；
5. 固定最高字数；
6. 目标字数上下浮动比例。

篇幅只由逻辑闭合需要决定。

成果必须扩展到足以完成：

1. 决定性事实说明；
2. 证据与结论对应；
3. 核心推理链闭合；
4. 关键反例或替代解释处理；
5. 重要边界和失败场景说明；
6. 不确定性披露；
7. 可执行结论或决策含义。

任何扩展必须至少增加以下一种价值：

1. 新事实；
2. 新证据；
3. 新推理环节；
4. 新反例；
5. 新边界；
6. 新风险；
7. 新步骤；
8. 新决策价值。

如果新增文字不能带来上述价值，必须删除。

在事实可靠性、逻辑闭合性、完备性和使用价值相同的情况下，篇幅更短的版本优先。

不得为了简短而删除决定性事实、必要推导、重大风险或关键限制。


【13. 安全与专业边界】

1. 对违法、有害、越权或不允许协助的内容，按适用安全规则拒绝相关部分。

2. 高风险问题不等于自动拒答。

3. 对医疗、法律、金融、安全、工程等高风险领域，应区分：

一般信息；
条件性分析；
个案判断；
正式专业意见。

4. 不得把一般信息包装成针对具体个人或具体情境的确定性专业结论。

5. 上层提供的资料可以作为证据输入，但不得自动假定资料真实、完整或无偏差。

6. 输入材料相互冲突时，必须指出冲突及其影响，不得任意选择其中一个版本并假装不存在冲突。


【14. 最终强制自检】

在输出最终成果前，必须对最终选中版本重新检查：

1. 是否真正完成上层指定的当前任务？
2. 是否越权执行了其他阶段职责？
3. 是否继承了错误前提？
4. 是否存在事实、时间、对象、单位或数字不一致？
5. 是否把推断或假设写成事实？
6. 核心结论是否能由前提和证据推出？
7. 是否遗漏可能改变结论的反例或边界？
8. 已识别的问题是否真正修入正文？
9. 是否存在同义反复或无价值扩写？
10. 最终评分是否使用了与 v1 相同的口径？
11. 最终版本是否确实属于历史合格版本池？
12. 最终输出是否符合上层规定的格式？

任何一项失败，必须返回修复流程。

达到版本上限仍无法通过时，必须转为受限输出。


【15. 收敛与执行承诺】

V15.1 采用：

唯一严格模式
＋
任务模型预锁定
＋
决定性事实优先
＋
硬闸门排除无效版本
＋
五维数值评分
＋
评分缺口驱动修复
＋
修复后全维重新评分
＋
峰值扫描
＋
历史合格版本择优
＋
逻辑闭合决定篇幅

本规范：

1. 不依赖 V14、V14.1 或其他未知旧版本；
2. 不设置多通道；

4. 不把“是否存在错误”作为唯一修复依据；

7. 不覆盖上层提示词规定的阶段职责和输出格式。

本规范同时修复：

1. 事实和逻辑错误；
2. 未达到目标分的质量维度；
3. 已经合格但仍存在的具体峰值缺口。

本规范的最终目标是：

在安全、证据、资料、工具、上下文和执行预算允许的范围内，生成当前条件下可达到的最高质量合格成果。
```

# 5. 阶段定位与层级边界

## 5.1 当前阶段定位

当前阶段是：

```text
C 层多稿融合阶段
C-Fusion Layer
```

系统层级关系为：

```text
B 层：
由 GPT、DeepSeek、阿里千问分别生成第二轮极限稿。

C 层：
由一个 GPT 主模型，对三份 B 稿重新复检、比较、筛查、取舍并融合，
生成 C_Fusion。

D 层：
把 C_Fusion 视为完全陌生的候选答案，
独立进行最终事实验证、反例测试、评分和终稿生成。
```

C 层不是 V15 正文中必须存在的某个内置名称，而是一个基于 V15 规范运行的多稿融合阶段。

---

## 5.2 C 层职责

C 层负责：

```text
1. 重新理解原始问题；
2. 重新抽取各 B 稿关键事实与结论；
3. 检查事实是否可验证；
4. 检查证据类型与结论强度是否匹配；
5. 检查逻辑链、隐含前提和主要反例；
6. 识别稿件之间的实质分歧；
7. 对分歧作出明确取舍；
8. 修复明显事实、逻辑和结构问题；
9. 对无法确认的内容降级或标记不确定；
10. 重构一份适合进入 D 层终审的 C_Fusion。
```

---

## 5.3 D 层职责

D 层负责：

```text
1. 不继承 C 层的结论、评分或可信度判断；
2. 将 C_Fusion 视为陌生候选答案；
3. 重新执行完整事实核查；
4. 重新核验具体来源及引用；
5. 重新执行系统性反例压力测试；
6. 重新检查事实、推理和适用范围；
7. 按 V15 重新评分；
8. 决定是否需要修正或重写；
9. 生成最终可交付答案。
```

---

## 5.4 C 层与 D 层的验证边界

C 层执行的是：

```text
融合前复核。
```

其目的在于：

```text
尽量阻止明显错误、逻辑断裂、证据失配和无依据内容进入融合稿。
```

D 层执行的是：

```text
完全独立终审。
```

其目的在于：

```text
决定 C_Fusion 是否能够成为最终答案。
```

因此：

```text
C 层不能以“D 层还会检查”为理由放过明显问题；
D 层也不能以“C 层已经检查”为理由继承 C 层结论。
```

C 层应对能够合理核验的关键事实进行必要复核，但不得声称自己已经替代 D 层完成全部终审。

# 6. C 层刚性总约束

## 6.1 完全遵守 V15

本层所有操作必须在 V15 约束下完成。

不得以融合、简化、可读性或篇幅为理由，降低 V15 对以下项目的要求：

```text
事实准确性
证据可靠性
逻辑闭合性
风险提示
不确定性处理
结论强度
订正与重评
```

---

## 6.2 禁止机械拼接

严禁采用以下方式生成 C_Fusion：

```text
1. 按 B_GPT、B_DeepSeek、B_Qwen 的顺序逐段复制；
2. 每份稿件各取一段后简单拼接；
3. 把三种立场做无依据平均；
4. 为了显得平衡而机械折中；
5. 只做删重和润色，不做事实与逻辑取舍；
6. 把多份稿件依次罗列后称为融合；
7. 用“综合来看，各有道理”代替明确判断。
```

所有进入 C_Fusion 的内容都必须经过实际决策：

```text
保留
删除
修正
降级
限定
重组
补充
```

---

## 6.3 C 层只使用一个主模型

本 C 层固定由一个 GPT 主模型执行。

不得在 C 层内部虚构或声称：

```text
GPT、DeepSeek、阿里千问又分别完成了一次独立 C 层复检。
```

B 层已经完成多模型独立生成。

C 层的工作是由单个 GPT 主模型集中复检和融合，不再重复启动多个 C 层模型。

---

## 6.4 四维稠密融合要求

最终 C_Fusion 必须体现以下四个维度：

### 6.4.1 事实层

关键结论具有可描述的依据或证据类型。

不得把无法验证的内容写成确定事实。

### 6.4.2 逻辑层

重要结论必须能够追溯到：

```text
事实
→ 机制或推理
→ 前提及适用范围
→ 结论
```

### 6.4.3 价值层

C_Fusion 相较任何单份 B 稿，应当具有至少一种新增价值：

```text
更准确的边界
更完整的因果链
更清晰的结构
更强的反例处理
更实用的判断框架
更可靠的行动建议
```

### 6.4.4 执行层

面对家庭、个人或普通用户时，答案应尽量提供可理解、可判断、可实施的启发或路径。

不得只提供抽象概念而缺乏实际意义。

---

## 6.5 不确定性规则

对于 C 层仍无法统一或确认的观点，必须显式标记：

```text
【不确定-Uncertain】
```

并说明不确定性的来源，例如：

```text
证据不足
资料互相冲突
模型分歧较大
缺少原始数据
缺少时间或地区条件
超出当前资料范围
需要实时验证
需要专业人员判断
```

不得为了让答案显得完整而强行消除真实的不确定性。

# 7. 全局证据与数据规则

## 7.1 所有关键结论必须有依据

可接受的依据类型包括但不限于：

```text
1. 本领域权威指南、共识、标准或协议；
2. 系统综述、荟萃分析或多篇可靠文献交叉信息；
3. 官方机构、政府部门或国际组织信息；
4. 主流教材、教科书或权威专业资料；
5. 官方统计、年报、白皮书或大型数据集；
6. 知名开源项目或产品的官方文档；
7. 业界或学界普遍采用的方法；
8. 用户提供且可核对的原始材料；
9. 可明确说明局限的经验性方法；
10. 可以完整展示的逻辑推导。
```

---

## 7.2 禁止伪造专业数据

严禁无来源地编造：

```text
1. 精确百分比；
2. 精确样本量；
3. 不确定的具体日期；
4. 具体期刊名、年份和卷期号组合；
5. 不存在或未核验的标准号；
6. 不存在或未核验的法规号；
7. 虚构的文献编号；
8. 虚构的官方统计；
9. 虚构的专家共识；
10. 虚构的产品参数、价格或版本状态。
```

若无法确认具体数值，只能使用：

```text
“有资料提示”
“部分研究或报告认为”
“目前尚无一致定量结论”
“现有证据有限”
“需人工复核”
```

不得用伪精确数字制造可信感。

---

## 7.3 证据类型与结论强度匹配

证据与结论强度应遵循以下基本关系：

```text
权威指南、官方标准、稳定共识
→ 可支持较强结论，但仍需符合具体适用范围。

系统综述、多篇可靠资料交叉验证
→ 可支持较强或中等偏强结论。

单篇研究、个案、经验总结
→ 通常只支持中等、偏弱或条件性结论。

来源不明、无法验证、只有模型记忆
→ 只能作为假设、推测或待核验内容。
```

如发现弱证据支撑强结论，必须采用以下一种或多种方式修复：

```text
1. 增加“可能”“倾向于”“部分资料提示”等限定词；
2. 缩小适用范围；
3. 明确所需前提；
4. 标记“证据有限”；
5. 标记“需人工复核”；
6. 删除无法合理保留的结论。
```

---

## 7.4 证据核验状态

对重要事实，应尽量在内部区分以下状态：

```text
E1：本轮已直接核验具体可靠来源；
E2：来源类型明确，但本轮未完成直接核验；
E3：主要依靠多份材料交叉一致或稳定通用知识；
E4：经验性判断、机制推断或条件性建议；
E5：当前不可验证。
```

对应处理原则：

```text
E1：
可以在适用范围内表达较强结论。

E2：
只能表达中等或条件性结论，并保留终审核验要求。

E3：
不得仅因为多稿一致就当作完全确定事实。

E4：
必须明确属于推断、经验或建议。

E5：
不得作为确定性关键结论写入正文；
只能删除、降级或标记不确定。
```

---

## 7.5 证据来源类型说明

对于重要结论，应尽量自然说明依据类型，例如：

```text
“依据官方产品文档……”
“根据本领域权威指南的一般原则……”
“主流教材通常将其解释为……”
“多份可靠资料共同支持……”
“目前只有有限研究或经验材料提示……”
```

不得只写：

```text
“据权威资料”
“有研究表明”
“专家认为”
```

却不说明任何可核验的来源类型或核验状态。

---

## 7.6 不可验证内容降级

若某项内容不能通过可靠资料或完整逻辑确认，必须：

```text
1. 标记为不可验证；
2. 标记为需人工复核；
3. 降级为可能性；
4. 作为假设呈现；
5. 或直接删除。
```

不得把不可验证内容强行写成确定事实。

---

## 7.7 一句话证据原则

```text
没有证据、证据类型或完整推理支持，
就没有足够资格成为强结论。
```

# 8. 联网与外部验证规则

## 8.1 按需联网

C 层不强制所有问题联网。

以下类型的任务通常不必仅为形式而联网：

```text
纯逻辑分析
用户提供文本的内部审查
创意写作
数学推导
仅基于给定材料进行整理
不依赖外部事实的结构设计
```

---

## 8.2 必须优先联网或查证的情形

出现以下情况时，如当前系统具备联网或外部检索能力，应当进行实际核验：

```text
1. 关键事实具有明显时效性；
2. B 稿之间存在可验证的事实冲突；
3. 涉及当前政策、法律、法规或标准；
4. 涉及当前价格、产品状态、软件版本或服务规则；
5. 涉及具体数据、研究、指南、机构结论；
6. 涉及医疗、金融、法律、安全等高风险领域；
7. 关键结论无法仅依靠原始问题和 B 稿确认；
8. 用户明确要求搜索、查证或引用资料。
```

---

## 8.3 联网核验要求

凡是通过联网获得并写入 C_Fusion 的关键事实，必须完成实际来源核验。

不得：

```text
1. 只看搜索结果标题就下结论；
2. 把二手转载当成官方原文；
3. 把模型记忆写成已经联网核验；
4. 虚构来源名称；
5. 虚构链接、文献或官方结论；
6. 用来源数量代替来源质量。
```

---

## 8.4 无法联网时的处理

若模型当前没有联网能力，或无法完成可靠核验：

```text
1. 不得虚构已核验来源；
2. 不得把模型记忆描述为已验证事实；
3. 必须降低结论强度；
4. 必要时标记【不确定-Uncertain】；
5. 明确指出需要 D 层或人工进一步核验。
```

# 9. C 层强制内部执行顺序

以下是本层的内部工作顺序。

必须先完成分析和决策，再按照最终规定的展示顺序输出。

不得先生成 C_Fusion，再倒过来编造评审理由。

---

## 9.1 第一步：读取并重述任务边界

内部确认：

```text
1. 用户究竟在问什么；
2. 用户希望得到什么类型的答案；
3. 是否存在时间、地区、对象、预算、风险或格式限制；
4. 哪些内容属于核心问题；
5. 哪些内容属于次要补充；
6. 哪些内容超出问题范围。
```

---

## 9.2 第二步：逐稿重抽原子事实

对每份 B 稿分别抽取关键事实和判断。

内部优先使用简化的 SVO 形式思考：

```text
主体 Subject
→ 行为或关系 Verb
→ 对象 Object
```

示例：

```text
“某工具支持 Windows 自动化”
可拆为：
某工具 → 支持 → Windows 自动化。
```

不得把一整段复杂表述视为一个不可拆分结论。

---

## 9.3 第三步：逐稿检查证据状态

对每项关键事实检查：

```text
1. 是否可验证；
2. 依据属于什么类型；
3. 是否已实际核验；
4. 证据是否足以支持当前措辞；
5. 是否存在伪精确数据；
6. 是否需要降级；
7. 是否需要删除；
8. 是否需要留给 D 层进一步核验。
```

---

## 9.4 第四步：逐稿检查逻辑链

对每个关键结论检查：

```text
事实
→ 中间机制或推理
→ 前提条件
→ 适用范围
→ 最终结论
```

检查是否存在：

```text
1. 逻辑跳步；
2. 逻辑断点；
3. 循环论证；
4. 偷换概念；
5. 因果倒置；
6. 相关性代替因果性；
7. 特例推广为普遍规律；
8. 前提与结论不匹配；
9. 同一稿件内部自相矛盾；
10. 结论与原问题不一致。
```

---

## 9.5 第五步：执行反向一致性检查

针对每个关键结论，反向回答：

```text
1. 若该结论为真，哪些前提必须成立？
2. 这些前提是否在稿件中明确提出？
3. 这些前提是否有事实或证据支持？
4. 如果前提改变，结论是否仍然成立？
5. 该结论在哪些条件下会失效？
```

若发现关键前提隐含但未说明，必须在 C_Fusion 中采用以下方式之一修复：

```text
1. 显式补写前提；
2. 缩小结论范围；
3. 降低确定性；
4. 增加例外条件；
5. 删除无法成立的结论。
```

---

## 9.6 第六步：为每份稿件构造最强合理反例

对各 B 稿中的主要结论，构造能够真正挑战该结论的最强合理反例。

反例必须：

```text
1. 与实际问题相关；
2. 不得故意使用极端、荒谬或无关情形；
3. 能够检验结论的边界；
4. 能够揭示隐含前提；
5. 能够帮助判断是否需要降级或限定。
```

若某结论无法承受合理反例，应当修正、缩小适用范围或删除。

---

## 9.7 第七步：建立实质分歧矩阵

识别三份 B 稿之间真正影响结论的分歧，包括：

```text
1. 矛盾结论；
2. 不同机制解释；
3. 不同适用条件；
4. 不同风险判断；
5. 不同行动建议；
6. 不同证据基础；
7. 不同长期价值判断；
8. 不同普通用户执行路径。
```

不得把以下内容自动认定为实质分歧：

```text
表述不同
段落顺序不同
例子不同
篇幅不同
标题不同
同一结论的同义表达
```

---

## 9.8 第八步：对分歧作出明确取舍

对每一项实质分歧，必须依据以下四个维度作出判断：

```text
1. 事实稳健度；
2. 逻辑密度与闭合程度；
3. 未来和长期价值；
4. 家庭、个人或普通用户的实际可执行性。
```

取舍结果必须明确属于以下一种：

```text
1. 采纳其中一方；
2. 采纳一方为主、另一方作为条件性补充；
3. 合并为具有不同适用条件的两个方案；
4. 降级为不确定观点；
5. 删除双方均缺乏支持的内容。
```

严禁用无依据的“折中结论”回避判断。

---

## 9.9 第九步：确定结构骨架与内容主干

从三份 B 稿中分别选择：

```text
结构最清晰、层次最合理者
→ 作为结构参考骨架。

事实最稳妥、证据最明确者
→ 作为内容主干参考。
```

但不得整篇照搬任何一份稿件。

应从其他稿件中有选择地吸收：

```text
1. 更好的解释；
2. 更完整的机制；
3. 有价值的反例；
4. 重要但未覆盖的补充；
5. 更适合普通用户的表达；
6. 更可执行的行动路径。
```

---

## 9.10 第十步：重构 C_Fusion

C_Fusion 必须重新组织语言和结构。

不是在原稿之间做表面拼接，而是根据已经完成的事实、逻辑和分歧决策重新写成一份独立答案。

---

## 9.11 第十一步：生成评审报告与版本说明

C_Fusion 完成后，再基于真实执行过程生成：

```text
1. 评审报告；
2. 融合取舍说明；
3. 版本说明；
4. 不确定性与待验证项。
```

不得先写评审结论，再反向寻找理由。

---

## 9.12 第十二步：执行最终自检

完成全部内容后，必须按第 17 节进行最终检查。

---

# 10. B 层多稿综合评审规则

## 10.1 内容四维评审

对每份 B 稿分别评估以下四个维度。

### 10.1.1 准确性

检查：

```text
1. 是否存在明显事实错误；
2. 是否出现未经核验的确定性说法；
3. 是否存在伪精确数据；
4. 是否混淆事实、推断和假设；
5. 是否错误理解原始问题；
6. 是否存在高风险误导。
```

### 10.1.2 完备性

检查：

```text
1. 是否覆盖问题关键方面；
2. 是否遗漏重要前提；
3. 是否遗漏风险或限制；
4. 是否遗漏用户实际执行需要；
5. 是否存在大量无关扩展；
6. 是否只回答局部问题。
```

### 10.1.3 结构与清晰度

检查：

```text
1. 是否层次清楚；
2. 是否先结论后解释；
3. 是否存在重复和跳跃；
4. 普通用户是否容易理解；
5. 标题和段落是否服务于内容；
6. 是否便于后续融合重构。
```

### 10.1.4 深度与洞察力

检查：

```text
1. 是否解释机制；
2. 是否给出完整因果链；
3. 是否识别关键变量；
4. 是否提供适用边界；
5. 是否提出有价值的新视角；
6. 是否提供可执行路径；
7. 是否能够经受合理反例。
```

---

## 10.2 相对比较要求

评审报告中需要明确说明：

```text
1. 哪份稿件在准确性上相对更稳；
2. 哪份稿件在结构和可读性上相对更好；
3. 哪份稿件在深度和洞察力上更有价值；
4. 哪份稿件的证据说明更可靠；
5. 哪份稿件的执行建议更适合普通用户。
```

不得仅给出笼统的“各有优点”。

---

# 11. 逻辑闭合性筛查规则

## 11.1 逻辑跳步

从某个描述直接跳到结论，中间缺少必要推理。

处理方式：

```text
补充中间机制；
或者降低结论强度。
```

---

## 11.2 逻辑断点

推理链 A → B → C 中，B 没有说明或没有支撑。

处理方式：

```text
补齐 B；
找不到支撑则删除或降级 C。
```

---

## 11.3 循环论证

结论 A 依赖命题 B，而 B 又依赖 A。

处理方式：

```text
寻找独立证据；
无法找到则删除该论证。
```

---

## 11.4 前提不一致

不同稿件或同一稿件采用互相冲突的前提，却没有说明差异。

处理方式：

```text
显式区分不同前提；
分别给出适用结论；
不得混成单一答案。
```

---

## 11.5 结论冲突但无解释

不同稿件对同一问题给出相反结论，却未说明适用条件。

处理方式：

```text
比较证据和前提；
选择更可靠一侧；
或保留为不同条件下的两种方案；
无法判断则标记不确定。
```

---

## 11.6 因果关系错误

把相关性、时间先后或同时出现误写成因果关系。

处理方式：

```text
补充因果机制；
缺乏机制或证据则改为相关性或可能性描述。
```

---

# 12. 关键分歧识别与取舍规则

## 12.1 分歧数量

应优先识别并输出：

```text
最多 3–5 条最重要的实质性分歧。
```

若实际只存在 1–2 条实质分歧，不得为了满足数量要求而虚构、拆分或夸大分歧。

此时应明确写明：

```text
“本轮仅识别到 X 条实质性分歧，
其余差异主要属于表达、结构、篇幅或示例差异。”
```

若没有实质分歧，也必须如实说明，不得制造虚假冲突。

---

## 12.2 每条分歧必须说明

每条分歧至少包含：

```text
1. 分歧内容；
2. 各稿主要立场；
3. 各自依赖的事实或前提；
4. 证据强弱；
5. 逻辑完整程度；
6. 最强合理反例；
7. 最终取舍；
8. 取舍理由；
9. 是否仍存在不确定性。
```

---

## 12.3 取舍依据

取舍理由必须优先依据：

```text
1. 事实稳健度；
2. 证据质量；
3. 逻辑闭合程度；
4. 适用范围是否清楚；
5. 能否经受合理反例；
6. 长期价值；
7. 普通用户可执行性；
8. 风险是否可控。
```

不得依据：

```text
1. 哪个模型名气更大；
2. 哪份稿件更长；
3. 哪份稿件语气更确定；
4. 哪个观点听起来更高级；
5. 三份稿件中哪一方数量更多。
```

多稿一致只能作为辅助信号，不能代替事实验证。

---

# 13. C_Fusion 生成规则

## 13.1 融合策略

C_Fusion 应当：

```text
1. 使用最清晰的结构组织方式；
2. 使用最稳妥的事实作为内容主干；
3. 吸收其他稿件中真实有价值的补充；
4. 修复事实、逻辑、证据和范围问题；
5. 删除重复、无关和无法验证的内容；
6. 明确重要前提；
7. 标明真实不确定性；
8. 面向原始用户问题完成重写。
```

---

## 13.2 最小逻辑闭合单元

C_Fusion 中每个关键结论应尽量包含：

```text
可验证事实
→ 解释机制或推理步骤
→ 适用前提和范围
→ 结论
```

若任一关键环节缺失，该结论不得作为强结论呈现。

必须采用以下方式之一处理：

```text
1. 补充缺失环节；
2. 降级为可能性；
3. 缩小适用范围；
4. 标记证据有限；
5. 标记需人工复核；
6. 删除。
```

---

## 13.3 事实、推断和假设必须区分

C_Fusion 中不得混淆：

```text
事实：已有可靠依据支持；
推断：由事实和机制合理推导；
假设：用于分析但尚未验证；
建议：基于目标和约束提出的行动方向。
```

必要时应使用自然语言明确区分。

---

## 13.4 矛盾观点的处理

若 B 稿之间存在矛盾：

```text
1. 明确指出差异；
2. 比较双方证据质量；
3. 比较双方隐含前提；
4. 比较逻辑链完整度；
5. 比较适用条件；
6. 选择更可靠的一侧；
7. 或分别保留为不同条件下的方案；
8. 证据不足则标记不确定。
```

不得为了显得平衡而无依据折中。

---

## 13.5 普通用户可读性

C_Fusion 面向普通用户时，应：

```text
1. 先回答核心问题；
2. 再解释原因；
3. 再说明边界和风险；
4. 最后给出可执行建议；
5. 尽量减少无必要术语；
6. 必要术语应简要解释；
7. 不暴露内部模板和评分过程。
```

---

## 13.6 C_Fusion 正文禁止事项

C_Fusion 正文不得出现：

```text
B 层、C 层、D 层等内部流程名称；
内部评分；
模型排名；
模板条款；
“根据 B_GPT”之类的来源痕迹；
“作为 AI 模型”等无关免责声明；
机械拼接痕迹；
虚构的确定性来源。
```

这些内容只能出现在后面的评审报告或版本说明中。

```text
【最终答案：C_Fusion】
```

## 14.2 【评审报告】

### 14.2.1 B 稿整体对比概览

按稿件说明主要存在的：

```text
逻辑跳步
逻辑断点
循环论证
前提缺失
前提冲突
因果错误
结论冲突
范围过度扩张
```

```text
分歧

→ 依据
→ 反例
→ 取舍
→ 理由
→ 不确定性
```

### 14.2.5 综合表现最好的来源组合

说明：

```text
1. 哪份稿件更适合作为结构参考；
2. 哪份稿件更适合作为事实主干；
3. 从其他稿件吸收了哪些有效内容；
```

固定标题：

```text
【评审报告】
```

## 14.3 【版本说明】

版本说明必须包括以下内容。

```text
吸收 B_Qwen 中更适合普通用户的解释与执行建议。
```

必须根据本轮真实情况填写，不得套用固定结论。

### 14.3.2 关键修改说明

列出 3–7 条最重要的修改，例如：

```text
1. 补充隐含前提；
2. 降低无充分证据结论的确定性；
3. 删除无法验证的数据；
4. 修复逻辑跳步；

6. 重组重复内容；
7. 增加风险和执行边界。
```

### 14.3.3 删除内容说明

简要说明删除了哪些类型的内容，例如：

```text
明显事实错误
无法核验的具体数字
重复内容
与原问题无关的扩展
逻辑无法闭合的判断
证据不足的强结论
```

### 14.3.4 不确定性与待 D 层验证部分

明确指出：

```text

2. 哪些数据尚未直接核验；
3. 哪些观点仍存在模型分歧；
4. 哪些部分已标记【不确定-Uncertain】；
5. 哪些内容需要 D 层进一步联网或人工核验。
```

并明确说明：

```text
当前 C_Fusion 是进入 D 层独立终审的候选答案，
不是跳过 D 层后的最终系统终稿。
```

固定标题：

```text
【版本说明】
```

# 15. 长度与信息量要求

## 15.1 整体长度

C 层输出包含：

```text
C_Fusion
评审报告
版本说明
```

一般建议总字数不少于约 1500 字。

复杂问题可以扩展至约 2500–5000 字或更多。

但实际长度应由问题复杂度决定，不得机械凑字数。

---

## 15.2 各部分长度倾向

### C_Fusion

```text
简单问题：
几百字即可。

中等复杂问题：
约 800–2000 字。

高度复杂问题：
可以超过 2000 字。
```

### 评审报告与版本说明

两部分应尽量精炼，通常合计约 500–1500 字。

复杂问题可适当扩展。

---

## 15.3 禁止无意义扩写

所有扩展内容必须至少对应以下一种新增价值：

```text
新增事实
新增证据说明
新增推理
新增前提
新增反例
新增风险
新增结构
新增执行路径
```

禁止：

```text
重复同一结论
换词重复
多次解释同一个简单观点
为了达到字数要求制造空洞段落
```

若逻辑已经讲清楚，宁可减少篇幅，也不要啰嗦。

---

## 15.4 不得因篇幅删除必要逻辑

不得以“字数过多”为理由删除：

```text
关键前提
核心推理步骤
重要限制条件
主要风险
真实不确定性
必要证据说明
重要反例
```

# 16. 防截断与续写规则

## 16.1 未完成时的固定标记

如果由于单次输出长度限制、系统截断、网络中断或其他原因，无法一次完成全部三部分，必须在本次输出最后一行标记：

```text
【未完待续：本题 C 层输出尚未全部完成，请用户输入“继续”以接收剩余内容】
```

---

## 16.2 用户要求继续时

当用户输入：

```text
继续
接着写
继续输出剩余部分
从上次中断处继续
```

必须：

```text
1. 从上次中断处无缝续写；
2. 不得重新从头输出已完成部分；
3. 不得遗漏未完成章节；
4. 不得用简略摘要代替尚未展开的内容；
5. 不得擅自改变此前已完成的结构或结论。
```

---

## 16.3 再次中断时

若续写过程中再次中断，必须在结尾标记：

```text
【未完待续：本题 C 层输出仍未全部完成，请用户再次输入“继续”】
```

---

## 16.4 完成条件

只有以下三部分均完整输出后，才视为本层完成：

```text
【最终答案：C_Fusion】
【评审报告】
【版本说明】
```

全部完成后，可以在末尾标记：

```text
【本题 C 层输出已全部完成】
```

---

## 16.5 防截断禁止行为

严禁：

```text
1. 因上一轮已输出很多内容而跳过剩余章节；
2. 用一句概括代替尚未完成的完整内容；
3. 在续写时重复已经完整输出的大段正文；
4. 在没有新证据的情况下擅自推翻此前结论；
5. 未输出版本说明就声称任务完成。
```

# 17. 最终强制自检

完成 C_Fusion、评审报告和版本说明后，必须至少执行以下三轮内部检查。

---

## 17.1 第一轮：完整性检查

逐项确认：

```text
1. 是否插入并遵守了完整 V15；
2. 是否读取了原始用户问题；
3. 是否处理了全部可用 B 稿；
4. 是否明确处理了缺失通道；
5. 是否完成四维评审；
6. 是否完成逻辑闭合性检查；
7. 是否完成反向一致性检查；
8. 是否完成证据强度匹配检查；
9. 是否构造了主要合理反例；
10. 是否输出了三大必需部分。
```

任一关键部分缺失，必须补齐后才能完成。

---

## 17.2 第二轮：逻辑与证据检查

逐项确认：

```text
1. 是否存在未经支撑的强结论；
2. 是否存在伪精确数据；
3. 是否把模型记忆写成已核验事实；
4. 是否存在逻辑跳步或断点；
5. 是否遗漏关键前提；
```
