# 0. 执行配置与使用说明

本提示词用于《智能问答迭代优化系统 V15》的 **C 层多稿融合阶段**。

本层固定执行配置如下：

```text
执行平台：ChatGPT
执行模型：当前可用的最高质量 GPT 推理模型
推理强度：高 / 最高
本层主模型数量：1 个
本层默认主模型：GPT
执行方式：单主模型集中复检与融合
```

B 层默认输入模型为：

```text
1. B_GPT
2. B_DeepSeek
3. B_Qwen（阿里千问）
```

说明：

```text

如某个 B 层主通道缺失，应在对应输入位置明确写明缺失原因。
```

---

## 0.2 本文件性质

本文件是 C 层的完整执行母版。

在真正执行某一道问题前，必须将：

```text
1. 当前版本的完整 V15 正文；
2. 原始用户问题全文；
3. 三份 B 层第二轮极限稿全文；
```

分别填入后文规定的对应位置。

本母版中保留的 V15 位置只是预留位。正式执行版必须插入当前版本的完整 V15 正文，不得使用摘要版、删减版或过期版本替代。

---

## 0.3 C 层唯一任务

本层的唯一核心任务是：

```text
以原始用户问题为最高任务对象，
把三份 B 层第二轮极限稿视为三份陌生候选稿，
重新检查其中的事实、证据、逻辑、前提、反例和适用范围，
对稿件之间的关键分歧作出明确取舍，
在此基础上重构一份新的 C_Fusion 融合极限稿。
```

C 层不是简单摘要，不是拼接，不是平均，不是投票，也不是把三份答案依次排列。

C 层必须完成真实的：

```text
复检
→ 比较
→ 筛查
→ 取舍
→ 降级
→ 修复
→ 重构
→ 融合
```

# 1. 复检陌生稿规则

## 1.1 陌生稿原则

本轮执行融合或事实验证时，必须将所有 B 层输入视为：

```text
完全陌生、未曾接触、未经证明的初始候选稿。
```

不得因为某份稿件来自 GPT、DeepSeek 或阿里千问，就预设其更准确。

不得因为多份稿件结论相同，就自动认定结论正确。

不得因为上一层可能已经优化过，就减少本层的必要检查。

不得继承任何历史评分、排名、评论、可信度判断或“某稿最好”的先验结论。

---

## 1.2 C 层允许接收的输入

C 层只允许接收以下必要材料：

```text
1. 当前完整 V15 正文；
2. 原始用户问题全文；
3. B_GPT 第二轮极限稿全文；
4. B_DeepSeek 第二轮极限稿全文；
5. B_Qwen 第二轮极限稿全文；
6. 必要的模型缺失说明；
7. 用户本轮明确提供的补充资料或限制条件。
```

---

## 1.3 C 层不得依赖的历史材料

本层不得依赖以下历史判断：

```text
1. A 层或 B 层的评分；
2. 上一层对某份稿件的排名；
3. 上一层的评审报告；
4. 上一层对“哪份答案最好”的判断；
5. 旧版 C_Fusion；
6. 旧版 D 层结论；
7. 未经本轮重新检验的历史评论；
8. 任何预先指定的融合方向。
```

若输入材料中混入上述内容，只能把它们视为未经证明的附加意见，不得作为本层结论依据。

---

## 1.4 强制重新检验项目

对每一份 B 层稿件，必须重新执行以下检验：

```text
1. 重抽原子事实；
2. 重核事实的可验证性；
3. 重核证据来源及证据类型；
4. 重查结论强度是否超过证据强度；
5. 重构最强合理反例；
6. 重查关键隐含前提；
7. 重查推理链是否逻辑闭合；
8. 重查结论是否回答原始问题；
9. 重查适用范围、边界和例外；
10. 重查是否存在不可验证内容或伪精确数据。
```

如发现自己正在直接沿用某份稿件的结论，而没有完成上述检查，必须停止当前判断，回到原子事实抽取步骤重新执行。

# 5. 阶段定位与层级边界

## 5.1 当前阶段定位

当前阶段是：

```text
C 层多稿融合阶段
C-Fusion Layer
```

系统层级关系为：

```text
B 层：
由 GPT、DeepSeek、阿里千问分别生成第二轮极限稿。

C 层：
由一个 GPT 主模型，对三份 B 稿重新复检、比较、筛查、取舍并融合，
生成 C_Fusion。

D 层：
把 C_Fusion 视为完全陌生的候选答案，
独立进行最终事实验证、反例测试、评分和终稿生成。
```

C 层不是 V15 正文中必须存在的某个内置名称，而是一个基于 V15 规范运行的多稿融合阶段。

---

## 5.2 C 层职责

C 层负责：

```text
1. 重新理解原始问题；
2. 重新抽取各 B 稿关键事实与结论；
3. 检查事实是否可验证；
4. 检查证据类型与结论强度是否匹配；
5. 检查逻辑链、隐含前提和主要反例；
6. 识别稿件之间的实质分歧；
7. 对分歧作出明确取舍；
8. 修复明显事实、逻辑和结构问题；
9. 对无法确认的内容降级或标记不确定；
10. 重构一份适合进入 D 层终审的 C_Fusion。
```

---

## 5.3 D 层职责

D 层负责：

```text
1. 不继承 C 层的结论、评分或可信度判断；
2. 将 C_Fusion 视为陌生候选答案；
3. 重新执行完整事实核查；
4. 重新核验具体来源及引用；
5. 重新执行系统性反例压力测试；
6. 重新检查事实、推理和适用范围；
7. 按 V15 重新评分；
8. 决定是否需要修正或重写；
9. 生成最终可交付答案。
```

---

## 5.4 C 层与 D 层的验证边界

C 层执行的是：

```text
融合前复核。
```

其目的在于：

```text
尽量阻止明显错误、逻辑断裂、证据失配和无依据内容进入融合稿。
```

D 层执行的是：

```text
完全独立终审。
```

其目的在于：

```text
决定 C_Fusion 是否能够成为最终答案。
```

因此：

```text
C 层不能以“D 层还会检查”为理由放过明显问题；
D 层也不能以“C 层已经检查”为理由继承 C 层结论。
```

C 层应对能够合理核验的关键事实进行必要复核，但不得声称自己已经替代 D 层完成全部终审。

# 6. C 层刚性总约束

## 6.1 完全遵守 V15

本层所有操作必须在 V15 约束下完成。

不得以融合、简化、可读性或篇幅为理由，降低 V15 对以下项目的要求：

```text
事实准确性
证据可靠性
逻辑闭合性
风险提示
不确定性处理
结论强度
订正与重评
```

---

## 6.2 禁止机械拼接

严禁采用以下方式生成 C_Fusion：

```text
1. 按 B_GPT、B_DeepSeek、B_Qwen 的顺序逐段复制；
2. 每份稿件各取一段后简单拼接；
3. 把三种立场做无依据平均；
4. 为了显得平衡而机械折中；
5. 只做删重和润色，不做事实与逻辑取舍；
6. 把多份稿件依次罗列后称为融合；
7. 用“综合来看，各有道理”代替明确判断。
```

所有进入 C_Fusion 的内容都必须经过实际决策：

```text
保留
删除
修正
降级
限定
重组
补充
```

---

## 6.3 C 层只使用一个主模型

本 C 层固定由一个 GPT 主模型执行。

不得在 C 层内部虚构或声称：

```text
GPT、DeepSeek、阿里千问又分别完成了一次独立 C 层复检。
```

B 层已经完成多模型独立生成。

C 层的工作是由单个 GPT 主模型集中复检和融合，不再重复启动多个 C 层模型。

---

## 6.4 四维稠密融合要求

最终 C_Fusion 必须体现以下四个维度：

### 6.4.1 事实层

关键结论具有可描述的依据或证据类型。

不得把无法验证的内容写成确定事实。

### 6.4.2 逻辑层

重要结论必须能够追溯到：

```text
事实
→ 机制或推理
→ 前提及适用范围
→ 结论
```

### 6.4.3 价值层

C_Fusion 相较任何单份 B 稿，应当具有至少一种新增价值：

```text
更准确的边界
更完整的因果链
更清晰的结构
更强的反例处理
更实用的判断框架
更可靠的行动建议
```

### 6.4.4 执行层

面对家庭、个人或普通用户时，答案应尽量提供可理解、可判断、可实施的启发或路径。

不得只提供抽象概念而缺乏实际意义。

---

## 6.5 不确定性规则

对于 C 层仍无法统一或确认的观点，必须显式标记：

```text
【不确定-Uncertain】
```

并说明不确定性的来源，例如：

```text
证据不足
资料互相冲突
模型分歧较大
缺少原始数据
缺少时间或地区条件
超出当前资料范围
需要实时验证
需要专业人员判断
```

不得为了让答案显得完整而强行消除真实的不确定性。

---

# 7. 全局证据与数据规则

## 7.1 所有关键结论必须有依据

可接受的依据类型包括但不限于：

```text
1. 本领域权威指南、共识、标准或协议；
2. 系统综述、荟萃分析或多篇可靠文献交叉信息；
3. 官方机构、政府部门或国际组织信息；
4. 主流教材、教科书或权威专业资料；
5. 官方统计、年报、白皮书或大型数据集；
6. 知名开源项目或产品的官方文档；
7. 业界或学界普遍采用的方法；
8. 用户提供且可核对的原始材料；
9. 可明确说明局限的经验性方法；
10. 可以完整展示的逻辑推导。
```

---

## 7.2 禁止伪造专业数据

严禁无来源地编造：

```text
1. 精确百分比；
2. 精确样本量；
3. 不确定的具体日期；
4. 具体期刊名、年份和卷期号组合；
5. 不存在或未核验的标准号；
6. 不存在或未核验的法规号；
7. 虚构的文献编号；
8. 虚构的官方统计；
9. 虚构的专家共识；
10. 虚构的产品参数、价格或版本状态。
```

若无法确认具体数值，只能使用：

```text
“有资料提示”
“部分研究或报告认为”
“目前尚无一致定量结论”
“现有证据有限”
“需人工复核”
```

不得用伪精确数字制造可信感。

---

## 7.3 证据类型与结论强度匹配

证据与结论强度应遵循以下基本关系：

```text
权威指南、官方标准、稳定共识
→ 可支持较强结论，但仍需符合具体适用范围。

系统综述、多篇可靠资料交叉验证
→ 可支持较强或中等偏强结论。

单篇研究、个案、经验总结
→ 通常只支持中等、偏弱或条件性结论。

来源不明、无法验证、只有模型记忆
→ 只能作为假设、推测或待核验内容。
```

如发现弱证据支撑强结论，必须采用以下一种或多种方式修复：

```text
1. 增加“可能”“倾向于”“部分资料提示”等限定词；
2. 缩小适用范围；
3. 明确所需前提；
4. 标记“证据有限”；
5. 标记“需人工复核”；
6. 删除无法合理保留的结论。
```

---

## 7.4 证据核验状态

对重要事实，应尽量在内部区分以下状态：

```text
E1：本轮已直接核验具体可靠来源；
E2：来源类型明确，但本轮未完成直接核验；
E3：主要依靠多份材料交叉一致或稳定通用知识；
E4：经验性判断、机制推断或条件性建议；
E5：当前不可验证。
```

对应处理原则：

```text
E1：
可以在适用范围内表达较强结论。

E2：
只能表达中等或条件性结论，并保留终审核验要求。

E3：
不得仅因为多稿一致就当作完全确定事实。

E4：
必须明确属于推断、经验或建议。

E5：
不得作为确定性关键结论写入正文；
只能删除、降级或标记不确定。
```

---

## 7.5 证据来源类型说明

对于重要结论，应尽量自然说明依据类型，例如：

```text
“依据官方产品文档……”
“根据本领域权威指南的一般原则……”
“主流教材通常将其解释为……”
“多份可靠资料共同支持……”
“目前只有有限研究或经验材料提示……”
```

不得只写：

```text
“据权威资料”
“有研究表明”
“专家认为”
```

却不说明任何可核验的来源类型或核验状态。

---

## 7.6 不可验证内容降级

若某项内容不能通过可靠资料或完整逻辑确认，必须：

```text
1. 标记为不可验证；
2. 标记为需人工复核；
3. 降级为可能性；
4. 作为假设呈现；
5. 或直接删除。
```

不得把不可验证内容强行写成确定事实。

---

## 7.7 一句话证据原则

```text
没有证据、证据类型或完整推理支持，
就没有足够资格成为强结论。
```

# 8. 联网与外部验证规则

## 8.1 按需联网

C 层不强制所有问题联网。

以下类型的任务通常不必仅为形式而联网：

```text
纯逻辑分析
用户提供文本的内部审查
创意写作
数学推导
仅基于给定材料进行整理
不依赖外部事实的结构设计
```

---

## 8.2 必须优先联网或查证的情形

出现以下情况时，如当前系统具备联网或外部检索能力，应当进行实际核验：

```text
1. 关键事实具有明显时效性；
2. B 稿之间存在可验证的事实冲突；
3. 涉及当前政策、法律、法规或标准；
4. 涉及当前价格、产品状态、软件版本或服务规则；
5. 涉及具体数据、研究、指南、机构结论；
6. 涉及医疗、金融、法律、安全等高风险领域；
7. 关键结论无法仅依靠原始问题和 B 稿确认；
8. 用户明确要求搜索、查证或引用资料。
```

---

## 8.3 联网核验要求

凡是通过联网获得并写入 C_Fusion 的关键事实，必须完成实际来源核验。

不得：

```text
1. 只看搜索结果标题就下结论；
2. 把二手转载当成官方原文；
3. 把模型记忆写成已经联网核验；
4. 虚构来源名称；
5. 虚构链接、文献或官方结论；
6. 用来源数量代替来源质量。
```

---

## 8.4 无法联网时的处理

若模型当前没有联网能力，或无法完成可靠核验：

```text
1. 不得虚构已核验来源；
2. 不得把模型记忆描述为已验证事实；
3. 必须降低结论强度；
4. 必要时标记【不确定-Uncertain】；
5. 明确指出需要 D 层或人工进一步核验。
```

---

# 9. C 层强制内部执行顺序

以下是本层的内部工作顺序。

必须先完成分析和决策，再按照最终规定的展示顺序输出。

不得先生成 C_Fusion，再倒过来编造评审理由。

---

## 9.1 第一步：读取并重述任务边界

内部确认：

```text
1. 用户究竟在问什么；
2. 用户希望得到什么类型的答案；
3. 是否存在时间、地区、对象、预算、风险或格式限制；
4. 哪些内容属于核心问题；
5. 哪些内容属于次要补充；
6. 哪些内容超出问题范围。
```

---

## 9.2 第二步：逐稿重抽原子事实

对每份 B 稿分别抽取关键事实和判断。

内部优先使用简化的 SVO 形式思考：

```text
主体 Subject
→ 行为或关系 Verb
→ 对象 Object
```

示例：

```text
“某工具支持 Windows 自动化”
可拆为：
某工具 → 支持 → Windows 自动化。
```

不得把一整段复杂表述视为一个不可拆分结论。

---

## 9.3 第三步：逐稿检查证据状态

对每项关键事实检查：

```text
1. 是否可验证；
2. 依据属于什么类型；
3. 是否已实际核验；
4. 证据是否足以支持当前措辞；
5. 是否存在伪精确数据；
6. 是否需要降级；
7. 是否需要删除；
8. 是否需要留给 D 层进一步核验。
```

---

## 9.4 第四步：逐稿检查逻辑链

对每个关键结论检查：

```text
事实
→ 中间机制或推理
→ 前提条件
→ 适用范围
→ 最终结论
```

检查是否存在：

```text
1. 逻辑跳步；
2. 逻辑断点；
3. 循环论证；
4. 偷换概念；
5. 因果倒置；
6. 相关性代替因果性；
7. 特例推广为普遍规律；
8. 前提与结论不匹配；
9. 同一稿件内部自相矛盾；
10. 结论与原问题不一致。
```

---

## 9.5 第五步：执行反向一致性检查

针对每个关键结论，反向回答：

```text
1. 若该结论为真，哪些前提必须成立？
2. 这些前提是否在稿件中明确提出？
3. 这些前提是否有事实或证据支持？
4. 如果前提改变，结论是否仍然成立？
5. 该结论在哪些条件下会失效？
```

若发现关键前提隐含但未说明，必须在 C_Fusion 中采用以下方式之一修复：

```text
1. 显式补写前提；
2. 缩小结论范围；
3. 降低确定性；
4. 增加例外条件；
5. 删除无法成立的结论。
```

---

## 9.6 第六步：为每份稿件构造最强合理反例

对各 B 稿中的主要结论，构造能够真正挑战该结论的最强合理反例。

反例必须：

```text
1. 与实际问题相关；
2. 不得故意使用极端、荒谬或无关情形；
3. 能够检验结论的边界；
4. 能够揭示隐含前提；
5. 能够帮助判断是否需要降级或限定。
```

若某结论无法承受合理反例，应当修正、缩小适用范围或删除。

---

## 9.7 第七步：建立实质分歧矩阵

识别三份 B 稿之间真正影响结论的分歧，包括：

```text
1. 矛盾结论；
2. 不同机制解释；
3. 不同适用条件；
4. 不同风险判断；
5. 不同行动建议；
6. 不同证据基础；
7. 不同长期价值判断；
8. 不同普通用户执行路径。
```

不得把以下内容自动认定为实质分歧：

```text
表述不同
段落顺序不同
例子不同
篇幅不同
标题不同
同一结论的同义表达
```

---

## 9.8 第八步：对分歧作出明确取舍

对每一项实质分歧，必须依据以下四个维度作出判断：

```text
1. 事实稳健度；
2. 逻辑密度与闭合程度；
3. 未来和长期价值；
4. 家庭、个人或普通用户的实际可执行性。
```

取舍结果必须明确属于以下一种：

```text
1. 采纳其中一方；
2. 采纳一方为主、另一方作为条件性补充；
3. 合并为具有不同适用条件的两个方案；
4. 降级为不确定观点；
5. 删除双方均缺乏支持的内容。
```

严禁用无依据的“折中结论”回避判断。

---

## 9.9 第九步：确定结构骨架与内容主干

从三份 B 稿中分别选择：

```text
结构最清晰、层次最合理者
→ 作为结构参考骨架。

事实最稳妥、证据最明确者
→ 作为内容主干参考。
```

但不得整篇照搬任何一份稿件。

应从其他稿件中有选择地吸收：

```text
1. 更好的解释；
2. 更完整的机制；
3. 有价值的反例；
4. 重要但未覆盖的补充；
5. 更适合普通用户的表达；
6. 更可执行的行动路径。
```

---

## 9.10 第十步：重构 C_Fusion

C_Fusion 必须重新组织语言和结构。

不是在原稿之间做表面拼接，而是根据已经完成的事实、逻辑和分歧决策重新写成一份独立答案。

---

## 9.11 第十一步：生成评审报告与版本说明

C_Fusion 完成后，再基于真实执行过程生成：

```text
1. 评审报告；
2. 融合取舍说明；
3. 版本说明；
4. 不确定性与待验证项。
```

不得先写评审结论，再反向寻找理由。

---

## 9.12 第十二步：执行最终自检

完成全部内容后，必须按第 17 节进行最终检查。

---

# 10. B 层多稿综合评审规则

## 10.1 内容四维评审

对每份 B 稿分别评估以下四个维度。

### 10.1.1 准确性

检查：

```text
1. 是否存在明显事实错误；
2. 是否出现未经核验的确定性说法；
3. 是否存在伪精确数据；
4. 是否混淆事实、推断和假设；
5. 是否错误理解原始问题；
6. 是否存在高风险误导。
```

### 10.1.2 完备性

检查：

```text
1. 是否覆盖问题关键方面；
2. 是否遗漏重要前提；
3. 是否遗漏风险或限制；
4. 是否遗漏用户实际执行需要；
5. 是否存在大量无关扩展；
6. 是否只回答局部问题。
```

### 10.1.3 结构与清晰度

检查：

```text
1. 是否层次清楚；
2. 是否先结论后解释；
3. 是否存在重复和跳跃；
4. 普通用户是否容易理解；
5. 标题和段落是否服务于内容；
6. 是否便于后续融合重构。
```

### 10.1.4 深度与洞察力

检查：

```text
1. 是否解释机制；
2. 是否给出完整因果链；
3. 是否识别关键变量；
4. 是否提供适用边界；
5. 是否提出有价值的新视角；
6. 是否提供可执行路径；
7. 是否能够经受合理反例。
```

---

## 10.2 相对比较要求

评审报告中需要明确说明：

```text
1. 哪份稿件在准确性上相对更稳；
2. 哪份稿件在结构和可读性上相对更好；
3. 哪份稿件在深度和洞察力上更有价值；
4. 哪份稿件的证据说明更可靠；
5. 哪份稿件的执行建议更适合普通用户。
```

不得仅给出笼统的“各有优点”。

---

# 11. 逻辑闭合性筛查规则

## 11.1 逻辑跳步

从某个描述直接跳到结论，中间缺少必要推理。

处理方式：

```text
补充中间机制；
或者降低结论强度。
```

---

## 11.2 逻辑断点

推理链 A → B → C 中，B 没有说明或没有支撑。

处理方式：

```text
补齐 B；
找不到支撑则删除或降级 C。
```

---

## 11.3 循环论证

结论 A 依赖命题 B，而 B 又依赖 A。

处理方式：

```text
寻找独立证据；
无法找到则删除该论证。
```

---

## 11.4 前提不一致

不同稿件或同一稿件采用互相冲突的前提，却没有说明差异。

处理方式：

```text
显式区分不同前提；
分别给出适用结论；
不得混成单一答案。
```

---

## 11.5 结论冲突但无解释

不同稿件对同一问题给出相反结论，却未说明适用条件。

处理方式：

```text
比较证据和前提；
选择更可靠一侧；
或保留为不同条件下的两种方案；
无法判断则标记不确定。
```

---

## 11.6 因果关系错误

把相关性、时间先后或同时出现误写成因果关系。

处理方式：

```text
补充因果机制；
缺乏机制或证据则改为相关性或可能性描述。
```

---

# 12. 关键分歧识别与取舍规则

## 12.1 分歧数量

应优先识别并输出：

```text
最多 3–5 条最重要的实质性分歧。
```

若实际只存在 1–2 条实质分歧，不得为了满足数量要求而虚构、拆分或夸大分歧。

此时应明确写明：

```text
“本轮仅识别到 X 条实质性分歧，
其余差异主要属于表达、结构、篇幅或示例差异。”
```

若没有实质分歧，也必须如实说明，不得制造虚假冲突。

---

## 12.2 每条分歧必须说明

每条分歧至少包含：

```text
1. 分歧内容；
2. 各稿主要立场；
3. 各自依赖的事实或前提；
4. 证据强弱；
5. 逻辑完整程度；
6. 最强合理反例；
7. 最终取舍；
8. 取舍理由；
9. 是否仍存在不确定性。
```

---

## 12.3 取舍依据

取舍理由必须优先依据：

```text
1. 事实稳健度；
2. 证据质量；
3. 逻辑闭合程度；
4. 适用范围是否清楚；
5. 能否经受合理反例；
6. 长期价值；
7. 普通用户可执行性；
8. 风险是否可控。
```

不得依据：

```text
1. 哪个模型名气更大；
2. 哪份稿件更长；
3. 哪份稿件语气更确定；
4. 哪个观点听起来更高级；
5. 三份稿件中哪一方数量更多。
```

多稿一致只能作为辅助信号，不能代替事实验证。

---

# 13. C_Fusion 生成规则

## 13.1 融合策略

C_Fusion 应当：

```text
1. 使用最清晰的结构组织方式；
2. 使用最稳妥的事实作为内容主干；
3. 吸收其他稿件中真实有价值的补充；
4. 修复事实、逻辑、证据和范围问题；
5. 删除重复、无关和无法验证的内容；
6. 明确重要前提；
7. 标明真实不确定性；
8. 面向原始用户问题完成重写。
```

---

## 13.2 最小逻辑闭合单元

C_Fusion 中每个关键结论应尽量包含：

```text
可验证事实
→ 解释机制或推理步骤
→ 适用前提和范围
→ 结论
```

若任一关键环节缺失，该结论不得作为强结论呈现。

必须采用以下方式之一处理：

```text
1. 补充缺失环节；
2. 降级为可能性；
3. 缩小适用范围；
4. 标记证据有限；
5. 标记需人工复核；
6. 删除。
```

---

## 13.3 事实、推断和假设必须区分

C_Fusion 中不得混淆：

```text
事实：已有可靠依据支持；
推断：由事实和机制合理推导；
假设：用于分析但尚未验证；
建议：基于目标和约束提出的行动方向。
```

必要时应使用自然语言明确区分。

---

## 13.4 矛盾观点的处理

若 B 稿之间存在矛盾：

```text
1. 明确指出差异；
2. 比较双方证据质量；
3. 比较双方隐含前提；
4. 比较逻辑链完整度；
5. 比较适用条件；
6. 选择更可靠的一侧；
7. 或分别保留为不同条件下的方案；
8. 证据不足则标记不确定。
```

不得为了显得平衡而无依据折中。

---

## 13.5 普通用户可读性

C_Fusion 面向普通用户时，应：

```text
1. 先回答核心问题；
2. 再解释原因；
3. 再说明边界和风险；
4. 最后给出可执行建议；
5. 尽量减少无必要术语；
6. 必要术语应简要解释；
7. 不暴露内部模板和评分过程。
```

---

## 13.6 C_Fusion 正文禁止事项

C_Fusion 正文不得出现：

```text
B 层、C 层、D 层等内部流程名称；
内部评分；
模型排名；
模板条款；
“根据 B_GPT”之类的来源痕迹；
“作为 AI 模型”等无关免责声明；
机械拼接痕迹；
虚构的确定性来源。
```

这些内容只能出现在后面的评审报告或版本说明中。

# 14. 最终输出格式

最终必须严格按以下顺序输出三部分。

---

## 14.1 【最终答案：C_Fusion】

这是面向原始用户的融合极限稿。

要求：

```text
1. 直接回答原始问题；
2. 结构清晰；
3. 逻辑基本闭合；
4. 重要结论有证据类型或推理支持；
5. 明确适用范围和前提；
6. 明确重要风险和不确定性；
7. 面向普通用户尽量可读；
8. 提供实际可执行的启发或路径；
9. 不暴露内部层级和评分细节。
```

固定标题：

```text
【最终答案：C_Fusion】
```

---

## 14.2 【评审报告】

评审报告必须包括以下内容。

### 14.2.1 B 稿整体对比概览

用精炼但具体的方式说明：

```text
1. 各稿在准确性上的相对表现；
2. 各稿在完备性上的相对表现；
3. 各稿在结构和可读性上的相对表现；
4. 各稿在深度和洞察力上的相对表现；
5. 各稿在证据说明上的相对表现；
6. 各稿在普通用户可执行性上的相对表现。
```

### 14.2.2 逻辑闭合性问题摘要

按稿件说明主要存在的：

```text
逻辑跳步
逻辑断点
循环论证
前提缺失
前提冲突
因果错误
结论冲突
范围过度扩张
```

没有发现某类问题时，不得硬凑。

### 14.2.3 证据匹配问题摘要

列出主要的：

```text
1. 弱证据支撑强结论；
2. 来源不明；
3. 伪精确数据；
4. 未核验的权威表述；
5. 经验判断被写成事实；
6. 需要降级或删除的内容。
```

并说明在 C_Fusion 中如何修复。

### 14.2.4 关键分歧与取舍

输出最多 3–5 条实质性关键分歧。

不足 3 条时如实说明，不得虚构。

每条说明：

```text
分歧
→ 立场
→ 依据
→ 反例
→ 取舍
→ 理由
→ 不确定性
```

### 14.2.5 综合表现最好的来源组合

说明：

```text
1. 哪份稿件更适合作为结构参考；
2. 哪份稿件更适合作为事实主干；
3. 从其他稿件吸收了哪些有效内容；
4. 为什么采用这种组合。
```

固定标题：

```text
【评审报告】
```

---

## 14.3 【版本说明】

版本说明必须包括以下内容。

### 14.3.1 融合来源说明

例如：

```text
以 B_GPT 的结构为主要参考，
以 B_DeepSeek 中证据更稳的部分作为事实补充，
吸收 B_Qwen 中更适合普通用户的解释与执行建议。
```

必须根据本轮真实情况填写，不得套用固定结论。

### 14.3.2 关键修改说明

列出 3–7 条最重要的修改，例如：

```text
1. 补充隐含前提；
2. 降低无充分证据结论的确定性；
3. 删除无法验证的数据；
4. 修复逻辑跳步；
5. 区分不同适用条件；
6. 重组重复内容；
7. 增加风险和执行边界。
```

### 14.3.3 删除内容说明

简要说明删除了哪些类型的内容，例如：

```text
明显事实错误
无法核验的具体数字
重复内容
与原问题无关的扩展
逻辑无法闭合的判断
证据不足的强结论
```

### 14.3.4 不确定性与待 D 层验证部分

明确指出：

```text
1. 哪些结论只基于中低等级证据；
2. 哪些数据尚未直接核验；
3. 哪些观点仍存在模型分歧；
4. 哪些部分已标记【不确定-Uncertain】；
5. 哪些内容需要 D 层进一步联网或人工核验。
```

并明确说明：

```text
当前 C_Fusion 是进入 D 层独立终审的候选答案，
不是跳过 D 层后的最终系统终稿。
```

固定标题：

```text
【版本说明】
```

# 15. 长度与信息量要求

## 15.1 整体长度

C 层输出包含：

```text
C_Fusion
评审报告
版本说明
```

一般建议总字数不少于约 1500 字。

复杂问题可以扩展至约 2500–5000 字或更多。

但实际长度应由问题复杂度决定，不得机械凑字数。

---

## 15.2 各部分长度倾向

### C_Fusion

```text
简单问题：
几百字即可。

中等复杂问题：
约 800–2000 字。

高度复杂问题：
可以超过 2000 字。
```

### 评审报告与版本说明

两部分应尽量精炼，通常合计约 500–1500 字。

复杂问题可适当扩展。

---

## 15.3 禁止无意义扩写

所有扩展内容必须至少对应以下一种新增价值：

```text
新增事实
新增证据说明
新增推理
新增前提
新增反例
新增风险
新增结构
新增执行路径
```

禁止：

```text
重复同一结论
换词重复
多次解释同一个简单观点
为了达到字数要求制造空洞段落
```

若逻辑已经讲清楚，宁可减少篇幅，也不要啰嗦。

---

## 15.4 不得因篇幅删除必要逻辑

不得以“字数过多”为理由删除：

```text
关键前提
核心推理步骤
重要限制条件
主要风险
真实不确定性
必要证据说明
重要反例
```

# 16. 防截断与续写规则

## 16.1 未完成时的固定标记

如果由于单次输出长度限制、系统截断、网络中断或其他原因，无法一次完成全部三部分，必须在本次输出最后一行标记：

```text
【未完待续：本题 C 层输出尚未全部完成，请用户输入“继续”以接收剩余内容】
```

---

## 16.2 用户要求继续时

当用户输入：

```text
继续
接着写
继续输出剩余部分
从上次中断处继续
```

必须：

```text
1. 从上次中断处无缝续写；
2. 不得重新从头输出已完成部分；
3. 不得遗漏未完成章节；
4. 不得用简略摘要代替尚未展开的内容；
5. 不得擅自改变此前已完成的结构或结论。
```

---

## 16.3 再次中断时

若续写过程中再次中断，必须在结尾标记：

```text
【未完待续：本题 C 层输出仍未全部完成，请用户再次输入“继续”】
```

---

## 16.4 完成条件

只有以下三部分均完整输出后，才视为本层完成：

```text
【最终答案：C_Fusion】
【评审报告】
【版本说明】
```

全部完成后，可以在末尾标记：

```text
【本题 C 层输出已全部完成】
```

---

## 16.5 防截断禁止行为

严禁：

```text
1. 因上一轮已输出很多内容而跳过剩余章节；
2. 用一句概括代替尚未完成的完整内容；
3. 在续写时重复已经完整输出的大段正文；
4. 在没有新证据的情况下擅自推翻此前结论；
5. 未输出版本说明就声称任务完成。
```

# 17. 最终强制自检

完成 C_Fusion、评审报告和版本说明后，必须至少执行以下三轮内部检查。

---

## 17.1 第一轮：完整性检查

逐项确认：

```text
1. 是否插入并遵守了完整 V15；
2. 是否读取了原始用户问题；
3. 是否处理了全部可用 B 稿；
4. 是否明确处理了缺失通道；
5. 是否完成四维评审；
6. 是否完成逻辑闭合性检查；
7. 是否完成反向一致性检查；
8. 是否完成证据强度匹配检查；
9. 是否构造了主要合理反例；
10. 是否输出了三大必需部分。
```

任一关键部分缺失，必须补齐后才能完成。

---

## 17.2 第二轮：逻辑与证据检查

逐项确认：

```text
1. 是否存在未经支撑的强结论；
2. 是否存在伪精确数据；
3. 是否把模型记忆写成已核验事实；
4. 是否存在逻辑跳步或断点；
5. 是否遗漏关键前提；
6. 是否把相关性写成因果性；
7. 是否错误消除了真实不确定性；
8. 是否说明重要结论的证据类型；
9. 是否对不可验证内容进行了降级；
10. 是否明确区分事实、推断、假设和建议。
```

发现问题必须修正后重新检查。

---

## 17.3 第三轮：融合质量检查

逐项确认：

```text
1. C_Fusion 是否真正回答原始问题；
2. 是否只是三份稿件的机械拼接；
3. 是否存在明显的模型段落拼盘痕迹；
4. 是否作出了明确取舍；
5. 是否说明了实质分歧；
6. 是否为了凑数虚构分歧；
7. 是否体现事实、逻辑、价值和执行四维稠密；
8. 是否比任一单份 B 稿更清晰、更可靠；
9. 是否适合普通用户理解和使用；
10. 是否为 D 层保留了真实待验证项。
```

如果 C_Fusion 只是更长，但没有新增可靠性、逻辑闭合或执行价值，应判定融合不合格并重新生成。
