# Conflict Policy

## Skill Conflicts

Before installing or updating a skill with an existing name:

1. Read local `SKILL.md`.
2. Read external `SKILL.md`.
3. Compare triggers and responsibilities.
4. Identify local custom experience that must be preserved.
5. Recommend one of:
   - do not install,
   - read as reference only,
   - install under a new name,
   - merge selected rules into a draft,
   - replace only after explicit approval.

## File Conflicts

Never overwrite user changes or unrelated work. If the same file must be edited, inspect it first and preserve user changes.

## Route Conflicts

When multiple skills apply, choose the minimum set that covers the task. State the order and why.
