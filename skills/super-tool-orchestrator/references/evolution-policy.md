# Evolution Policy

Evolution means turning validated experience into reusable assets. It does not mean automatically rewriting the system after every task.

## Eligible

- repeated operations,
- validated checklists,
- reusable templates,
- deterministic scripts,
- safer stop conditions,
- clear skill rule improvements.

## Not Eligible

- secrets, cookies, API keys, account details,
- one-off guesses,
- unverified GPT suggestions,
- production config changes,
- private user data,
- broad rules that would increase false triggers.

## Sedimentation Priority

1. checklist,
2. template,
3. script,
4. skill rule,
5. automation,
6. long-term configuration.

Long-term configuration needs explicit user approval.

## Anti-Bloat Rule

Keep `SKILL.md` lean. Put detailed experience in references. Archive obsolete rules after validation shows they are no longer useful.
