# V2.4.3-R2 复杂单结单与无人接续验收

2026-11-20 北京时间。R2 继承 R1 的已验结单路径，增加独立的一次实机验收。

Pi 是唯一主执行者，负责接单、确定性验收、组织签字、接续及交付读回。GPT 和 Gemini 只独立签收。正式发布由任务合同中已授权的 Windows 桌面执行器调用原发布命令。成熟短单沿原配方直接自验交付。

## 接单就检查发布入口

- 先查原任务号、原 Pi 会话、原接单时间、现有签证和完成事件。事件已经存在时只读核对 GUI，直接收尾。记录本单的发布入口、授权范围和可调用执行者，做一次无业务写入的连通检查。合同需要签前拒发实测时，只跑一次，保留 `REJECTED`、退出码 3、零完成事件、入口和包指纹。
- Windows Terminal 里的 Pi `!`／`!!` 仍可能是 RID 4096。退出码 2 是沙箱拦截，预定路径回显不算回执。遇到此结果直接切到本单已授权的普通 Windows CMD（RID 8192），记录真实父进程链、主机、原 Pi 会话标识和回执来源。授权或真实执行器缺失时立即报具体阻断。独立业务工作照常推进，受阻终审留到入口可用后。不得把另一单的临时批准当作本单授权。

## 一次冻结、双签、一次发布

1. **Pi 定稿并验收。** 复用原合同的独立检查器，逐项核对必答和业务数据。回归、业务检查和稳定证据齐备后冻结一次，并重算清单全部哈希。计时、易变探针输出、引用包指纹的 GUI 及发布回执另存。正式 GUI 读回必须绑定最终指纹。浏览器明确拦截本地文件协议时，可用已批准的本机环回预览，仅公开本任务成品和状态页。若拒签证据绑定前一候选，须能证明业务产物哈希不变且合同及审核接受；否则在此前签收关口补证。
2. **Pi 组织双签。** 本类结单沿已验顺序先 GPT、后 Gemini。两方看相同合同、成品与证据指纹，Gemini 独立判断。以 `任务号 + 最终指纹 + 审核方 + 轮次` 记录唯一发送意图。逐字或合同认可的规范化全文核对后提交。回执丢失先按标记读原标签，已发送只补读，发送不明保留待核账，入账前核对完整正文、身份、轮次、指纹和唯一裁决。
3. **Pi 发起一次放行并收尾。** 签齐后把任务号、原 Pi 会话、最终指纹、固定发布命令和回执位置交给已授权的桌面执行者。以 `任务号 + 最终指纹` 占用一次发布执行权，检查已有事件后再调用原发布命令。程序先验指纹、必答及最新真实签字，再交叉核验 GUI，才允许写完成事件。已有同指纹事件只读回。Pi 从实际发布页读回 `COMPLETE` 与唯一事件，确认和账本一致，再结单与停止巡检。退出码 0、签证齐全和页面单独显示完成都不足以结单。

## 审核与浏览器异常

- 有效 `REWORK` 只返工明确缺项，复验受影响步骤。若指纹改变，两方签新指纹；若只有读取或签证存档出错，只补证，无需重冻重发。同指纹后到的真实拒签必须拦截。单签只沿原 V2.4.3 已允许的真实 Gemini 故障路线执行；有效 `REWORK` 不得触发降级。
- Pi 使用独立 Chrome 实例和配置目录，每单按订单键登记专属页面。按实测 CPU 和可用内存逐页准入，高水位复测后恢复；页数不设固定上限。完工或异常时回收归属可证且未提交或结果已落盘的页面。提交状态未知先按原键核账。不同订单可以并行，只有冲突的账号写入和同一业务键需要互斥。遇通道超时先在已授权入口读原任务页，同一故障无新证据不重试；明确拒绝访问时停止该动作并记录原因。
