# 远端同步与读回

## 状态与诊断

- 本地 commit 表示改动已落盘。push 将提交送到远端，退出或超时后由远端分支和对应文件内容证明是否收录。Windows 增强 Pi 的实际加载版本另行读回。
- 将工具等待返回、连接或无进展诊断、任务整体截止分开。允许 Git 命令在后台继续并轮询。禁止用 15、22、30、35 秒固定墙钟作为上传失败判定。确证连接失败、鉴权拒绝或重试需先结束现有连接时，记录具体状态再处理。
- 一次只保留一个推送。在返回不明、超时或断开后，先 fetch 并检查远端目标内容。原提交可用 git merge-base --is-ancestor 检查，服务产生重整提交时，用 git show 读回精确路径和目标内容。已经收录就结束，避免重复提交。远端查询也失败时记为状态未知。
- 分支前移且目标内容尚未收录时，保留本地提交，抓取并 rebase 到新分支头。解决明示冲突，验证后正常 push，禁止强推。连接不畅时记录失败阶段和错误，排除前一推送后再重试。HTTP/1.1 可作单次连接对照，不能从一次成功推断原协议故障。
- 推送结束后读回技能标题以及新增引用文件。保存本地提交、远端分支头和读回结论。终端返回慢时不重复造提交，也不据此推断文件过大、配置错误或业务本身失败。

## 已核对的恢复案例

- V1.13 提交 3071a3f。前序尝试出现低传输速率超时，后续仓库远端跟踪记录为 update by push。收到远端状态后用 git show 核对 V1.13 标题和新章节。HTTP/1.1 尝试与先前尝试有重叠，无法据此断定哪个连接完成更新。
- V1.14 提交 a2146c2。两次有界等待退出后，后来 fetch 直接读回该提交，后续远端提交仍包含它。这说明客户端等待退出不足以判定远端未写入。
- 证据提交 7ce9358。曾用固定墙钟结束两次推送，返回码 124 表示本地等待上限触发。本次重新 fetch 已读回 7ce9358，确认远端实际已收录，无需重推该提交。
