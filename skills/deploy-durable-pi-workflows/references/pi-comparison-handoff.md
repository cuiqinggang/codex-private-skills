1. 核对正在运行的任务，复用已验收环境和成熟步骤。锁定增强派命令行、各方案版本、原始输入、任务入口、同一故障点和验收合同。记录各组具体由谁保存状态、谁执行、谁裁决及谁签收。正式运行前确认依赖和用户界面入口已就绪。
2. 先让自有 ECC 3.1.1 和 Matt 1.3.2 分别经同一增强派完成同一个小改动，从真实按钮路径走到独立签收。分别保存运行环境、业务检查和界面证据。Temporal、Conductor 在等价完整方案中验证调度及恢复。若把完整方案横向比较，使用相同业务任务、增强派和验收标准，记录组装差异。
3. 在同一已写入业务步骤后、回执送达前注入中断。通过原任务编号读取持久检查点、业务账本和已写产物；再核对原任务恢复及写入唯一。以同一案例触发需 GPT 裁决的疑难点，逐项核验真实请求、送达、裁决、回传、派实际消费及修正后的真实界面签收。只有系统自行完成整条链才登记无人值守通过。实时 GPT 或 Codex 介入时记录具体动作和时间，保留介入后的交付结果。
4. 小任务通过后，再跑同条件的正式长任务。从实际入口首次接单起计到最终独立签收，等待、故障、裁决和返工全部计入。不加人为任务时限。没有完整签收就记录实际阻塞和已有证据，不登记合格时间。DBOS 仍从官方隔离恢复短测起步；Cadence 保留历史记录。
