# Pi 长流程并行复测与能力登记

## 本轮任务与两条路线

沿用 Louez 隔离租赁预约业务、G00–G12 界面步骤、合成账本、备份还原和独立验收器。冻结源码、输入、工作量、模型与推理档、审核规则、资源和故障边界。采用原小时级代表业务，记录实际有效工作和等待；提前完成照实签收，不靠睡眠凑时长。每路从「Oh My Pi 增强 V3」接单。先用普通长任务描述验证 Pi 能召回本规程，留存选路和实际加载组件的回执。

| 路线 | 执行组合 | 要回答的问题 |
|---|---|---|
| C（主测） | 增强 Pi＋Temporal OSS | 检验持久化调度、Worker 接管和重启后接续 |
| B（对照） | 同一增强 Pi＋Superpowers 桌面直跑 | 检验不挂调度器时的业务交付与自动接续 |

沿用原编号以便核对历史回执。本轮跳过 A（Pi 原生）和 D（Conductor）。未来有具体业务需求时再评估 Conductor。对比结果归属各自的完整组合，不能据此单独量化 Superpowers 的增益。

不能证明某路线实际配置时，标为未验。历史 R170 的 Temporal＋Pi＋Superpowers 只归原组合。原 Run 优先只读核账；部分已运行的旧单保留证据，用新的隔离身份做公平计时。

## 派工与故障

1. Pi 用成熟配方分配独立任务号、工作目录、业务库、端口、队列和会话。预检实际执行身份、服务就绪及观测读回。独立构建、计算和取证并行，共享桌面 GUI、剪贴板及同一业务写入按所有者排队。共享调度服务有其他活动任务时，使用既有隔离实例或错开故障注入。按 V2.4.3 只在允许的 DeepSeek 时段新增收费调用。
2. 各路先做正常轮。核对可见预约操作、刷新后的账本、隔离还原、终稿及独立验收。正常交付和故障恢复分别签收。一条路线失败时保留其现场，其余独立路线继续。
3. 用不同隔离任务验证两个故障窗口。① 已有检查点时中断执行进程：有 Worker 的路线中断所属 Worker，直跑路线中断所属 Pi 执行进程。看谁主动接回、是否需要人工唤醒。② 业务写入成功但回执尚未落盘时中断回传。恢复后先查原订单和账本，仅补缺失回执。两项都检查唯一业务效果、原任务身份、历史证据与最终 GUI。没有自动接管者则记录该项未通过；观察者不得代接后申报无人值守。
4. C 增测调度服务重启，用原持久存储读回同一运行并签收。B 此项记不适用。已完成任务重开应只读核账。发生具体可修复问题时保留首次失败，只修相关节点，复验受影响场景并关联新回执。

## 审核、比较和复用

GPT 和 Gemini 读取同一份冻结验收条件、成品与证据，各自给出 PASS 或具体返工项。常规执行由 Pi 继续；关键分歧才交叉复核。Pi 根据缺项返工并提交新版指纹。Gemini 故障按双智能系统规则由 GPT 单签，记录实际审核方。若审核者在执行中提供救援，单独记录介入点；该轮能证明组合能力，不能据此认定 Pi 独立解决了该问题。

每路报告正常交付、各项自动恢复、真实 GUI、账本唯一写入、人工干预数、模型救援、实际并发区间及资源争用。完整 T_VALID 从正式 GUI 接单计到独立签收，含排队、半价窗口等待、失败和返工。另报整批墙钟。只有同质量、同负载、同故障及同审核条件的合格轮次才作速度比较。并行批次缩短的时间和单路线提速分别报告。

签收后把路线、适用任务、已通过的故障范围、正式入口、恢复检查点、实测时间及证据路径登记在本技能的已有实测索引。未来 Pi 遇到多阶段长任务、跨会话接续或写后回执丢失，先查该索引，选择覆盖当前要求的成熟路线。未验证的场景继续标为候选。另用一个新任务从 GUI 验证自动召回并走对入口，记录后再宣布自动调用通过。
