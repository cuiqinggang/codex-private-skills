## 核心能力
将参考视频拆解为可复用、可编辑的视频工作流；支持镜头、文案、字幕、B-roll、特效和节奏替换，采用文字锚点对齐；可生成多变体，也允许不调用外部生成模型、仅编译已有素材与代码渲染视觉元素。
注意：官网宣称的“100条”“爆款播放量”属于营销描述，未在用户设备上验收，不能视为结果承诺。

## 与已有视频制作流程的接口
已有视频技能包保持主控与验收；Hypit作为可选“参考视频结构复刻/字幕B-roll编排/可重渲染模板”节点。
输入：参考视频路径、合法使用的人物/音频/素材、目标脚本、目标宽高比、视频时长、选用的模型服务或本地素材。
输出：可编辑工作流、素材引用清单、渲染 MP4、制作成本/时间、许可证和素材来源说明。
与 ComfyUI 图片/视频生成节点形成互补，不替代既有图生图、音频、合成和质量检验能力。
不自动启动另一个浏览器、不修改 FlClash / 系统代理、不修改成熟 ComfyUI 环境；安装新依赖先检查后隔离。

## 成熟方式（仅提供官方入口，实际安装须按当前环境确认）
官方 Skill 安装：npx skills add hypit-ai/hypit -g
支持 Codex、Claude Code 等代理。首次使用由 Agent 检查 CLI 和运行依赖；生成模型服务费用、账号另计。优先使用已有模型/本地素材，避免重复部署。

## 试验与验收
1. 环境审计：记录 Node / npm / npx、Hypit CLI、GPU/CPU、当前已安装依赖；先不改现有生产流程。
2. 无外部模型的最小闭环：用自有参考视频 + 自有静态素材完成“输入→结构/字幕/镜头替换→渲染 MP4→本地播放”。
3. 质量比较：对齐镜头节奏/字幕准确性/人物稳定性/源素材版权，计时端到端耗时与真实费用。
4. 符合“虚拟成熟→整套 Freeze→一次 Reality”总规则；未成功真实渲染前不得标记生产成熟。
5. 只有净收益、稳定性及许可证均通过后，才写入既有视频制作技能包的主索引，并赋予正式调用入口。
