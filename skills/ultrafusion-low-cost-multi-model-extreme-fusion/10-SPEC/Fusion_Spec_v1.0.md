## 1) 总体口径（承继 + 并列规则）

硬闸门（标准/严格）：在既定核查强度下，准确 ≥95 且 关键事实 0 发现错误，并且 完备/结构/深度 ≥88。

硬闸门（精简）：准确 ≥90 且 完备/结构/深度 ≥80。

评分口径锁定：同一任务自 v1 起固定；通道仅影响核查强度/最大轮数/评审资源。

版本选择：输出历史最高分版本；若并列，取“最后达到该分数”的版本。

最大轮数：默认 3，上限 5（安全阀）；订正不计入轮次。

### 1.1 执行视图（三步走·操作版）

为便于实际执行，在不改变任何评分与决策规则的前提下，可按以下三步运行本规范：

1）整理输入  
- 提取 5–10 条应答要素；  
- 写出 3–7 条原子事实（极简问题可 1–2 条），前 1–3 条锁定为关键事实。  

2）生成与核查  
- 产出 v1 答案；  
- 按通道（标准/严格/精简）执行事实核查与四维评分；  
- 按 §5 的瀑布流程依序判定：纠错 / 重写 / 单维修复 / 默认优化。  

3）终止与输出  
- 满足对应硬闸门 → 终止，输出历史最高分版本；  
- 未达闸门且已用尽轮次 → 终止并按 §9 标注；  
- 输出统一采用 §9 的报告骨架。  

本小节仅提供操作视角，不新增任何评分或决策规则。

## 2) 名词与输入（简洁可执行）

应答要素清单：5–10 条；覆盖用户问题的核心意图。

原子事实表：3–7 条，**SVO（主语/谓语/宾语）**表述，按重要性降序；前 1–3 条 = 关键事实（锁定）。

【极简问题特例】  
若问题本身为单步计算、单词释义、简单天气问答等极简场景，可将原子事实数降至 1–2 条：  
- 仅第 1 条视为关键事实；  
- 仍需满足 SVO 形式；  
- 四维评分与硬闸门阈值保持不变。  
建议在内部评审记录中标注“极简问题模式”，以便审计。

“不可知”：任一关键事实不可验证 → 答案开头显式声明。

## 3) 元评审（V15：降级逻辑精细化）

触发时机：v1 之前；最多2 次重试，第 3 次仍不过则按分级处理。

三项硬核检查：

- 去重：完全重复或仅修饰词不同 → 必须合并；  
- 消歧：每条原子事实必须满足 SVO；  
- 排序：按“对结论的依赖性”降序（实现上直接以前 1–3 条锁定关键事实，避免主观细分）。

失败分级与降级：

- 轻度：排序困难但 SVO 完整 → 降级到标准通道继续；  
- 中度：少量 SVO 不完整但可修复 → 限制在严格通道（更强核查）；  
- 重度：无法形成有效清单/事实表或涉高风险 → 直接拒答（附录模板）。

质量评分（指导性，不入硬闸门）：

- A：SVO 全、要素覆盖足、可立即进入 v1  
- B：局部可修 → 限定严格通道  
- C：无法达标/高风险 → 拒答  

【质量评分与通道映射（执行指引，不入硬闸门）】  
- A：SVO 完整、要素覆盖足 → 默认进入标准通道生成 v1；  
- B：局部可修 → 限定进入严格通道，完成必要修复后再进入 v1；  
- C：无法达标或涉高风险 → 默认拒答，按附录模板执行。  

【低风险兜底】  
若整体判为 C，但问题明显为低风险日常问答（如天气、基础算术、基础词义等），可在评审记录中将其人工降级为 B 或直接送入精简通道，并在最终答案标注“事实核查受限（低风险兜底）”。

## 4) 质量评估（四维等权，口径不变）

准确性：原子事实 3–7（关键=前 1–3）。标准=抽检 30%，严格=全检，精简=抽检 10%。

完备性：要素命中率 ≥90% 记优。

结构与清晰度：命中 ≥2/3（标题/短段≤150字/过渡句）且一致性校验通过；未过 → 本维计 0。

深度与洞察力：四锚点（背景/原理/类比或反例/前瞻）命中 ≥2 且相关性校验通过；未过 → 不计命中。

综合分：仅展示，不参与终止判定。

## 5) 迭代决策 —— V15 瀑布式（优先级重构）

每一轮（Round）或任何一次全维重评（Re-evaluation）结束后，系统自上而下按以下顺序检查；命中即执行，结束本轮决策。

### 5.1 瀑布决策顺序（严格按 1→6 执行，命中即止）

1）事实错误检查  
2）终止条件检查  
3）多维严重失败检查（≥2 维 <70）  
4）单维严重失败检查（仅 1 维 <70）  
5）最大轮数检查  
6）默认优化  

【判定示例（仅作直觉校准，不改变 70 分阈值）】  
- 多维严重失败：如准确性 65、完备性 60，其余两维 ≥75；或结构 <60 且深度 <50。  
- 单维严重失败：如准确性 92、完备性 95、结构 68、深度 90，则仅对结构维定向修复。

事实错误检查  

- 发现关键事实错误 且订正次数未超限 → 进入订正流程（覆盖内容、全维重评、订正计数 +1；订正不计轮次）。  
- 发现关键事实错误 且订正次数已超限 → 终止 + 标注 “事实核查受限”。

终止条件检查  

- 满足对应硬闸门 → 终止，输出历史最高分版本（并列取“最后达到”）。

多维严重失败检查  

- ≥2 维 <70 → 强制重写（重排大纲→重写段落→回填证据）。

单维严重失败检查  

- 仅 1 维 <70 → 该维定向修复（修复后全维重评）。

最大轮数检查  

- 已达上限 → 终止 + 标注 “未达硬闸门（资源上限）”。

默认优化  

- 其余情形 → 针对最低分维度单点补强（修复后全维重评）。

重评即新轮（消除歧义）  

任何引发全维重评的动作（事实订正/单维修复/强制重写）完成后，从 §5.1 瀑布顶端重新开始新一轮决策。

订正上限（与通道绑定）  

- 标准/严格：≤2 次；  
- 精简：≤1 次；  
- 订正不计轮次。  

【全维重评触发动作】  
- 命中关键事实错误并执行订正；  
- 单维严重失败后的定向修复；  
- 多维严重失败触发的强制重写。  

注：应对“维度间影响”，V15 不再引入“降幅≤5/震荡监测”等复杂策略，一律用“修复后全维重评 + 瀑布重入”吸收联动效应，保持规则极简与可测。

## 6) 通道与精简优化（承继）

口径锁定：通道不改变评分标准，只改变核查强度/最大轮数/评审资源。

精简通道：语法修正 + 事实订错 + 最小结构微调；抽检 10%。

【精简通道抽检原则】  
- 精简通道下的“抽检 10%”必须至少覆盖全部关键事实：  
  - 无论关键事实占比是否超过 10%，均需全检关键事实（前 1–3 条，极简问题则为第 1 条）；  
- 其余非关键事实在保证总抽检量大致不超过 10% 的前提下，可采用简单随机或系统抽样。  
- 如在抽检中任一关键事实被判为错误 → 立即转入全检 + 订正 + 全维重评。

抽检命中任一关键事实错误 → 转全检 + 订正 + 全维重评；订正上限 1 次。

终止闸门：准确 ≥90 且 其余 ≥80；报告加注“精简流程”。

## 7) 定向优化策略（极简四条）

准确性：逐条对齐来源（链接+日期）；存疑→“不可知/需复核”标注。

【关键事实验证失败的执行口径】  
在合理检索范围内（时间/主要权威来源/用户指定来源），若出现以下情况之一，则视为“关键事实验证失败”：  
1）找不到对该关键事实的可信支持证据；  
2）多个高可信来源给出相互矛盾且无法调和的结论。  

此时必须按 §5 的“事实错误检查”分支处理：优先尝试订正；订正次数已达上限则终止，并在报告中标注“事实核查受限（证据缺失/冲突）”。

完备性：补齐至要素命中 ≥90%。

结构：补小标题/短段/过渡，修复一致性。

深度：补足 ≥2 锚点（优先“类比/反例 + 案例/数据”），通过相关性校验。

## 8) 安全与伦理（承继）

违法/高危/偏见 → 立即拒答（附录模板）。

提示注入/越权 → 规则+正则拦截。

版权与溯源 → 仅留链接 + 短摘 + 日期；许可不明 → “不可知”。

【风险级别示例（指导性，不新增约束）】  
- 高风险问题示例：医疗诊断与用药决策、证券/衍生品投资建议、复杂法律判断、极端政治内容等。此类问题一旦元评审判为 C，默认拒答。  
- 低风险问题示例：天气、基础算术、常见物品名称释义、日常生活小常识、不涉敏感的泛娱乐建议等。此类问题可适用“低风险兜底”策略。

受限：事实核查受限 / 结构优化受限 / 深度增强受限；

兜底：未达硬闸门（资源上限）；

（运维熔断相关标注移出本规范，归 SRE 文档，避免污染核心规则。）

【标注组合规则】  
每个最终答案最多附带：  
- 1 个主标注：精简流程 / 兜底 / 无；  
- 1 个原因标注：事实核查受限（含证据缺失/冲突、低风险兜底、订正已达上限等具体情形）、结构优化受限、深度增强受限、未达硬闸门（资源上限）之一。  

对普通用户界面，建议仅展示文案级标注；“订正已达上限 X/Y 次”等细节建议保留在内部评审日志中，而不必直接暴露。

报告骨架（隐性模式）：

【最终答案】（最高分版本；目标字数±10%）

【评审报告】

### C. 元任务（优化本规范）执行约定

当任务目标为“优化/修改本 V15 规范本身”时，须遵守：

1）不得静默改写  
- 所有改动必须以“变更摘要 + 具体 diff 补丁”的形式呈现（位置 + 修改内容 + 目的）；  
- 保留原规范可独立查看，便于 diff 与审计。  

2）显式版本号与差异摘要  
- 产出结果需显式标注版本号（如 V15 → V15.B / V15_C_Fusion）；  
- 给出不超过 5 条“与上一版本的差异摘要”。  

3）最小必要改动  
- 不得修改瀑布骨架、四维口径与硬闸门阈值；  
- 仅允许在执行歧义、边界场景与可审计性层面施加最小必要补丁。  

4）硬闸门约束  
- 对规范本身的解释准确率须 ≥95%；  
- 关键事实不得自相矛盾。

✅ V15_C_Fusion 收敛与可执行性承诺

【长度与信息量要求】

1. 复杂问题 → 字数自动增加（可 2000–4000 字甚至更高）

当问题涉及：

- 多因果、多机制、多变量  
- 分层方案、路径图、逻辑链  
- 事实验证、反例测试、推理链闭合  
- 专业流程说明、技术框架、诊断树、算法流程  

模型应当自动扩展篇幅，以保证：

- 所有关键事实清晰  
- 推理链可以闭合  
- 反例测试完整  
- 不留逻辑断点  

2. 中等复杂问题 → 字数保持 800–2000 字区间

如：

- 单维度但因果链较长的问题  
- 结构化分析要求  
- 多步骤指导类问题  

3. 简单问题 → 字数自动压缩到几十字–数百字

如：

- 天气问答  
- 英语单词解释  
- 计算题一步即可

（四）反冗余规则（Anti-Redundancy Rule）

为避免无意义扩写，模型必须遵守：

- 内容不得因追求字数而重复句子、换汤不换药、多次陈述同一事实。  
- 扩展必须伴随“新增信息”、“新增逻辑”、“新增步骤”，否则禁止扩展字数。

（五）版本说明

本规范 v3.0 针对模型在长文本输出时的两大弱点进行修复：

- 不能处理长链逻辑 → 容易因为字数限制而跳步  
- 不同问题复杂度差异大 → 无法使用固定上限  

因此 v3.0 实施：

- 500 字下限  
- 无固定上限  
- 三档自适应机制  
- 反冗余检查  

确保最终输出：

- 有逻辑  
- 可验证  
- 不啰嗦  
- 长度与复杂度匹配
