# UltraFusion 6.1 官网三模型极限答案工作台

日期：2026-07-02
版本：6.1

## 1. 6.1 核心结论

UltraFusion 当前正式路线从 6.0 的：

```text
GPT 官网订阅版 + Kimi 官网会员版 + GLM-5.2 / GLM Coding Plan
```

修正为 6.1 的：

```text
GPT 官网版 + DeepSeek 官网版 + 千问/Qwen 官网版
```

这不是普通小修，而是模型路线、使用边界、公共服务理解、V15 注入规则和验收规则的整体校准。

## 2. 关键变化

| 维度 | 6.0 | 6.1 | 变化性质 |
|---|---|---|---|
| 主组合 | GPT + Kimi + GLM-5.2 | GPT + DeepSeek + Qwen | 核心模型路线重构 |
| 选型原则 | 低成本 + 多智能体 + 工程执行 | 官网/官方产品质量优先 | 评价标准重构 |
| GPT | 质量锚点、最终融合 | 主脑/总控/最终验收/视觉入口 | 地位进一步固定 |
| Kimi | 正式核心复杂任务模型 | 降级备用，仅高价值 Agent Swarm 标杆 | 从核心降级 |
| GLM-5.2 | 正式核心工程执行模型 | 不进答案主链，仅工程执行候选 | 从答案链移出 |
| DeepSeek | 降级备用 | 回归核心，但只走官网 | 从备用回归核心 |
| Qwen | 备用综合模型 | 进入主组合，第三视角和中文补充 | 新增核心成员 |
| API | 可作为备用自动化路线 | 不进入当前极限答案主流程 | API 边界收紧 |
| 公共服务 | 偏向寻找低成本模型链 | 官网质量层 + 未来工程层 | 架构分层 |
| V15 | A/B/C/D 都要注入质量标准 | 必须粘贴 V15_FULL，不准只写模式名 | 注入规则硬化 |
| 验收 | 有 D 层审计 | 三轮实际测试 + 截图验证 | 验收标准强化 |

## 3. 模型新定位

### GPT 官网版

```text
主脑 / 总控 / 最终融合 / 最终验收 / 视觉多模态入口
```

GPT 必须在主组合中，不再作为候选项讨论。

### DeepSeek 官网版

```text
低成本深度分析主力 / 反方审稿 / V15 极限答案模型
```

硬规则：

```text
DeepSeek 只走官网，不走 API。
DeepSeek API 不进入极限答案主流程。
```

使用方式：

```text
不需要当前信息：问题 -> DeepSeek 官网专家/深度模式 + V15_FULL -> GPT 融合
需要当前信息：专业搜索前置 -> DeepSeek 官网专家/深度模式 + V15_FULL -> GPT 融合
```

### 千问/Qwen 官网版

优先入口：

```text
1. 千问中文官网 qianwen.com
2. Qwen 国际版 chat.qwen.ai
```

模型优先级：

```text
优先：Qwen3.7-Max
备用/深度审稿：Qwen3-Max-Thinking
不优先：Qwen3.5-Flash
不用于问答主链：Qwen3-Coder
```

角色：

```text
第三视角 / 中文资料补充 / 搜索前置候选 / 多样性审稿 / 漏点检查
```

### Kimi

从核心降级为备用：

```text
少量高价值问题审稿；
Agent Swarm 标杆样本；
复杂任务抽样测试；
需要时短期开通；
暂时不买、不进主链。
```

### GLM-5.2

从答案主链移出，只保留为：

```text
Coding / 工程执行 / 技能包制作 / 文档结构化 / Kilo 或 Claude Code 执行候选
```

不负责普通公共问答主链，不参与默认 A/B 极限答案链。

## 4. 官网三模型的边界

6.1 明确：

```text
官网三模型组合 = 极限答案工作台 / 高价值问题增强 / 模型互审 / 提示词评测台
不是 = 大规模自动化公共服务后端
```

可用场景：

```text
个人/内部高质量答案；
V15 提示词测试；
多模型互审；
高价值问题人工增强；
模型能力对标；
公共服务前的质量基准。
```

不可用场景：

```text
大规模自动化调用官网网页；
高频公共服务后端；
批量脚本控制网页；
完全无人值守商业服务。
```

## 5. 公共服务两层架构

第一层：官网极限质量层。

```text
GPT 官网 + DeepSeek 官网 + 千问官网
```

用途：最高质量、半自动/人工、高价值问题、A/B/C/D 流程验证。

第二层：未来公共服务工程层。

```text
用户入口；
问题分级；
缓存库；
低成本基础回答；
高价值问题升级；
人工/半自动审核；
合规 API 或私有化部署；
风控和服务稳定性。
```

## 6. 6.1 推荐流程

### 不需要联网的问题

```text
1. GPT 做问题拆解/初判；
2. DeepSeek 官网专家/深度模式 + V15_FULL 做 A 关；
3. 千问 Qwen3.7-Max + V15_FULL 做 A 关；
4. GPT 汇总 DeepSeek/Qwen/GPT 自身结果；
5. GPT 输出最终答案；
6. 进入三轮实际测试/截图验证。
```

### 需要联网的问题

```text
1. GPT 或千问先做专业搜索前置；
2. 整理关键事实、来源、时间、证据等级；
3. DeepSeek 官网专家/深度模式 + V15_FULL 做深度分析；
4. 千问 + V15_FULL 做第三视角补充；
5. GPT 最终融合；
6. 进入三轮实际测试/截图验证。
```

### 极限答案任务

```text
A关：DeepSeek + Qwen + GPT 各自极限答案；
B关：反方审稿 / 查漏 / 初步融合；
C关：GPT 主导统一极限融合稿；
D关：GPT 输出最终答案 + 审计报告 + 不确定性；
验收：三轮实际测试 + 截图证据。
```

## 7. V15 注入硬规则

```text
不能只写“进入 V15 极限答案模式”。
必须真实粘贴完整 V15_FULL。
```

标准拼装结构：

```text
V15_Guard_Prefix
+ V15_FULL
+ 当前层模板
+ 用户问题 / 输入材料
+ 输出格式要求
```

后续必须定位并固化：

```text
V15_FULL
V15_Guard_Prefix
V15_FULL_WITH_GUARD
V15_Injection_Hard_Gate
Prompt_Assembly_Rules
A_Extreme_Answer
B_Extreme_Fusion
```

## 8. 验收规则

写入技能包、知识库或 GitHub 后，不能直接标记 FINAL PASS。

必须完成：

```text
三轮实际测试 + 截图验证
```

建议三轮：

```text
1. 不联网问题测试；
2. 需要联网/当前信息问题测试；
3. 技能包/知识库写入后路由测试。
```

没有截图的验证，状态只能是：

```text
PENDING_THREE_ROUND_SCREENSHOT_VALIDATION
```
