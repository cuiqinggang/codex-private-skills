# V2 全帧真实源图方法

状态：METHOD_SPEC_READY / REALITY_CERTIFICATION_PENDING。来源：权威父包 `CODEX_H3_V2_FULL_FRAME.md`，提交 `ada04131c5389356eb539108e509f0312e57ed64`；入口关联提交 `d03e233859c820b4d34faf013a60d95adb977d37`。

## 固定规格

本次场景为阳光厨房果篮微动作短片：一个藤编果篮、恰好两个橙子、一个白橙条纹小南瓜、一个透明空玻璃瓶、一把木勺、一块米色条纹布、一只自然的人手。固定厨房背景与木桌、左上暖阳；手接近、接触、轻提、整理、放回布料并撤离，镜头轻推。

一般任务先确定整数 N 与 FPS，再以 T=N/FPS 得到准确时长，不能对非整数 T×FPS 静默取整。本次固定 N=56、FPS=24。所有源文件命名 `frame_001.png` 至 `frame_056.png`。

## 每次调用必须保留

每帧记录至少包括 `frame_index`、`attempt_id`、真实调用方式、可获取的调用 ID / 模型 / 参数、完整提示词、首帧与上一合格帧输入路径及 SHA-256、输出原图路径及 SHA-256、开始/结束时间和耗时、调用错误、验收结果与验收者。未暴露字段写 `NOT_EXPOSED`，不得凭推测填写。

首帧没有上一帧，将其参考字段明确设为 `NOT_APPLICABLE_FIRST_FRAME`。后续帧两张参考图须真实输入模型。只在提示词里说“参考上一帧”但未传图不满足合同。输入证据应来自工具调用、请求清单或服务记录；若无法证明双参考输入，写 `SOURCE_REFERENCE_UNVERIFIED` 并停止正式认证。

生成每帧的极小动作变化由统一轨迹决定；以实际画面核查完成程度，不能把提示词中的坐标当作输出画面坐标。合格首帧固定为身份锚点，上一合格源帧为直接动作锚点。参考输入可以是原始模型图，或有完整一对一派生记录的规范化 PNG；后一种必须记录参考 PNG 及其原始模型输出的映射。模型可能造成物品、手指或背景漂移，必须逐帧拦截。真实来源证明与画面合理变化证明分别完成，56 个不同文件或哈希都不足以认证。

每个真实模型调用独立留证。不得复制、改名、修改元数据、编码重写、简单位移、光流或插帧冒充新的模型源图。允许中间候选 REJECT；删除或覆盖失败证据会损害来源链。需要修复已接受的早期帧时，原后续链标为 STALE，逐帧重新确认参考关系和连续性。

## 原图到编码输入的透明处理

原始模型 PNG 原件留存。编码派生图位于独立目录，标为 `DERIVED_ENCODING_INPUT`。所有 56 张派生图一对一映射真实源图；派生处理不是额外生图。

本次存在 1681×936 等原图；已读取 frame_004_result.json 报告第 004 帧原图为 1684×934，经 `scale=864:480:flags=neighbor` 空间处理得到 864×480，`temporal_interpolation=false`。逐帧实际尺寸须分别记录，不能假设所有模型输出尺寸一致。原任务没有“必须原生 864×480”的硬门禁，非原生输出本身不判 FAIL；不可把派生尺寸宣称为模型原生输出。尺寸不一致时明确记录统一缩放/裁切/填边方式、工具版本、参数、处理时间及前后哈希。统一处理不能逐帧改变构图或引入新的镜头运动；默认保留纵横比，既有轻微纵横比调整如采用须透明记录并实际复验品质。必要裁切须先证明不损害手指、物品或画面完整性。若缩放产生质量损失，保留原图并复验派生图。

## A 模式无插帧编码门禁

编码前须核对：恰好 56 个连续编号、PNG 可解码、源图身份与调用证据完整、尺寸处理一致、逐帧 PASS、相邻连续性 PASS、没有复制/伪装/重复源图。任何条件未通过，正式编码 `BLOCKED_BY_FRAME_GATE`。调试编码如确有必要必须放在候选目录并标 `INVALID_DEBUG_ONLY`，不能作为交付。

以下是已过门禁后的 FFmpeg 命令形态，具体路径由任务模板填入；运行前记录版本，不强制安装新工具：

```text
ffmpeg -framerate 24 -start_number 1 -i <encoding_frames>/frame_%03d.png -frames:v 56 -fps_mode passthrough -c:v libx264 -crf 18 -pix_fmt yuv420p -movflags +faststart <candidate>/video_only.mp4
```

禁止插帧 filter、重复帧、生成式重绘或改乱顺序。不要用新的输出 `-r` 作为偷偷补帧的手段。源图序列以输入 24 FPS 产生时间戳；实际输出仍须验证 56 帧及 PTS。

音频采用合法可追踪素材或本次实际生成/录制声音。厨房环境及布料摩擦应能听到且与动作配合。复用 V1 音轨时须证明来源与质量；不因旧片已有 AAC 而自动通过。生成音频须记录生成来源，不能把合成噪声擅自称为真实录音。

在视频已保留独立原片的前提下封装音轨；允许视频码流 copy 与正常 AAC 编码。音轨需按 56/24 秒裁切/对齐并检测尾部编码 padding；视频帧数与时长判断以视频流及 PTS 为准，容器时长差异单独解释。正式合格仍须声音内容和播放听检。

## H3 辅助

接口能力先实查，缺失记 NOT_AVAILABLE，未运行记 NOT_RUN。H3 生成候选与 A 模式分开保存，比较手部、道具、光照、动作、声音与真实耗时。H3 未保留全部源帧时不能称作 A 模式，也不能替代本次 56 张真实源图要求。暂停的 ROI 门禁不启用；真实阶段耗时照常记录。
