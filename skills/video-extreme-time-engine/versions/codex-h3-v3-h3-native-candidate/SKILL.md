# 《Codex＋MiniMax H3 商业级视频制作》V3候选｜2026-10-13

**状态：隔离候选；非 V2 替换、非正式通过、非商业视频实际交付。**

## 1. 为什么改变
V2 的正式 C 链仅 C001–C003 PASS，C004 连续三次真实生图分别动作过大、过大、近零，精确局部时序移动不可稳定保证；旧 A/B 目录已有更多 PNG 不能冒充正式 C 链。V2 的 56 张独立真实源图在“精确每帧都必须由图像模型生成”特殊合同下保留，但**普通商业短片不再把 24FPS×时长等同于需独立画出的静帧数**。

H3 原生生成连续视频和音频，官方允许 4–15 秒、24FPS；线上可到 2K，开放权重本地基础输出768短边。Codex/GPT 负责导演、素材、分镜、官方提示词、调用和验收；H3负责时间连续性、运动与原生音频；成熟工具负责裁切、封装与审计。

不修改已冻结 V2 或 V1、不删除任何原资产。此候选执行遵守《三人行》V2 C002 的“按需选择、完整有效墙钟、先复用、Exactly-once、只在冻结后正式现实验收”原则；该《三人行》V2 本身是已保存但尚非全局默认。

## 2. 三条成熟候选（最多三条，不凑数）

**A 云端 H3 Ref2VA 全参考一段 15 秒｜首选**
来源：MiniMax H3 官方云端 Video Generation V2 + 官方 h3-prompt-writing / brand-promo-video-generator；借用 MiniMax Hub 广告技能的节奏表方法，不假设 Hub 专用 hub_* 工具在 Codex 中存在。
1. 选用有来源的真实主体/道具/场景参考图，最多9图；按需参考视频最多3段，总15秒内；参考音频最多3段且不能单独作为唯一输入。
2. Codex 编制中文创意与 15s 分秒分镜、身份/物件清单；按官方 ref-en 六段结构写 H3 英文执行提示词，台词/画面文字保持原文。
3. 经已经授权的官方 H3 云端账户/API，提交 **MiniMax-H3 / Ref2VA / 15s / 16:9 / 原生音频**，必要时使用官方托管2K。
4. 下载原片、保存真实任务ID/费用/耗时/输出sha、逐镜观看并听检；不成功至多有限次按实际缺陷单点重做，失败不造PASS。

**B 云端 H3 FL2VA 首尾帧直控 15 秒｜单镜头备选**
来源：MiniMax H3 官方 FL2VA（零、一、二张图）+ 官方 CLI 视频生成V2；不是旧 Hailuo-02 模型。
1. 验收同一场景的首帧和**确实存在且独立验收**的终帧；不能把 003 冒充 15 秒结束画面。
2. Codex 用官方 base-en 三段提示词明确从首到尾的动作因果、镜头、声音，15秒内仅一个主要动作。
3. 用经授权 H3 云端服务提交两帧+prompt，15秒16:9原生声音；回收、逐帧抽检、实际播放和商业验收。
4. 如果结束位置稳定但身份/中间动作弱，转 A 的多参考机制，不凭空追加数百图。

**C 本地 ComfyUI H3 Ref2VA / 多帧参考｜离线条件下的备选**
来源：ComfyUI 官方 MiniMax H3 原生模板及 Multiframe Reference（Add Guide 时间锚）。
1. 用现存 H3 pruned INT8权重、Qwen3VL编码器、视频/音频VAE及已有ComfyUI；先核对版本、显存/内存、端口、模型hash与完整许可，不默认重装或改变代理。
2. 选择 Reference-to-Video / Multiframe Reference 官方模板；最多9图参考，用关键时间点锚定（不是每帧强制独立图）；普通品质先不启用过度的Turbo LoRA，参考锁定重要时官方建议20步。
3. 15s/24FPS/16:9、本地约768短边生成原生音视频；留存ComfyUI prompt_id、历史状态、工作流json、原MP4与音轨。
4. 有OOM、超时或许可不满足则停止，转经授权云端A，不牺牲质量或重复支付算力税。

## 3. 同题对照与虚拟成熟冻结
同一测试题：既有“阳光厨房果篮＋米色条纹布＋一只手”场景，保留旧C001–003合格参考原件。目标 15s/16:9/24fps，有镜头目的、连贯动作、自然布料声、无虚假商品标识。商业可用只在相应权利许可有证据时允许宣布。

统一时间轴：0–3秒环境/构图锁定；3–6秒手接近并接触布料；6–9秒拾起并平顺展开；9–12秒整理归位；12–15秒自然退出，摄影机轻推并稳定收尾。每段主要动作只有一个，保持两个橙子/一小南瓜/一透明空玻璃瓶/一木勺/一果篮位置一致，不跳镜/不多手/不凭空新增物品。

虚拟比选（定性机制比较、非现实实测）：
- A：原生时间运动+多参考+托管2K与原声，最适合品质优先和商业交付；代价是账户/API和每次云端成本，未验收成本。
- B：输入门槛低、固定头尾构图好，适合单个镜头；需要合格的15s终帧，多物体/人物一致性未实证。
- C：复用本地开放模型、有参数控制、理论上无按次API生成费；本地长片资源和商用许可风险明显，不能以“零API费”冒充零成本。
- 旧V2：每张独立图片可严格追溯，但精确微步已实测阻塞，不应作为一般商业视频首选。
- 本轮选择 A 为最高优先候选；B 为需要明确收尾关键帧时的选择；C 仅商用许可及资源合格时备用。**排序是结构性虚拟成熟结果，不是商业质量或 T_VALID 实测排序。**

## 4. 正式生产及独立验收门禁
- 先验收素材来源、角色/道具一致性、业务声明和商用授权；费用/外部发布等另有权限门禁，不能因用户要求生产就擅自对外发布广告。
- 预审提示词/时间轴/身份锚点/负例；整体候选 Freeze 后才做一次真实生产路径。
- 记录 TASK_ACCEPTED、API提交/任务ID、排队、生成、下载、修复、独立验收全程实际墙钟；无数据记 UNKNOWN。不得以一次媒体输出替代可重复生产能力。
- 成片逐段观看、听检：15秒、实际视频24FPS、画面/声轨不空、首中尾身份和道具数量、人物手部解剖、动作因果、相邻时空连续、声画同步、镜头语言/光照/可传播性、无水印、商用权利状态。缺一必要项则不写 FINAL_VALID。
- 对每次失败执行 GOOD/BAD/FIRST_DELTA → 优先成熟组件最小修复 → 原合同有界重验；任何三次同类失败冻结，不放宽判定。
- C分支本地许可：ComfyUI 官方当前说明本地权重商用需另有许可，Comfy Cloud 作品另有已包括权利；不同平台需按实际上线条款核对，不做泛化法律担保。
- 正式结果以 [REALITY_AND_EVIDENCE.md](REALITY_AND_EVIDENCE.md) 更新的真实证据为准；**当前不可报告已生成H3新片**。
