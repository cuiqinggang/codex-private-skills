# Reasonix具体模型、力度、工具与智能体控制

本专题在资源分派或专项验收时加载。当前版本0.3.0。

## 职责和成熟入口

Codex负责主控、环境核对和结果验收；AI资源总调度2.0核心精简版负责按任务选择agent、provider、model、effort、技能与工具；Reasonix落实实际请求和工具执行。复用现有CLI/ACP/受支持本地接口或已有桌面自动化适配器，读取当前help/技能正文后使用，不能猜测参数。

Reasonix桌面和CLI不默认共用同一个profile、模型目录、会话或配置。记录实际provider/model目录和profile映射。CLI通过只能证明该控制入口；用户桌面的菜单读回与真实调用要另有对应证据。若CLI/ACP可设置同一目标环境、模型与工具，可将它用作Codex自动控制Reasonix的成熟入口，无需强制机械点菜单。桌面界面状态是否同步单独记录，不虚称已操作桌面。

## 最低需要做到

1. 读出当前可选provider/model及对应支持的effort。截图里的deepseek-v4-flash和deepseek-v4-pro只是优先核查对象，当前实际不存在则不能硬造。auto/disabled/low/high/max也不代表所有模型都支持。
2. 通过真实接口明确选择模型，用至少两个当前可用模型各执行一次短任务。模型不可用则报告该路线，不把同一模型的两段自述当作两模型实测。
3. 对实际支持力度设置的模型，采用至少两个不同有效档位各发一次真实请求，记录原参数和接口转换后的发送值。可以与两模型测试复用，但不同模型不同力度不证明同一模型的力度切换；需注明覆盖关系。预算允许时优先同一模型验证两档。
4. Reasonix实际调用任务所需的成熟技能及文件/终端/MCP工具，产生可检查的成果；Codex在外部读取成果独立核对。只有文本回答或Codex代替Reasonix执行，不算Reasonix工具能力通过。
5. 让现有调度根据至少两个不同特征的任务自动选择资源，记录简洁选择依据与最终实际调用参数。不要人工把每次选择填死后称为智能路由。合理选择同一资源可以成立，但不能据此宣称已验证不同模型切换或性能最优。
6. 任务确有两个可独立工作包时，沿现有调度调用至少两个真实独立智能体上下文，记录启动及回执；至少一个经Reasonix路线，另一个可用调度选择的Codex/Reasonix等。每个上下文记录自己的模型/力度和工作包，不要求两者模型必须不同；顺序运行也可验证分派，只有运行时间确实重叠才称并行通过。普通任务不常驻多智能体。
7. 不支持的模型/力度要在发送前识别，或以真实接口错误明确呈现；只在有明确策略的情况下转换/换路，并记录转换，不能静默忽略。权限/登录错误遵从真实边界，不换账户目录或扩权绕过。

## 生效证据要分开

| 层级 | 记录 | 能说明什么 |
|---|---|---|
| 选择状态 | 实际菜单/会话设置、provider、requested_model、requested_effort | 控制状态已设置 |
| 请求执行 | 既有安全诊断或脱敏任务日志的resolved_request_model、sent_effort、request/session id | 该任务实际发出所需模型与力度参数 |
| 返回结果 | 工具/终端回执、产物、provider_reported_model（若有） | 调用完成和任务成果 |
| 外部验收 | 产物解析及预设期望值 | 任务是否达标 |

服务端不返回模型或隐藏推理细节时写UNKNOWN；不要求打印私有思维链，也不从回答风格、耗时、token数或模型自报身份推断底层模型和思考强度。请求参数证明发送生效，不证明供应商内部实现。auto可证明发送auto策略，不把其内部最终档位猜成high/max。
仅能读到界面而无法观察请求或现成等价运行记录时，状态为“选择已设置／请求生效未验证”，不报全通过。优先复用既有日志，不开启全量敏感网络抓包。

## 作用域、权限与成本

- 每次在隔离测试会话或任务参数层设置，保留用户原会话。确需改变已授权的共享选择时先读取原值并在结束恢复；不改全局默认、密钥、代理或权限模式。
- “询问／自动／Yolo”不是effort；不为使测试自动通过切换到Yolo或降低权限限制。
- 使用既有已配置资源与额度；按任务最小调用，不遍历全部供应商×模型×力度组合。
- 记录elapsed、可观察的token/费用和重试次数，缺数据写UNKNOWN；截图金额不当作当前余额，也不向外发送。
- 修正只限本技能绑定与本次受支持参数，不升级/重装Reasonix，不修改原资源调度算法；原组件真实缺口单列。
