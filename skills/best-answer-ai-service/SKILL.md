# Best Answer AI Service

## Purpose

Use this skill to preserve and advance the Best Answer AI project.

Best Answer AI is not another chatbot and not a claim that one model is always stronger than GPT or Claude. It is a web service that pushes existing AI systems closer to their real answer limit through a repeatable answer process:

```text
UltraFusion Engine = V15 + A/B/C/D extreme drafts + cross-absorption + dense fusion + final stress test
```

The product must stay web-first, English-first, and outcome-first. Domain name, trademark, and app packaging are lower priority until answer quality and willingness to pay are proven.

## Core Rules

1. Treat `Best Answer AI` as the user-facing product name.
2. Treat `UltraFusion Engine` as the internal process/engine name.
3. Do not make mobile apps before the web MVP proves demand.
4. Do not prioritize premium domains or trademarks before the core answer effect is proven.
5. Do not offer full A/B/C/D for free by default; protect model cost with routing, quotas, and credits.
6. Keep V15 as the hard quality standard. Do not silently replace the full V15 invocation with a short system prompt when running formal A/B/C/D tests.
7. Keep A/B/C/D as all-extreme layers. Temperature controls divergence vs convergence; it does not downgrade quality.
8. Treat `max_tokens` as a measured test variable until real output data shows safe defaults.
9. Use mature SaaS and AI web app paths before inventing custom architecture.
10. Save useful decisions and test evidence into references so the project accumulates memory instead of rediscovering the same logic.

### 2. Keep the Product Simple

Default product shape:

```text
One web page
One question box
Three modes: Quick Answer / Deep Answer / Best Answer
One clear final answer report
Credits or paid checkout for expensive runs
```

Avoid early distractions:

```text
No native app
No expensive domain chase
No complex brand system
No unlimited paid plan until costs are measured
No fully automated large system before thin-slice tests pass
```

### 3. Use the Current Product Language

Preferred front-page language:

```text
Best Answer AI
Not a bigger model. A better answer process.
```

Alternative lines:

```text
For questions where a quick answer is not enough.
Get the answer after AI has argued with itself.
Turn raw AI output into a stress-tested final answer.
```

### 4. Preserve Decisions

When a new decision becomes useful, add it to the most relevant reference file. If it is a cross-cutting decision, add it to `references/08-continuous-memory-rules.md` and cite where it affects the process.

Do not create many loose notes. Keep the skill durable and structured.

## Deliverables This Skill Should Produce

Depending on the request, produce one or more of:

- Product positioning summary
- Mature path checklist
- A/B/C/D execution plan
- Runtime parameter update
- Free/paid pricing sketch
- Cost control policy
- MVP web plan
- Validation test matrix
- Codex command package brief
- Updated skill reference file

## Acceptance Standard

A good output from this skill should answer:

1. What is the shortest mature path?
2. What should be tested next?
3. What should not be done yet?
4. How does the decision protect cost and quality?
5. Where should the decision be preserved for future use?
