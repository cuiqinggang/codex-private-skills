# Mature Web SaaS Path

## Principle

Follow mature paths. Do not invent a custom startup route when proven AI SaaS patterns already exist.

The mature path is:

```text
Web-first -> English-first -> free light tier -> paid credit tier -> real user validation -> iteration
```

## Why Web First

Users dislike extra steps. A web page is easier than an app:

- no download;
- no installation;
- no app store approval;
- works through a shared link;
- easier to test globally;
- faster to change.

Do not build a native app until the web product proves repeated demand.

## English-First Market

Prioritize English because:

- higher SaaS payment habit;
- stronger credit card/Stripe culture;
- larger global professional market;
- more willingness to pay for productivity and knowledge services;
- higher chance that a serious answer service can charge enough to cover AI costs.

Initial target regions:

```text
US
Canada
UK
Australia
New Zealand
Singapore
Hong Kong
Western Europe English-speaking users
```

Chinese support can exist, but it should not define the first paid market.

## Current Stage

The project is at function validation stage.

Do not overbuild. Current priority:

```text
Can Best Answer AI produce a visibly better answer than normal AI direct use?
Can it do so with controlled cost?
Will users pay for the full answer process?
```

## Mature Phases

### Phase 0: Manual/Concierge Validation

Use the existing UltraFusion/V15 workflow manually or semi-manually.

Goal:

- prove quality;
- estimate cost;
- refine output format;
- discover which questions deserve Full A/B/C/D.

### Phase 1: Simple Web Intake

Build a page with:

- product name;
- short value proposition;
- question input;
- mode selector;
- email or login capture;
- manual or semi-automated backend.

The page can use a temporary URL.

### Phase 2: Automated D-Lite

Create a free lightweight mode:

```text
Quick Answer + assumptions + main risk + counterargument + confidence
```

Free mode must not run full A/B/C/D by default.

### Phase 3: Paid Best Answer

Offer full A/B/C/D only through paid credits or limited paid packages.

Output should feel like a final report, not a chat bubble.

### Phase 4: Repeatable System

Automate:

- queue;
- cost ledger;
- routing;
- result storage;
- user history;
- payments;
- refund/failed-run handling.

## What Not to Do Yet

Do not:

- build a native app;
- spend money chasing premium domains;
- build many pages before one core page works;
- offer unlimited Full A/B/C/D;
- automate everything before 20-50 test questions prove value;
- target low-payment markets first;
- hide costs or skip cost logging.
