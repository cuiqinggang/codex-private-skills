## 关键失败与修复

| 失败 | 原因 | 修复 |
|---|---|---|
| Chrome 截图空白 | 部分抓屏工具与 GPU 合成不兼容 | 使用 PIL ImageGrab 或官方截图技能 |
| 左屏负坐标点击偏移 | 进程未启用 Per-Monitor DPI Awareness | 在截图/鼠标 API 前调用 `SetProcessDpiAwareness(2)` |
| 视觉模型直接报点误差过大 | 3840px 大图缩放后，小按钮只占少量像素 | 裁剪评论栏，再用网格定位 |
| 50–100px 网格仍太粗 | “回复”按钮比网格小 | 先 50px 粗定位，再用 20–25px 细网格 |
| 截图已保存但用户看不到 | 代理只内部查看或只报告路径 | 必须用 Markdown 图片直接发到对话正文 |
| 中文剪贴板乱码 | shell `clip` 编码不稳定 | 使用 tkinter UTF-8 文本源 |
| 回复可能成为独立评论 | 未确认 `回复@目标用户` 上下文，或 `Ctrl+A` 破坏焦点/状态 | 粘贴前后都截图；不默认 `Ctrl+A`；最终验证嵌套关系 |
| 可能重复发送 | 页面已由另一执行链完成，但当前链仍准备继续 | 每次开工先检查评论数和本账号现有回复 |

## 证据标准

一条完整证据链至少包含：

1. 三屏全景图。
2. 目标屏裁图。
3. 20–25px 细网格目标图。
4. 点击后带 `回复@目标用户` 的大输入框图。
5. 粘贴后的全文核对图。
6. 发送后的嵌套回复图。

每张图必须实际出现在对话正文；内部查看、工具预览或仅保存路径均不计入验收。
