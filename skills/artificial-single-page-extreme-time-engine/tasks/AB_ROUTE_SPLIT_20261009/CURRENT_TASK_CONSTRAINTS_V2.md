# 《A/B路线分叉任务目标与正反约束 第2版》

继承第1版（`CURRENT_TASK_CONSTRAINTS_V1.md`），此次目标扩展：明确单一外部入口、B最短运行链、实际版本/任务冻结自动定位与正确的A/B完整时间口径。

## 最终现实目标
在第28版成熟共同总纲的基础上，让GPT在**用户只需自然语言一次交付任务**时，可靠选择A双层或B单层路线，自动读取真实方法版本与该 TASK_ID 冻结，按实际授权持续推进到合法 DONE_WHEN/FINAL_VALID；不得因局部故障修复而提前结束。两路线以获得同一质量实质成果的完整有效时间作唯一比较。

## 正向约束
- 保持一份共同原第28版基线，A28/A25/A18独立保留；B按整数从B29/B26/B19连续向上升级，版本文件仅保留与先前继承规则的差异。
- 一个稳定标准技能入口 `SKILL.md` → `START_HERE.md`，按 `routes/A/ROUTE.md` 或 `routes/B/ROUTE.md` 自动定位路线的当期引擎/大脑/模板，不在用户提示词里复述它们。
- 所有任务必须有自己的真实合同/不可变Freeze和 `tasks/<TASK_ID>/CURRENT.md` 指针；写入必须可核验，不能从其它任务推断状态。
- GPT是实际规划与执行主脑；Dot/n8n/Codex/Playwright MCP/Windows桥只按成熟能力、权限和完整成本选择。B可以不使用n8n。
- B一页一个自然节点，节点内多步且可修复故障连续推进；节点结束即Freeze，任务没完成需要下一个GPT单层页面按最短信封继续。
- A/B比较从同样用户任务输入到**相同VALID实质成果**的全部时间：B重新建页、重新理解、再完成工作的时间必须计算，A派发/合并也计算；不比较孤立局部开销。
- K盘已有ZIP为离线备份入口，每次重要方法升级后核对实际文件与提交再更新备份。原n8n共享浏览器任务F002单独保留，不篡改它。

## 反向约束
- 不将普通简单问答作为长流程成熟证据；不靠“新页面理解很快”推断A/B谁快；没有实证不写虚拟最优数。
- 不写自制通用状态机、调度器、资源锁、浏览器控制器；不复制两套完整方法。
- 不能声称标准GitHub SKILL.md对任何未安装/无权限用户自动可用；不能宣称Dot状态服务或GPT自动建页已验收。
- 不擅自发送业务消息、修改FlClash代理、关闭已登录浏览器；UNKNOWN不自动执行重复副作用。

## FINAL_VALID
统一调用路径与必要权限验收可用；A/B均在相同成果合同下能从接单恢复执行至最终有效验收；版本与Freeze准确且并行互不覆盖；能够提供有证据的完整T_VALID差异，正确自动或可恢复交接。只完成方法文件更新不等于最终通过。
