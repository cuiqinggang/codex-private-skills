## 最终目标
在不牺牲整个用户工作台多任务并行自由的前提下，复用成熟 n8n / 官方 Playwright MCP / 原浏览器业务技能包，建立可靠、可恢复、可实证的浏览器共享工作流，完成资源冲突协调及任务结果对账。
## 正向约束
- 允许 n8n、Codex 与其他获授权客户端共同使用原登录浏览器，互不冲突的任务不受无关任务阻塞。
- 同一会话、标签页或共享上下文的冲突操作需要有证据的局部协调。
- 先复用成熟组件，禁止重新开发通用调度器、锁、状态机及浏览器控制服务。
- 先虚拟成熟并核算完整有效时间/净收益，再在冻结后开展用户授权的现实验证。
- 每次状态变化自动持久化冻结状态，目标文件仅在目标/硬约束或成功定义改变时升级。
- 任何换页先保存，再确认自动接管；自动失败时提供可复制的最短恢复提示词。
## 反向约束
- 不得让任何单一业务独占浏览器，或封禁其他合法调用方。
- 不修改 FlClash 代理、不新开或关闭登录浏览器、不未经授权发送消息。
- 不凭 HTTP 200、去重标记或等待恢复断言外部副作用恰好一次。
- 结果 UNKNOWN 时不得自动重发，不得阻断无关资源。
- 不得虚构 Reality 结果、时间收益和已完成的资源级协调。
## FINAL_VALID
跨客户端同目标冲突协调、互不冲突目标实际并发、异常资源释放、UNKNOWN 结果对账、生产入口集成与恢复均具备可核验证据；完整有效时间相对成熟基线具有可信净收益；无真实业务误发送。
## 用户可见性
任务目标/冻结状态是内部权威任务数据，默认保存并供自动接管读取；不要求每一轮完整输出。用户要求查看、手动回退或存在无法自动恢复的阻塞时才展示必要摘要/路径/恢复提示词。不得因隐藏展示而省略真正的持久化。
