# 《B·新页面运行模板 第22版》

版本=B22｜继承B21→B20→B19→根`../../NEW_PAGE_TEMPLATE.md`第18版。明确覆盖B21的动态留页和三次Freeze上限，**B每自然节点正常完成就换新聊天**，但总任务已完成不多开无用聊天。

## 接力边界
- 先由GPT生成同TASK专属不可变Freeze（包括完成事实、证据、卡点、目标、下个节点）并更新/验证`tasks/<TASK_ID>/CURRENT.md`。持久化失败时不启动新聊天，保持原页并标记BLOCKED。
- 冻结成功后仅创建一个短 `NEXT_PAGE_PROMPT`。最低字段：权威网络仓库、`SKILL.md`入口、路线B、TASK_ID、该任务CURRENT状态定位路径、Freeze标签、下一自然节点；方法版本由路线当前指针自动解析，不贴整套旧聊天，不要求用户再懂各版号。
- 页面动作：①获取已确认的唯一信封（来自持久化冻结事件）→②在当前用户ChatGPT窗口的**同一浏览器**点击“新聊天”→③粘贴并一次提交，确认已提交后新GPT读取入口/状态继续任务。无论执行成功还是被拦截，不应盲重发相同信封。
- 控件识别采取成熟Windows UIAutomation，**禁止按猜测的屏幕坐标点击、禁止焦点不明就发送、禁止开专用浏览器或连接9223**；若不是正确ChatGPT页面，或者不能读到可用的“新聊天”按钮/消息编辑区，只保存信封并报告需要人工接续。
- 新聊天核对TASK_ID、当前合同/Freeze与唯一写者；新聊天恢复成功前，不得宣称自动交接已完成。受浏览器/工具限制时不虚构自动创建、提交或页面关闭。
- 如果新聊天打开时仍存在输入或提交状态未知：报告UNKNOWN，不自动重复提交。其它无冲突TASK不受影响。
- K盘ZIP不是每次Freeze的必要动作；每3天按调度备份一次（或用户指定时即时备份），与日常任务状态保存分离。

评估A/B32或B31时，必须以相同真实实质VALID的全链路时间和失败恢复成本作比较；不因运行时不再预测留页收益，就改变总纲的唯一时间标准。
