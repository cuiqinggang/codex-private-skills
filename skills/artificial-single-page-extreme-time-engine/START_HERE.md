1. 读取本文件并**先校验方法提交及所声明的路径是否真实存在**。若是超简单、GPT正常即可一次完成的任务，不应机械引入额外框架。

3. 新 TASK_ID：由 GPT 生成并真实保存该任务的《当前任务目标与正反约束 第1版》和《当前任务冻结状态 第1版》；用户应能看到简明任务目标。接续任务：严格依据 **TASK_ID** 从 `tasks/<TASK_ID>/` 读取该任务最新合法合同与已提交冻结文件，不猜测“全仓库最新 Freeze”，也不能把另一任务的状态借用。核对目标、版本、状态码、提交SHA和下一节点。
4. 只有涉及跨页交接/恢复时，才读取所选路线对应的新页面模板。是否换页优先于如何换页；先 Freeze/Persist，后新页接管，能在本页安全继续则不换页。自动交接能力若无实证，只能输出极简中文恢复信封供手动接续。
5. 专业执行工具只在需求存在且用户授权时按链接定位；若连接中断，明确 BLOCKED/UNKNOWN 并保留已证实的状态，不得假装完成。

**状态同步不是抄写状态**：本入口维护各路线最新方法的有效指针和版本，不在正文写入任何任务的动态 Freeze 数字。任务合同/Freeze 坚持每任务独立、真实保存、引用路径及提交可验证；自动交接不可靠时保留人工回退。避免入口变成全局可变任务状态文件而引发并行串扰。

## 任务执行职责（GPT为唯一任务执行大脑）

- GPT：理解原目标、规划、比较成熟方案、调用现有工具、持续推进合理自然节点、纠错与验证；无卡点时不停在阶段性报告，卡点修好后仍按同一任务合同继续至 DONE_WHEN 或有证据的 BLOCKED。
- n8n：必要时的外部触发、持久工作流/Wait、原生去重、可核对的调度记录；它的日志与去重**不能**单独证明外部副作用恰好一次。
- Dot：可探索自然语言接单、状态交接等辅助角色，但持久化和跨会话控制能力需验证；不以 Dot 名称宣称已有可靠状态机。
- Codex：确实需要代码库调用、代码修改、终端/环境修复时作为按需能力，不默认接管 GPT 的全局目标与流程执行。
- Playwright MCP：官方浏览器操作接口；原浏览器由多客户端共享，仅对真实资源冲突做局部协调。
- GPT直连Windows双路执行桥：仓库内已核实正式技能包 `skills/extreme-time-automation-bridge/SKILL.md` **v0.3.1**，主路 Desktop Commander Remote、备路 GitHub Actions + Windows runner。本引擎正式登记它为关键外部依赖，优先读取已有接口而不复制或重造执行桥。使用前仍要确认在线设备、操作授权与当前主/备路健康；不修改 FlClash 或破坏已登录浏览器。K盘离线备份另行包含该完整依赖技能包。

## 节点与 FINAL_VALID

共同标准：`T*=min(T_VALID)`。节点经过 REUSE_GATE→成熟BASELINE→≤3成熟候选→完整VIRTUAL_LOOP→STOP_GATE→Freeze→获授权才一次Reality。没有可复核的同边界 `T_BASE_REAL`、`T_VIRTUAL_BEST`、差值/百分比、完整恢复与维护成本，就不能宣称 `VIRTUAL_MATURE=YES`。
A路线在不同 GPT 主控/执行页之间传递冻结状态；B路线在一个 GPT 页内完成合理自然节点，必要时冻结换页。完成一个卡点、成功打开工具或保存 Freeze 均不等于原任务完成；最终必须按照任务合同的 FINAL_VALID 验证。
未授权不得发送业务消息、不能擅自开关已登录浏览器；对UNKNOWN外部写入结果禁止盲重试。
