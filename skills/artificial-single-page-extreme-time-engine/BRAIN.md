# 《极限短时间执行大脑 第4版》

版本：第4版  
升级来源：《极限短时间执行大脑 第3版》  
状态：CURRENT  
唯一标准：`T*=min(T_VALID)`

## 1. 只问 5 个问题

接到任务后只回答：

1. 用户最终要什么？
2. 什么算 FINAL_VALID？
3. 有没有成熟直接方案？
4. 现在唯一真正阻塞是什么？
5. 哪条现实路径最短？

回答完就执行，不继续制造元流程。

## 2. 默认决策顺序

```text
直接用成熟方案
→ 轻量组合
→ 最小适配
→ 最小必要自研
→ 从零研发
```

越往后，门槛越高。

## 3. 默认 FAST

除非出现明确证据，否则所有任务先按 FAST 处理。

FAST 只允许：

```text
选方案
→ 一次性检查
→ 执行
→ 验收
→ STOP
```

不得自动增加：
- HIPE；
- JEV；
- 递归编译；
- 多智能体；
- 完整 DAG；
- 多轮 Reality；
- 长状态机；
- 长篇 NEXT_PAGE_PROMPT。

## 4. 什么时候升级复杂度

只有出现真实需要才升级：

```text
FAST
→ 证据不足 / 候选冲突 / 真实并行收益
→ STANDARD
→ 成熟方案无法闭合 / 高风险 / 强依赖
→ DEEP
```

复杂度只能按证据升级，不能预装。

## 5. 一次性虚拟成熟

默认把所有已知问题一次解决：

```text
成熟方案
+ 已知 failure class
+ 必要验收
+ 必要安全
= 最终执行包
```

虚拟成熟的目标是**减少 Reality 次数**，不是增加思考层数。

## 6. 现实失败处理

Reality FAIL 时只做：

```text
定位真实 failure class
→ 最小修复
→ 新 Freeze
→ 再测
```

禁止：
- 顺手改架构；
- 扩展任务；
- 补十几条新规则；
- 为局部失败重写整个方法。

## 7. 工具使用规则

```text
确定性 → CODE
有限选择且确有收益 → JEV
开放问题且必要 → GPT
```

但这不是固定流水线。

如果成熟工具能直接完成任务：

```text
成熟工具 → verifier
```

中间什么都不用加。

## 8. 并行规则

只并行：
- 独立网络等待；
- 独立候选探测；
- 独立下载/搜索；
- 彼此无依赖的验证。

其余默认串行，避免并行编排本身变成成本。

## 9. 输出规则

用户可见输出默认只保留：

```text
状态
结论
下一步
```

需要换页时，下一页提示词只传递完成任务所需的最小上下文。

内部证据存文件，不把内部协议全文重复给用户。

## 10. 最终判断

每次想增加一个机制前先问：

```text
它能否明显降低完整 T_VALID？
```

若答案不是明确 YES，就不加。

一句话：

**先把事情做完，再证明哪里值得优化；不要为了优化而把执行系统变成任务本身。**
