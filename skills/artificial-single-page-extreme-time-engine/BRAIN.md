# 《极限短时间执行大脑 第9版》

版本：第9版  
升级来源：《极限短时间执行大脑 第8版》  
状态：CURRENT  
唯一标准：T*=min(T_VALID)

## 1. 每轮只算一笔账

EXPECTED_GAIN = 预计未来运行次数 × 每次预计节省时间  
OPT_COST = 本轮优化成本  
NET_GAIN = EXPECTED_GAIN - OPT_COST

NET_GAIN 明显为正：继续。  
NET_GAIN 不为正或收益太小：停止。

没有“关键未知”分支。

## 2. 每轮只攻击一个最大净收益点

不是找最大耗时点，也不是找所谓关键位置。

只找：

当前完整方案中，预计能带来最大整体 NET_GAIN 的那个点。

然后：

≤3 个成熟候选  
→ 选 1 个  
→ 虚拟替换  
→ 刷新完整数据  
→ 再算下一轮

## 3. 中间不做 Reality

虚拟循环连续运行，直到下一轮优化已经不划算。

然后：

Freeze → 一次正式 Reality → 验收

Reality 是最终整包认证，不是探索步骤。

## 4. 整体优先

局部点即使不是最快，只要保留它能让整条链路更快、更稳、NET_GAIN 更高，就保留。

局部最优必须服从整体 T_VALID 和 NET_GAIN。

## 5. 候选数

默认最多 3 个成熟替代。

只有继续扩展搜索本身仍有明确正 NET_GAIN，才从 3 扩到 5。

## 6. Reality FAIL

真实 failure class  
→ 搜成熟修复  
→ ≤3 个成熟候选  
→ 虚拟修复  
→ 重算 NET_GAIN  
→ 重新收敛  
→ 新 Freeze  
→ 再 Reality

## 7. 硬规则

- 禁止自研；
- 禁止从零研发；
- 禁止同时维护多个完整架构；
- 禁止中途逐点 Reality；
- 禁止把最大耗时点自动等同于最大优化价值点；
- 禁止收益小于成本还继续优化。

一句话：

**优化不是找“关键点”，而是不断做净收益最高的成熟优化，直到下一轮不划算。**
