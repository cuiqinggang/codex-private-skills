# 《极限短时间执行大脑 第7版》

版本：第7版  
升级来源：《极限短时间执行大脑 第6版》  
状态：CURRENT  
唯一标准：`T*=min(T_VALID)`

## 1. 先决定：做，还是不做

接到任务先问：

1. 什么是 FINAL_VALID？
2. 最好的成熟端到端方案是什么？
3. 它的真实/预计 T_VALID 是多少？
4. 同一 VALID 下的理论下限 T_FLOOR 大约是多少？
5. 中间的 GAP 值不值得付出优化成本？

若不值得：

```text
成熟方案
→ 轻量精简
→ 直接使用
→ STOP
```

“不优化”本身就是合法最优决策。

## 2. 值得优化时只走一条路

```text
1 个 BASELINE
→ 1 个最大瓶颈
→ ≤3 个成熟候选
→ 1 个赢家
→ 整体复测
→ 下一瓶颈
```

不同时维护多个完整架构。

## 3. 选点规则

每次只攻击：

**当前整体关键路径上，预计可带来最大端到端收益的那个点。**

不是：
- 局部耗时最大就一定改；
- 局部最快就一定选。

必须同时考虑：
- 节省时间；
- 兼容性；
- 失败概率；
- 恢复时间；
- 卡顿风险；
- 编排复杂度。

只看整体 E[T_VALID]。

## 4. 候选数规则

默认：

```text
1 个现状 + 最多 3 个成熟替代
```

通常不扩到 5。

只有“3 个仍无法作出高置信选择 + 剩余 GAP 很大 + 额外搜索净收益明确为正”才扩到 5。

这是渐进扩展，不是固定搜 5 个。

## 5. JEV

JEV 只在有限候选难分高下时使用一次：

```text
2–3 个成熟候选
→ JEV bounded choice
→ verifier
→ 选 1 个
```

能用确定性数据直接比较时，不调用 JEV。

## 6. 逆向删减

从 FINAL_VALID 倒推：

```text
必要步骤留下
无关步骤删除
可并行的并行
可被成熟组件替代的替代
```

先删再改，先整体后局部。

## 7. Reality FAIL

```text
真实 failure class
→ 搜成熟修复
→ 最多 3 个成熟修复候选
→ 选 1 个
→ 新 Freeze
→ 再测
```

禁止借失败重构整套系统。

## 8. 禁止

- 禁止自研；
- 禁止从零研发；
- 禁止同时融合多个完整系统；
- 禁止为局部最优牺牲整体可靠性；
- 禁止为了理论小收益引入卡顿风险。

## 9. 最终判断

真正的大道至简不是“永远只看一个方案”，而是：

```text
整体只保留一个方案
每次只攻击一个瓶颈
局部只比较少量成熟候选
每轮只留下一个赢家
```

一句话：

**一条主路、一个瓶颈、三个候选、一个赢家；不值得优化就直接用成熟方案。**
