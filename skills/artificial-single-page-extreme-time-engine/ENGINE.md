# 《自动化单页面极限短时间引擎 第23版》

版本：第23版
升级来源：第22版
状态：CURRENT
唯一标准：T*=min(T_VALID)


## 0. 命名与自动化边界（第23版）

- 正式名称改为《自动化单页面极限短时间引擎》；原《人工单页面极限短时间引擎》为历史兼容别名，旧冻结记录不追溯改名。
- “自动化”指接单后，在既有授权、证据和工具能力范围内，自动进行成熟方案选择、虚拟成熟、判断、冻结与交接；不等于无需授权即可进行生产写入，也不等于所有 Reality 环境天然可用。
- 用户指定“自主连续虚拟成熟”时，规划、阶段性分析或提出操作建议都不构成节点完成；必须继续执行到 STOP_GATE → Freeze，或明确记录不可恢复阻塞。不能伪造工具结果和验证证据。
- 复杂问题训练可作为外层任务复用本引擎，不能将题目数量当作能力成熟证明；验收依据是未见案例的独立解题表现与可迁移证据。
- 除名称及自动化语义澄清外，第22版的主流程、职责、唯一时间标准、Freeze/Reality 边界不变。

## 1. 定位：整套方法的总纲

本引擎是整个极限短时间任务体系的最高运行总纲。

它不只负责“一个自然执行节点内部怎么成熟”，而是规定：

- 一个现实任务从接收到 FINAL_VALID 的完整运行顺序；
- 执行大脑、任务目标与正反约束、冻结状态、新页面运行模板、CEO、Executor 之间的职责边界；
- 哪些原则任何下游版本都不得违反；
- 什么时候属于下游模块升级，什么时候必须升级本引擎。

下游文件可以独立升级，但必须继续满足本引擎的总纲约束。

## 2. 唯一目标

先进入 VALID 集合，再比较完整时间：

```text
T*=min(T_VALID)
```

任何局部更快，如果导致：
- 最终结果无效；
- 用户路径不可接受；
- 目标漂移；
- 证据不足；
- 恢复性变差；
- 完整 T_VALID 反而增加；

都不是有效优化。

## 3. 下游层级与职责

### A. 《极限短时间执行大脑》

负责“具体怎么判断和怎么干”。

包括：
- 初次收到任务后如何生成任务目标与正反约束；
- 如何拆节点；
- 如何决定串行/并行；
- 如何冻结状态；
- 如何决定 CEO 换页；
- 如何调用本引擎规定的节点内虚拟成熟流程。

### B. 《当前任务目标与正反约束 第N版》

是具体任务运行后产生的防漂移状态，不是常驻方法规范。

负责：
- 当前最终现实目标；
- 正向约束；
- 反向约束；
- FINAL_VALID / DONE_WHEN；
- 用户路径；
- 范围与硬边界。

只有这些内容本身改变时才升级版本。

### C. 《当前任务冻结状态 第N版》

是具体任务的连续状态。

负责：
- 已完成什么；
- 当前现实结果；
- 证据位置；
- Reality Delta；
- 当前 T*；
- 下一控制节点。

它回答“现在做到哪里”，不改写任务目标。

### D. 《新页面运行模板》

负责页面生命周期和 NEXT_PAGE_PROMPT 母模板。

它规定：
- 初次页和接续页分别读取什么；
- CEO / Executor 页面怎么使用；
- 什么时候换页；
- handoff 如何保持最小充分。

### E. CEO / Executor

CEO 是唯一控制面和全局状态写者。

Executor 是执行面：
一个页面只承担一个完整自然执行节点；
节点结束后先 Freeze，再回报，再关闭。

## 4. 端到端标准运行顺序

### 新现实任务

```text
用户任务
→ 执行大脑理解任务
→ 生成《当前任务目标与正反约束 第1版》
→ 生成《当前任务冻结状态 第1版》
→ 判断页面拓扑
→ 进入执行
```

### 执行阶段

```text
选择成熟 BASELINE
→ 连续 VIRTUAL_LOOP
→ 找当前最大净收益点
→ ≤3 个成熟候选
→ 虚拟替换
→ 刷新完整方案
→ 重算 NET_GAIN
→ 继续循环
→ STOP_GATE
→ Freeze
→ Reality once
```

### Reality 后

PASS：

```text
冻结结果
→ CEO Merge
→ 更新当前任务冻结状态
→ 继续下一节点或 FINAL_VALID
```

FAIL / Delta：

```text
冻结已通过事实
→ 冻结 Reality Delta
→ 回新的虚拟成熟节点
→ 刷新后续完整方案
→ 再成熟到 STOP_GATE
→ 再 Freeze
→ 再整体 Reality
```

Reality 是验收器，不是逐点优化器。

## 5. 页面拓扑总原则

简单任务：

```text
CEO = Executor
```

复杂任务：

```text
一个活动 CEO
+
最少必要 Executor 页面
```

硬原则：

- 一个 Executor 页面只运行一个完整自然执行节点；
- Executor 成功、失败、UNKNOWN、BLOCKED 都必须先冻结结果，再关闭页面；
- CEO 不承载重执行历史；
- 页面不是长期资产，冻结状态才是；
- Persist / Freeze First → Close Second；
- 并行只有在无依赖、无共享写冲突、无稀缺资源冲突且完整 T_VALID 更低时才成立。

CEO 具体何时换页、最多连续承接多少 Freeze，由执行大脑和新页面运行模板定义；本引擎只要求“页面健康优先、上下文保持最小充分”。

## 6. 节点内核心方法

一个自然执行节点内部始终遵循：

```text
成熟 BASELINE
→ 现实 NET_GAIN
→ 最大净收益点
→ ≤3成熟候选
→ 虚拟替换
→ 刷新整体
→ 重算
→ 自动继续
→ STOP_GATE
```

禁止：

- 找到一个优化点就停止；
- 找到一个优化点就 Reality；
- 为了局部更快牺牲完整 VALID；
- 为了“架构完整”强行增加页面、Agent、工具或新实现。

## 7. 版本边界

### 本引擎升级

只有当整套方法的总纲发生实质变化时才升级，例如：

- 端到端主流程改变；
- CEO / Executor 根本职责改变；
- 虚拟成熟与 Reality 的关系改变；
- 任务定义、冻结状态、页面连续性的层级关系改变；
- 唯一优化目标或 VALID 原则改变。

### 下游独立升级

以下变化若不改变本引擎总纲，不要求升级本引擎：

- 执行大脑内部判断规则优化；
- 当前任务目标/正反约束版本变化；
- 当前任务冻结状态版本变化；
- NEXT_PAGE_PROMPT 显示格式优化；
- 页面模板字段或母模板改进；
- 某个 Executor 的实现或工具替换。

原则：

> 下游版本可以变；总纲没变，本引擎版本不动。

如果下游变化与本引擎冲突：
要么回退下游变化；
要么先明确升级本引擎，再让下游按新总纲演进。

## 8. 单一权威与最小重复

本引擎只定义：
- 总目标；
- 总顺序；
- 模块职责；
- 跨模块硬原则。

具体执行细节只放在对应下游文件中。

禁止同一规则在多个文件重复维护。

权威来源：

```text
REPO=cuiqinggang/codex-private-skills
PATH=skills/artificial-single-page-extreme-time-engine/
```

## 9. 不可违反的总纲硬规则

- 先锁定任务目标与 FINAL_VALID，再执行；
- 任务不得静默漂移；
- 节点内必须连续虚拟成熟到合法停止门；
- Reality 只验证冻结方案；
- 一个 Executor 页面只承担一个完整自然执行节点；
- CEO 是唯一全局状态写者；
- 先 Freeze / Persist，再 Close；
- 新页面继承结论，不继承完整噪声历史；
- 只使用最少必要页面和执行器；
- 成熟方案优先，不自研优先；
- 同等 VALID 下只比较完整 T_VALID。

## 10. 一句话总纲

**本引擎规定“整个任务从接单到 FINAL_VALID 应该怎样运行”；执行大脑负责具体判断，任务目标与正反约束负责防漂移，冻结状态负责不断线，新页面模板负责保持页面干净，Executor 负责一个节点内连续成熟到底。**
