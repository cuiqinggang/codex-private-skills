# 《人工单页面极限短时间引擎 第10版》

版本：第10版  
升级来源：《人工单页面极限短时间引擎 第9版》  
状态：CURRENT  
唯一标准：`T*=min(T_VALID)`

## 1. 第一性原理

默认保持谦虚：

```text
WORLD_SOLVED = YES
```

现实世界里，同类问题通常已经被别人做过很多遍。  
先搜索、比较、复用成熟经验，不把“自己重新做一遍”当能力。

**本引擎禁止自研新解法，禁止从零重建。**

如果暂时没有闭合方案：

```text
继续扩大成熟方案搜索
→ 换成熟组合
→ DEFER / STOP
```

不是转入自研。

## 2. 唯一默认流程

```text
TASK
→ 成熟方案池
→ 选最接近目标的成熟解
→ 简单融合
→ 攻击迭代
→ 一次性虚拟成熟
→ 一次 Reality
→ 最小验收
→ FINAL_VALID
→ STOP
```

这就是主流程。

禁止默认加入多层编译、多智能体、完整 DAG、长状态机、长提示词和多轮微版本。

## 3. 简单融合原则

只允许**简单融合**：

- 一个成熟方案已经能完成大部分目标；
- 最多补少量成熟组件；
- 不重写核心；
- 不为了理论优势制造新架构；
- 不把多个成熟系统强行揉成一个复杂系统。

优先级固定：

```text
成熟直接方案
> 两个成熟方案的简单组合
> 少量成熟组件补齐
> 继续搜索更合适的成熟方案
> STOP / DEFER
```

不存在“自研”和“从零重建”分支。

## 4. 攻击迭代

攻击迭代不是重新发明。

它只允许围绕成熟方案做：

- 删除多余步骤；
- 替换为更成熟的组件；
- 比较 2–3 个成熟候选；
- 把真实独立等待并行；
- 修复已知 failure class；
- 去掉复杂度税。

目标：

```text
成熟方案
→ 更简单
→ 更快
→ 仍然成熟
```

## 5. 一次性虚拟成熟

Reality 前一次性完成：

```text
成熟候选
→ 简单融合
→ 主要失败点
→ 攻击迭代
→ 最终执行包
```

已知问题尽量一次解决。

禁止：
- 一个小问题建一个新节点；
- 每发现一点就开新页面；
- 十几条规则堆叠；
- 为了证明优化而反复 Reality。

## 6. 复杂工具全部按需

HIPE、JEV、递归编译、DAG、多智能体都只是工具。

```text
默认 = 不启用
确有明显净收益 = 才启用
```

而且它们只能用于：
- 搜索成熟方案；
- 比较成熟候选；
- 选择成熟组合；
- 删除现实关键路径。

**不得用来生成新的自研路线。**

## 7. 页面与提示词

能短就短。

默认页面交接只传：

```text
任务
冻结事实
4个方法文件路径
下一动作
必要禁止项
```

内部证据留在文件里，不重复粘贴到每一页。

能 5–10 行说清，就不写 50–100 行。

## 8. 失败处理

Reality 失败：

```text
真实 failure class
→ 在成熟方案池里找对应成熟修复
→ 简单替换/组合
→ 新 Freeze
→ 再测
```

禁止因一次失败开始重构或自研。

## 9. 停止规则

立即 STOP：
- FINAL_VALID 已达成；
- 成熟方案已接近现实下限；
- 剩余收益小于现实抖动；
- 新融合开始增加复杂度；
- 页面开始卡顿或长时间无输出。

## 10. 核心冻结

```text
成熟方案优先
简单融合
成熟方法上的攻击迭代
一次性虚拟成熟
一次 Reality
最小验收
有效即停
禁止自研
禁止从零重建
```

一句话：

**不重新发明世界已经解决的问题；只把成熟方法选对、简单拼好、压到更快。**
