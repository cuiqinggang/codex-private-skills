## 第一原则：只算成本账

先选 1 个成熟端到端方案作为 BASELINE。

每一轮只算：

EXPECTED_GAIN = 预计未来运行次数 × 每次预计节省时间  
OPT_COST = 本轮搜索 + 分析 + 融合 + 虚拟成熟 + 最终验证 + 卡顿/维护成本  
NET_GAIN = EXPECTED_GAIN - OPT_COST

判断：

- NET_GAIN 明显为正：继续；
- NET_GAIN 不为正或收益太小：停止；
- 新方案让整体预计 T_VALID 更差：淘汰。

不存在“关键未知所以提前 Reality”的默认分支。

## 虚拟攻击循环

值得继续时：

1 条成熟主路  
→ 找当前预计 NET_GAIN 最大的 1 个优化点  
→ 为这个点搜索最多 3 个成熟候选  
→ 选 1 个整体收益最高且可靠的候选  
→ 虚拟替换  
→ 刷新完整方案的数据  
→ 再找新的最大 NET_GAIN 点  
→ 继续

不是找“最大耗时点”，而是找“最大整体净收益点”。

## 每轮只刷新

- 当前完整预计 T_VALID；
- 各步骤时间；
- 预计未来运行次数；
- 每次预计节省；
- 新增优化成本；
- 可靠性、失败、卡顿和维护成本；
- 新的 NET_GAIN 排名。

中途不做 Reality。

## 候选数

默认最多 3 个成熟替代。

只有继续多看 2 个候选本身仍有明确正 NET_GAIN，才允许从 3 扩到 5。

整体始终只保留 1 条主路。

## 整体优先

局部最快不等于整体最快。

某个局部步骤即使不是最快，只要替换它会让整体 T_VALID、可靠性或 NET_GAIN 变差，就保留原步骤。

## 什么时候结束虚拟成熟

只看成本账。

当下一轮最值得做的优化已经：

NET_GAIN <= 0

或收益小到不值得投入时：

STOP_VIRTUAL_OPTIMIZATION = YES

然后：

Freeze → 一次正式 Reality → 最小验收

停止不是因为“关键位置”或“未知信息”，只是因为继续优化不划算。

## Reality FAIL

真实 failure class  
→ 搜最多 3 个成熟修复  
→ 虚拟修复  
→ 重算 NET_GAIN  
→ 重新收敛  
→ 新 Freeze  
→ 再 Reality

## JEV

JEV 只在 2–3 个成熟候选无法用确定性数据直接排序时做一次有限选择。

JEV 只能选择成熟候选，不生成新路线。

## 硬规则

- 禁止自研；
- 禁止从零重建；
- 禁止中途逐点 Reality；
- 禁止把最大耗时点自动等同于最大优化价值点；
- 禁止收益小于成本还继续优化。

一句话：

**每轮只做净收益最高的一次成熟优化；下一轮不划算，就停止。**
