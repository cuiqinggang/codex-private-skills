## 2. 唯一主流程

成熟 BASELINE  
→ 算现实 NET_GAIN  
→ 选最大净收益点  
→ ≤3 个成熟候选  
→ 选 1 个  
→ 虚拟替换并刷新整体  
→ 再算下一轮  
→ 不划算即停止  
→ Freeze  
→ 1 次 Reality  
→ 验收

禁止中途逐点 Reality。

## 3. 唯一收益账

EXPECTED_GAIN = N_REALISTIC × 单次预计节省  
OPT_COST = 搜索 + 分析 + 融合 + 虚拟成熟 + 最终验证 + 失败/卡顿/恢复/维护成本  
NET_GAIN = EXPECTED_GAIN - OPT_COST

N_REALISTIC 只取当前可预见的真实使用次数。  
未来规模变化时再重算，不预支未来收益。

## 4. 低成本顺手优化

虚拟成本极低、可立即回退、不增加长期复杂度且不明显增加失败/卡顿风险时，允许轻量试一次。

变好→保留。  
无收益/变差/卡顿/复杂化→立即回退。  
不得为了微小收益进入长期修复链。

## 5. 每轮选择

不是找最大耗时点，而是找当前完整方案中预计 NET_GAIN 最大的点。

局部更快但整体更差，不换。  
找不到更优成熟候选，保留原方案。

候选默认最多 3 个；只有继续搜索本身仍明显划算时才扩到 5。

## 6. 概率判断工具门

PROBABILITY_TOOL_DEFAULT = OFF

概率工具不是默认流程，也不是默认依赖。

只有先证明下面这笔时间账为正，才允许调用：

T_DIRECT = 不调用概率工具时完成该判断的端到端时间

T_PROB = 准备输入 + 启动/连接 + 网络 + 概率判断 + 解析 + verifier + 失败/重试期望成本

TOOL_GAIN = T_DIRECT - T_PROB

仅当：
- TOOL_GAIN 明显为正；
- 能降低完整 T_VALID；
- 不增加明显卡顿/恢复风险；

才临时启用。

不能只比较“模型判断本身很快”，必须把整个调用成本算进去。

当前 1→3→1 流程中，单轮通常只有少量成熟候选，因此默认直接用确定性数据/当前智能体判断，不额外启动概率工具。

概率工具只在候选判断本身已经成为明显耗时点，或可批量处理多个有限选择时考虑。

## 7. 停止与回退

下一轮 NET_GAIN 不为正，或收益已小到不值得投入：停止虚拟优化。

最终 Reality：
- 更好→保留；
- 无明显收益→回退成熟 BASELINE；
- FAIL→回退最近成熟冻结；
- 明显卡顿/复杂化→立即回退。

禁止自研。

禁止发明新架构。  
禁止为局部最优牺牲整体 T_VALID。
