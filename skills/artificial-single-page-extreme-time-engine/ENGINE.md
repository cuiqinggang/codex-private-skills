## 2. 唯一主流程

成熟 BASELINE  
→ 算现实 NET_GAIN  
→ 选最大净收益点  
→ ≤3 个成熟候选  
→ 选 1 个  
→ 虚拟替换并刷新整体  
→ 再算下一轮  
→ 不划算即停止  
→ Freeze  
→ 1 次 Reality  
→ 验收

禁止中途逐点 Reality。

## 3. 唯一收益账

EXPECTED_GAIN = N_REALISTIC × 单次预计节省  
OPT_COST = 搜索 + 分析 + 融合 + 虚拟成熟 + 最终验证 + 失败/卡顿/恢复/维护成本  
NET_GAIN = EXPECTED_GAIN - OPT_COST

N_REALISTIC 只取当前可预见的真实使用次数。  
禁止假设未来百万次或无限运行；未来规模变化时再重算。

## 4. 低成本顺手优化

若同时满足：

- 虚拟成本极低；
- 可立即回退；
- 不增加长期复杂度；
- 不明显增加失败/卡顿风险；

允许轻量试一次。

变好→保留。  
无收益/变差/卡顿/复杂化→立即回退。  
不得为了微小收益进入长期修复链。

## 5. 每轮选择

不是找最大耗时点，而是找当前完整方案中预计 NET_GAIN 最大的点。

局部更快但整体更差，不换。  
找不到更优成熟候选，保留原方案。

候选默认最多 3 个；只有继续搜索本身仍明显划算时才扩到 5。

## 6. 停止与回退

下一轮 NET_GAIN 不为正，或收益已小到不值得投入：停止虚拟优化。

最终 Reality：
- 更好→保留；
- 无明显收益→回退成熟 BASELINE；
- FAIL→回退最近成熟冻结；
- 明显卡顿/复杂化→立即回退。

## 7. 工具

JEV/HIPE 不是默认层。  
只有 2–3 个成熟候选难以用确定性数据排序时，才按需使用一次。

## 8. 硬规则

禁止自研。  
禁止从零重建。  
禁止发明新架构。  
禁止为局部最优牺牲整体 T_VALID。  
禁止用假想规模放大收益。

一句话：**一条成熟主路，每轮只做最划算的一次优化；不划算就停，变差就退。**
