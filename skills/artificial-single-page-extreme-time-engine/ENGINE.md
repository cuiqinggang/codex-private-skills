# 《人工单页面极限短时间引擎 第11版》

版本：第11版  
升级来源：《人工单页面极限短时间引擎 第10版》  
状态：CURRENT  
唯一标准：`T*=min(T_VALID)`

## 1. 权威来源

本技能包权威来源固定为**网络共同工作区**：

```text
REPO=cuiqinggang/codex-private-skills
PATH=skills/artificial-single-page-extreme-time-engine/
```

不得先去 C 盘寻找方法。  
C 盘只允许作为临时执行、缓存和产物落点。

## 2. 第一性原则

默认：

```text
WORLD_SOLVED=YES
```

先相信外部已经有成熟经验。

**禁止自研。**  
**禁止从零重建。**  
**禁止为了“更聪明”发明新架构。**

如果现有成熟方案不能闭合：

```text
扩大成熟方案搜索
→ 换成熟组合
→ DEFER / STOP
```

不转入自研。

## 3. 唯一流程

```text
TASK
→ 成熟方案池
→ 选最合适成熟解
→ 简单融合
→ 攻击迭代
→ 一次性虚拟成熟
→ 一次 Reality
→ 最小验收
→ FINAL_VALID
→ STOP
```

不增加别的默认层。

## 4. 简单融合

简单融合只允许：

- 以一个成熟方案为主；
- 补少量成熟组件；
- 不重写核心；
- 不制造新框架；
- 不把多个成熟系统复杂拼接。

优先级：

```text
成熟直接方案
> 成熟方案简单组合
> 成熟组件补齐
> 扩大成熟方案搜索
> STOP / DEFER
```

## 5. 攻击迭代

攻击迭代只能发生在成熟方法上：

- 删除多余步骤；
- 换成更成熟、更快的组件；
- 比较少量成熟候选；
- 并行真实独立等待；
- 用成熟修复解决真实 failure class；
- 删除复杂度税。

目标：

```text
成熟 → 更简单 → 更快 → 仍成熟
```

## 6. 一次性虚拟成熟

Reality 前一次性完成：

```text
成熟候选
→ 简单融合
→ 已知失败点
→ 攻击迭代
→ 最终执行包
```

禁止一个小问题一个节点、一个小问题一个页面、十几条规则堆叠。

## 7. 复杂工具

HIPE / JEV / DAG / 多智能体 / 递归编译都不是默认流程。

只有已经存在的成熟方案确实需要，并且能明显降低完整 T_VALID 时才使用。

它们不得产生自研路线。

## 8. 页面最小信息

每次页面只保留：

1. 四字段定位；
2. 状态机；
3. 时间锚；
4. 网络共同工作区来源；
5. 当前任务与下一动作；
6. 真正必要的禁止项。

其余证据全部放文件，不塞进提示词。

## 9. 失败处理

```text
真实 failure class
→ 搜成熟修复
→ 简单替换/组合
→ 新 Freeze
→ 再测
```

不重构，不扩任务，不自研。

## 10. 停止

满足任一即 STOP：

- FINAL_VALID 已达成；
- 成熟方案已接近现实下限；
- 剩余收益小于现实抖动；
- 新融合开始增加复杂度；
- 页面出现明显卡顿风险。

一句话：

**只选成熟方法、简单组合、一次做熟；绝不重新发明。**
