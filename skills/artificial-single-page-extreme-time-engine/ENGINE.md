## 1. 权威来源

本技能包只认网络共同工作区：

```text
REPO=cuiqinggang/codex-private-skills
PATH=skills/artificial-single-page-extreme-time-engine/
```

禁止先去 C 盘找方法。C 盘只做临时执行、缓存和产物落点。

## 2. 第一性原理：先判断“值不值得优化”

默认：

```text
WORLD_SOLVED=YES
```

先选一个综合最强、最可靠的成熟端到端方案作为 BASELINE。

同时估计在同一 VALID 下的理论下限 `T_FLOOR`。

```text
GAP = T_BASELINE - T_FLOOR
```

如果 GAP 很小，或预计可获得的收益不足以覆盖分析、融合、验证、卡顿和恢复成本：

```text
DIRECT_USE_MATURE = YES
→ 直接采用成熟方案
→ 必要时只做删除冗余的轻量精简
→ STOP
```

禁止为了“做极限方案”而做极限方案。

若任务会重复运行，再比较：

```text
预计总收益
= 预计运行次数 × 单次可实现节省
- 优化建设时间
- 复杂度/失败/卡顿成本
```

只有预计总收益明显为正，才进入攻击迭代。

## 3. 最简最优搜索：1 → 3 → 1

默认不用 3 个或 5 个完整方案同时融合。

固定采用：

```text
1 个成熟端到端 BASELINE
→ 找当前整体关键路径上最长/最值钱的 1 个瓶颈
→ 只为这个瓶颈搜索最多 3 个成熟候选
→ 选 1 个能让整体 T_VALID 最低且仍可靠的候选
→ 替换或保持原方案
→ 重新测整体
→ 再攻击新的最大瓶颈
```

这叫：

```text
单基线 · 三候选 · 一替换
```

优点：
- 不产生多方案组合爆炸；
- 每次只处理一个点，页面保持轻；
- 仍有足够搜索广度，避免只看一个方案的局部最优；
- 每一次变化都由整体 T_VALID 决定，而不是局部毫秒决定。

## 4. 为什么不是固定 1 / 3 / 5 个完整方案

### 只看 1 个完整方案
最简单，但容易被其历史结构锁住。

### 同时融合 3 个完整方案
搜索更广，但很容易把成熟系统的不同假设一起带进来，产生集成复杂度。

### 同时融合 5 个完整方案
边际信息继续增加，但上下文、比较、兼容和卡顿成本增长更快。

因此默认不是“选几个完整方案”，而是：

```text
整体只保留 1 个 BASELINE
局部瓶颈最多看 3 个成熟替代
最终只留 1 个
```

只有同时满足以下条件，局部候选才允许从 3 扩到 5：
- 前 3 个难分高下或证据明显不足；
- 距离 T_FLOOR 仍有很大空间；
- 多看 2 个候选的预期收益明显高于增加的复杂度和卡顿风险。

否则禁止扩到 5。

## 5. 全局优先，局部允许“不最优”

局部最快不等于整体最快。

比较候选时必须看端到端：

```text
预计 E[T_VALID]
≈ 正常关键路径时间
+ 失败概率 × 恢复时间
+ 卡顿概率 × 卡顿损失
+ 编排/兼容复杂度
```

Reality 的正式结果仍以真实 `T_VALID` 为准。

所以一个局部阶段即使不是最快，只要它：
- 更可靠；
- 更兼容；
- 少恢复；
- 少编排；
- 让整条路径更短；

就应该保留。

## 6. 逆向删减：从 FINAL_VALID 倒推

每轮优化先从最终结果倒推：

```text
FINAL_VALID
← 哪些步骤绝对必要？
← 哪些只是历史遗留？
← 哪些可以删除？
← 哪些可以并行？
← 哪些可以被成熟组件直接替代？
```

无法改变 FINAL_VALID、整体 T_VALID、可靠性或恢复能力的步骤，默认删除。

先删步骤，再优化步骤。

## 7. 攻击迭代

每轮只攻击一个整体最值钱的瓶颈：

```text
测整体
→ 找关键路径最大瓶颈
→ 搜 ≤3 个成熟替代
→ 虚拟比较整体收益
→ 选 1 个
→ 一次性虚拟成熟
→ Reality
→ 重新测整体
```

攻击只允许使用成熟方案和成熟组件。

**禁止自研。**
**禁止从零重建。**
**禁止发明新架构。**

找不到更好的成熟替代就保留原方案，不强改。

## 8. JEV 的唯一位置

JEV 不是常驻层。

只有当：
- 已有 2–3 个成熟候选；
- 候选是有限、可枚举的；
- 人工规则难以稳定排序；
- 有确定性 verifier；

才允许 JEV 做一次 bounded choice（有限选择）。

JEV 只负责“选哪个成熟候选”，不得产生自研路线。

## 9. 停止规则

立即 STOP：
- BASELINE 已接近 T_FLOOR；
- 预计总收益不为正；
- 当前最大瓶颈没有成熟替代；
- 新替代降低局部时间但增加整体 E[T_VALID]；
- 剩余收益低于现实抖动；
- 页面开始明显卡顿。

## 10. 核心

```text
先问值不值得做
不值得 → 直接用成熟方案

值得 →
1 个成熟 BASELINE
→ 1 个最大瓶颈
→ 最多 3 个成熟候选
→ 只留 1 个
→ 整体复测
→ 循环

始终以整体 T_VALID 为目标
禁止自研
禁止从零重建
```

一句话：

**入口可以稍广，过程必须收窄；一次只攻击一个点，永远只保留一条整体最优路径。**
