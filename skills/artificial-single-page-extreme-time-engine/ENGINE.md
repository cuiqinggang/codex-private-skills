版本：第25版
升级来源：第24版
状态：CURRENT
唯一标准：T*=min(T_VALID)


## 0. 命名与自动化边界（第23版）

- 正式名称改为《自动化单页面极限短时间引擎》；原《人工单页面极限短时间引擎》为历史兼容别名，旧冻结记录不追溯改名。
- “自动化”指接单后，在既有授权、证据和工具能力范围内，自动进行成熟方案选择、虚拟成熟、判断、冻结与交接；不等于无需授权即可进行生产写入，也不等于所有 Reality 环境天然可用。
- 用户指定“自主连续虚拟成熟”时，规划、阶段性分析或提出操作建议都不构成节点完成；必须继续执行到 STOP_GATE → Freeze，或明确记录不可恢复阻塞。不能伪造工具结果和验证证据。
- 复杂问题训练可作为外层任务复用本引擎，不能将题目数量当作能力成熟证明；验收依据是未见案例的独立解题表现与可迁移证据。
- 除名称及自动化语义澄清外，第22版的主流程、职责、唯一时间标准、Freeze/Reality 边界不变。

## 0.1 成熟能力复用硬禁令（第24版，覆盖旧模糊措辞）

**禁止自行开发已有成熟方案覆盖的通用能力；不是“不自研优先”，而是“禁止重造”。** 本条对 CEO、Executor、Codex、GPT、Reasonix 等所有执行者生效。

1. 用户已提供技能包、进程入口、成熟框架或权威实现时，**先实际读取和调用现有入口**；不得无视指定入口另起实现。网络权威技能包优先于本地临时复制。
2. 状态机、任务队列/编排、幂等事务、租约/锁、持久化、故障恢复、浏览器/CDP 控制、日志/监测等成熟通用能力，**禁止作为新子系统独立开发**。不得以“测试版”“临时 SQLite”“先做虚拟模拟”“代码更短”“局部性能可能更好”为由绕开。
3. **允许适配**：使用成熟框架的配置、连接器、参数映射、薄胶水代码、现有插件扩展点、必要的业务特定校验和最小兼容补丁。适配必须以已选成熟实现为主干、可指认上游入口、范围明确，不得自行接管生命周期、事务语义或恢复调度。
4. **不允许伪装适配的自研**：一旦适配代码自己维护新的状态转换引擎、通用调度循环、锁/租约机制、独立持久化/重试体系，直接判定为重造并停止该候选。
5. 确实找不到满足硬约束的成熟实现时，只能提交“缺口证据 + 已比较成熟候选 + 最小必要补丁边界”并暂停该通用组件的自研实施；**不得由执行者自行扩大例外**。需要改变禁令范围时，由用户明确授权并先正式修订方法版本。
6. 启用开发前必须通过 `REUSE_GATE`：已核对用户指定技能包/入口；已检索同类成熟能力；已记录采用的成熟基线与可复用接口；已判定代码仅为适配；已核算配置/启动/恢复/维护在内的全程成本。任何一项缺失：`REUSE_GATE=FAIL`，禁止编码和进入 Reality。
7. 与原有 `STOP_GATE` 的关系：`REUSE_GATE` 在虚拟成熟开始前；之后仍按成熟候选→完整虚拟成熟→Freeze→一次 Reality，失败回到虚拟成熟。不能先自研、通过一轮测试后再补成熟方案分析。

**2026-10-08 反例（V24/F011）：** 已明确存在原浏览器技能包及成熟通用工作流能力，却先行新增 `virtual_browser_v4.py`、`v24_f010_orchestrator.py` 的状态机/调度实现并反复验收。这是**硬约束执行失效**，不是普通优化失误。此前真实单会话与五任务测试成果可作为证据保留，但自建调度器**不得因测试通过而成为新的方法基线**。应优先把已通过的业务适配代码迁入成熟框架的扩展点，并停止继续演进自建通用实现。

## 1. 定位：整套方法的总纲

本引擎是整个极限短时间任务体系的最高运行总纲。

它不只负责“一个自然执行节点内部怎么成熟”，而是规定：

- 一个现实任务从接收到 FINAL_VALID 的完整运行顺序；
- 执行大脑、任务目标与正反约束、冻结状态、新页面运行模板、CEO、Executor 之间的职责边界；
- 哪些原则任何下游版本都不得违反；
- 什么时候属于下游模块升级，什么时候必须升级本引擎。

下游文件可以独立升级，但必须继续满足本引擎的总纲约束。

## 2. 唯一目标

先进入 VALID 集合，再比较完整时间：

```text
T*=min(T_VALID)
```

任何局部更快，如果导致：
- 最终结果无效；
- 用户路径不可接受；
- 目标漂移；
- 证据不足；
- 恢复性变差；
- 完整 T_VALID 反而增加；

都不是有效优化。

## 2.1 极限优化与停止原则（第24版释义澄清）

- 保护有效性，不保护旧实现。已通过验收的方案是有效比较基线，不是优化终点；允许采用更优成熟架构替换低效实现。
- 完整有效时间最短仍是唯一时间目标：T*=min(T_VALID)。不设置人为最小节省门槛，0.01秒也计入收益。
- 停止取决于长期预期净收益，而不是已有能力是否可用。持续选择最大净收益点、比较不超过三个成熟候选、刷新整体方案；核算真实使用频率、适配、部署、运行、恢复、维护与风险成本。预期净收益不大于零或明确阻塞时才触发停止门。
- 禁止重造成熟通用能力的硬约束不变。允许成熟框架整体替换、现成能力组合和最小适配；更先进只是候选理由，真实效率和完整有效性才是采纳证据。
- 已授权浏览器和既有技能包入口允许跨任务复用，但须保证任务隔离、页面所有权和共享资源仲裁，不得相互干扰。

本节仅澄清既有规则，不改变第24版端到端流程、冻结与现实验收顺序，也不触发总纲版本升级。

## 3. 下游层级与职责

### A. 《极限短时间执行大脑》

负责“具体怎么判断和怎么干”。

包括：
- 初次收到任务后如何生成任务目标与正反约束；
- 如何拆节点；
- 如何决定串行/并行；
- 如何冻结状态；
- 如何决定 CEO 换页；
- 如何调用本引擎规定的节点内虚拟成熟流程。

### B. 《当前任务目标与正反约束 第N版》

是具体任务运行后产生的防漂移状态，不是常驻方法规范。

负责：
- 当前最终现实目标；
- 正向约束；
- 反向约束；
- FINAL_VALID / DONE_WHEN；
- 用户路径；
- 范围与硬边界。

只有这些内容本身改变时才升级版本。

### C. 《当前任务冻结状态 第N版》

是具体任务的连续状态。

负责：
- 已完成什么；
- 当前现实结果；
- 证据位置；
- Reality Delta；
- 当前 T*；
- 下一控制节点。

它回答“现在做到哪里”，不改写任务目标。

### D. 《新页面运行模板》

负责页面生命周期和 NEXT_PAGE_PROMPT 母模板。

它规定：
- 初次页和接续页分别读取什么；
- CEO / Executor 页面怎么使用；
- 什么时候换页；
- handoff 如何保持最小充分。

### E. CEO / Executor

CEO 是唯一控制面和全局状态写者。

Executor 是执行面：
一个页面只承担一个完整自然执行节点；
节点结束后先 Freeze，再回报，再关闭。

## 4. 端到端标准运行顺序

### 新现实任务

```text
用户任务
→ 执行大脑理解任务
→ 生成《当前任务目标与正反约束 第1版》
→ 生成《当前任务冻结状态 第1版》
→ 判断页面拓扑
→ 进入执行
```

### 执行阶段

```text
初始节点先筛选最多3个强成熟候选（通常3个；不足不凑数）
→ 全链路比较与强点互补评估
→ 选择净收益最优的成熟 BASELINE（可为低复杂度成熟组合）
→ 连续 VIRTUAL_LOOP
→ 找当前最大净收益点
→ ≤3 个成熟候选
→ 虚拟替换
→ 刷新完整方案
→ 重算 NET_GAIN
→ 继续循环
→ STOP_GATE
→ Freeze
→ Reality once
```

### Reality 后

PASS：

```text
冻结结果
→ CEO Merge
→ 更新当前任务冻结状态
→ 继续下一节点或 FINAL_VALID
```

FAIL / Delta：

```text
冻结已通过事实
→ 冻结 Reality Delta
→ 回新的虚拟成熟节点
→ 刷新后续完整方案
→ 再成熟到 STOP_GATE
→ 再 Freeze
→ 再整体 Reality
```

Reality 是验收器，不是逐点优化器。

## 4.1 初始三强比较门（第25版总纲变更）

- **初始大节点和后续局部攻击一视同仁：先比较，再承诺基线。** 在既有环境、用户指定入口、授权和 VALID 硬约束下，默认选取三个优势互补的强成熟候选；不足三个合格候选不凑数，已存在明显支配优势时可据证据提前淘汰，不强制安装三个系统。
- 先作完整链路评比：原有资产复用、操作系统兼容、部署与迁移、任务完成时间、并发隔离、恢复与幂等、维护和高频使用累计净收益。不以单一营销指标或技术先进性宣布胜出。
- 同时评估**最优单体**与**成熟强点互补组合**。只在成熟接口能够直接复用、且完整净收益为正时组合；组合不获得自行开发通用状态机/调度/租约/恢复的例外许可。
- 初始选型成本也计入决策；只做足以改变结论的证据采集，避免每次都部署三个。筛选后确定 BASELINE，继续按原最大净收益点、≤3 候选、整套虚拟刷新、STOP_GATE、Freeze、Reality once 推进。
- 故障发生后允许回到三强比较门，不能因已选框架产生沉没成本锁定；保留已验证有效业务能力作为对照，但不保护低效实现。

## 5. 页面拓扑总原则

简单任务：

```text
CEO = Executor
```

复杂任务：

```text
一个活动 CEO
+
最少必要 Executor 页面
```

硬原则：

- 一个 Executor 页面只运行一个完整自然执行节点；
- Executor 成功、失败、UNKNOWN、BLOCKED 都必须先冻结结果，再关闭页面；
- CEO 不承载重执行历史；
- 页面不是长期资产，冻结状态才是；
- Persist / Freeze First → Close Second；
- 并行只有在无依赖、无共享写冲突、无稀缺资源冲突且完整 T_VALID 更低时才成立。

CEO 具体何时换页、最多连续承接多少 Freeze，由执行大脑和新页面运行模板定义；本引擎只要求“页面健康优先、上下文保持最小充分”。

## 6. 节点内核心方法

一个自然执行节点内部始终遵循：

```text
初始三强比较确定成熟 BASELINE
→ 现实 NET_GAIN
→ 最大净收益点
→ ≤3成熟候选
→ 虚拟替换
→ 刷新整体
→ 重算
→ 自动继续
→ STOP_GATE
```

禁止：

- 找到一个优化点就停止；
- 找到一个优化点就 Reality；
- 为了局部更快牺牲完整 VALID；
- 为了“架构完整”强行增加页面、Agent、工具或新实现。

## 7. 版本边界

### 本引擎升级

只有当整套方法的总纲发生实质变化时才升级，例如：

- 端到端主流程改变；
- CEO / Executor 根本职责改变；
- 虚拟成熟与 Reality 的关系改变；
- 任务定义、冻结状态、页面连续性的层级关系改变；
- 唯一优化目标或 VALID 原则改变。

### 下游独立升级

以下变化若不改变本引擎总纲，不要求升级本引擎：

- 执行大脑内部判断规则优化；
- 当前任务目标/正反约束版本变化；
- 当前任务冻结状态版本变化；
- NEXT_PAGE_PROMPT 显示格式优化；
- 页面模板字段或母模板改进；
- 某个 Executor 的实现或工具替换。

原则：

> 下游版本可以变；总纲没变，本引擎版本不动。

如果下游变化与本引擎冲突：
要么回退下游变化；
要么先明确升级本引擎，再让下游按新总纲演进。

## 9. 不可违反的总纲硬规则

- 先锁定任务目标与 FINAL_VALID，再执行；
- 任务不得静默漂移；
- 初始大节点必须经过最多三个强成熟方案的比较及必要的组合收益评估，才能锁定 BASELINE；
- 节点内必须连续虚拟成熟到合法停止门；
- Reality 只验证冻结方案；
- 一个 Executor 页面只承担一个完整自然执行节点；
- CEO 是唯一全局状态写者；
- 先 Freeze / Persist，再 Close；
- 新页面继承结论，不继承完整噪声历史；
- 只使用最少必要页面和执行器；
- **通用成熟能力禁止自行开发或重造；必须直接调用现有成熟实现。仅允许最小适配与经证实的局部补丁。**
- **成熟实现检索及复用证据未通过，不得进入自编状态机、调度器、租约、持久化、恢复、浏览器控制等通用组件的编码或 Reality。**
- 同等 VALID 下只比较完整 T_VALID。

## 10. 一句话总纲

**本引擎规定“整个任务从接单到 FINAL_VALID 应该怎样运行”；执行大脑负责具体判断，任务目标与正反约束负责防漂移，冻结状态负责不断线，新页面模板负责保持页面干净，Executor 负责一个节点内连续成熟到底。**
