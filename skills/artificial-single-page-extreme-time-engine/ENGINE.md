# 《人工单页面极限短时间引擎 第9版》

版本：第9版  
升级来源：《人工单页面极限短时间引擎 第8版》  
状态：CURRENT  
唯一标准：`T*=min(T_VALID)`

## 1. 第一性原理

只优化一件事：

```text
从合法起点到 FINAL_VALID 的完整现实时间
```

任何“优化”只要让分析更长、提示词更长、状态更多、恢复更难、页面更容易卡顿，就必须把这些成本算进总时间。

```text
净收益 = 真实节省时间 - 复杂度税
```

净收益不明显为正，就不加。

## 2. 默认流程：大道至简

绝大多数任务默认只走：

```text
TASK
→ 找成熟直接解
→ 最小适配/组合
→ 一次性虚拟成熟
→ 一次 Reality
→ 最小独立验收
→ FINAL_VALID
→ STOP
```

禁止默认进入多层编译、多模型循环、多节点状态机、长提示词和多轮微优化。

## 3. 三档路线

### FAST｜默认
适用于：
- 目标清楚；
- 市面已有成熟方案；
- 验收简单；
- 风险低。

只做：
```text
成熟解 → 最小改造 → 一次检查 → 执行 → 验收
```

### STANDARD｜证据不足才升级
仅当：
- 有 2–3 个真实候选需要比较；
- 存在明显独立等待，可并行；
- FAST 无法直接闭合。

允许少量候选比较、必要并行、一次整包虚拟成熟。

### DEEP｜少数复杂任务
仅用于：
- 新问题；
- 高风险；
- 多系统强依赖；
- 长流程；
- 成熟方案无法闭合。

只有 DEEP 才允许复杂 DAG、递归编译、多层智能体和重恢复协议。

**禁止把 DEEP 的结构下沉到 FAST 任务。**

## 4. 成熟方案优先

固定优先级：

```text
成熟直接方案
> 成熟方案轻组合
> 最小适配
> 最小必要自研
> 从零重建
```

默认最多快速比较 3 个成熟候选。

若成熟方案已经接近现实下限，不再为了很小的理论收益重做整套系统。

## 5. 一次性虚拟成熟

Reality 前只做一次整包检查：

```text
目标
→ 成熟候选
→ 主要失败点
→ 必要安全/验收
→ 可并行项
→ 最终执行包
```

已知问题尽量一次解决。

禁止：
- 一个小问题一个新节点；
- 一条一条补洞；
- 十几条“必须”把简单任务写成复杂协议；
- 为了证明方法而制造 Reality 轮数。

Reality 失败后：

```text
真实失败证据
→ 只修真实 failure class
→ 新 Freeze
→ 再执行
```

不允许顺手重构无关部分。

## 6. HIPE / JEV / 编译器：按需，不常驻

第8版的工具继续保留，但从主流程退出。

```text
HIPE_ALWAYS_ON = NO
JEV_ALWAYS_ON = NO
RECURSIVE_COMPILE_ALWAYS_ON = NO
```

只有满足以下条件才启用：
- 决策本身是主要时间瓶颈；
- 有多个真实候选；
- 预计节省明显大于调用与编排成本；
- 能降低完整 T_VALID。

简单确定性任务直接 CODE/工具执行。

**工具是加速器，不是流程本身。**

## 7. 并行：只并行真实等待

```text
有独立等待 → 并行
没有独立等待 → 不并行
```

FAST 任务禁止先画完整 DAG。

只有实际依赖复杂、串行等待明显影响 T_VALID 时，才构建 DAG。

## 8. 页面与提示词必须短

默认交接只保留：

```text
任务
当前冻结事实
唯一目标/VALID
下一动作
必要禁止项
```

能 5 行说清，不写 50 行。

机器标签、证据、哈希可以存文件，不得把全部内部细节重复塞进每一页正文。

## 9. 停止规则

满足任一立即 STOP：
- FINAL_VALID 已达成；
- 剩余收益小于现实抖动；
- 新机制增加的复杂度大于预计收益；
- 已有成熟方案足够接近现实下限；
- 页面开始出现明显卡顿/长时间无输出风险。

## 10. 第9版核心冻结

```text
先成熟直解
再最小组合
一次性虚拟成熟
一次 Reality
最小验收
有效就停

复杂工具按需
复杂流程升级触发
绝不默认复杂化
```

一句话：

**极限短时间不是“把所有优化工具都装上”，而是“用最少必要步骤最快得到有效结果”。**
