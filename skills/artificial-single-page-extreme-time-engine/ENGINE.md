## 2. 先判断值不值得优化

先选综合最强、最可靠的成熟端到端方案作为 BASELINE，再估计同一 VALID 下的理论下限 T_FLOOR。

GAP = T_BASELINE - T_FLOOR

若 GAP 很小，或预计收益不足以覆盖分析、融合、验证、卡顿和恢复成本：

成熟方案 → 轻量删减 → 直接使用 → STOP

“不优化”本身就是合法最优决策。

## 3. 虚拟阶段：1 → 3 → 1

值得优化时固定采用：

1 个成熟 BASELINE  
→ 找当前整体最值钱的 1 个瓶颈  
→ 为该瓶颈搜索最多 3 个成熟候选  
→ 选 1 个整体收益最高且可靠的候选  
→ 虚拟替换  
→ 刷新整条路径的预计时间、依赖和风险  
→ 找新的最大瓶颈  
→ 继续

这里的“刷新”是虚拟重算，不是 Reality。

## 4. 中途不做 Reality

每解决一个瓶颈就正式测试，会把尚未成熟的方案反复送入 Reality，增加串行等待、卡顿和恢复成本。

默认规则：

连续虚拟攻击 → 整体收益收敛 → Freeze → 一次正式 Reality → 最小验收

Reality 是最终冻结方案的认证器，不是每轮探索器。

## 5. 每次虚拟刷新只更新

- 整体预计 T_VALID；
- 当前关键路径；
- 当前最大瓶颈；
- 兼容性；
- 失败/恢复风险；
- 距离 T_FLOOR 的剩余 GAP。

不重新展开已解决部分，不重做完整分析。

## 6. 候选数

默认：1 个现状 + 最多 3 个成熟替代。

只有“3 个仍难分高下 + 剩余 GAP 很大 + 多看 2 个的净收益明确为正”时，局部才允许扩到 5。

整体始终只保留 1 条主路。

## 7. 全局优先

局部最快不等于整体最快。候选选择必须服从整体 E[T_VALID]，同时考虑正常时间、失败恢复、卡顿损失和编排兼容复杂度。

一个局部组件即使更慢，只要让整条路径更短、更稳，就保留。

## 8. 虚拟成熟停止条件

满足任一条件即停止虚拟攻击：

- 已接近 T_FLOOR；
- 当前最大瓶颈没有更好的成熟替代；
- 剩余预计收益低于复杂度税或现实抖动；
- 继续展开会显著增加卡顿风险；
- 所有高收益瓶颈已处理。

然后：Freeze → 一次正式 Reality → 最小独立验收。

## 9. Reality FAIL

只有最终 Reality 失败时才回虚拟：

真实 failure class → 搜成熟修复 → ≤3 个成熟候选 → 虚拟修复并重新收敛 → 新 Freeze → 再 Reality

禁止自研。禁止从零重建。禁止发明新架构。

## 10. JEV

JEV 只在 2–3 个成熟候选难以用确定性数据排序时做一次有限选择；只负责选成熟候选，不生成新路线。

## 11. 核心

先判断值不值得优化。  
值得时：1 条主路 → 1 个瓶颈 → ≤3 个成熟候选 → 1 个赢家 → 虚拟刷新 → 下一个瓶颈 → 整体做熟 → 1 次 Reality。

一句话：**所有攻击尽量在虚拟里一次做熟，Reality 只验证最终整包。**
