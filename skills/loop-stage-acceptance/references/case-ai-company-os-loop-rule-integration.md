## Case Type

This is a command-package example for integrating Loop Prompt rules into a target skill package.

It is not a request to execute Stage 4A, write a real Vault, connect a real skill-index, or generate a final Dashboard. Its value is the structure: how to add Loop rules to a skill package while preserving boundaries, backups, evidence, verification, and sync records.

## Reusable Intent

Use this pattern when the user says:

- 把 Loop 机制沉淀进某个技能包
- 生成规则文件和执行模板
- 更新 SKILL.md 但不破坏原结构
- 不进入真实执行阶段
- 不写真实 Vault
- 不接真实 skill-index
- 生成 manifest / evidence / 验证报告
- 同步 H 盘备份

## Boundary Pattern

Always split the command package into `允许` and `禁止`.

Allowed actions may include:

1. Read prior acceptance reports and target skill package files.
2. Read and back up the target `SKILL.md`.
3. Add Loop rule documents.
4. Add Loop execution templates.
5. Add a stage-specific usage rule.
6. Update a rule index or `SKILL.md` navigation.
7. Generate visual evidence.
8. Generate a manifest.
9. Sync backup locations.
10. Run verification scripts.

Forbidden actions must be explicit when relevant:

1. Do not enter the next real execution stage.
2. Do not write a real Vault.
3. Do not connect a real skill-index.
4. Do not modify protected original files.
5. Do not execute real templates.
6. Do not generate final production dashboards.
7. Do not touch accounts, API keys, cookies, or payment state.
8. Do not delete old evidence.
9. Do not claim the next stage is complete.

## Core Rule File Pattern

Create a rule file such as:

```text
rules/LOOP_PROMPT_REPAIR_REVIEW_CORE_RULE.md
```

Required content:

1. Definition of Loop Prompt.
2. The core formula:

```text
目标定方向
样品定气质
标准定好坏
第一版打底
评分找差距
修复逼近目标
复查防自嗨
停止防乱跑
沉淀变技能
下一轮复用
```

3. Where the mechanism applies.
4. Hard rules:
   - complex tasks cannot stop at the first draft
   - complex tasks must include scoring
   - complex tasks must include repair
   - complex tasks must include re-check
   - complex tasks must include stop conditions
   - completed complex tasks must create reusable rules or templates

## Execution Template Pattern

Create a template such as:

```text
templates/LOOP_PROMPT_EXECUTION_TEMPLATE.md
```

Sections:

1. 任务名称
2. 目标定方向
3. 样品定气质
4. 标准定好坏
5. 第一版打底
6. 评分找差距
7. 修复逼近目标
8. 复查防自嗨
9. 停止防乱跑
10. 沉淀变技能

## Stage-Specific Usage Rule Pattern

When a future stage needs the Loop mechanism, create a stage rule such as:

```text
rules/STAGE4A_LOOP_PROMPT_USAGE_RULE.md
```

State clearly that the stage is not a normal execution task. Each key artifact must embed:

1. goal definition
2. reference sample
3. acceptance criteria
4. first version
5. scoring
6. repair
7. re-check
8. stop condition
9. skill lesson capture

Also list the artifacts or workflows that must use this loop.

## SKILL.md Update Pattern

Before editing the target skill:

1. Create a timestamped or named backup, for example `SKILL.before_loop_prompt_rule.md`.
2. Preserve the original structure.
3. Add a concise section such as `## Loop Prompt Repair Review Rule`.
4. Link to the new rule file, execution template, and stage usage rule.
5. Do not remove existing validation or trigger behavior.

## Evidence And Manifest Pattern

For command-package style work, produce:

1. visual flow evidence, when useful
2. a rule-deployment report
3. a manifest listing all generated or updated files
4. verification output
5. backup/sync evidence
6. explicit non-actions, such as:
   - 是否修改真实 Vault：否
   - 是否接真实 skill-index：否
   - 是否进入 Stage 4A：否
   - 是否生成最终 Dashboard：否

## Self-Check Criteria

Score or check these before claiming `PASS`:

1. Core Loop rule file exists.
2. Execution template exists.
3. Stage usage rule exists, if requested.
4. Target `SKILL.md` was backed up.
5. Target `SKILL.md` links to the new Loop rules.
6. Evidence or visual flow exists, if requested.
7. Deployment report exists.
8. Manifest exists.
9. Verification script passes or failure is reported honestly.
10. Backup/sync result is recorded.
11. Forbidden actions were not performed.
12. Final status is not overstated.

## Final User Report Pattern

Report:

1. whether Loop rule integration completed
2. core rule path
3. execution template path
4. stage usage rule path
5. backup path
6. updated `SKILL.md` path
7. evidence path
8. deployment report path
9. manifest path
10. verification result
11. backup/sync result
12. explicit boundary statement
13. recommended next step

## Lesson

This case adds a specialized Loop pattern: `rule integration loop`.

The important part is not only the Loop formula, but the operational boundary around it. A rule-integration task can prepare the next stage without entering that stage. It can improve a skill package without touching live project data. It can generate evidence and manifest files without claiming production completion.
