## 核心共识

这不是 ChatGPT 专用技巧，而是网页、网站、桌面软件都通用的普通人可视操作方法。

核心逻辑：

```text
普通人能稳定操作
-> 页面/软件存在可识别状态
-> 截图能识别状态
-> 坐标在同一状态内稳定
-> 状态变化可以通过归一化分支处理
-> 测试次数足够后，失败会变成规律分支
-> 成熟流程在正常网络/账号/软件状态下应追求工程意义 100% 成功
```

## 方法不是每站一个大状态机

正确形态是：

```text
一套通用方法 + 轻量坐标数据表
```

不为每个网站写大技能包；只记录每个网站/软件在某个状态下的坐标数据：

```text
对象
页面/软件状态
动作
坐标
键盘等价动作
成功次数
失败修正
证据路径
最后验证时间
```

## 通用流程

```text
截图
识别当前状态
定位目标控件
绑定当前状态下坐标
执行一个普通用户动作
再截图
验收结果
失败则归一化状态并记录分支
重复测试直到稳定
```

## 状态归一化

以下不叫真正异常，而是普通人方法里的修复分支：

```text
页面没打开 -> 打开页面
标签页错了 -> 切换或新开
旧页面/旧会话 -> 新建
输入框脏 -> Ctrl+A / Backspace
焦点丢失 -> 重新点击输入框
页面卡住/旧生成没停 -> 点击停止或刷新后重新进入干净状态
小按钮坐标漂移 -> 优先用普通用户键盘等价动作，例如 Enter
布局变化 -> 重新截图，重新绑定当前状态坐标
```

真正阻断只包括：

```text
登录失效
验证码
账号/安全/权限提示
网络断开
服务不可用
付款/删除/发布/授权等高风险确认
```

## 后续使用规则

当用户要求操作网页、软件、官网模型、截图点击、坐标定位、普通人方法、不要复杂方法时：

1. 优先调用 **普通人坐标截图法**。
2. 用截图确认当前状态。
3. 当前状态有坐标数据就复用。
4. 没有坐标数据就现场截图定位。
5. 成功后记录坐标数据。
6. 失败时先归一化状态，不转复杂方法。
7. 只有普通人修复分支截图证明失败后，才标记方法失败。
