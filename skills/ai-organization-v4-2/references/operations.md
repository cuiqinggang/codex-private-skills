# 执行与恢复要点

## 发起与验收

最小输入是“做什么、材料在哪里、交付什么、达到什么标准”；可从上下文推断时不重复问。成本或外部行为边界不清且影响实际动作时补齐。默认 GPT 主执行，只有证据支持完整交付净收益才增加执行者。

采用成熟基线→至多三候选→比较融合→虚拟成熟→STOP_GATE→Freeze→一次整体业务验收。简单任务不强加三方案或多智能体。普通错误在原合同内修复，验收质量不降低。

区分文件存在、可发现、已加载、真实执行成功和本次验收通过；旧回执只证明其范围。完整 T_VALID 不以响应时间、脚本时间或局部测试替代。

## Windows 执行桥 V12.0.4：收费 A 优先与本地批量

首次本机调用前原生加载 gpt-windows-execution-bridge 当前有效版（本次 V12.0.4）。A=收费 Remote Desktop Commander，B=免费 GPT-Windows-MCP-Bridge，C=GitHub Actions Windows Runner。先动态 list_devices 选择在线设备，再无副作用探针；A 成功后该任务保持 A。工具返回 running/call_id 时用 get_tool_result 等正式取结果入口，有 PID 时用 read_process_output，禁止重复提交。

A 失败：重新发现→限一次复验→保存工具、设备、时间、错误→核清业务副作用。满足这些条件才进入 B；进入 C 需 B 的同类证据。不可用工具如实报告，不能把别的通道改称 A。连接器、浏览器和业务异常分别处理。

### A/B 共用批量派发

同一设备、相同授权边界、输入已明确并能在本地完成和校验的步骤，优先合并为一次远程调用。多文件纯读用原生 read_multiple_files；本地处理闭环用 start_process 与既有成熟脚本。不要把GPT端循环5次远程调用称为一次本地批量。批量大小不固定5项；不为凑批次等待，不强制本地并行。

逐项返回状态、正确性校验和汇总计数；实际计时包含派发、执行、续读和验收。部分成功、超时或UNKNOWN先核账，只续做CONFIRMED_NOT_EXECUTED项；不能整批盲重发或换通道重复提交。等待用户审批、依赖新的外部结果或不可逆外部提交时，按边界拆批。明确授权的A/B对照属于测试，不是A故障降级。

## 接续任务

沿用已有任务编号、N000 与节点回执。先读线上最新状态；线上不可用再读 C 盘镜像；使用既有机制保存，不另造调度。最少记录：目标与验收、TASK_ID、NODE_ID、已确认成果路径与回执、当前状态、未完成项、唯一下一动作、副作用状态。

CONFIRMED_COMMITTED：继承，禁止重复；CONFIRMED_NOT_EXECUTED：才允许在原授权内重试；UNKNOWN：先只读核账。文件已保存不证明外部预约或支付已提交，外部成功也不代表检查点已保存。

换页前保存恢复包，给用户一段恢复文字。新页先读文件与最新回执，再继续未完成节点。没有真实持久执行器接单，不承诺关闭聊天后仍在运行。跨页自动加载取决于环境，必要时显式指定技能或原文件路径。
