# Verified Windows Docker startup incident — 2026-10-24

## Evidence and causes

Host: DESKTOP-4A1EGTM. This follows the existing windows-hermes-operations V1.1 incident from 2026-10-22.

- The current Remote Desktop Commander process environment had empty ProgramData; CommonApplicationData resolved to C:\ProgramData. The 2026-10-22 incident already established that launching Docker without standard environment variables can crash its backend with "unable to get 'ProgramData'".
- Existing Hermes launcher headers had the repair, but direct Docker Desktop launch commands bypassed those headers. Fixing one script does not correct every process that starts Docker.
- At the user's earlier request to temporarily stop containers, the old Docker shortcut/OpenWebUI auto-open entry were parked. The user subsequently authorized restoring automatic startup. That deliberate disable was not itself a runtime failure.
- Other task commands explicitly relaunched Docker between 18:39 and 18:41, Beijing time. The Docker native AutoStart setting remained false.
- Active consumers were Tymeslot, Radicale, Mailpit, n8n-local and open-webui-clean. The DSH browser MCP configuration used local Node.js and CDP 127.0.0.1:9223, without Docker.
- The old rollback container open-webui-clean-pre-20261004-180127 had restart=always, 41 observed restarts and a configured host port 3000 shared with the current Open WebUI configuration. This proves an unwanted rollback-instance restart loop and overlapping configuration; it does not by itself prove the exact internal crash cause.

## Applied repair

1. Reuse the current user's Windows Startup folder as the sole managed Docker login entry: Docker-Quiet-Autostart.vbs.
2. Run Start-DockerQuiet.ps1 through the existing PowerShell Reliability Guard. The VBS hides the process at creation, waits and propagates the exit code.
3. Resolve standard Windows process variables before launching Docker; affect only this process and its children.
4. Use bounded Engine probes. Exit immediately when ready; wait for an existing backend instead of duplicating it. If there is no Docker process, invoke the installed Docker Desktop.exe -AutoStart once.
5. Preserve native AutoStart=false to avoid a second login path. Preserve old browser-opening startup entries disabled.
6. Disable the exact old rollback container's restart policy and stop that backup instance without deleting it. Preserve active business containers and data.

## Rollback and prevention

Backups, status.json and startup.jsonl: C:\AI\Docker-Autostart-20261024.
The previous temporarily parked launchers remain in C:\AI\StartupQuiet-20261024\disabled-startup.

To remove this startup behavior, remove only Docker-Quiet-Autostart.vbs after recording it. Restore a previous launcher only if the user requests that behavior; do not restore multiple entries. The old rollback container's original policy was always; restore it only for an explicitly requested rollback with port conflict review.

Never keep .bak/.disabled files in Startup. Never fix startup by factory reset, prune, deleting VHDX, unregistering WSL, changing proxy, or repeatedly killing shared Docker. Preserve full task evidence before disruptive recovery.
