# 从 1.0.1 到 2.0.0 的迁移与回退

## 固定原则

- 1.0.1是已冻结历史基线，不在原目录内直接改写。
- 2.0.0从1.0.1已经验证的路由与执行能力收敛而来，不重新开发执行器。
- 同一技能名不得同时存在两个活动目录，否则可能造成重复发现或版本不确定。
- 归档不是删除；回退必须可恢复。

## 迁移前记录

至少保存：

- 1.0.1技能目录、版本、文件清单和SHA-256；
- 专用Profile路径和SHA-256；
- 六项原始验收结果；
- R6综合QA的证据根和阻塞结论；
- 当前活动技能条目数量；
- 2.0.0包的文件清单和SHA-256。

## 最小迁移范围

允许：

- 将1.0.1活动目录移动到既有安全备份位置；
- 将2.0.0放入正式技能目录；
- 只更新与本技能直接相关的专用Profile条目；
- 新建2.0独立验收证据根。

禁止：

- 删除1.0.1归档；
- 将1.0.1和2.0.0作为两个同名活动技能保留；
- 修改默认全局配置、代理、FlClash、DNS、VPN、账户、密钥或Provider；
- 修改Reasonix配置或Playwright实现；
- 恢复Omnigent、ACP或ACPX路线；
- 复用R6目录覆盖旧证据。

## 回退条件

发生以下任一情况即回退到1.0.1：

- 2.0正式入口不可发现或不可调用；
- C01～C08存在无法在本轮最小范围内解释的核心失败；
- 2.0产生重复技能条目；
- 修改范围触及禁止区域；
- 2.0无法恢复1.0已有的Reasonix、Playwright或Codex回退能力。

回退后验证1.0.1目录、文件哈希、活动条目唯一性和原正式入口；不得把回退成功写成2.0验收通过。
