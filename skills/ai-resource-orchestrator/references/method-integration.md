## 六个实际触发点
1. 接单分析：先有成功态，再按正式方法记录当前成熟能力 / 实际缺口 / 缺口原因及证据 / 复用成熟方案与最小适配。没有缺口也记录复用来源。
2. 成熟方案匹配：已有匹配技能 → find-skills 查原始技能正文 → 官方成熟项目或方法。先完全匹配，再核心问题相似；核对前提，剔除不适用方案，找到合格方案即停。未知原因写“待验证假设/UNVERIFIED”，不得默认归因权限、网络或模型。
3. 资源分派：每行实际缺口对应最终产物所需能力，再用原 routing-contract 选资源、模型和力度；视觉/音频能力优先于低价文本。只适配真实差异，不启动另一个调度器。
4. 成果验收：按冻结标准读取真实产物、工具回执和来源；区分 PASS/FAIL/BLOCKED/UNTESTED/EVIDENCE_GAP。发送意图、实际请求和供应商返回分别取证，未知保留 UNKNOWN。
5. 失败修复/返工：更新同一四列表，先查正式入口、误报和外因；改动必须对应有证据的缺口，一次只改明确因素，原失败输入先复测，再测受影响相邻能力。不得降低验收标准。重复失败无新证据停止该分支；合法兼容路线成果不能抹去原分支失败。
6. 经验复用：仅实测成功且边界明确的规则进入成熟复用记录，带来源、版本、输入范围、证据和最近使用时间。未测规则标 candidate；下一任务开工读取已证实记录及原失败复盘。
