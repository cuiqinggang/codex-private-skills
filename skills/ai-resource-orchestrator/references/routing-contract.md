# 2.0 Core 路由合同

只在需要判断档位、执行者、强度或回退时读取。

## 一、选择顺序

按以下优先级判断，后面的条件不能推翻前面的硬条件：

1. 用户明确选择；
2. 必需能力或工具；
3. 安全与外部副作用；
4. 质量底线和错误代价；
5. 已验证可用性；
6. 相对成本；
7. 速度偏好。

## 二、四档定义

| 档位 | 进入条件 | 默认执行方式 | 默认强度 | 禁止的浪费 |
|---|---|---|---|---|
| 经济档 | 单一目标、低风险、规则明确、结果容易核对 | 最便宜的已验证合格路径；无合适低价路径时使用 Codex | LOW | 子代理、浏览器、独立复核 |
| 标准档 | 普通分析、一般编码或多步骤但边界清楚 | Codex 主智能体 | MEDIUM | 无依据并行、重复执行 |
| 高质量档 | 跨文件、复杂推理、重要交付或错误代价较高 | 高能力主执行器；必要时一次独立复核 | HIGH | 多个角色重复做同一件事 |
| 极限档 | 疑难故障、生产级决策、强耦合长流程或极高错误代价 | 最强可用路径；只对可分离工作使用子代理 | MAX | 无限重试、无边界探索 |

档位是质量与风险等级，不是固定模型名称。模型供应、价格或额度变化时，使用当前已经验证的执行器配置，不在技能中硬编码未经验证的价格排名。

## 三、执行者决策

| 可观察条件 | 主执行者 | 说明 |
|---|---|---|
| 用户明确指定 Reasonix | Reasonix | 使用 `reasonix run`；失败一次后回退 Codex |
| 低风险、边界明确、输出可机械验收且成本敏感 | Reasonix 或已验证低成本路径 | 如果可用性或质量未知，使用 Codex，不得猜测 |
| 必须操作真实网页、登录态、上传下载或浏览器证据 | Playwright | 调用既有 `playwright-native-ai-browser` 成熟技能 |
| 两个以上工作包真正独立，并行有明显时延收益 | Codex 子代理 | 分派互不覆盖的任务；主智能体最终合并 |
| 需要独立审查且错误代价较高 | 一个 Codex 子代理 | 只做独立审查，不重复整个项目 |
| 付款、发布、删除、敏感写入或登录授权 | 人工确认 | 确认后再由适当执行器继续 |
| 其他情况 | Codex 主智能体 | 默认路径 |

## 四、强度决策

- `LOW`：答案可直接核对，错误可轻易纠正。
- `MEDIUM`：需要多步推理或一般实现，但风险有限。
- `HIGH`：需要跨组件推理、复杂实现或严格证据。
- `MAX`：只有高风险、疑难、强耦合问题才使用；不能因用户文字很长自动使用。

如果用户指定了质量目标，选择达到目标的最低强度。执行后若没有满足明确断言，只允许升级一个档位或回退一次，并说明触发证据。

## 五、普通任务快捷路径

同时满足以下条件时直接由 Codex 主智能体完成，不展开完整编排：

- 只有一个主要输出；
- 不需要真实浏览器或外部系统；
- 不需要多个独立专业判断；
- 没有高风险外部副作用；
- 用户没有明确指定执行器。

## 六、停止条件

- 同一执行器、同一根因已经失败一次；
- 没有新的证据支持升级或换路径；
- 所需权限、凭据或人工选择缺失；
- 继续执行会扩大文件、费用、安全或外部副作用范围。

达到停止条件时报告 `BLOCKED` 和直接证据，不自行扩大权限或创建新系统。
