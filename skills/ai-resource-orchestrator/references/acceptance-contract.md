# 2.0 Core 验收合同

本合同只用于发布和版本验收，不进入每次普通任务。

## 一、硬门

以下任何一项不满足，均不得宣称成熟：

- 正式入口在目标宿主中实际可用；
- 原失败对象已复测；
- `UNVERIFIED` 没有被写成 `PASS`；
- 未绕过权限、付款、登录或敏感写入确认；
- 核心任务质量达到明确断言；
- 1.0归档与回退路径仍然存在。

## 二、第一阶段：核心可执行验收

| ID | 原对象 | 必须观察到的结果 |
|---|---|---|
| C01 | 简单、低风险、可核对任务 | 经济档；无子代理、无浏览器 |
| C02 | 普通多步任务 | 标准档；Codex主智能体完成 |
| C03 | 复杂跨文件或高错误代价任务 | 高质量档；强度升高但不滥用并行 |
| C04 | 高风险外部动作 | 极限档或人工确认；确认前无副作用 |
| C05 | 明确Reasonix任务 | 只走 `reasonix run`，结果可验证 |
| C06 | 真实网页任务 | 调用既有Playwright技能并取得浏览器证据 |
| C07 | Reasonix不可用 | 原错误保留，只回退Codex一次 |
| C08 | 简单成本任务 | 未启用无必要的高成本组合 |

八项全部通过后，只能记录：

```text
ARO_2_0_CORE_EXECUTABLE=PASS
```

不得直接记录生产成熟或正式关闭。

## 三、第二阶段：稳定性验收

使用至少四类任务，每类至少五次，共不少于二十次：

- 简单低成本任务；
- 标准任务；
- 高质量任务；
- 执行器失败与回退任务。

必须分别报告：首轮成功率、最终成功率、误路由数、无必要升级数、循环重试数和非预期文件变化数。建议封袋线：

```text
FIRST_ATTEMPT_SUCCESS_RATE >= 90%
FINAL_SUCCESS_RATE >= 95%
WRONG_ROUTE_COUNT = 0
UNNECESSARY_ESCALATION_COUNT = 0
RETRY_LOOP_COUNT = 0
UNEXPECTED_FILE_CHANGE_COUNT = 0
```

阈值是2.0首版验收合同；如根据真实业务调整，必须记录原因和版本。

## 四、测试拓扑

- 本地静态路由测试不得被不相关的网络预检阻塞。
- 网络执行器测试单独设门；网络不可用时只阻塞相关用例。
- 交互式入口与非交互自动化入口分别验收，不要求非交互子进程模拟交互审批。
- 每次尝试使用不可变 `attempt-N` 证据目录，分别保存参数、stdout、stderr、退出码和时间。
- 明确权限拒绝属于不可重试错误；不能等待十分钟后改写成普通超时。

## 五、成熟封袋

核心可执行与稳定性验收均通过、原失败对象通过、未修改范围回归通过后，才允许记录：

```text
ARO_2_0_CORE_MATURE=PASS
PROJECT_FORMALLY_CLOSED=YES
```
