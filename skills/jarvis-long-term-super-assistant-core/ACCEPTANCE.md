# JARVIS 长期超级助手核心方法 v0.1.0｜最小验收

本文件不是最终 99 分标准，只定义当前方法是否被正确使用。

## 方法验收

一次任务至少满足：

1. **不是再造执行器**
   - 优先调用已有 Codex / n8n / Reasonix / Playwright / pywinauto / Skill 等成熟能力。
2. **读取相关记忆**
   - 只取会改变当前决策的个人、项目、经验或世界成熟方案信息。
3. **固定 VALID**
   - 正确性、质量、安全、权限、完成概率和证据先决定候选有效性。
4. **极限短时间选路**
   - 在 VALID 候选中按 `T*=min(T_VALID)` 选择。
5. **运行路径最小**
   - 能两个组件完成，不因为能力池里还有更多工具而增加第三、第四层。
6. **可恢复**
   - 页面、会话、进程或长时间任务中断后，可以从持久状态继续，而不是依赖完整旧聊天。
7. **不无限等待**
   - 合理时间无有效进展时按第一性原理恢复、换路径或重新 Virtual Mature。
8. **Reality Verify**
   - 完成必须由现实结果和证据验证。
9. **经验回流**
   - 只有会改变未来同类任务最短有效路径的经验才进入长期记忆或 Skill。
10. **长期时间尺度不另造架构**
   - 8小时、7天、30天任务继续使用同一套可靠自动化与阶段性极限收敛。

## 当前明确 FAIL

以下任一情况出现，视为偏离本技能：
- 为建设 JARVIS 又开发一个通用 Codex/Manus 类执行器；
- 每个任务固定启动全部能力；
- 四列法重新进入当前 JARVIS 主流程；
- 把全部聊天历史当作记忆；
- 当前路径明显无进展仍无限等待；
- 执行失败即终止而不判断成熟恢复路径；
- 未验证现实结果却写“完成”；
- 为长任务另造与短任务完全不同的方法体系。
