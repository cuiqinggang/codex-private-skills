# Static Site Factory V1.0

版本：1.0.0  
语言：zh-CN

## 1. 技能定位

本技能不是再造一个单纯“网页设计技能”，而是作为现有网站类 Skills 的**总路由与交付层**：

- 设计技能负责从零生成视觉与页面结构；
- 克隆技能负责从参考网页提取布局、组件和视觉规律；
- 本技能负责判断能否静态化，并把内容生成、数据注入、SEO、表单、构建、部署、验证串成完整闭环。

禁止直接覆盖或改写现有稳定 Skills。发现同类技能时，优先以 `references/integration-map.md` 所述方式编排调用。

## 2. 适用边界

### 适合静态网站

- 企业官网、产品介绍站、作品集、文档站、博客、活动页、营销落地页；
- 内容更新频率低或可通过重新构建发布；
- 需要高速度、低服务器成本、高安全性和较强 SEO；
- 批量页面结构相同、内容由 JSON/CSV 驱动的站群或目录站。

### 不应强行静态化

- 登录后高度个性化后台；
- 高频实时写入、复杂权限、交易状态、聊天和协同系统；
- 依赖大量服务端业务逻辑的 SaaS 主应用。

这些项目应采用“静态营销前台 + 动态应用/API”的混合架构。

## 3. 强制决策闸门

开始编码前输出：

1. 中文名称；
2. 要解决的问题；
3. 预计收益；
4. 预计成本；
5. 量化指标；
6. 收益成本判断；
7. 是否执行。

若无法说明静态化带来的明确收益，或动态需求占主导，停止本技能并转交全栈/应用技能。

## 4. 三条执行路线

### Route A：从零设计静态网站

需求澄清 → 信息架构 → 视觉方向 → 组件设计 → 响应式实现 → SEO → 表单 → 构建部署 → 三轮验收。

### Route B：合法参考复刻

URL/截图取证 → 页面分区 → 字体/间距/色彩/组件规律提取 → 独立重写代码 → 替换品牌和文案 → 响应式校准 → 视觉对比 → 部署。

不得复制受保护源码、商标、品牌资产或伪装成原站；默认目标是“结构和体验参考”，不是欺骗性镜像。

### Route C：批量静态站/批量页面

JSON/CSV 数据标准化 → 模板组件化 → 构建时循环生成 → sitemap/robots/canonical → 批量构建 → 抽样与全量自动检查 → CDN 部署。

## 5. 推荐技术选择

- 内容型、多页面、SEO 优先：Astro；
- 单页落地页、简单交互：Vite + TypeScript；
- 已有 React 组件资产：Astro Islands 或 Vite React；
- 部署：Cloudflare Pages、Netlify 或 Vercel；
- 表单：平台表单、Formspree、Getform，或独立 API；
- 实时咨询：外链到 WhatsApp、企业微信、Crisp 等，不为此引入完整后端。

禁止仅因“熟悉 WordPress”而默认上 WordPress，也禁止仅因“静态便宜”而把动态应用硬改成静态。

## 6. 标准执行流程

### Gate 0：现有资产盘点

搜索现有 Skills，至少检查：

- 网站设计/前端设计；
- 网页克隆/URL 转代码；
- 截图转前端；
- SEO；
- 部署；
- 视觉回归测试。

输出复用、补充、冲突三栏，不重复造轮子。

### Gate 1：静态化判定

计算：

- 静态页面占比；
- 动态功能数量；
- 更新频率；
- 是否需要登录和权限；
- 是否依赖数据库实时写入。

建议阈值：静态页面占比 ≥ 80%，且核心转化不依赖复杂服务端状态时，优先静态方案。

### Gate 2：输入契约

必须取得或生成：

- 目标用户与转化目标；
- 页面清单；
- 品牌色/字体/Logo；
- 文案与图片来源；
- 参考站 URL 或截图（若有）；
- 域名与部署目标；
- 表单收件方式；
- SEO 关键词。

### Gate 3：架构与内容模型

建立：

- 页面路由表；
- 组件清单；
- 数据 schema；
- 公共布局；
- SEO metadata 模板；
- 图片资产清单。

批量站必须数据与模板分离，禁止复制粘贴生成数十个独立 HTML 文件。

### Gate 4：实现

要求：

- 语义化 HTML；
- 移动端优先；
- 无障碍基础支持；
- 图片尺寸与懒加载；
- 无未使用的大型 JS 包；
- 组件复用；
- 不产生无意义动态运行时。

### Gate 5：SEO 与转化

至少完成：

- title、description、canonical；
- Open Graph；
- sitemap.xml；
- robots.txt；
- 结构化数据（适用时）；
- 明确 CTA；
- 表单成功/失败反馈；
- 分析代码延迟加载。

### Gate 6：构建与部署

- 本地生产构建必须通过；
- 检查 404 和资源路径；
- 绑定 CDN/Pages；
- 配置 HTTPS、缓存和重定向；
- 保存部署配置与回滚说明。

### Gate 7：三轮验收

1. **结构验收**：链接、路由、资源、表单、metadata；
2. **视觉验收**：桌面/平板/手机截图，对比参考或设计稿；
3. **线上验收**：生产 URL、HTTPS、速度、表单真实提交、SEO 文件。

任何一轮缺证据，不得宣称 PASS。

## 7. 量化验收指标

默认目标：

- 生产构建成功率：100%；
- 内部链接错误：0；
- 关键页面移动端与桌面端布局阻断错误：0；
- Lighthouse Performance/SEO/Accessibility/Best Practices：核心页建议均 ≥ 90；
- 未压缩超大图片：0；
- 表单真实端到端测试：至少 1 次成功；
- 参考复刻关键区块视觉差异：人工与截图证据确认，无明显结构错位；
- 批量页面：全量 schema 校验通过，至少抽样 10% 且不少于 10 页。

## 8. 输出契约

最终必须返回：

- 路线选择及原因；
- 复用的现有 Skills；
- 项目路径；
- 技术栈；
- 页面数量；
- 构建结果；
- 三轮测试证据；
- 部署地址（若已部署）；
- 实际收益数据；
- 未完成项与风险。

只返回“已生成网站”或一个文件夹路径，视为 FAIL。

## 9. 长期复用与防落灰

- 开工前运行全局复用预检，并先检查本技能、相关网站技能及失败复盘。
- 失败时写入 `references/FAILURE-REVIEW.md`，不得只在对话中口头复盘。
- 每次真实调用后追加 `references/RECENT-USE-LOG.md`，记录任务、路线、结果与证据。
- 部署与触发验收见 `evidence/acceptance.html`。
- 全局规则补丁候选见 `references/AGENTS-PATCH-DRAFT.md`；未经用户确认不得覆盖全局 `AGENTS.md`。
