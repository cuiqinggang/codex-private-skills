# 人类介入与示范驱动演化｜参考构思评审

所属：n8n 多智能体运行指挥台技能包 v0.1.1（文档归档版）。
状态：仅参考、未实现、未启用。日期：2026-09-26。

## 1. 归档结论
这份构思与既有体系相通，值得保存为后续按需取用的资料，不适合现在整体并入运行链。最有价值的是把“自动化中的人工补位”和“从人工经验形成下一版候选规则”分开，而不是增加一个长期必经的人工岗位。
本轮完成的是资料整理和采用边界审查，不是完整虚拟成熟、现实认证或功能发布。

## 2. 与现有架构的搭配
原运行主链继续保持：接单登记 → 绑定成功标准与冻结方案 → 受控执行 → 独立验收 → 保存并回传。
MOA 管成果，ARO 管已批准范围内的资源选择，执行器调用技能，n8n 管任务状态与观察。智能体 CEO 是已有职责的比喻，不据此另建一个平级总控。浏览器是执行通道，不重复当成最高决策者。
人工介入只作为特定已授权任务中的候选分支：临时执行、纠偏、示范或否决；示范经验的抽取和成熟不成为每个普通任务的必经步骤。
不要以“减少 IF/Switch”为目标。确定性的权限、状态和故障判断仍应明确；不是把所有判断重新交给生成模型。

## 3. 从原始构思中保留什么
| 构思 | 参考价值 | 本轮处理 |
|---|---|---|
| 人只接管有问题的节点 | 尽量保留已验证结果，缩小返工范围 | 保存；恢复边界以后单独验证 |
| 临时执行、纠偏、示范三类作用 | 区分一次性操作、修正和可复用经验 | 保存；不把全部干预都当训练数据 |
| 人工否决与最终控制权 | 保留人对授权和结果的决定权 | 保存；不得因提速自动取消 |
| 记录状态、动作、结果、原因和时间 | 为后续诊断和复用提供证据 | 保存字段建议；本轮不启动采集 |
| 示范转候选、经过一虚一实认证 | 防止单次偶然成功直接进入生产 | 保存；不承诺一次示范就能泛化 |
| PAUSE/CORRECT/TAKEOVER/RESUME/TEACH 入口 | 是未来交互设计候选 | 不创建按钮或工作流，也不声明现成可用 |

## 4. 原文不能直接成为运行规则的地方
### 4.1 人不一定最终从所有任务中消失
减少不必要的人工搬运不等于消除必要的人类授权、用户指定审核或仍需人操作的现实任务。是否可替代取决于任务定义、授权与可验证能力，不以全自动为独立核心指标。

### 4.2 人工改方案后，不能直接恢复旧冻结任务
两类情况必须分开：
- 冻结合同事先包含该人工步骤、输入范围、验证器和恢复检查点，且实现已验证：人工结果验证通过后，允许按该冻结分支继续。
- 人临场改变路径、实现、成功标准或其他被冻结内容：原尝试停止，记录现实差异，回虚产生新冻结；业务任务标识与总时间账连续保留，新尝试使用新身份。原来的失败终态不能改写为成功。
原文“从页面 A 改用 API B，更新当前计划后直接恢复”的例子只有在变更不超出已批准冻结候选时才可能成立，否则按第二类处理。

### 4.3 暂停画布不等于停止远端执行
未来接管必须证明停止新派发、处理在途请求、确认实际资源占用与副作用、交接执行权。人工和机器不能同时控制同一不可隔离桌面或重复提交同一操作。
这是一项未来验证要求，不是本版已有功能。取消、否决、超时不能默认进入恢复或自动批准；效果未知时先核对证据，不能盲目重试。

### 4.4 示范是候选证据，不是自动训练或自动发布
记录一次操作不会自动产生可靠机器能力，也不意味着修改了模型权重。先生成可审查的规则、脚本或工作流候选；检查适用条件、反例、权限和副作用；经实现级虚拟验证与冻结后，再做目标环境认证。
跨多个场景重复出现且证据支持的经验才考虑晋升。一次成功保留为案例，失败与反例同样留存。正式替换人工环节仍需显式授权，不能后台自改技能。

### 4.5 不默认完整录屏或采集敏感内容
默认只记录解决问题所需的最小结构化证据。截图、录屏或更细粒度动作跟踪需要明确授权，并限定范围、保存期和访问权限。不得记录密码、验证码、令牌、会话 Cookie 或无关隐私；不要把恢复链接和凭据写进可共享技能包。
人工结果同样要验收，“人做完了”不能替代成功判据。

### 4.6 示例数值不是成熟证明
原文 60/40、99/1、83 秒、55 秒、31 秒及“第 N 次全自动”等都是构思示例，不是本机数据、承诺、目标或概率估计。
耗时最大的人工段不一定是最优改造对象：需判断它是否位于关键路径、能否真正消除等待，以及替代路径的总开销与有效性。只比较同一任务标准下的完整 T_VALID，不比较表面自动化比例。

## 5. 当前做到哪一步最合理
**现在只到资料归档。** 不添加人类节点，不改原来的五节点主链，不把这份构思变成 v1.0 的必做清单，也不因此重做既有部署。
基础闭环完成后，若真实任务反复出现同一类阻断，再单独选一个窄范围用例评估，例如“机器遇到已定义的不确定结果 → 经授权请求人工处理 → 回读并验证 → 从已知安全检查点继续”。
建议先验证受控补位，再根据证据决定是否需要示范抽取与候选自动化；不一开始就建设全部按钮、录屏系统和自学习平台。这些是未来采用建议，不是排期或执行授权。

## 6. 未来最小证据记录（字段建议，未实现）
一次干预至少能定位：业务任务、节点、尝试、冻结版本、触发原因、介入前状态、人工授权范围、介入类型、实际动作、成果引用、独立验收结果、开始结束时间、恢复位置、候选经验引用。
时间应明确时区；同一控制器用单调时钟计算总耗时，不直接相减不同机器的单调时钟。等待、人工操作、返工、恢复属于该业务闭环时全部计入 T_VALID；另行诊断人工段不等于从总账中扣除。

## 7. 未来启用前的必要证据
在既有 n8n 运行闭环完成后，针对选定用例明确：输入输出合同、人工权限、身份/任务/尝试绑定、受控停止与资源交接、验收和恢复检查点、幂等、过期/重复/迟到回执处理、超时/否决/取消终态，以及保留期与回滚路径。
先在“虚”里物化真实实现、攻击成功和失败分支及验证器，形成一致冻结，再做“实”的目标环境认证。未知或越界变化固定回虚，不授予现场自由修复权。
同一冻结版本的完整证明可以在满足适用性与哈希一致条件时复用，但不得用状态机兼容性证书的时间代替业务接单到交付的时间。
