# n8n 多智能体运行指挥台技能包 v0.1.1

## 本版性质与版本边界
本版只保存参考资料、明确可借鉴的机制及采用边界，不包含新的执行实现。
用户此前使用的版本名称为 v0.1.0；本轮在已检索的共同仓库主分支与 n8n 命名分支中未找到旧独立包正文及完整发布回执。因此本版是同名技能的文档归档入口，不是对已核实旧部署的原位更新，也不证明其他分支或用户本机不存在旧包。
v1.0.0 仍是整体运行闭环的后续目标，不因本次归档而获得认证。此前 R2 是流程逻辑审查包，不是本技能版本号。

## 当前允许的用途
读取参考资料、恢复版本与证据边界、在用户提出实际需求时评估其中一个小功能。仅阅读本技能不触发任何执行任务。
禁止因本版存在而自动启用人工接管、屏幕记录、示范学习、运行时改计划、自动发布技能或更改 n8n 工作流。不得把下述描述性元数据当成已经部署的强制安全机制。

## 保留既有职责
n8n 负责入口、状态与观察；MOA 0.3.1 负责成功态与验收；ARO 2.0.3 负责已批准候选内的资源选择；Codex / Reasonix 执行；浏览器、pywinauto 与其他技能按需调用；ECC v3.1.1 是长流程能力，不是平级总控。
原五个逻辑节点保留：接单登记 → 绑定成功标准与冻结方案 → 受控执行 → 独立验收 → 保存并回传。
本版仅在资料层描述可选的异常/人工授权分支，不新增必经人工节点或另一个 CEO 系统。

## 方法与采用边界
沿用整体闭环极限短时间引擎 v5.0.2，顶层仍只有“虚→实”，唯一目标 T*=min(T_VALID)。
未来需要实现时：候选经验进入虚阶段，完成实际实现、测试、故障注入、验证器攻击及冻结，再按冻结合同进行现实认证。资料归档不等于完整虚拟成熟。
原冻结合同明确覆盖且经验证的人工分支，可以在验收通过后按合同继续；改变方法、实现或其他冻结内容时，记录 Reality Delta、停止原尝试、回虚形成新冻结，不得临场改计划后沿用旧成功记录。
保留人工否决、用户要求的授权与治理。示范成功仅是候选证据，不能直接变成生产规则。
同一业务闭环中的人工等待、操作、返工和恢复计入 T_VALID；人工比例只作诊断，不设为并列核心指标。
