# 极限短时间引擎 v4.7.5

## 核心
- 方法只有：虚、实。
- 成熟极限时间锚：T_MATURE*=00:03:14.419。
- Reality Foundation（现实底座）=1.1.8。
- T_CLOSED_REAL（现实闭环墙钟）继续在机器时间账本中记录，但不要求每条用户回答展示。

## 唯一状态
状态只写纯数字二段码：01-03。
前两位=方案代；后两位=本方案代第几次正式现实尝试。
配合唯一阶段：虚/实。
例：01-03｜虚 = 第一代方案，第3次现实尝试前的虚阶段。

## 用户可见最简状态锚
默认只显示：
【页面名｜任务名｜01-03｜虚】 极限锚03:14.419

只显示一个时间：当前成熟极限时间锚。
不再默认显示年月、月份、完整墙钟、偏差、目标内/超目标。
短期任务确需显示现实时间时，用户可见最多用“24日 21:15:08”；机器内部仍保留完整 ISO 时间戳用于审计。

页面回答缺状态锚，按技能语义记为 RESPONSE_DRIFT（回答漂移）。当前 ChatGPT 页面没有外部发送前拦截器，因此这里只作为自检规则，不冒充机器硬阻断。

## 六次强制回头
同一方案代只允许现实尝试 01–06。
01-01实 FAIL -> 01-02虚。
01-05实 FAIL -> 01-06虚。
01-06实 FAIL -> 必须方案重组 -> 02-01虚。
01-07 永远非法。
若第1–5次已经发现结构性错误，也允许提前重组到下一方案代的 01。
阈值6只能通过升版和现实证据调整，不能临场放宽。

## 虚
- 读取现实底座1.1.8。
- 使用成熟方案，不自由探索。
- 定义 FINAL_VALID（最终有效）条件。
- 关闭已知失败门。
- GPT 当前工具能低成本现实预跑的关键公开子路径，冻结前先真实预跑。
- 生成唯一 FREEZE_ID（冻结方案编号）。

## 虚→实原子交付
虚成熟最后一个动作就是交付现实任务。
同一轮完成：冻结、数字状态、四定位、现实合同、时间账、PASS/FAIL合同、发布/自动发送 Codex 任务。
没有现实任务，不允许宣布虚完成。


## 执行硬门的位置

v4.7.5 修正 v4.7.4 的结构性错误：状态机硬门不再放在 Codex 本地子进程内部认证。

状态机/序号/Freeze/时间锚这些规则，属于“任务是否可以发给 Codex”的控制面规则，必须在 GPT↔Codex 控制层 PRE-DISPATCH（发送前）机械验证。

因此：

- 状态机 gate（门）PASS 后，才允许任务进入 Codex；
- 状态机 gate 本身不依赖 PowerShell/Node 子进程；
- 1344 不再阻塞“状态规则是否正确”的认证。

对真正需要本机子进程的业务 REAL（现实）任务，另设 executor capability（执行器能力）条件：

- 必须记录当前 EXECUTION_CHANNEL_ID（执行通道标识）；
- 当前通道必须通过真实 PROCESS_SPAWN_CERTIFIED_CURRENT_CONTEXT=PASS；
- 这个 PASS 必须来自当前通道的真实子进程启动，不允许由虚拟测试字段或历史别的通道代替；
- 只知道工作目录曾 PASS 不足以放行；
- 若当前通道 1344 且历史备用通道没有稳定可定位标识，STOP，返回 EXECUTION_CHANNEL_UNRESOLVED（执行通道未解析）。

v4.7.3/4.7.4 连续两次 1344 证明“让 Codex 自己启动子进程来认证上游状态门”是错误路径；本轮按结构性错误提前重组方案代。

## 实
Codex 是现实执行器。
同一 FREEZE_ID 只允许一次正式 REAL（现实）发布。
REAL 中禁止重新设计和现场修方案。
REAL FAIL（现实失败）只能：最小 Reality Delta（现实差异）-> STOP（停止）-> 回虚 -> 新 FREEZE_ID。
不得使用同一 FREEZE_ID 直接重跑。

## 时间规则
用户可见固定只保留：极限锚03:14.419。
机器内部时间账保留：任务开始、现实发布、Codex开始/结束、GPT最终确认、T_CLOSED_REAL。
这样时间核心不会丢，又不让显示字段反过来增加复杂度。

## Reality Foundation（现实底座）1.1.8
真实版本链：1.1.3 -> 1.1.4 -> 1.1.5 -> 1.1.6 -> 1.1.7 -> 1.1.8。
1.1.8 新增关键修正：同一个历史曾 PASS 的窄工作目录，在当前 Codex 执行通道仍可 1344；因此工作目录只作为风险降低提示，不再作为“子进程一定能启动”的证明。
真正相关的是当前 execution channel（执行通道）/ token context（令牌上下文）。

## 语言
用户可见内容中文优先。
必须出现的英文术语首次出现时附中文解释。
机器字段、公式、路径、版本号、SHA256 可直接保留英文。

## 真正机器硬门
机器硬门只校验即将进入 Codex/自动化执行链的任务状态，不再尝试验证每一条 ChatGPT 页面自然语言回复。
只检查七个必要不变量：
1. 数字状态合法且尝试号<=06；
2. 极限锚等于当前 T_MATURE*；
3. 虚→实有新 FREEZE_ID；
4. 虚→实已发布/自动发送现实任务；
5. 同一 FREEZE_ID 不得第二次 REAL；
6. REAL FAIL 后必须新 FREEZE_ID，第6次 FAIL 必须新方案代01；
7. REAL PASS 才允许 FINAL。

## 最终一句话
只要始终知道：哪个页面/任务、当前数字状态、现在是虚还是实、成熟极限时间是多少；同一方案最多现实6次，第6次仍失败必须重组。
