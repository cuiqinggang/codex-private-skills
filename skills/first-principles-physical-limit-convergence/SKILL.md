# 极限短时间引擎 v4.4.2

## 根基：现实底座

```text
本地 AI 现实底座永久资产
local-ai-reality-foundation
当前版本=v1.1.0
```

它不是第三步，而是“虚/实”共同的现实根基。

虚开始前必须读取与任务有关的最小充分现实；缺少会影响有效性或 T_VALID 的关键现实事实时，虚未完成。

实结束后必须做现实底座吸收检查：只有能缩短未来 T_VALID 或避免重复失败/重复测量的新现实事实才吸收，否则不吸收、不升版。

## 唯一锚定物

```text
T_VALID = 从任务开始到第一个现实有效结果出现的端到端时间
T* = min(T_VALID)
```

所有规则都服从：

```text
先过有效硬门，再只比较 T_VALID。
```

不能保证有效、缩短当前或未来 T_VALID、或避免重复失败/重复测量的内容，删除。

## 虚

```text
【页面名｜任务名｜序号｜虚】
```

基于现实底座，冻结当前预测 T_VALID 最短的有效方案。

### 冻结闭环门

**冻结不是“方案写完”，而是虚阶段最后一个验收动作。**

现实执行链必须先展开为完整步骤图；每一个会在“实”中发生的步骤，在冻结前都必须满足：

```text
输入=已知或已冻结
动作=已定义
成功后置条件=已定义
失败差异=可分类
下一步=唯一
外部依赖=已证明或已有冻结兜底
产物=可定位且可校验
```

任一步缺一项：

```text
FREEZE=BLOCK
VIRTUAL_COMPLETE=NO
```

尤其是 GitHub、模型 API、浏览器、账号、网络、文件、GPU、外部服务等边：

```text
若外部依赖不是任务本身必须测量的对象：
    不得成为现实启动的单点硬依赖；
    必须在虚阶段预先物化/缓存/固定不可变标识，
    并冻结无需该外部服务也能启动的本地或内联兜底。

若外部依赖本身就是任务有效性的组成部分：
    必须把其可用性与失败分类写入有效门，
    不能当作默认成立的环境假设。
```

冻结前必须运行一次独立的闭环验收：

```text
EXECUTION_CHAIN_CLOSED=PASS
EXTERNAL_DEPENDENCIES_CLOSED=PASS
IMMUTABLE_ARTIFACT_PINNED=PASS
FREEZE_CLOSURE_VERIFIER=PASS
```

四项全 PASS 后才允许：

```text
FROZEN_SOLUTION=YES
```

### 虚完成条件

```text
现实底座=足够
有效门=通过
预测T_VALID=有
执行链闭合=通过
外部依赖闭合=通过
不可变产物=已固定
冻结闭环验收=通过
冻结方案=有
```

## 实

```text
【页面名｜任务名｜序号｜实】
```

严格执行冻结方案，量出真实有效性和真实 T_VALID。

现实阶段不得补设计、补依赖、补兜底；这些都属于虚阶段未完成。

如果在第一条真实动作之前发现冻结方案所需前置条件未被闭合，应记录：

```text
VALID_REAL=未开始
REALITY_DELTA=REAL_ENTRY_PRECONDITION_NOT_CLOSED:<最小差异>
ACTION=STOP
RETURN_TO_VIRTUAL=YES
```

如果已进入冻结执行链后失败，则记录最小现实差异后停止。

完成必须有：

```text
有效=通过
现实T_VALID=有
现实底座吸收检查=完成
```

失败只允许：

```text
最小现实差异 -> 停止 -> 回虚
```

执行器不得现场改变冻结方案。

## 收口

```text
虚无现实根基/预测时间/闭合执行链/冻结闭环验收/冻结方案 -> 未完成
实无现实有效结果/现实时间 -> 未完成
答不出当前现实最短有效时间 -> 未收口
```

只有“虚/实”，无第三步。
