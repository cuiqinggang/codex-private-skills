## v1.9.0 变更范围

v1.9.0 只修正执行收敛语义：

1. 保留 `NO_FREE_EXPLORATION=YES`；
2. GPT 仍必须在执行前设计完整 Virtual-99 和条件铁路；
3. Codex 仍不能添加候选、改顺序、扩展运行、自由 profiling；
4. 预定义 PASS / FAIL / NOT_APPLICABLE 可以在同一 batch 内自动进入预定义下一 stage；
5. 只有 `MATERIAL_REPLAN_TRIGGER` 才提前回 GPT；
6. “实际收益远大于/小于预测但仍落在预定义分支”不再触发重规划；
7. 禁止同一候选在执行期无限拆成 preflight-A/B/C；
8. Residual Virtual Convergence 默认移动到 batch boundary。

这修复了 v1.8 中“要求完整 Virtual-99”与“每个 stage 都必须返回 GPT”之间的收敛效率冲突。

`METHOD_LOGIC_ACCEPTANCE=PASS` 只表示远端方法合同静态自洽；不表示本机 runtime 已安装 v1.9.0，也不表示某个项目已经完成 v1.9 的真实批次验证。
