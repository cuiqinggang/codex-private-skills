# VIRTUAL MATURE PATH + PORTFOLIO ROI（虚拟成熟路径 + 组合收益停止）

本规则属于 `first-principles-physical-limit-convergence v1.4.0`。

## 1. 核心纠偏

第一性原理负责计算边界，不等于从零自由探索。

复杂任务的正式路径不是：

```text
发现一个点 → 试一个点 → 再发现一个点 → 再试一个点 → V1…Vn
```

而是：

```text
第一性原理物理边界
→ 极简真实运行
→ 真实态极限区间
→ 吸收成熟方案
→ 完整虚拟运行到99
→ 形成成熟执行路径
→ Codex按路径快速验证
→ 偏离时重新推演，而不是自由探索
```

---

## 2. 第一步：两个极限区间 + 极简真实运行

### 2.1 T_PHY（第一性原理物理极限）

固定任务合同和当前有效硬件边界后，计算：

```text
T_PHY（第一性原理物理极限）
= 物理规律、不可避免工作量、硬件资源共同决定的理论下界区间
```

它是最终方向参照，不因为现实实现较慢而放宽。

### 2.2 T_MACHINE_STAR_PRE（现实极限初算）

根据：

- 当前真实硬件；
- 当前软件栈；
- 已知成熟实现；
- 历史经验先验；

先计算现实可实现区间初稿。

### 2.3 MRE（极简真实运行）

复杂系统必须尽快完整跑通一次最小真实链路。

目标不是优化，而是把“静态机器”变成“真实运行中的机器”。必须得到：

- 实际各阶段时间；
- 冷启动 / 预热 / 稳态差异；
- 真正设备放置；
- 模型装载、卸载、缓存、预取、编译、显存、内存行为；
- 真实故障和依赖；
- 与纸面推算不一致的地方。

默认目标是在约 10 分钟级工程时间内获得足以校准方向的数据；如果任务本身更长，则缩成机制一致的最小任务合同。

### 2.4 T_MACHINE_STAR_REAL（真实态现实极限区间）

用：

```text
T_PHY
+ 静态事实
+ MRE真实运行数据
+ 历史经验先验
+ 已知成熟方案能力
```

重新计算：

```text
T_MACHINE_STAR_REAL（真实态本机稳定理论极限区间）
```

必须记录哪些初始假设被真实运行修正。

---

## 3. 第二步前半：先吸收成熟方案

执行 `MATURE_FRONTIER_SCAN（成熟前沿扫描）`：

1. 官方稳定方案和官方性能提交；
2. 同硬件 / 同模型 / 同任务的真实成熟方案；
3. 已反复验证的成熟开源工作流、量化、缓存、预取、编译、内存管理和模型格式；
4. 本机历史已经验证成功的经验包。

把它们与 MRE 真实数据对齐，只保留真正作用于当前瓶颈、兼容当前合同的方案。

成熟方案不是最终答案，而是虚拟运行的第一批现成模块。

---

## 4. 第二步核心：VIRTUAL MATURE PATH（虚拟成熟路径）

### 4.1 定义

`VIRTUAL_MATURE_PATH（虚拟成熟路径）` 不是单个候选的纸面估算。

它必须在真正修改机器之前，基于真实运行数据，把：

```text
当前真实状态
→ 成熟方案收益收割
→ 剩余最大Gap攻击
→ 后续次大Gap攻击
→ ……
→ 99
```

整条路径先完整推演出来。

最终形成一份可执行的“虚拟99路线图”。

### 4.2 每一步必须包含

对每一个步骤 i，必须写清：

```text
STEP_i（步骤）
CURRENT_STATE（当前状态）
TARGET_BLOCK（攻击时间块）
MECHANISM（采用机制）
SOURCE（成熟来源 / 真实数据依据）
EXPECTED_REMOVABLE_TIME（预计可消灭时间）
NEW_OVERHEAD（新增开销）
PROJECTED_RESULT（预计新结果）
QUALITY/STABILITY RISK（质量/稳定风险）
ROLLBACK（回滚）
VERIFICATION（Codex验证方式）
```

并按顺序递推：

```text
PROJECTED_STATE_i
→ 成为 STEP_(i+1) 的 CURRENT_STATE
```

禁止把多个收益简单相加而忽略重叠、相互作用和新开销。

### 4.3 虚拟路径必须先到99

在进入长时间实际执行前，推理层应先回答：

- 按当前真实数据，最短成熟路线是什么；
- 哪些成熟方案先吃；
- 成熟方案吃完后还剩哪些 Gap；
- 剩余 Gap 用什么数据支持的定向方法处理；
- 每一步预计做到什么时间；
- 哪一步可能失败；
- 失败后的替代路径是什么；
- 最终怎样进入 `T_MACHINE_STAR_REAL` 或经济性99区间。

也就是说：

```text
先形成虚拟99方案
再实际执行
```

而不是一边执行一边自由探索。

---

## 5. Codex 的职责：验证，不负责发明路线

当 `VIRTUAL_MATURE_PATH` 已形成后，Codex 主要负责：

- 精确部署；
- 运行指定测试；
- 采集指定数据；
- QC；
- 验证预计时间；
- KEEP / ROLLBACK；
- 保存证据；
- Git 收口。

正常情况下，每一个实际步骤都应是“小而明确的验证任务”。

如果实测偏离虚拟路径：

```text
ACTUAL_RESULT（实测结果）
!= PROJECTED_RESULT（预计结果）
```

则：

```text
停止自由延伸
→ 回到高质量推理层
→ 用新数据重算剩余虚拟路径
→ 再继续执行
```

禁止让 Codex 在本机自行连续探索出 V1…Vn。

## 6. PORTFOLIO ROI（组合收益停止）

### 6.1 不能按单个点判断停止

停止条件不能只问：

```text
“这个点还能不能省0.5秒？”
```

也不能逐个点孤立判断。

因为剩余优化通常是一个组合：

```text
S = {优化点1, 优化点2, …, 优化点n}
```

真正要比较的是这整个剩余组合的长期价值。

### 6.2 先在虚拟路径中计算剩余组合

对仍值得考虑的全部优化点，按真实依赖顺序推演，得到：

```text
T_CURRENT（当前一次运行时间）
T_PROJECTED_FINAL（剩余优化全部完成后的预计一次运行时间）

DELTA_T_PORTFOLIO
= T_CURRENT - T_PROJECTED_FINAL
```

这里的 `DELTA_T_PORTFOLIO（组合单次总节省）` 必须来自顺序推演后的最终差值，禁止把各点理论收益直接相加造成重复计算。

### 6.3 计算生命周期总收益

```text
EXPECTED_LIFETIME_BENEFIT_PORTFOLIO
≈ DELTA_T_PORTFOLIO
× EXPECTED_FUTURE_RUNS（预计未来运行次数）
× VALUE_FACTOR（时间/资源价值系数）
+ 其他可量化资源收益
```

### 6.4 计算整个剩余组合的总成本

```text
PORTFOLIO_COST
= Σ工程实施成本
+ Σ验证成本
+ Σ风险成本
+ 方案之间的集成/交互成本
+ 必要维护成本
```

### 6.5 继续深化的条件

```text
EXPECTED_LIFETIME_BENEFIT_PORTFOLIO
> PORTFOLIO_COST
```

则继续把剩余优化组合纳入虚拟99路径并执行。

否则：

```text
PORTFOLIO_ECONOMIC_STOP=YES（组合经济性停止）
```

### 6.6 为什么小收益仍可能值得

即使剩余每个点单独只节省：

```text
0.1秒 / 0.2秒 / 0.5秒
```

只要未来是基础能力，会执行几千、几万次，那么组合后的长期总收益可能远高于今天的一次性优化成本。

因此不能因为“单个点看起来小”就提前停止。

反之，如果未来只运行很少次数，即使某个点能省1秒，也可能不值得。

---

## 7. 99 的最终含义

99 不是要求数学绝对物理极限，也不是看到单个小Gap就停止。

99 要求：

1. `T_PHY（物理极限）` 已计算；
2. MRE 极简真实运行完成；
3. `T_MACHINE_STAR_REAL（真实态现实极限区间）` 已校准；
4. 成熟方案已系统吸收并进入虚拟路径；
5. `VIRTUAL_MATURE_PATH（虚拟成熟路径）` 已完整推演到99；
6. 实际执行按成熟路径验证，没有无边界自由探索；
7. 实测偏离时已回到推理层重新规划；
8. 剩余全部优化点按 `PORTFOLIO ROI（组合收益）` 计算；
9. 要么剩余高收益已吃完，要么 `PORTFOLIO_ECONOMIC_STOP=YES`；
10. correctness / quality / stability / safety 全部通过；
11. 最终认证与共同事实源收口通过。

一句话：

> **先算第一性原理物理极限，再用一次极简真实运行校准现实极限；把世界成熟方案作为现成模块吸收进来，在真实数据上先把从当前状态到99的整条虚拟成熟路径完整跑通；Codex随后只做短而明确的验证。是否继续深化，不看单个小点，而看剩余全部优化组合在未来大规模运行中的总生命周期收益是否大于整个优化组合的总成本。**
