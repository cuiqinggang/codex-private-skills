# 视频情报源策略

## 核心定位

视频平台是一等信息源，不是文字来源的附属。尤其当用户确认抖音是主要信息入口时，系统进化必须把抖音关注流、公开视频搜索、YouTube、TikTok、Bilibili、快手、视频号、小红书、西瓜视频、Vimeo 和技术演讲纳入来源池。

## 来源分层

1. 低风险公开视频源：YouTube 公开搜索、频道 RSS/watchlist、Bilibili 公开视频、Vimeo、会议技术演讲。
2. 高噪声趋势源：抖音公开视频搜索、TikTok、快手、小红书、西瓜视频。
3. 用户账号只读源：抖音关注流和其他已登录关注流；用户已把视频情报纳入任务后，视为任务级授权，可直接只读采集，不逐条等待批准。

## 账号安全边界

- 可以只读：浏览关注流、公开作者页、公开视频标题、公开互动量、截图、字幕/语音转写。
- 不自动做：点赞、关注、评论、私信、收藏、发布、修改资料、绕过验证码、批量刷接口。
- 默认两小时任务自动处理公开视频/RSS；账号关注流在任务级授权下可直接只读浏览和留证据。
- 只有账号写操作、长期后台刷流、绕过平台限制、验证码/安全提示、付费墙或隐私内容需要停止。

## 入选标准

- 对应用户系统模块：Hermes、Codex、Open WebUI、本地模型、浏览器自动化、AI 视频、低成本工具链、长编程流程。
- 至少记录两类公开信号：作者、链接、发布时间、点赞、评论、收藏、转发。
- 必须保存证据：截图、链接、字幕/转写、摘要、采集时间。
- 必须二次核实：官方文档、GitHub、release、公开视频案例、评论区实测反馈至少命中一项。
- 能转成 Codex/Hermes 验证任务、skill、脚本、流程或昨日重现案例。
