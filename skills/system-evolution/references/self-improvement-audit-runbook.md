# Periodic Self Improvement Audit Runbook

Purpose: every two weeks by default, turn repeated
Codex/Hermes/OpenClaw/ComfyUI/ECC/AI company work into reusable assets.

Scope:

- Read recent output reports, session index, memory registry, relevant skills,
  and known H-drive skill indexes.
- Do not read keys, tokens, cookies, account passwords, or secret file bodies.
- Do not scan all of `H:\AI\skills`; use known relevant directories and index
  files only.
- Do not change production services, start services, stop services, or edit live
  gateway configuration.
- Prefer extending existing skills over creating broad duplicate skills.

Recommended cadence:

- Default: every two weeks.
- Manual extra run: after an unusually dense sprint across several systems.
- Weekly: only during a short high-change period.
- Monthly: acceptable when the system is stable and little new work happened.
- Never hourly or daily by default; repeated work needs time to emerge.

Periodic workflow:

1. Collect evidence.
2. Identify repeated workflows.
3. Build candidate list with evidence paths.
4. Classify candidates as now / later / skip.
5. Write minimal change proposals.
6. Run only low-risk report generation automatically.
7. Leave production changes and broad skill writes for user confirmation.

Prompt improvement slot:

- If a better public self-improvement audit prompt or skill-packaging prompt is
  discovered, record the source URL, date, and exact reason it improves this
  workflow.
- Do not replace the local prompt just because it is popular. It must improve
  evidence quality, candidate scoring, verification, or rollback clarity.
- Keep the original monthly audit function: find repeated work, summarize it,
  and turn mature paths into reusable assets.
