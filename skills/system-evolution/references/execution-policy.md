# 系统进化执行策略

## 初始阶段

默认 `Approval` 模式。24 小时内最多自动生成一次报告、提醒和待执行方案，但不修改生产系统。

## 自动阶段

用户明确授权后可改为 `Auto` 模式。`Auto` 仍只允许：

- 生成报告和日志。
- 更新 output 目录内状态。
- 同步 `H:\AI_System_Evolution` 下的副本。
- 生成 Codex/Hermes 验证任务。
- 执行不会修改生产配置的本地验证脚本。
- 处理公开视频/RSS 视频来源。
- 在用户已明确下达视频情报任务后，只读浏览已登录视频账号的关注流并保存证据。

## 视频来源任务级授权

用户已经明确要求把抖音、YouTube、TikTok、Bilibili 等视频来源纳入系统进化后，视为任务级授权。只读浏览、截图、记录标题/作者/链接/公开热度、字幕转写和摘要不需要逐条等待批准。

停止条件：

- 点赞、关注、评论、私信、收藏、发布或修改账号。
- 绕过验证码、账号安全提示或平台限制。
- 长期后台刷流。
- 付费墙、隐私内容或非公开内容。

## 永远需要批准

- 修改 Hermes 主配置。
- 修改 Codex 全局 AGENTS.md。
- 修改 Open WebUI 配置。
- 安装长期服务。
- 创建或修改非本 skill 的 Windows 定时任务。
- 改动 H 盘正式 skill。
- 使用付费 API、账号密钥、Cookie 或 Token。

## Business Intelligence Execution Boundary

当 system-evolution 处理聚合分发网站商业情报增强系统任务时，默认按 Level 1 执行。允许读取公开信息、整理本地报告、生成验证任务、更新本 skill 文档和草案。

必须升级为 Level 3 并停止的情况：需要登录账号；需要读取或写入 Cookie、Token、API Key；需要调用付费 API 或产生费用；需要真实购买、注册、发帖、私信、下单；需要绕过平台限制；需要修改生产配置；需要创建非 system-evolution skill 的长期后台服务；需要修改 Windows 计划任务；需要对真实客户、供应商或平台执行写操作。

商业情报输出最低要求：不只贴链接；必须区分低买线索、高卖线索、成熟案例、风险坑点、验证任务；每条关键判断必须说明证据来源或待验证状态；不得把未经验证的信息写成确定结论；能转化为小验证任务的，必须给出最小验证任务；能沉淀成 skill 的，必须给出 skill 更新草案。
