# 视频多角色方法与本版四类责任的关系

## 一、证据边界

上传视频展示的是一份多角色团队参考设计。它能证明视频提出了角色配置和协作顺序，不能证明某次任务真实启动了多个智能体、独立上下文或独立工作空间。正式运行仍必须使用系统侧回执。

## 二、保留的责任

| 视频中的责任 | 本版归属 | 中文说明 |
|---|---|---|
| 编排与调度 | 控制角色 | 目标、拆解、路由、汇总和边界 |
| 研究与资料 | 资料角色 | 来源、比较、置信度和资料包 |
| 建造与产出 | 工程执行角色 | 代码、配置、报告、说明和交付产物 |
| 质量复核 | 独立审计角色 | 事实复核、现实测试和交付安全检查 |
| 人工关口 | 用户或指定负责人 | 高风险或不可逆动作授权，不计入智能体数量 |

视频中的具体职位名称不进入ECC固定角色。正式机器角色始终只有控制、资料、工程执行、独立审计四类；同一类可以按独立工作包增加多个真实智能体。

## 三、吸收的方法

- 资料断言分为已核实、估计值和推测；推测不得进入正式结论。
- 审计先独立复核关键事实，再检查格式、依赖、元数据、密钥、内部路径、临时材料、附件和失效引用。
- 上游错误使用定向驳回包，只返修失败范围，不全量重跑已接受内容。
- 跨智能体消息包含工作包、输入版本、产物校验值、已通过项、拒绝项、目标层和主控接收决定。

## 四、不吸收的内容

- 不把角色说明当成真实智能体回执；
- 不把视频中的职位数定为固定智能体数量；
- 不建立第五类正式角色；
- 不把共享资料目录当成独立上下文；
- 不让人工在每个可逆技术步骤都成为等待点。
