# 来源吸收与取舍记录

## 目的

说明上传的阶段验收闭环技能如何进入ECC十二层，以及哪些内容因风险、重复或环境变化没有直接吸收。

## 一、直接吸收

| 来源能力 | 新版位置 | 理由 |
|---|---|---|
| 每个阶段先定义目标和关键验收标准 | 第4层和阶段闭环 | 防止先执行后补标准 |
| 先产生完整第一版 | 第6层 | 形成可检查对象 |
| 列出失败和不确定项目 | 第8、9层 | 不只写优点 |
| 优先修失败或高风险项目 | 第10层 | 避免无关改动 |
| 修复后重新检查 | 第8、9、10层 | 防止修完不复验 |
| 同一阶段默认最多三轮 | 第10层 | 防无限循环和模型用量黑洞 |
| 三轮仍失败则阻塞 | 第10、12层 | 诚实停止 |
| 每轮记录变化、原因和决定 | 第10、11层 | 支持恢复和审计 |
| 通过、部分完成、阻塞 | 第9、12层 | 防止二元假通过 |
| 可观察目标、执行、验证、决定 | 第4、6、8、9层 | 形成成熟闭环 |
| 继续、停止、回滚、人工审查 | 第10层 | 增加真实决策 |
| 相同失败不能重复相同假设 | 第10层 | 防无效重试 |
| 现实信号优先于模型自评 | 第8、9层 | 提高可信度 |

## 二、改造后吸收

### 自查

原技能由同一执行者自查。新版保留自查作为提交前预检，但正式接受权交给独立审计角色；可用脚本或现实证据时，模型自评不能单独支持通过。

### 三轮上限

原技能固定三轮。新版保留默认三轮，但允许用户在看到成本、策略变化和剩余价值后明确扩大预算。没有新策略的重复不算有效轮次。

### 评分八分

原提示词示例使用十分制和八分门槛。新版不把八分作为所有领域的统一硬门：

- 主观设计可以使用评分，但必须说明标准和人工关口；
- 可执行产物优先使用测试、字段、勾稽和明确布尔条件；
- 关键项不能靠平均分掩盖。

### 可复用经验沉淀

原技能建议未来运行发现经验后直接加入技能。新版改为：先保存“候选经验”，经过技能治理、对比测试和明确授权后再修改技能，防止技能在运行中自行膨胀或写入错误经验。

## 三、不直接吸收

### 逻辑隔离作为多智能体替代

不吸收。正式长任务必须有真实子智能体和运行系统回执；逻辑隔离只能组织资料。

### H盘同步和旧路径

不吸收为当前路线。当前用户环境以C盘为权威源，H盘仅历史，K盘仅在用户明确同意时备份。来源案例中的旧路径只说明历史，不参与运行。

### 自动覆盖目标技能

不吸收。新版建立独立候选技能，不覆盖原ECC或上传闭环技能；修改正式技能必须经过单项证据和授权。

### 每个任务都用同一种循环模板

不吸收。简单任务不应触发本长任务技能；长任务按领域适配器选择验证器和证据。

### 只靠文件存在验收

不吸收。文件存在只证明结构，不证明行为和效果；新版增加字段、关系、真实回执、错误案例和独立审计。

## 四、原ECC规则的保留

保留：

- 十二层原名、原序和权责；
- 四阶段跨工具协作；
- 第6层执行声明与第9层接受分离；
- 第10层返修所有拒绝项目；
- 第11层交接和恢复；
- 第12层最终验收权；
- 生产时间预算与耐力验证区分；
- 真实检查点和诚实恢复；
- 中文可审计输出；
- C盘权威源。

修正：

- 删除正式模式的逻辑隔离放行口；
- 删除生产任务最低固定时长；
- 增加异常提前完成复核；
- 增加四角色真实多智能体；
- 增加技能实际使用前置关口；
- 把后期失败补丁贯通到十二层和验证脚本；
- 统一检查点计算；
- 区分候选验收资料和独立最终签署。

## 五、仍需真实运行验证

新版结构通过不等于比原版更有效。正式替换前应比较：

- 首次通过率；
- 返修轮次；
- 实际总用时；
- 模型和工具成本；
- 错误放行数量；
- 子智能体写入冲突；
- 技能使用漏检；
- 检查点恢复；
- 人工干预次数。

未经过真实对比前，本版是候选新版本，不应覆盖原版入口。

## 六、原ECC完整资料包二次回查后的补回项

二次回查103个原资料文件后，补回：

- 十二层固定中文名和逐层固定字段；
- 十二层均不可跳过及本任务具体应用；
- 执行声明、产物清单、脚本结果、声明验收矩阵、返修记录、压缩交接、证据索引和最终报告；
- `final-acceptance.md`与`final-acceptance.json`双份最终验收；
- 已声明要求和完成台账100%映射；
- 成熟组件优先及自研理由；
- ECC 2.0按需触发、工具清单、工作区和密钥脱敏；
- 耐力任务原始时间、持续驱动、中断恢复、晚检查点和最终检查点；
- 模型和工具路线漂移、动作级检查点、未跟踪产物和中文状态证据。

没有恢复原资料中已经被后续事实否定的两项：生产任务固定最低时长；逻辑隔离作为正式多智能体替代。

## 七、视频多角色方法的吸收边界

视频可确认的是多种职位配置，不是多个真实并行智能体的运行证明。

吸收：三级置信度、两阶段审计、三层防护、项目归属、定向驳回、标准消息包和人工高风险闸门。

改造：不吸收视频职位名，只保留控制、资料、工程执行、独立审计四类责任；工程任务中的报告和说明仍由工程执行角色交付。

不吸收：固定五个智能体、角色文件冒充回执、单一共享知识库作为唯一实现、单一来源自动支持高风险结论、每个步骤都等待人工。

## 八、从原规定到新版闭环的逻辑链

| 原来正确的规定 | 实际运行后暴露的错误 | 新版如何融合 | 为什么这样改 |
|---|---|---|---|
| 十二层固定、执行与验收分离 | 后续补丁散落在口头要求和附加文件，十二层正文没有同步 | 十二层仍是唯一主轴；每层固定十六项，新增规则必须注明落层 | 保留成熟骨架，同时防止补丁成为平行流程 |
| 第5层使用子智能体隔离上下文 | 实际出现未启动子智能体却声称使用，甚至主动禁止子智能体 | 正式长任务100%真实多智能体；平台回执、父子运行和独立空间形成第5层硬门 | 长任务需要并行、独立审计和可证伪回执；逻辑隔离只能辅助组织资料 |
| 长任务设置时间和检查点 | 固定最低时间导致提前粗糙通过或完成后空等 | 生产任务改为时间预算与异常早完复核；只有耐力验证保留最低时长 | 时间不能代替目标，异常短也不能直接相信 |
| 第10层负责返修 | 一次修复后没有复验，或相同策略无限重复 | 第6层第一版、第8层检查、第9层独立审计、第10层定向返修，再回第8、9层；默认最多三轮 | 形成有边界、能停止、能回到根因层的闭环 |
| 第3层按需加载技能 | 技能只在报告或第12层出现，实际执行没有使用 | 第3层准备、第4层绑包、第5层绑智能体、第6至9层保存和验证运行事件、第10层返修 | 技能的价值在于使用成熟方法，不是最终清单中出现名字 |
| 四阶段组织跨工具工作 | 四阶段可能被误写成另一套主流程 | 四阶段只作为外壳，所有执行和验收仍必须生成十二层实例 | 解决跨阶段协作，但不削弱十二层核心 |
| 固定角色帮助分工 | 视频中的职位简介容易被误认成已运行智能体 | 只保留控制、资料、工程执行、独立审计四类责任，实例数按独立工作包动态扩展 | 区分“角色类别”和“真实运行实例”，避免固定数量或角色文件造假 |
| 领域技能可以补充执行 | 专业技能被误解为十二层之外的附加步骤 | 任何领域技能都在第3层按需加载并贯穿对应工作包，不新增第13层 | 保持领域中立和一个运行主轴 |

这张表是逻辑说明，不是新的执行步骤。正式运行仍只以固定十二层及其十六项结构为核心。
