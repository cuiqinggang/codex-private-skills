# 正式执行命令模板

## 定位

本模板只在资料、技能、工作包和角色计划准备完成后使用。它是启动正式执行的命令，不是资料包，也不能证明任务已经完成。

复制后替换尖括号中的内容。任务涉及英文工具名或字段时，紧接着补一句中文解释。

## 可直接复制的命令

```text
使用 $ecc-four-role-loop-orchestration 执行下面的正式长任务。

一、目标和边界
任务目标：<逐项写出可观察目标>。
不做事项：<禁止扩大范围、禁止操作或暂不处理内容>。
正式工作区：<权威工作区>。
影子工作区：<候选和试验工作区>。
正式修改授权：<已授权／只允许准备和影子候选>。
最终验收权：<根主控／用户／指定负责人>。

二、时间规则
任务类型：<真实生产任务／开放式优化任务／耐力验证任务／准备任务>。
预计时间范围或最长预算：<有同类历史时给范围，没有时只给预算>。
真实生产任务不得设置最低耗时；达到目标和所有关口后立即结束，不得等待凑时间。
每次都由独立审计智能体做早完异常判断。实际用时明显低于可靠历史下界时执行专项复核；没有可靠历史数据时，首次运行直接执行完整保守复核。复核通过即可接受效率收益，复核不通过则返修；不得写死比例判失败。
开放式优化必须预先写基线、目标、候选方向、连续无收益轮数、风险上限、最长窗口和独立停止审计者。
只有明确测试持续运行能力的耐力验证任务，才填写最低耐力时间和检查点间隔。

三、真实多智能体硬门
必须在系统能力允许范围内使用真实多智能体，禁止以逻辑隔离、角色文档或主控自述代替。
默认建立四个独立上下文：
1. 控制角色：目标、拆解、调度、状态和返修路由；
2. 资料角色：来源、项目记忆、必需技能和资料包；
3. 工程执行角色：生成第一版或修复版，只提交执行声明；
4. 独立审计角色：只读或隔离复验，独立接受或拒绝。

正式长任务默认四类角色各有真实独立上下文。复杂任务按独立工作包和可测收益增加更多资料、工程执行或审计智能体，不设形式化固定上限。每个智能体必须有唯一编号、独立上下文、独立工作空间、有边界责任、启动回执、回传回执和实际贡献证据。

如果系统当前不能启动真实子智能体，不得降级为单智能体正式通过；可以保存准备成果，但正式状态必须为“真实多智能体关口阻塞”。

四、技能和资料关口
必需技能：<列出名称、路径、版本或校验值>。
每个工作包开始前，先确认对应技能已读取、依赖可用并绑定到真实智能体。
技能名称写进计划不等于已经使用；第6至9层必须保存读取、调用、产物符合性和独立审计证据。任何必需技能未准备或未实际使用时，立即阻断当前工作包，返回第3、5或6层修复，不得拖到最终验收。

五、十二层和工作包
严格保留下列十二层名称、顺序和责任：
1. Control Plane / Orchestrator（主控调度层）；
2. Short Entry / Memory（短入口 / 项目记忆层）；
3. Skills / Progressive Disclosure（技能按需加载 / 渐进加载层）；
4. Planning / Work Decomposition（任务拆解层）；
5. Subagents / Context Isolation（子智能体 / 上下文隔离层）；
6. Execution Plane（执行平面）；
7. Hooks / Lifecycle Triggers（生命周期钩子层）；
8. Scripts / Deterministic Checks（脚本确定性检查层）；
9. Verification Plane（独立验证平面）；
10. Repair Loop（返修循环层）；
11. Compact / Handoff（压缩交接层）；
12. Final Acceptance（最终验收层）。

一项任务只建立一套任务级十二层，不为每个工作包复制。完整中文十六项以`twelve-layer-standard.md`为权威：标准证据模式保存标准校验值，并逐层记录本次输入、动作、产物、证据、状态和下一关口；严格审计模式才逐层展开全部十六项。十二层均不允许跳过。

为每个工作包写明目标、输入、依赖、必需技能、执行智能体、审计智能体、允许范围、禁止范围、第一版产物、关键验收标准、验证器、错误案例、返修目标层、回滚方式和停止条件。没有验收标准、验证器、独立审计或失败返回的工作包不得执行。

六、逐工作包返修闭环
每个工作包执行：明确目标和验收标准 → 第一版 → 确定性检查 → 独立审计 → 缺陷和不确定项 → 定向修复 → 重新检查 → 独立复审。
第0轮是第一版，默认最多三轮返修。连续失败必须改变假设、策略或拆包；重复同一失败和同一方案不得继续。达到上限仍有关键失败时，停止该工作包并标记阻塞；不受影响的独立工作包可以继续。

七、并行和写入安全
采用有依赖关系的流水并行：资料准备下一批，执行处理已通过资料关口的当前批，审计验证上一批，主控负责冻结依赖和路由返修。
同一正式对象只能有一个写入所有者；执行智能体使用隔离工作区，资料和审计智能体默认只读正式对象。出现共享写入冲突、未分配文件或合并冲突时，返回第4或5层重新拆包，不得静默覆盖。

八、验收和证据
证据模式：<标准／严格>。一般可逆工程任务默认标准七文件；完整法证审计、不可逆部署、高风险发布、多系统迁移、技能治理、证据争议或耐力验证使用严格模式。
每个检查点必须有新增事实、产物、测试、审计或返修决定，禁止空心跳和只报耗时。
第6层只能提交执行声明；第8层脚本通过不等于最终通过；第9层由独立审计接受或拒绝；所有拒绝进入第10层；第12层只能汇总前面已经通过的关口。
最终输出必须逐项对齐原目标，列出已完成、未完成、拒绝、阻塞、技能使用、多智能体回执、验证、返修轮次、恢复入口和中文最终状态。不得把准备包、候选文件、目录存在或部分结果写成正式任务已通过。
```

## 下发前检查

只有以下项目均已准备，才能把上面的命令交给执行环境：

- 当前目标和不做事项；
- 权威来源与历史反例；
- 必需技能及使用合同；
- 工作包、依赖和文件所有权；
- 真实多智能体角色计划；
- 确定性验证器和错误案例；
- 返修、停止、回滚和人工关口；
- 时间类型、预算和异常早完规则；
- 证据目录和最终验收人。

缺一项时返回对应前层补齐，不用一句“执行十二层”代替完整准备。
