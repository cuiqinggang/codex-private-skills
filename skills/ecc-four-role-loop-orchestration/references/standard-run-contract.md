# 标准生产模式七文件证据合同

## 一、适用范围

标准模式用于一般可逆的工程长任务。它完整运行固定十二层，但把固定规范与本次事实分开：十六项固定规则由`twelve-layer-standard.md`的版本和校验值继承；运行包只记录每层本次发生了什么。

以下情形改用严格模式：完整法证审计、不可逆部署、高风险外部发布、多系统迁移、修改ECC本身、批量改变全局技能或自动触发规则、证据争议、历史造假复现或耐力验证。普通单技能可逆修改仍使用本标准模式。

## 二、七个必需文件

| 文件 | 中文作用 |
|---|---|
| `run-config.json` | 目标、任务类型、时间预算、十二层标准版本、角色和技能总配置 |
| `run-ledger.json` | 用户要求、十二层动态状态、真实智能体和工作包 |
| `runtime-evidence.json` | 系统运行事件、技能事件和产物清单 |
| `verification.json` | 执行声明、成功与错误检查、独立审计、返修和交付安全 |
| `checkpoints.json` | 阶段、重要返修、中断恢复和最终检查点 |
| `final-acceptance.json` | 机器可读最终状态、异常早完复核和恢复入口 |
| `final-report.md` | 面向用户的中文结果和证据摘要 |

七个是固定合同文件。实际用到技能或命令时，另保存小型只读附件：技能入口副本、检查原始输出、平台原始回执或任务产物副本；附件不展开成新的流程文档。没有外部来源、返修或跨会话恢复时，不制造空文件。

## 三、十二层运行记录

`run-ledger.json`中的`layers`必须恰好十二项，固定层名、中文名和顺序完全一致。每项记录：

```yaml
layer_number: 层号
english_name: 固定英文名
chinese_name: 固定中文名
status: PASS | PARTIAL | BLOCKED | REJECTED
skippable: false
actual_inputs: 本次真实输入
actual_actions: 本次真实动作
new_artifacts: 本次新增或确认的产物
evidence_ids: 可追踪证据编号
next_gate_or_failure_return: 下一关口或失败返回层
```

这不是十六项摘要。`run-config.json`必须保存完整标准文件的版本和真实校验值，审计者可据此恢复每层十六项固定要求；动态记录只避免重复抄写永久规范。

## 四、真实多智能体证据

`run-ledger.json`中的每个智能体记录唯一编号、父级、四类角色之一、独立上下文、独立空间、平台运行编号、真实起止时间、工作边界和证据编号。

`runtime-evidence.json`必须存在对应的系统启动和回传事件。允许来源只有系统追踪、运行接口或平台事件日志；事件必须带唯一平台回执编号和运行导出标记。最终验收还必须保存独立审计角色的平台侧回读方法和证据编号。

验证器只能检查字段和交叉一致性，不能认证平台签名；它只返回“结构检查通过”，不能单独把真实多智能体判为最终通过。第9层必须与平台界面、运行接口或受信事件日志核对。

正式通过必须同时存在控制、资料、工程执行和独立审计四类真实上下文。角色文件、自填编号和逻辑隔离都不能替代系统事件。

## 五、工作包、技能和闭环

- 每项用户要求至少进入一个工作包；每个工作包有不同的工程执行者和独立审计者。
- 总配置中的每个必需技能必须下沉到至少一个工作包。有必需技能时，读取和使用事件必须记录真实路径、证据目录内入口副本、真实校验值、平台运行编号和唯一回执；只写技能名或`used=true`无效。
- 每个工作包至少有第0轮、执行声明、真实产物、成功案例、错误案例和独立审计决定。
- 最终通过时成功和错误案例都必须真实执行并按预期通过；每个检查绑定平台运行事件、命令或方法、退出码、原始结果附件及校验值。“未运行”或检查本身失败不能冒充错误案例。
- 任务本体产物必须绑定工程执行者的产物创建事件、工作包、平台运行编号、真实副本和校验值；控制台账和证据文件不能默认冒充任务本体。
- 第1轮起必须改变策略；最后一轮决定与工作包状态一致。
- 没有发生返修时只保留第0轮，不制造“假返修”。

## 六、时间与最终状态

普通生产任务不得设置最低耗时。每次生产或开放式优化运行都必须包含独立审计者填写的早完异常判断。低于可靠历史下界时必须专项复核；没有可靠历史数据时，首次运行也执行完整保守复核。复核通过后立即接受，不等待补时间。

开放式优化还必须在第4层预先保存优化停止合同：基线指标、目标指标、初始候选、连续无收益轮数、成本或风险上限、最长窗口和独立停止决定。

标准模式不用于耐力验证。耐力任务必须改用严格模式。

最终状态只有`PASS`（通过）、`PARTIAL`（部分完成）、`BLOCKED`（阻塞）、`REJECTED`（拒绝），并在同处写中文解释。

## 七、确定性验证

```bash
python3 scripts/validate_standard_evidence.py <证据目录>
```

脚本通过只表示结构、交叉引用和可确定硬门成立，不替代独立审计和人工高风险关口。
