# 十二层完整新版标准

**规范版本：V2.0.0（第2版，2026-07-19）**

本版本号必须与`SKILL.md`首页的技能包版本一致。标准运行证据还必须记录本文件的真实校验值，用“版本号判断先后、校验值确认内容完全一致”。

## 一、不可改写规则

十二层不是普通十二步，也不是只列标题的说明书。英文名、固定中文名、顺序和层间权责必须逐字保留：

1. `Control Plane / Orchestrator`（主控调度层）
2. `Short Entry / Memory`（短入口 / 项目记忆层）
3. `Skills / Progressive Disclosure`（技能按需加载 / 渐进加载层）
4. `Planning / Work Decomposition`（任务拆解层）
5. `Subagents / Context Isolation`（子智能体 / 上下文隔离层）
6. `Execution Plane`（执行平面）
7. `Hooks / Lifecycle Triggers`（生命周期钩子层）
8. `Scripts / Deterministic Checks`（脚本确定性检查层）
9. `Verification Plane`（独立验证平面）
10. `Repair Loop`（返修循环层）
11. `Compact / Handoff`（压缩交接层）
12. `Final Acceptance`（最终验收层）

每次运行必须生成一套任务级十二层实例，不能只写“十二层完整”，也不能为每个工作包复制整套十二层。每层完整规范包含：本层定位、目的、输入、动作、产物、文件要求、内容要求、禁止事项、时间门槛关联、多智能体要求、验证方法、失败返回、证据路径、连接下一层条件、本任务具体应用、是否允许跳过。十二层均不允许跳过；某层无返修动作时也要写明“不适用的理由和证据”。

标准证据模式用本文件版本和校验值继承固定规范，只记录本次状态、输入、实际动作、新增产物、证据和下一关口；严格审计模式逐层展开十六项运行实例。下面出现的逻辑文件名在标准模式可作为合并证据文件中的同名字段，在严格模式才要求独立文件。两种模式都不能删除层、改名、调序或放松关口。

## 二、十二层逐层标准

### 第1层：`Control Plane / Orchestrator`（主控调度层）

一、本层定位：定义任务的控制面，不执行任务本体。

二、本层目的：锁定目标、项目归属、范围、权限、角色、时间类型、停止条件和最终验收权。

三、本层输入：用户要求、权威源、当前项目、历史反例、系统能力和安全边界。

四、本层动作：建立已声明要求台账；声明生产、耐力或准备任务；选择操作类型和规模；规定四角色、动态扩展、工作区、人工关口、时间预算和异常早完阈值。

五、本层产物：运行配置、项目归属记录、已声明要求、禁止事项、角色计划、验收合同。

六、本层文件要求：`run-config.json`、`declared-requirements.json`和第1层实例记录。

七、本层内容要求：每项用户强制要求都有唯一编号、验收标准和关键性；模型、工具、执行环境及允许回退路线明确；普通任务按需声明ECC 2.0触发项。

八、本层禁止事项：目标不清就执行；把准备任务写成正式执行；用“长任务”名称自动强制最低时长；未经授权安装ECC、复制配置、启用工具或执行不可逆动作。

九、本层时间门槛关联：生产任务使用预算和异常参照；耐力任务才使用最低时间；异常早完只触发复核，不触发等待。

十、本层多智能体 / 上下文隔离要求：正式长任务必须真实多智能体；默认控制、资料、执行、审计四角色；系统不支持时正式关口阻塞。

十一、本层验证方法：检查目标覆盖、项目归属、任务类型、权限、角色、工具路线、时间策略和最终签署者。

十二、失败返回：目标、权限、安全、项目归属或时间类型不清时留在第1层；运行中发生范围或授权变化时返回第1层。

十三、证据路径：运行配置、用户授权、要求台账、项目归属和角色计划的索引。

十四、连接到下一层的条件：所有关键要求、边界和验收权已冻结。

十五、本任务中的具体应用：逐项写当前任务的目标、禁止事项、权威工作区和完成定义，不能照抄通用说明。

十六、是否允许跳过：否。

### 第2层：`Short Entry / Memory`（短入口 / 项目记忆层）

一、本层定位：建立当前项目记忆和可信短入口，隔离旧任务污染。

二、本层目的：让后续角色只使用属于当前项目、当前时间和当前目标的资料。

三、本层输入：项目入口、权威源、历史记录、失败清单和信息路由规则。

四、本层动作：把材料分为已核实、估计值、推测、历史反例和禁止复用；记录信息类别、存放位置、保留期限、写入者和验收者。

五、本层产物：可信来源索引、置信度登记、历史反例索引、禁止复用索引和上下文预算记录。

六、本层文件要求：`source-confidence-register.json`、来源索引和第2层实例记录。

七、本层内容要求：已核实必须有来源；估计值必须标注不确定性和下游限制；推测不得进入正式结论；高风险断言按风险多源交叉验证。

八、本层禁止事项：混入其他项目记忆；伪造缺失历史；把旧通过报告当成当前证据；把H盘历史或K盘备份当成当前权威源。

九、本层时间门槛关联：保存真实来源时间和上下文恢复时间，不重置原始开始时间。

十、本层多智能体 / 上下文隔离要求：资料角色在独立上下文准备材料；控制角色只接受带来源、置信度和下游限制的资料包。

十一、本层验证方法：抽查来源、日期、项目归属、置信度和禁止复用项；检查正式产物是否使用了未获准的估计或推测。

十二、失败返回：来源污染、项目归属错误、置信度缺失或历史误用时返回第2层。

十三、证据路径：来源登记、校验值、资料角色回执和主控接收记录。

十四、连接到下一层的条件：当前事实、估计、推测和历史边界可审计。

十五、本任务中的具体应用：写明本任务读取哪些入口、跳过哪些历史报告以及原因。

十六、是否允许跳过：否。

### 第3层：`Skills / Progressive Disclosure`（技能按需加载 / 渐进加载层）

一、本层定位：选择和准备技能、成熟组件、工具、模型及领域规则。

二、本层目的：优先复用成熟方法，避免写了技能名称却没有真实使用，或无理由从零自研。

三、本层输入：可信来源、任务类型、本地技能、成熟组件、工具清单和外部搜索能力。

四、本层动作：读取技能入口及其明确必读资料；记录名称、路径、版本、依赖和适用工作包；比较直接采用、小幅适配、轻量试用、只作参考和从零自研；建立工具与模型路由清单。

五、本层产物：技能准备清单、成熟组件路线比较、工具清单、模型路由、冲突解决表和ECC 2.0按需触发清单。

六、本层文件要求：`tool-inventory.json`、技能绑定表、成熟组件比较和第3层实例记录。

七、本层内容要求：外部搜索未完成只能写“未完成”，不能写“没有找到”；选择自研必须写具体原因；任何领域技能都只按当前工作包需要加载，不全量灌入上下文，也不优待某个行业。

八、本层禁止事项：技能未读就声称使用；自动安装插件或ECC；复制全局配置；记录密钥值；工具或模型未经授权静默回退。

九、本层时间门槛关联：技能准备计入真实工作，不以长时间阅读无关历史凑时长。

十、本层多智能体 / 上下文隔离要求：技能必须绑定到真实智能体和工作包；新增智能体同时声明允许工具、禁止工具和成本。

十一、本层验证方法：检查技能读取证据、依赖可用性、成熟组件路线、模型实际路线、工具调用和密钥脱敏。

十二、失败返回：技能缺失、选错、冲突、依赖不可用、路线漂移或成熟组件比较缺失时返回第3层。

十三、证据路径：技能路径与校验值、工具清单、搜索状态、路线决定和调用证据。

十四、连接到下一层的条件：每个工作包都有可用技能、工具和路线决定。

十五、本任务中的具体应用：写明当前实际选了哪些技能、放弃哪些组件以及理由。

十六、是否允许跳过：否。

### 第4层：`Planning / Work Decomposition`（任务拆解层）

一、本层定位：把目标拆成可并行、可验证、可回退的工作包。

二、本层目的：形成依赖清晰、写入不冲突、失败可局部返修的执行结构。

三、本层输入：前三层产物、操作类型、规模、技能绑定、时间和角色能力。

四、本层动作：为每个工作包定义目标、输入、声明要求、技能、执行者、审计者、产物、验证、正负案例、依赖、写入所有权、返修层、回滚和停止条件。

五、本层产物：工作包清单、依赖图、文件所有权、流水并行计划、检查点、返修路由和人工关口。

六、本层文件要求：`work-packages.json`、依赖与所有权记录和第4层实例记录。

七、本层内容要求：缺陷修复先复现；功能变更记录旧行为和新行为；新增功能先研究复用；重构保持行为；大型任务完整运行十二层。

八、本层禁止事项：无验收标准执行；多个智能体共享写同一对象；没有失败返回；没有错误案例；用等待时间包装工作量。

九、本层时间门槛关联：生产任务按里程碑设检查点；耐力任务按公式设时间检查点；都必须有真实产物或判断变化。

十、本层多智能体 / 上下文隔离要求：一个工作包必须分开执行和审计；增加智能体要有独立工作包、空间、责任和可测收益。

十一、本层验证方法：检查依赖无环、所有权唯一、技能绑定、验收标准、验证器、回滚和停止条件。

十二、失败返回：拆包、依赖、范围、所有权或验收错误时返回第4层。

十三、证据路径：工作包、依赖图、文件范围、角色和技能绑定索引。

十四、连接到下一层的条件：至少有一个真实工作包，且每个包都能独立执行和审计。

十五、本任务中的具体应用：列出当前所有工作包及其执行／审计归属，不用通用示例代替。

十六、是否允许跳过：否。

### 第5层：`Subagents / Context Isolation`（子智能体 / 上下文隔离层）

一、本层定位：真实建立多智能体实例、独立上下文、权限和工作空间。

二、本层目的：让资料、执行和审计互相独立，避免上下文污染、自我验收和写入冲突。

三、本层输入：工作包、技能绑定、工具、模型、来源范围、禁止范围和空间计划。

四、本层动作：启动真实子智能体；记录编号、父子关系、四类角色之一、责任、上下文、空间、分支、工具、技能、起止时间、回执、产物和贡献；按工作包动态扩展。

五、本层产物：角色分派、系统启动与回传回执、独立工作区、标准交接消息包和主控接收台账。

六、本层文件要求：`agents.json`、角色回执、消息包和第5层实例记录。

七、本层内容要求：默认建立控制、资料、工程执行、独立审计四个真实上下文；文章、说明和交接文件由工程执行角色随工作包生成，不另设写作者；并发不足时分波次；每个新增实例记录时间收益、质量收益和合并成本。

八、本层禁止事项：逻辑隔离冒充真实智能体；角色文档冒充运行回执；执行与审计同一实例；无独立空间；复制相同任务制造数量；越权工具调用。

九、本层时间门槛关联：记录真实开始、返回和主控接收时间；禁止补写虚假回执或时间。

十、本层多智能体 / 上下文隔离要求：正式长任务100%使用真实多智能体；默认四类角色各有真实独立上下文，复杂任务可按工作包增加同类实例；系统不可用则正式任务阻塞。

十一、本层验证方法：核对系统回执唯一性、上下文和空间唯一性、父子关系、角色职责、技能、工具、贡献和接收记录。

十二、失败返回：实例、权限、空间、回执、角色或工具错误时返回第5层。

十三、证据路径：系统启动、任务分派、回传、主控接收、工作空间和贡献证据索引。

十四、连接到下一层的条件：真实角色、技能和空间全部成立，执行与审计独立。

十五、本任务中的具体应用：列出当前实际启动的智能体，不把计划中的角色当成已启动。

十六、是否允许跳过：否。

### 第6层：`Execution Plane`（执行平面）

一、本层定位：在授权空间生成任务本体的第一版或修复版，只提交执行声明。

二、本层目的：产生真实代码、文件、模型、报告、配置或影子候选。

三、本层输入：已通过的工作包、资料、技能、工具、角色回执和验收合同。

四、本层动作：复现基线；检查技能已实际读取或调用；产生第一版；记录命令、变更、产物、校验值、风险和回滚点；提交逐条执行声明。

五、本层产物：`execution-claims`（执行声明）、`artifact-manifest`（产物清单）、命令日志、变更清单、技能使用证据和风险清单。

六、本层文件要求：`execution-claims.json`、`artifact-manifest.json`及第6层实例记录。

七、本层内容要求：每个声明映射工作包、产物、要求和技能证据；每个产物有路径、校验值、生产者和状态；上游错误使用定向驳回包，不全量重跑。

八、本层禁止事项：无实际产物；必需技能未用；执行者自称最终通过；修改审计记录；隐藏未跟踪产物；相同失败重复同一方案。

九、本层时间门槛关联：执行时间必须对应动作和产物变化；禁止空等或纯心跳。

十、本层多智能体 / 上下文隔离要求：只有写入所有者修改对应对象；执行声明不得由审计角色代写。

十一、本层验证方法：第8层检查产物和命令，第9层独立接受或拒绝声明。

十二、失败返回：实现错误返回第6层；资料、技能、拆包、空间或授权错误返回对应前层并由第10层登记。

十三、证据路径：差异、命令输出、产物校验值、技能调用和执行声明索引。

十四、连接到下一层的条件：第一版完整、可检查、可回滚，执行声明和产物清单齐全。

十五、本任务中的具体应用：写明本轮真正生成或修改了什么，不用目录存在代替。

十六、是否允许跳过：否。

### 第7层：`Hooks / Lifecycle Triggers`（生命周期钩子层）

一、本层定位：在关键生命周期节点触发刹车和继续许可。

二、本层目的：在错误扩散到其他工作包或最终报告前阻断。

三、本层输入：运行配置、角色状态、工作包、技能门、工具路线、检查点和禁止事项。

四、本层动作：在阶段开始、工具使用前、并行写入前、角色返回、无进展、超时、审计拒绝、交接和最终通过前触发检查。

五、本层产物：触发记录、检查点、冻结／解冻记录、超时与恢复事件和继续许可。

六、本层文件要求：`checkpoints.json`、生命周期事件和第7层实例记录。

七、本层内容要求：每个检查点记录真实时间、层、工作包、动作、产物差异、命令／测试／审计引用；ECC 2.0触发时检查会话快照、工具清单和工作区状态。

八、本层禁止事项：工具失败后继续；连续无产物；伪造时间；重置开始时间；交接前无快照；未经授权模型或工具回退。

九、本层时间门槛关联：生产任务按事件；耐力任务按真实时间和间隔；晚检查点必须记录原因和恢复，不补造整点。

十、本层多智能体 / 上下文隔离要求：角色返回必须有标准消息包；局部失败只冻结依赖分支；控制角色不能吞掉审计拒绝。

十一、本层验证方法：检查时间顺序、动作级证据、产物变化、路由一致、恢复事件和空心跳。

十二、失败返回：按原因返回第1、3、4、5、6、7、8或10层。

十三、证据路径：检查点、事件、命令、差异、角色回执和恢复日志索引。

十四、连接到下一层的条件：当前候选没有未处理的触发项，并获得运行检查许可。

十五、本任务中的具体应用：列出本任务实际触发的事件和处置，不照抄全部钩子。

十六、是否允许跳过：否。

### 第8层：`Scripts / Deterministic Checks`（脚本确定性检查层）

一、本层定位：用可重复脚本和现实信号检查声明和产物。

二、本层目的：把模型自述转成机器可解析或可重现的证据。

三、本层输入：执行声明、产物、验收标准、技能合同、工具路线、回执、时间和检查点。

四、本层动作：运行测试、构建、格式、数据勾稽、截图对比、正负案例、校验值、证据结构、未跟踪产物、密钥脱敏、工作区冲突和目标覆盖检查。

五、本层产物：`script-verification-result`（脚本验证结果）、失败清单、正负信号矩阵和证据完整性结果。

六、本层文件要求：`deterministic-checks.json`和第8层实例记录。

七、本层内容要求：每个检查有命令、预期、观察、退出码、结果和证据；正常速度和异常早完都检查要求覆盖；成熟组件路线和技能使用纳入检查。

八、本层禁止事项：只检查文件存在；脚本失败仍继续；删除错误案例换通过；只看失败不看成功；暴露密钥；自动清理脏或冲突工作区。

九、本层时间门槛关联：生产任务验证预算和异常早完；耐力任务同时验证原始起止时间、持续驱动、检查点、恢复事件和最终检查点。

十、本层多智能体 / 上下文隔离要求：检查真实回执、角色和空间唯一性、执行与审计分离、写入所有权和贡献证据。

十一、本层验证方法：验证脚本自身有合规样本、违规样本和错误案例；脚本通过仍不等于最终通过。

十二、失败返回：检查器错误留在第8层；产物或证据错误进入第10层并返回根因层。

十三、证据路径：命令、退出码、原始输出、结构化结果和检查产物索引。

十四、连接到下一层的条件：关键确定性检查均按预期通过，失败项已明确送审或返修。

十五、本任务中的具体应用：列出本任务实际运行的检查和错误案例。

十六、是否允许跳过：否。

### 第9层：`Verification Plane`（独立验证平面）

一、本层定位：由独立审计角色接受或拒绝每条执行声明。

二、本层目的：防止执行者自查、脚本通过或漂亮报告替代独立验收。

三、本层输入：声明、产物、脚本结果、技能、角色、置信度、原目标和成熟组件路线。

四、本层动作：先进行事实复核子环节，重新抽取关键断言并独立核实；再进行交付安全子环节，检查交付格式、外部依赖、引用附件、元数据、密钥、内部路径和临时材料；逐条接受或拒绝。

五、本层产物：`claim-acceptance-matrix`（声明验收矩阵）、独立审计结果、交付安全检查和定向驳回包。

六、本层文件要求：`claim-acceptance-matrix.json`、`delivery-safety-check.json`和第9层实例记录。

七、本层内容要求：每条声明有审计者、决定、理由、独立证据、事实复核、交付复检和返修目标层；估计值和推测按下游限制处理。

八、本层禁止事项：执行与审计同一实例；只复用资料角色结论；只依赖执行摘要；降低标准；审计者直接修补产物后自我接受。

九、本层时间门槛关联：异常早完由本层执行逐项复核；耐力证据与功能证据分别接受。

十、本层多智能体 / 上下文隔离要求：审计空间默认只读，并从干净候选重现；审计智能体编号必须不同于执行者。

十一、本层验证方法：抽样复跑、重算、重建、查看原始输出并与原目标和要求台账对齐。

十二、失败返回：任何关键拒绝进入第10层；审计设计不独立时返回第9层重建审计。

十三、证据路径：审计回执、复跑输出、接受矩阵、交付检查和驳回包索引。

十四、连接到下一层的条件：每条声明都有决定；有拒绝进入第10层，无拒绝也要在第10层登记“无开放拒绝”。

十五、本任务中的具体应用：列出当前接受、拒绝和不确定声明及证据。

十六、是否允许跳过：否。

### 第10层：`Repair Loop`（返修循环层）

一、本层定位：登记所有拒绝并把修复路由到真实根因层。

二、本层目的：形成有界的“修复—重检—独立复审”闭环，避免无限重试和假关闭。

三、本层输入：拒绝矩阵、驳回包、失败证据、轮次、依赖、回滚点和上一轮策略。

四、本层动作：分类根因；冻结依赖；只修失败或高风险项；任何失败后的下一轮改变策略；重新运行第8和第9层；记录继续、通过、部分完成、阻塞、回滚或人工审查。

五、本层产物：`repair-loop-log`（返修记录）、策略变化、前后差异、复验、复审和最终决定。

六、本层文件要求：`rounds.json`和第10层实例记录。

七、本层内容要求：第0轮是第一版；轮次从0连续；默认最多三轮返修；定向驳回注明已完成、需修复、依赖冻结和返回层。

八、本层禁止事项：相同失败重复相同策略；跳号；超过上限；降低标准；删除坏例；隐藏阻塞；把关键失败写成后续优化；全量重跑不受影响内容。

九、本层时间门槛关联：每轮必须有可测变化；连续两次无进展立即换策略、重拆或阻塞，不等待耗时。

十、本层多智能体 / 上下文隔离要求：修复仍由执行角色完成，复审仍由独立审计角色完成；主控只路由和冻结。

十一、本层验证方法：核对轮次连续、执行／审计与工作包一致、策略变化、产物差异和第8、9层新证据。

十二、失败返回：按根因返回第1至9层；三轮后关键失败仍存在则阻塞或回滚。

十三、证据路径：每轮假设、变更、命令、产物、审计、决定和恢复点索引。

十四、连接到下一层的条件：没有开放拒绝，或已形成诚实且隔离清楚的部分完成／阻塞结论。

十五、本任务中的具体应用：列出本任务各包轮次、策略差异和停止原因；没有返修时写“无开放拒绝”并引用第9层矩阵。

十六、是否允许跳过：否。

### 第11层：`Compact / Handoff`（压缩交接层）

一、本层定位：把长上下文压缩成可恢复、可验证的交接包。

二、本层目的：中断、角色切换或上下文压缩后不丢目标、证据、拒绝、技能和恢复入口。

三、本层输入：十二层状态、要求台账、角色、声明、产物、检查、审计、返修和风险。

四、本层动作：只压缩已验证事实；记录完成、失败、跳过及理由、开放拒绝、阻塞、下一角色、下一目标层、恢复命令和剩余风险。

五、本层产物：`compact-handoff`（压缩交接）、会话快照、证据索引、完成台账和恢复入口。

六、本层文件要求：`handoff.json`、`evidence-index.json`、`completion-ledger.json`和第11层实例记录。

七、本层内容要求：标准消息包包含发送者、接收者、工作包、输入版本、产物校验值、断言置信度、通过项、拒绝项和下一目标层；ECC 2.0触发时加入工具与工作区生命周期摘要。

八、本层禁止事项：只返回文件夹；隐藏拒绝；把未验证材料写成事实；遗漏跳过项；缺恢复入口；把交接当最终验收。

九、本层时间门槛关联：保存原始开始、真实中断、恢复、最后验证和交接时间。

十、本层多智能体 / 上下文隔离要求：保存每个真实实例回执、技能使用、贡献、合并成本和下一接收者。

十一、本层验证方法：由新上下文按恢复入口复现当前状态；核对证据索引和完成台账无断链。

十二、失败返回：交接不完整留在第11层；发现前层问题返回对应层并由第10层登记。

十三、证据路径：交接、快照、证据索引、完成台账和恢复试验索引。

十四、连接到下一层的条件：所有已声明要求、声明、产物、拒绝和阻塞都有状态与证据路径。

十五、本任务中的具体应用：写明当前从哪里恢复、下一角色做什么、哪些内容绝对不能误认为完成。

十六、是否允许跳过：否。

### 第12层：`Final Acceptance`（最终验收层）

一、本层定位：只汇总前十一层已经形成的接受事实，决定整体状态。

二、本层目的：逐项对齐原目标，防止准备包、执行自述、脚本通过、目录存在或部分成果冒充最终完成。

三、本层输入：十二层实例、已声明要求、完成台账、角色、技能、声明、产物、检查、审计、返修、交接、时间和人工关口。

四、本层动作：检查每项要求、声明、工作包和关键风险；确认签署者独立；生成用户可读和机器可读的双份最终验收。

五、本层产物：`final-acceptance.md`（最终验收文档）、`final-acceptance.json`（结构化最终验收）和最终报告。

六、本层文件要求：双份最终验收缺一不可；文件别名必须在证据索引中映射。

七、本层内容要求：十二层逐层通过；要求台账100%有状态；至少一个真实工作包；真实多智能体、技能、产物、正负检查、独立审计、返修、交接和交付安全关口通过；最终状态和证据相符。

八、本层禁止事项：首次发现技能或智能体没用；开放拒绝仍通过；异常状态字符串；执行者签署最终验收；只有路径无摘要；英文无中文解释。

九、本层时间门槛关联：生产任务不看是否耗满预算；异常早完必须通过独立复核；耐力任务必须满足时间、持续驱动、恢复和最终检查点。

十、本层多智能体 / 上下文隔离要求：最终签署者不能是工作包执行者；根主控可汇总，但不能推翻独立审计未关闭的拒绝。

十一、本层验证方法：运行确定性证据验证器，再由独立审计和最终验收人核对原目标；脚本结果不替代签署。

十二、失败返回：可修复问题进入第10层；缺权限、工具、真实智能体或安全条件时阻塞；方案不满足目标时拒绝。

十三、证据路径：双份最终验收、最终报告、证据索引和签署记录。

十四、连接到下一层的条件：无；本层只输出通过、部分完成、阻塞或拒绝。

十五、本任务中的具体应用：逐条列出用户原要求、结果、证据、未完成和风险，不用“整体完成”一句话代替。

十六、是否允许跳过：否。

## 三、层间返修路线

| 问题 | 返回层 |
|---|---:|
| 目标、项目归属、范围、权限、安全或时间类型 | 1 |
| 来源、置信度、历史或项目记忆污染 | 2 |
| 技能、成熟组件、工具、模型或依赖 | 3 |
| 工作包、依赖、所有权、验收、回滚或检查点计划 | 4 |
| 智能体、回执、权限、上下文、空间或专业角色 | 5 |
| 产物、声明、代码、模型或报告 | 6 |
| 生命周期、路由、超时、检查点或恢复 | 7 |
| 测试、脚本、验证器、正负案例或证据结构 | 8 |
| 审计独立性、事实复核、交付复检或接受判断 | 9 |

所有修复由第10层登记和路由；修复后重跑受影响的第8、9层。第10层本身失败时停止、回滚或请求人工决定。

## 四、四阶段关系

- 第一阶段输出控制规范和第1层草案。
- 第二阶段只读事实、准备技能、成熟组件、角色计划和第2至5层，不正式执行第6层。
- 第三阶段生成包含十二层实例、工作包、证据合同和命令的完整执行包。
- 第四阶段执行第6至12层，并按拒绝返回前层。

四阶段是跨工具协作外壳，十二层是任务内部主轴，阶段验收循环嵌入第6、8、9、10层；三者不能互相替代。
