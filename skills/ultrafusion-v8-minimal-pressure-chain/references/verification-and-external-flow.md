# ultrafusion-v8-minimal-pressure-chain detailed reference

## 8. 逐层提前预警

A/B/C/D 每层末尾都必须有提前预警。

中文格式：

```text
提前预警：
- 质量风险：无 / 低 / 中 / 高
- 平衡状态：通过 / 警告
- 原因：
- 下一步动作：继续 / 修复一次 / 停止并返回 / 升级到 V7
```

质量风险为“高”的条件：

- 浅、假、脆弱类具体扣分点达到 2 个或更多。
- 自评分低于或等于 7.0。
- 核心问题没有回答。
- 当前层的必需验证块失败。

高风险处理：

```text
当前层最多修复一次。
修复后仍然高风险，就停止 V8 链路，输出当前最佳结果，并明确建议：
继续 GPT 直答 / 重试 V8 / 升级 V7。
```

## 9. B/C/D 防退化门

### 9.1 B 层验证

B 层必须产生新的、更强的、可直接交付的答案。

验证项：

```text
B 层是否产生增强答案：是 / 否
B 层是否可独立交付：是 / 否
B 层是否只是评论 A：是 / 否
```

失败条件：

- 没有增强答案。
- 不能独立交付。
- 只是评论 A。

失败后必须重跑一次。重跑仍失败，标记：

```text
B 层退化失败
```

### 9.2 C 层验证

C 层必须融合有效 B 稿，不能机械拼接。

验证项：

```text
是否处理冲突：是 / 否
是否标记弱证据：是 / 否
是否压缩重复：是 / 否
是否列出 D 层判断点：是 / 否
```

C 层内容密度门：

- 冲突处理必须写出至少 1 个具体冲突点；如果没有冲突，必须写“未发现具体冲突”并说明原因。
- 弱证据必须写出至少 1 个不确定点；如果没有弱证据，必须写“未发现弱证据”并说明原因。
- 重复压缩必须说明压缩了哪些重复内容。
- D 层判断点必须至少 2 个。

如果只写“已处理 / 已标记 / 已压缩”，算失败。

失败后必须重跑一次。重跑仍失败，标记：

```text
C 层拼接失败
```

### 9.3 D 层验证

D 层必须先攻击 C，再修复，再输出最终答案。

验证项：

```text
是否先攻击 C：是 / 否
是否发现或明确排除硬问题：是 / 否
是否完成修复：是 / 否
```

如果 D 只是润色语言，标记：

```text
D 层润色失败
```

## 10. D 层最终保险检查

D 层输出最终答案后，必须检查：

```text
是否回答核心问题：是 / 否
是否有可执行细节：是 / 否
是否处理风险、边界和反例：是 / 否
```

判定：

```text
3 个“是”：通过。
2 个“是”：有限通过。
0-1 个“是”：修复一次。
修复后仍只有 0-1 个“是”：V8 质量失败，建议升级 V7。
```

最终答案质量分与 D 层执行分区分规则：

D 层必须区分两个分数：

1. 最终答案质量分（SCORE_FINAL）
   用于评价最终交付答案本身的质量。
   Gain 只能使用这个分数计算。

2. D 层执行自评分
   用于评价 D 层是否完成攻击、修复、保险检查和最终判断。
   它不能代替 SCORE_FINAL。

硬规则：

- Gain = SCORE_FINAL - Score_0。
- 最终状态依据最终答案质量分（SCORE_FINAL）和 Gain 判断。
- D 层执行自评分只用于判断 D 层流程是否合格。
- 不得把 D 层执行自评分写成最终答案质量分。
- 不得把最终答案质量分和 D 层自评分混用。

## 11. 质量、架构、速度平衡门

V8.2 同时优化三件事：

- 质量：不能浅、脆、漏、假。
- 架构：不能变成 V7 那种重流程。
- 速度：可以比 GPT 直答慢，但不能像重型 基准评测。

新增任何步骤前先问：

```text
这个步骤是否能防止明显质量失败？
是否真的提高答案质量？
是否只是增加仪式感？
是否会让 V8 变得像 V7？
```

最终必须给出平衡判断：

```text
质量：
架构：
速度：
结论：平衡 / 太薄 / 太重 / 太慢
```

## 12. 标准工作流

1. 判断走 GPT 直答还是 V8.2。
2. 如果走 GPT 直答，直接回答并保持简洁。
3. 如果走 V8.2，先记录普通 GPT 直答的基线分（Score_0）。
4. A 层：GPT + DeepSeek + 千问分别写独立答案。
5. B 层：GPT + DeepSeek + 千问分别读取有效 A 稿，写增强答案。
6. C 层：GPT 融合有效 B 稿。
7. D 层：GPT 攻击 C、修复、评分、交付最终答案。
8. 最终输出 最终答案质量分（SCORE_FINAL） 和 提升值（Gain）。
9. 重要任务要保存运行记录。

Score_0 基线污染风险规则：

Score_0 必须来自未执行 A/B/C/D 前的普通 GPT 直答质量判断。

Score_0 的要求：

- 必须在 A 层之前记录。
- 不能使用 A/B/C/D 的内容反向修正。
- 不能使用外部模型答案反向修正。
- 不能用最终答案倒推普通直答分数。
- 如果普通直答已经受到 V8.2 提示词、外部模型内容或后续融合内容影响，必须标记基线污染风险。

基线污染风险字段：

```text
Score_0 是否在 A 层之前产生：是 / 否 / 未知
Score_0 是否使用了 A/B/C/D 内容：是 / 否 / 未知
Score_0 是否使用了外部模型内容：是 / 否 / 未知
基线污染风险：无 / 低 / 中 / 高 / 未知
Gain 可信度：高 / 中 / 低 / 未知
```

如果基线污染风险为中或高，Gain 必须标记为“参考值”或“未知”，不得硬称精确提升。

## 13. 模型缺失规则

如果 DeepSeek 或千问不可用：

- 必须明确标记缺失。
- 不得编造模型回答。
- 不得把有限路线说成完整三模型 V8.2。

如果只有 GPT：

```text
模型多样性受限：是
```

这时只能叫“受限 V8.2”，不能叫完整三模型路线。

V8.2 运行状态定义：

V8.2 每次运行必须明确标记运行状态：

1. FULL_V8_2
   - GPT、DeepSeek、千问都真实返回了 A 层答案。
   - GPT、DeepSeek、千问都真实返回了 B 层答案。
   - C 层由 GPT 执行。
   - D 层由 GPT 执行。
   - 可以称为完整三模型 V8.2。

2. LIMITED_V8_2
   - 只有部分外部模型真实返回。
   - 至少缺失 DeepSeek 或千问中的一个 A/B 答案。
   - 必须明确列出缺失模型和缺失层。
   - 不能称为完整三模型 V8.2。

3. GPT_ONLY_V8_2
   - 只有 GPT 参与。
   - 没有 DeepSeek 或千问真实返回文本。
   - 只能称为 GPT 受限 V8.2 或 GPT 内部压力链。
   - 不得声称完成多模型验证。

硬规则：

- Codex 不得代替 DeepSeek 或千问生成署名答案。
- 没有真实外部回答文本，不得写“DeepSeek 已参与”。
- 没有真实外部回答文本，不得写“千问已参与”。
- 如果用户只是让 Codex 生成复制包，运行状态应为“未运行”或“等待外部模型返回”，不能提前标记 FULL_V8_2。

## 14. V8.2 外部辅助规则

V8.2 外部辅助不是 V7，不是 Kimi 路线。

默认路线：

```text
V8.2 官方三模型辅助
```

含义：

- GPT、DeepSeek、千问参与 A 层。
- GPT、DeepSeek、千问参与 B 层。
- GPT 独自执行 C 层。
- GPT 独自执行 D 层。

在真实回答返回前：

- 不得声称 DeepSeek 已参与。
- 不得声称千问已参与。
- 不得声称已经完成多模型验证。

## 15. 用户可审计中文包规则

当提示词要给用户复制、检查、修改或审计时：

1. 默认使用中文。
2. 不使用只有英文的字段。
3. 模型名可以保留英文，例如 GPT、DeepSeek、Qwen。
4. 路线代号可以保留，但必须解释中文含义。
5. 不加多余的“开始复制 / 结束复制”。
6. A 层提示词要直接针对任务，不堆无意义元规则。
7. 用户看不懂的内容，就不应放进审核包。

推荐中文字段：

```text
第一版高质量答案
吸收增强答案
压力融合答案
最终判断答案
具体扣分点
自评分
已经修复的地方
提前预警
质量风险
平衡状态
下一步动作
```
