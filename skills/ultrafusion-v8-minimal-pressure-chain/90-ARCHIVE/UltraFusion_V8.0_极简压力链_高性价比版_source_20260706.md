# UltraFusion V8.0 极简压力链高性价比版

版本：`UltraFusion V8.0 Minimal Pressure Chain`
日期：2026-07-06  
定位：替代 V7.0 臃肿半自动 ABCD 方案的高性价比版本  
核心目标：**尽量保持 UltraFusion 的答案质量压力，同时显著降低提示词长度、人工复制成本、运行时间和执行复杂度。**

---

## 0. 一句话定义

UltraFusion V8.0 不是更复杂的新系统，而是把 V7.0 压缩成一条极简高压链：

```text
简单问题：GPT 直答。
复杂/高价值问题：ABCD 极简压力链。
A 独立极限回答。
B 吸收增强。
C 压力融合。
D 极限审判。
每层 SelfScore / Deduction / RepairDone。
低于 8.5 分必须自修复一次。
最终用 Gain 判断值不值。
```

---

## 1. V8.0 核心目标

### 1.1 原始目标

原 UltraFusion 的目标是多模型、多层融合，得到比单模型更强的答案。

V8.0 的目标不是继续加层，而是：

```text
用最短流程保留最大质量压力。
用最少提示词触发模型自审、自修复、自压榨。
用最低运行成本得到接近 V7.0 的答案质量。
```

### 1.2 质量目标

V8.0 要实现三件事：

| 目标 | 含义 |
|---|---|
| 高性价比 | 成本、时间、复制量显著下降 |
| 少降质 | 不追求完全等于 V7.0，但避免变成普通回答 |
| 易执行 | Codex、官网复制、手动运行都能理解和执行 |

### 1.3 成功标准

V8.0 成功不是看文本多长，而是看：

```text
1. 是否能快速判断问题该不该进链路。
2. 每层是否都有真实压力。
3. B 是否真的增强，不是评论。
4. C 是否真的融合，不是拼接。
5. D 是否真的审判，不是润色。
6. Final 是否比普通 GPT 答案明显更强。
7. Gain 是否足以证明链路值得。
```

---

## 2. 为什么旧流程有效

V7.0 / V15 的有效点不是“长”，而是它制造了压力：

```text
普通模型：回答完就结束。
UltraFusion：每层都必须证明自己没有漏答、浅答、编造、混乱、脆弱。
```

旧流程有效的原因：

| 旧机制 | 真正价值 |
|---|---|
| 多模型 A 层 | 获得不同初始框架 |
| B 层吸收 | 让模型基于更多材料重做答案 |
| C 层融合 | 去重、处理冲突、形成统一结构 |
| D 层审判 | 找硬伤、降级不确定表达、最终稳定 |
| 评分/Gain | 判断流程有没有真实增益 |
| 反例/风险 | 防止看似完整但实际脆弱 |

所以 V8.0 不能砍掉压力，只能砍掉包装。

## 3. V8.0 总架构

### 3.1 二分路由

只保留两种问题：

```text
Route 1：GPT_DIRECT
适用：简单、低风险、低价值、事实稳定、用户要快。
处理：GPT 直接回答，不进 UltraFusion。

Route 2：UF_V8_ABCD_MIN
适用：复杂、高价值、高风险、多方案、多约束、需要极限质量。
处理：进入 ABCD 极简压力链。
```

### 3.2 不再保留的复杂路线

V8.0 不再默认区分：

```text
D-Lite / C-Lite / V15-Full / Semi-Auto / Official-C / Official-D / 多种模式标签
```

所有复杂问题统一进入：

```text
UF_V8_ABCD_MIN
```

## 4. 路由判断规则

### 4.1 直接回答条件

满足以下任意情况，默认 GPT 直答：

```text
- 简单事实问题
- 简单解释
- 简单改写
- 用户明确要求简短
- 低风险日常建议
- 单模型足够完成
- 进入 ABCD 的成本明显高于收益
```

示例：

```text
法国首都是哪里？
这句话怎么改得更礼貌？
帮我列三个标题。
这个词是什么意思？
```

### 4.2 进入 ABCD 条件

满足以下任意情况，进入 UltraFusion V8.0：

```text
- 用户明确要求极限答案、架构、系统、方案、评估、长任务
- 结果错误代价高
- 涉及多目标权衡
- 涉及复杂执行路径
- 需要反例、风险、边界、验收标准
- 单模型容易浅答
- 需要多个模型/多个视角互相补强
```

示例：

```text
设计一个高性价比多智能体系统。
评估一个技能包是否值得部署。
做一个可以给 Codex 执行的命令包。
分析复杂医疗/法律/金融问题。
重构一个已有系统并保留质量。
```

### 4.3 默认原则

```text
能直答就直答。
需要极限质量才进链。
不要为了仪式感跑 UltraFusion。
```

## 5. 极简评分压力门

### 5.1 每层固定三字段

每层必须输出：

```text
SelfScore: 0-10
Deduction: 漏答/浅/假/乱/脆 中的扣分原因
RepairDone: 是否已修复；如果未修复，说明原因
```

### 5.2 五个扣分项

| 扣分项 | 判定标准 |
|---|---|
| 漏答 | 没回答用户核心问题，或漏掉关键约束 |
| 浅 | 只有原则、口号、模板，没有可执行细节 |
| 假 | 编造事实、模型状态、数据、引用，或把假设当事实 |
| 乱 | 结构混乱，前后冲突，结论不清 |
| 脆 | 没有处理反例、边界、风险、不确定性 |

### 5.3 分数门槛

```text
SelfScore < 8.5：
必须自我修复或重写一次。

8.5 <= SelfScore < 9.0：
可以进入下一层，但必须列明扣分原因。

SelfScore >= 9.0：
本层达标。

信息不足：
不能硬凑高分，必须标注受限原因。
```

### 5.4 评分纪律

```text
不能先给高分再找理由。
不能为了过关虚报分数。
必须先找扣分项，再给分。
如果无法验证事实，必须降级表达。
如果发现硬伤，必须修复后再输出。
```

## 6. A/B/C/D 层设计

## 6.1 A 层：独立极限回答

### 目标

```text
让每个模型在互不污染的情况下，给出当前能力范围内的最高质量答案。
```

### 输入

```text
原始问题 Q
必要背景资料
V8 极简评分门
```

### 输出

```text
A_EXTREME_ANSWER
SelfScore
Deduction
RepairDone
```

### A 层必须做到

```text
- 直接回答 Q。
- 明确目标、约束、假设。
- 给出可执行结构。
- 标出不确定项。
- 自查五类扣分项。
```

### A 层禁止

```text
- 简单总结。
- 套模板。
- 不承认不确定。
- 为了高分堆字数。
```

---

## 6.2 B 层：吸收增强

### 目标

```text
读取所有有效 A 稿，吸收强点、修复缺口，生成一份更强的新答案。
```

### 输入

```text
原始问题 Q
A1/A2/A3... 有效答案
V8 极简评分门
```

### 输出

```text
B_ENHANCED_ANSWER
新增了什么
修复了什么
提高了什么
SelfScore
Deduction
RepairDone
```

### B 层必须做到

```text
- 吸收所有 A 的有效强点。
- 修复 A 的共同缺陷。
- 处理 A 之间的冲突。
- 形成新的独立答案。
```

### B 层禁止

```text
- 只评价 A1/A2/A3。
- 机械拼接。
- 把 B 写成审稿意见。
- 不输出可直接使用的新答案。
```

---

## 6.3 C 层：压力融合

### 目标

```text
把多个 B 稿融合成统一、清晰、密度更高、冲突更少的候选最终答案。
```

### 输入

```text
原始问题 Q
B1/B2/B3... 有效答案
V8 极简评分门
```

### 输出

```text
C_FUSION
冲突处理说明
弱证据标记
压缩说明
D 层重点审判点
SelfScore
Deduction
RepairDone
```

### C 层必须做到

```text
- 去掉重复。
- 保留最强观点。
- 处理冲突。
- 区分事实、推断、建议。
- 标记证据强弱。
- 形成统一结构。
```

### C 层禁止

```text
- 简单合并。
- 低配总结。
- 忽略冲突。
- 把多个答案硬拼成一个长文本。
```

---

## 6.4 D 层：极限审判

### 目标

```text
从攻击者、审判者、交付者三种角度检查 C_FUSION，修复硬伤，输出最终可交付答案。
```

### 输入

```text
原始问题 Q
C_FUSION
V8 极简评分门
```

### 输出

```text
Ultra_Answer_Final
审判发现
修复记录
SCORE_FINAL
Gain
SelfScore
Deduction
RepairDone
```

### D 层必须做到

```text
- 先攻击答案，再修复答案。
- 检查结论、前提、反例、风险。
- 不确定的地方必须降级表达。
- 最终答案必须可以直接交给用户。
```

### D 层禁止

```text
- 只润色。
- 只说“没问题”。
- 忽略事实不确定。
- 发现硬伤却不改。
```

## 8. 最终评分与 Gain

### 8.1 Score_0

```text
Score_0 = 普通 GPT 直接回答的质量分。
```

可以由 GPT 或 D 层快速估计，不需要长报告。

### 8.2 SCORE_FINAL

```text
SCORE_FINAL = ABCD 完成后最终答案质量分。
```

### 8.3 Gain

```text
Gain = SCORE_FINAL - Score_0
```

### 8.4 判断规则

| Gain | 判断 |
|---:|---|
| < 0.5 | 链路不值得，普通回答足够 |
| 0.5 - 1.0 | 小幅提升，仅适合中等问题 |
| 1.0 - 2.0 | 有明显价值 |
| >= 2.0 | UltraFusion 明显有效 |
| UNKNOWN | 信息不足，不能强行证明有效 |

### 8.5 纪律

```text
不能为了证明 UltraFusion 有效而虚增 SCORE_FINAL。
Gain 不明显时必须承认。
低增益说明问题不值得进链，或某层执行失败。
```

## 9. 温度策略

V8.0 保留旧系统中最值得保留的温度策略：

| 层 | 目标 | 默认温度 |
|---|---|---:|

| C | 收敛融合，压冲突 | 0.35 |
| D | 稳定审判，防幻觉 | 0.20 |

### 不能设置温度时的文字模拟

```text
A/B 提示中强调：多角度、第一性原理、提出替代路径。
C/D 提示中强调：收敛、事实保守、处理冲突、交付稳定。
```

## 10. 模型数量与低成本策略

### 10.1 默认模型数

V8.0 不强制固定 3 模型。

```text
标准：A 层 2-3 个模型；B 层 1-2 个模型；C/D 可由最强模型完成。
低成本：A 层 2 个模型；B/C/D 单模型。
极简：A/B/C/D 全部单模型，但仍保留层内压力。
```

### 10.2 推荐低成本路线

```text
A1：GPT
A2：Qwen 或 DeepSeek
B：GPT 或 GLM
C：GPT
D：GPT / GLM / 最稳模型
```

### 10.3 缺失模型处理

```text
缺少模型不补编。
少于 2 个 A 稿时，标记 Limited_Model_Diversity。
模型不可用时，跳过并记录原因。
涉及当前模型状态、价格、政策时，必须查新。
```

## 11. 旧系统应该砍掉的复杂度

V8.0 明确砍掉：

```text
- 每层完整 V15 重复注入。
- C/D 超长官方模板。
- 多路线、多模式、多标签。
- 复杂网页自动化作为默认路径。
- 每层过度审计报告。
- 过长 manifest。
- 为了形式完整而跑满所有层。
- 把评分写成大表格。
- 把模板写到模型无法稳定执行。
```

V8.0 必须保留：

```text
- 简单/复杂二分。
- ABCD 四步质量骨架。
- 每层 SelfScore / Deduction / RepairDone。
- 低于 8.5 自修复。
- B 不是评论。
- C 不是拼接。
- D 不是润色。
- Score_0 / SCORE_FINAL / Gain。
- 缺失模型不伪造。
- 易变事实查新。
```

## 14. 对抗式审查

### 14.1 风险一：评分太松

问题：

```text
模型可能自评虚高，8.5 门槛形同虚设。
```

修复：

```text
评分必须先写 Deduction，再写 SelfScore。
只要存在事实不确定、执行缺口、未处理反例，不能给 9.0+。
D 层必须检查前面层的虚高分。
```

### 14.2 风险二：压力不够，答案变普通

问题：

```text
短提示词可能压不出极限答案。
```

修复：

```text
每层提示必须包含“不是普通回答/不是评论/不是拼接/不是润色”的反向定义。
每层必须写 RepairDone。
低于 8.5 必须重写一次。
```

### 14.3 风险三：B 变成评论

修复：

```text
B 输出字段必须是 B_ENHANCED_ANSWER。
评价 A 的内容只能放在 ComparedWithA。
如果没有新答案，B 层无效。
```

### 14.4 风险四：C 变拼接

修复：

```text
C 必须输出冲突处理、弱证据标记、重复压缩。
没有这些字段，C 层无效。
```

### 14.5 风险五：D 变润色

修复：

```text
D 必须先写 Judgement，再写 Ultra_Answer_Final。
发现硬伤必须修复；不能只美化语言。
```

### 14.6 风险六：质量低于 V7.0

修复：

```text
V8.0 定位为日常生产版，不取代 V7.0 benchmark。
如果任务极高价值、需要审计、需要完整证据链，可以升级回 V7.0 重型流程。
```
