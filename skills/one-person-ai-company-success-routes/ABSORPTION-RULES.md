# Absorption Rules

## 动作定义

- ABSORB：无需安装即可直接吸收思想、结构、字段、模板、治理规则。
- REPLAY：值得在 mock/read-only/demo 模式下复现一小段流程。
- WATCH：方向有价值但证据不足、成熟度不足、风险较高或需要后续观察。
- REJECT：不适合当前体系、依赖过重、风险大、无法本地化或没有可复用机制。
- DEPRECATED：旧路线已被更好方案 supersede，保留记录和原因。

## ABSORB 条件

- 机制可以用文档、模板、控制台原型或 mock 数据表达。
- 不需要真实账号、API key、生产配置或外部发送。
- 能映射到 Codex、Hermes、OpenClaw、小龙虾、ComfyUI、ECC、H:\AI\skills 或 AICompany Dashboard。
- 有来源和证据。

## REPLAY 条件

- 机制不能只靠阅读判断，必须小范围验证。
- 可在无真实 key、无生产配置、无真实发送的 mock/demo 环境中验证。
- replay 有明确输入、预期输出、停止条件和回滚路径。

## WATCH 条件

- 项目新、变化快、API/许可/账号边界不清。
- GitHub/API/官网证据不足。
- 与当前体系相关但还不是最小必要机制。

## REJECT 条件

- 需要真实密钥或生产账号才能判断核心价值。
- 主要价值是营销叙事，没有可复用机制。
- 要求修改生产配置或连接真实发送渠道。
- 不能本地化，或只能复制品牌/私有流程。

## 不盲目安装规则

安装不是吸收。默认顺序：公开文档 -> raw README -> 浅克隆 -> mock/demo -> 才考虑真实安装。任何真实安装都必须有明确目的、范围、成功标准、失败标准和回滚路径。
