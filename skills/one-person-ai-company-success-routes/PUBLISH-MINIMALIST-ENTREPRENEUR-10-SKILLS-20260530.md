# 一人公司必装的 10 个 Skill

来源：Sahil Lavingia《The Minimalist Entrepreneur》方法，以及 `slavingia/skills` 中的 10 个 Claude Code skills。

视频里介绍的核心意思是：把《The Minimalist Entrepreneur》里的创业方法拆成 10 个可以直接调用的技能。它不是先写代码、先做产品、先融资、先投广告，而是先找到社区，再验证问题，再用最小、手工、可收费的方式交付价值，最后才逐步产品化、营销、增长和招聘。

## 总路线

1. `/find-community`：寻找社区
2. `/validate-idea`：验证想法
3. `/mvp`：最小可行产品
4. `/processize`：流程化
5. `/first-customers`：获取首批客户
6. `/pricing`：定价
7. `/marketing-plan`：营销计划
8. `/grow-sustainably`：可持续增长
9. `/company-values`：公司价值观
10. `/minimalist-review`：极简复盘

## 1. `/find-community`：先找社区，不先找产品

创业第一步不是想一个产品，而是找到自己已经属于、愿意长期服务的社区。

要先问：

- 我已经属于哪些社区？
- 我平时在线上待在哪些地方？
- 这些社区里，人们反复抱怨什么问题？
- 哪个社区是我愿意服务很多年的？

判断社区时，要看：

- 我是不是真正理解这个社区的语言、文化和价值观。
- 这个问题是不是痛到别人愿意付钱解决。
- 我能不能触达这些人。
- 这个社区是不是足够具体，具体到我能站住位置。

最后输出：

- 1 到 3 个可以服务的社区。
- 每个社区里的持续痛点。
- 我与这个社区的连接。
- 这些人在哪里聚集。

## 2. `/validate-idea`：验证靠销售，不靠先做产品

验证不是先开发产品，而是先确认问题真实存在，并且有人愿意付费。

先定义问题：

- 谁有这个问题？
- 他们现在怎么解决？
- 这个问题有多痛？
- 他们愿不愿意花钱解决？

然后问：

- 我能不能先手工解决这个问题？
- 我能不能先为几个人亲自交付？
- 我有没有和至少 10 个潜在客户聊过？
- 有没有至少 3 个人愿意付费，或者真的付费？

开始做之前，还要问四个问题：

1. 能不能一个周末做出第一版？
2. 它是不是让客户生活好一点？
3. 客户愿不愿意为它付钱？
4. 能不能快速得到反馈？

如果说不出 10 个具体客户，只有朋友觉得“想法不错”，或者需要先教育别人他们有这个问题，就还不能做。

最后输出：

- 已验证、继续验证、或转向。
- 下一步要拿到什么证据。

## 3. `/mvp`：先做最小版本

MVP 的目标不是漂亮、完整、可规模化，而是尽快给真实用户交付价值。

MVP 分三步：

1. 手工做：自己就是产品、客服、履约和工程。
2. 流程化：把手工过程写下来，让别人也能照着做。
3. 产品化：只自动化已经被手工证明有效的部分。

MVP 要尽量小：

- 只做一件事。
- 不追求精致。
- 要收费。
- 能用现有工具就用现有工具。

不要做：

- 不做以后可能需要的功能。
- 不为规模构建。
- 网站能解决就不做 App。
- 表格能解决就不写代码。
- 无代码工具能解决就不先雇工程师。

最后输出：

- 产品最先只做的一件事。
- 最简单的实现方式。
- 这个周末能交付什么。
- 初始价格。
- 怎么收集反馈。

## 4. `/processize`：先流程化，再产品化

核心是：不要一开始就写软件，先证明自己能手工给真人交付价值。

要做：

1. 把产品削成一句话：它为客户做什么？
2. 说明客户使用前有什么，使用后得到什么。
3. 想象完全不用技术，只用自己、电话和表格，怎么交付。
4. 找到今天就需要它的人。
5. 设计完整手工版本。

手工版本要写成“魔法纸片”：

- 什么触发流程？
- 第一步做什么，第二步做什么，第三步做什么？
- 每一步用什么工具？
- 每一步花多长时间？
- 最后怎么交付给客户？

然后要收费。免费用户不给真实信号，哪怕 1 美元也比免费更真实。

什么时候才产品化？

- 已经手工交付给 10 个以上付费客户。
- 已经能预测他们会问什么。
- 流程几周没有明显变化。
- 花在交付上的时间开始超过找客户的时间。

最后输出：

- 手工版本的一句话说明。
- 完整手工流程。
- 本周要服务的 3 个具体对象。
- 初始价格。
- 以后最先自动化的一步。

## 5. `/first-customers`：不要先发布，先卖到 100 个客户

早期不要把希望放在“发布”上。先一个一个卖，边卖边学。

销售从同心圆开始：

第一圈：朋友和家人。

- 让他们成为第一批客户，不是投资人。
- 要真实反馈，不是转发和点赞。

第二圈：自己的社区。

- 找到写过、分享过、做过类似事情的人。
- 一个一个联系。
- 亲自讲产品。
- 要真实反馈。

第三圈：陌生人。

- 冷邮件、电话、私信都可以。
- 不要复制粘贴。
- 每一次拒绝都用来改进表达。

销售不是说服别人，而是帮助别人。产品应该给对方生活增加价值。每次没成交都要变成洞察：是找错人，还是产品还不够好。

不要在有 100 个付费客户前正式发布。到 100 个付费客户后，发布只是庆祝，不是获客策略。

最后输出：

- 本周要联系的 10 个亲友。
- 要联系的 10 个社区成员。
- 一个可以个性化的冷启动模板。
- 初始定价。
- 每周销售目标和记录方式。

## 6. `/pricing`：一定要收费

免费和 1 美元之间有巨大差别。不收费，就不知道客户真正看重什么，也无法让公司活下去。

两种定价：

1. 成本定价：成本加利润。
2. 价值定价：按客户得到的价值收费。

定价原则：

- 先低后高。
- 定价不是永久决定，可以迭代。
- 未来要逐渐形成分层定价。
- 不要默认免费。
- 可以试用，但要有清楚的付费路径。
- 不要把营销理解成免费送产品。

初始定价要问：

- 每个客户的成本是多少？
- 替代方案多少钱？
- 什么价格会让客户觉得很容易决定？
- 什么价格能从第一个客户开始盈利？

还要算：

- 自己每月需要多少钱生活。
- 按当前价格，需要多少客户。
- 如果每天新增一个客户，多久能达到。

最后输出：

- 定价模型。
- 初始价格和理由。
- 未来分层定价。
- 达到财务独立需要多少客户。
- 什么时候复盘并涨价。

## 7. `/marketing-plan`：先有客户，再做营销

营销是放大的销售，但不是一开始就投广告。先花时间，不先花钱。

做营销前应该已经有：

- 自己属于的社区。
- 已经有人付费的产品。
- 大约 100 个客户。
- 一对一销售经验。

客户路径：

1. 看到内容。
2. 关注你。
3. 研究产品。
4. 考虑价格和功能。
5. 购买。

内容分三层：

1. 教育：分享从业务中学到的东西。
2. 激励：分享自己的过程、困难和进展。
3. 娱乐：用更容易传播的方式表达观点。

社交媒体：

- 建个人账号和业务账号。
- 不发无意义状态。
- 重点是给出想法，不是自我推销。
- 公开构建，分享你在做什么、改了什么、学到了什么。
- 选一个主要平台，不要同时做太多。

邮件：

- 社交平台是租来的土地。
- 邮件列表是自己的土地。
- 要尽早建立邮件列表。
- 用有价值的东西换邮箱。

广告：

- 最后再花钱。
- 只有当自然增长有效、客户画像清楚后才考虑广告。
- 不要为一个客户花掉超过客户价值的钱。

最后输出：

- 主要内容平台和发布节奏。
- 教育、激励、娱乐各 5 个内容点。
- 邮件列表策略。
- 公开构建计划。
- 什么时候考虑付费广告。

## 8. `/grow-sustainably`：盈利是一种超能力

可持续增长的核心是：少花于所赚。盈利带来无限跑道、清晰和控制权。

公式：

```text
利润 = 收入 - 成本
```

成本分两类：

- 可变成本：支付处理、托管、风控等，随每单增长。
- 固定成本：域名、托管、人。最大固定成本通常是人。

成本规则：

1. 起步阶段给自己尽量少发工资。
2. 雇软件，不先雇人。
3. 不先租办公室。
4. 不为了创业搬去高成本地点。
5. 先自己和自动化，再自由职业者，再员工。

增长观：

- 不需要颠覆一切。
- 不需要一开始支配市场。
- 公司会按客户决定的速度增长。
- 工作更多小时不等于增长更快。

融资观：

- 先自举。
- 盈利会给融资更高主动权。
- 如果必须融资，也要优先选择适合可持续公司的方式。

还要防止精力耗尽。致命问题有两个：钱用完，精力用完。

最后输出：

- 这个决策对盈利的影响。
- 是否可逆。
- 是客户驱动还是虚荣驱动。
- 有没有更便宜简单的替代方案。
- 公司是默认活着还是默认死亡。

## 9. `/company-values`：招人前先定义价值观

招人之前，先定义自己要建什么样的公司。

价值观不是空泛口号，而是告诉人们在日常和极端情况下怎么行动。

价值观的作用：

- 告诉员工怎么做事。
- 吸引合适的人，劝退不合适的人。
- 让创始人和团队都能被问责。
- 让公司超越创始人本人。

建立价值观时问：

1. 我相信什么，而大多数人不相信？
2. 没人看着的时候，人应该怎么行动？
3. 即使一个人表现不错，我会因为什么开除他？
4. 即使不直接增加利润，我会庆祝什么？
5. 能不能写成故事，而不是口号？

价值观要公开使用：

- 写进招聘。
- 写进网站。
- 写进入职材料。
- 用在反馈里。
- 定期复盘。

最后输出：

- 3 到 5 条公司价值观。
- 每条价值观的说明和故事。
- 每条价值观在招聘中的体现。
- 每条价值观在日常工作中的体现。
- 每条价值观不代表什么。

## 10. `/minimalist-review`：用极简原则复盘每个重要决策

任何商业决策都可以用这 8 个问题检查：

1. 是否服务社区和客户，而不是自我、虚荣指标或模仿大公司？
2. 是否可以先手工做，再自动化？
3. 是否构建得足够少？
4. 是否已经有人付钱，而不是还没卖就先营销？
5. 是否能先花时间，而不是先花钱？
6. 是否让公司更接近盈利？
7. 是否按客户需要的速度增长？
8. 是否在建一家公司，而不是让公司反过来控制自己？

决策表：

| 问题 | 回答 |
|---|---|
| 是否服务我的社区或客户 | |
| 这是不是最简单的方法 | |
| 是否改善盈利 | |
| 如果不奏效是否可逆 | |
| 我是在花时间还是花钱 | |
| 客户是否要求过这个 | |
| 是否符合我的价值观 | |
| 一年后我还会想要它吗 | |

最后输出：

- 明确建议：做、不做、或简化后再做。
- 极简版本是什么。
- 最大风险是什么。
- 本周可以尝试的一个验证动作。
