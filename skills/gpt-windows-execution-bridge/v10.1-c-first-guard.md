# V10.1 C-FIRST 强制降级许可门禁
版本：10.1（2026-10-19）；继承 V10.0；不改变网络与代理。

## 强制路由合同
每个新的 Windows 任务先通过 Remote Desktop Commander 的 list_devices 动态发现目标设备，并通过 ping + 无副作用 PowerShell 命令确认。C PASS 则锁定 C；不可选择 A/B。
只有 C 发现/真实探针有明确失败证据，重新发现并有界重试后仍明确失败，才能申请 A 通道许可。UNKNOWN、旧 ID 离线、单次超时和业务命令失败都不能直接给出许可。
许可只针对 task_id 与当前安全检查点，不能跨任务复用，不能在存在未决副作用时重新执行。A 失败才允许 B，遵循同样证据要求。
任何执行 A 之前必须调用 guard_route.py 判断并生成审计决策，返回 DENY 时立即停止 A。不得通过另一个工具直接绕过门禁。
**能力边界**：本门禁可约束使用它的脚本与执行器；ChatGPT 的原生工具调用无法被本地脚本物理拦截。因此跨对话必须由执行入口加载本规则，仍需做真实入口回归。不能把文件存在说成平台层强制拦截完成。

## 判定和证据
输入 JSON：task_id, requested_route, target_device, c_discovery, c_ping, c_probe, retry_discovery, retry_ping, retry_probe, checkpoint_safe, a_status。
探针只接受 PASS/FAIL/UNKNOWN。切 A 必须三个 C 探针及其复验均为 FAIL、审计证据字符串非空、安全检查点为 true。若任何在线 C 真实验证 PASS，则一票否决切 A。
使用：python guard_route.py decision.json 。exit 0 仅表示请求通道得到批准；exit 3 表示 DENY。此工具不代替真实 C 发现和探测。
