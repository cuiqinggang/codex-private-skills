# Windows 执行桥 V12.0：A → B → C（简洁正式版）
日期：2026-10-21。V12 替代 V11 的字母含义；V11/V10 历史文件保留，仅用于追溯，不再指导新任务。

| V12 通道 | 唯一对应的执行入口 |
|---|---|
| **A（默认）** | Remote Desktop Commander（mcp__Remote_Desktop_Commander__，原 C） |
| **B（备用）** | GPT-Windows-MCP-Bridge（mcp__GPT_Windows_MCP_Bridge__，原 A） |
| **C（末级备用）** | GitHub Actions → Windows 自托管 Runner（原 B） |

## 唯一优先规则
1. Windows 本地任务先走 **A**：每次动态发现在线设备 ID，做无副作用真实命令探针；成功即继续走 A，**不调用 B/C**。
2. **A 确认不通**，重新发现设备并限一次复验仍失败，且当前操作结果已查清，才切换 **B**。
3. **B 确认不通**，限一次复验仍失败且结果已查清，才切换 **C**。
4. **UNKNOWN 不等于 FAIL**：ChatGPT 页面/回答断线、单次超时、旧设备 ID 离线、业务命令失败，都不能单凭此判定 A 通道故障。对可能已执行的写入先读回、对账，绝不盲目重做。

最小判定脚本：`route_v12.py`。它只给已接入的执行器判定通道，不自动探测，也**不能强制拦截 ChatGPT 原生工具调用**。没有跨会话入口实测，不宣称全局强制路由已实现。
边界：不改变 FlClash、代理、密钥、隧道、系统设置；不为了测试而破坏正常通道。
