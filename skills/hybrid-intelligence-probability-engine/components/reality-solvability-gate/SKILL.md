# 现实可解性判定门 v0.1.0（Reality Solvability Gate v0.1.0）

## 目的

禁止把“引擎第一次遇到”误写成“现实世界未知”。

任务分类依据不是领域名称，也不是我们以前有没有做过，而是：

**现实世界是否已经存在可验证的成熟直接解、成熟组合解，或成熟探索/测量流程。**

## 核心公式

定义：

- S = 任务规格足够完整；
- H = 规定的成熟方案证据范围已经完成检索；
- P = 不违反已知物理/逻辑硬约束；
- D = 存在成熟直接解决方案；
- C = 存在由成熟部件组成的闭环解决方案；
- E = 存在成熟探索/测量流程，可以把未知状态转化为可观测、可验证结果。

则：

```text
现实可解 W = D OR C OR E

真正前沿未知 U
= S AND H AND P AND NOT(W)
```

只有 U=true 才允许标记：
`FRONTIER_UNKNOWN / 前沿未知`。

## 七类状态

### 1. 信息不完整
任务目标、输入、约束或验收标准不足。

不是未知任务。
动作：补齐信息。

### 2. 成熟方案检索未完成
我们暂时不知道怎么做，但还没有完成成熟方案检索。

不是未知任务。
动作：查 Reality Foundation、成熟方案池、权威资料与现有工具。

### 3. 已知不可行/矛盾
目标违反已知物理、逻辑或明确硬约束。

不是未知任务。
动作：报告硬矛盾或重定义目标。

### 4. 成熟直接解
现实世界已有成熟、可重复、可验证的完整解决方案。

动作：复用，不重新发明。

### 5. 成熟组合解
不存在一个单独成品方案，但可以由成熟部件闭环组合。

组合闭环要求：
- 每个节点都有成熟部件；
- 输入/输出合同兼容；
- 依赖图无悬空边；
- 目标可达；
- 无未解决科学依赖；
- 最终结果可以验证。

动作：由成熟方案组合编译器生成执行 DAG，再进入 CODE/JEV/GPT 正向拆解。

### 6. 成熟探索任务
对象或环境状态未知，但“怎么探索/测量/取样/建图/验证”已经有成熟方法。

例如未探索洞穴测绘、深海调查等。

未知的是状态，不是解决方法。

动作：执行成熟探索协议，获取状态，再继续组合求解。

### 7. 前沿未知
在任务规格完整、成熟方案检索完成、物理上没有直接矛盾的前提下：
- 无成熟直接解；
- 无成熟闭环组合解；
- 无成熟探索协议可把关键未知转成可解状态。

这才属于真正需要新理论、新科学发现、新算法突破或新工程范式的任务。

## 重要区分

```text
UNREGISTERED_FAMILY != FRONTIER_UNKNOWN
SYSTEM_DOES_NOT_KNOW != WORLD_HAS_NO_MATURE_SOLUTION
UNKNOWN_STATE != UNKNOWN_METHOD
MISSING_INFORMATION != FRONTIER_UNKNOWN
```

## 生产路线

原始任务
→ 规格完整性门
→ 成熟方案证据检索门
→ 现实可解性分类
→ 成熟直接 / 成熟组合 / 成熟探索
→ 成熟方案组合编译
→ JEV舒适区导向正向拆解
→ CODE / JEV / GPT residual
→ Verifier

只有真正前沿未知：
→ 前沿研究模式
→ 不宣称生产级闭环或 T_VALID 已知。

## 未注册任务族

“未注册任务族”只表示：
**当前还没有冻结的确定性快路径模板。**

它可能仍然是完全成熟可解的任务。

第一次处理时允许：
- 检索成熟方案；
- 组合成熟部件；
- 用高智能模型编译执行图；
- 计入完整 T_VALID；
- 验证结果。

重复任务族在验证稳定后，可冻结成确定性快路径，减少以后在线编译时间。
