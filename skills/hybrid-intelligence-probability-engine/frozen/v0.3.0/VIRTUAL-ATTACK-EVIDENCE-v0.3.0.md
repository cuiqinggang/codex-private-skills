# 混合智能概率引擎 v0.3.0 — 虚拟攻击与淘汰证据

## 本轮攻击目的

不是证明“架构看起来合理”，而是主动找出会让混合方案失效、变慢或产生虚假收益的路径。

## 已发现并修复的问题

### 1. 历史 JEV 收益误当本轮收益

修复：
- JEV v0.4.0 的 560.9819 ms 只作为历史现实锚点；
- v0.3→v0.4 的 33.2645% / 1.49845x 不进入 HIPE v0.3.0 新收益。

### 2. 旧 48 节点预先带路由标签

修复：
- 完整时间从原始任务开始；
- 正向编译时间进入 Hybrid T_VALID；
- Full-GPT 与 Hybrid 从同一原始输入开始。

### 3. 正则表达式 residual 可被代码机械完成

修复：
- 删除正则 residual；
- 换成 8 个自然语言 SQL 构造任务；
- 用 SQLite 独立执行结果验证；
- 64 个安全/错误 SQL 注入测试 64/64 PASS。

### 4. 每次先用 GPT 在线拆解会产生串行高延迟税

修复：
- 已认证任务族使用冻结的确定性正向编译器；
- 未知任务族直接 Full-GPT；
- GPT 只在“虚”阶段建立/升级任务族，不作为已认证任务族热路径前置屏障。

### 5. 先用 JEV 路由也会增加串行屏障

修复：
- JEV 不作为整个工作流的前置 router；
- JEV 直接承担已经被确定性编译器识别出的 Choice 节点，并与 GPT residual 并行。

### 6. 竞速双跑会破坏成本门

修复：
- 不同时付费跑完整 Full-GPT 与 Hybrid 然后取最快；
- Full-GPT 只作为基准/未知任务兜底。

### 7. JEV v0.5.0 过度压缩语义合同

历史现实攻击：
- 0/30 PASS；
- 原因是删除 current_state / allowed_actions / dependency_ids 并改变 Choice 语义等。

修复：
- HIPE v0.3.0 的 JEV 路径严格复用 v0.4.0 语义合同。

### 8. JEV v0.5.1 虽保持语义但没有现实提速

历史现实结果：
- 30/30 PASS；
- min=956.2431 ms；
- 未打败 v0.4.0 560.9819 ms。

结论：
- 当前概率核心保持 v0.4.0；
- 不把“payload 更小”自动当成“时间更短”。

## 正向拆解攻击

- 10 个形式硬条件全部 2^10=1024 种组合穷举；
- 1024/1024 有唯一 fail-closed 路由；
- 128 个已认证任务族边界案例 128/128；
- 192 个结构/schema 变异攻击 192/192；
- 无法证明安全进入 JEV 的情况全部退 GPT。

## 输出/验证攻击

SQL residual：
- 8 个不同关系型查询结构；
- 每个测试 8 类合法/非法输入；
- 64/64 PASS；
- 禁止 DELETE/INSERT/UPDATE/DROP/ALTER/ATTACH/PRAGMA/CREATE/VACUUM/REPLACE；
- 禁止多语句；
- 只允许单个 SELECT/WITH。

## 数字孪生敏感性攻击

时间 25 组全部正收益：
- 最差 1.264183x；
- 最好 1.605502x。

成本 20 组全部正收益：
- 最差 2.358612x；
- 最好 2.635126x。

所以当前虚拟冠军不是只在单一“好看参数点”成立。

## 仍不能由虚阶段证明

- GPT 真实 30/30 SQL 生成；
- 本轮 JEV 真实延迟；
- OpenRouter 真实 provider 抖动；
- 真正 token usage / usage.cost；
- 真正完整任务最短时间。

这些被保留为 Reality 变量，而不是用 mock 假装 PASS。
