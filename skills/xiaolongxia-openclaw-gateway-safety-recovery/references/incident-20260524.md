# 2026-05-24 Xiaolongxia Autostart Isolation Incident

## Summary

During `XIAOLONGXIA-AUTOSTART-BROWSER-BASELINE-20260524`, the Xiaolongxia autostart/browser-open design mistakenly treated `http://localhost:3011` as the Xiaolongxia UI. The user observed Hermes/AiMaShi being opened when Xiaolongxia was expected. This was a serious isolation failure and the autostart/browser path was stopped.

Corrected outcome: use Windows OpenClaw gateway/browser on `http://127.0.0.1:18789/` for manual OpenClaw recovery. Do not use `3011` as Xiaolongxia UI. Do not keep the failed autostart enabled.

## What Went Wrong

- `3011` was misclassified as Xiaolongxia UI.
- In reality, `3011` is New API / model pool management for the Xiaolongxia free model pool.
- Browser opening was allowed before confirming the true product UI URL.
- The failure became visible because the user saw Hermes/AiMaShi instead of Xiaolongxia/OpenClaw.

## Reusable Safety Rules

1. Never use `http://localhost:3011` as Xiaolongxia product UI. It is New API/model-pool management.
2. Before any later Xiaolongxia/OpenClaw/browser recovery, independently start/open/login to `3011` as New API and write `3011_CONFIRMED_AS_NEW_API_NOT_XIAOLONGXIA_UI`.
3. Never assume `18798` is Xiaolongxia UI without a fresh listener/process/HTTP identity check.
4. Do not build browser autostart until the correct UI URL is proven in the same task.
5. If Hermes/AiMaShi opens during a Xiaolongxia task, stop immediately and treat it as isolation failure.
6. Keep `Xiaolongxia_Autostart_Logon` disabled after this incident unless a later task explicitly rebuilds the autostart flow from a proven UI URL.
7. Keep failed autostart scripts as disabled stubs unless a later verified redesign replaces them.
8. Use `18789` only for manual OpenClaw gateway/browser recovery on loopback.
9. Do not create scheduled tasks, enable autostart, or open browsers during discovery-only tasks.
10. Do not touch Hermes, Open WebUI, old 3001, 3011 configuration, or OpenClaw model configuration during browser recovery.
11. Do not print or store API keys, tokens, passwords, or admin credentials.
