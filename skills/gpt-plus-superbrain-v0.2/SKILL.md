# hermes-gpt-plus-superbrain

版本：v0.2  
状态：第一轮测试后修正版  
执行体：爱马仕数字助手 / Hermes Agent  
超级大脑：已登录的 ChatGPT Plus 网页 GPT  
本地动作层：Windows PowerShell + WSL Ubuntu-24.04 + agent-browser + Chrome CDP  
云端补充层：仅在 GPT 网页做不到、本地执行需要接口补充时使用

---

## 0. v0.2 更新重点

首次测试发现：如果任务开头不明确加载 GPT 使用原则，爱马仕容易把 GPT 页面当成普通问答工具，或者退回复杂机器协议思路。

因此 v0.2 新增最高优先级规则：

> 每次任务开始时，必须显式加载并声明“GPT Plus 网页作为爱马仕超级大脑的使用原则”，并要求本任务全程按这条规则执行。

如果没有显式加载，不能视为本技能包已生效。

---

## 1. 核心关系

```text
爱马仕 = 执行体 / 手脚 / 本地接口 / 文件与命令执行器
GPT Plus 网页 = 超级大脑 / 主判断器 / 编程器 / 方案生成器 / 试错指挥器
云端 API = GPT 网页做不到时的补充工具
```

本技能包的目标不是让 GPT 输出死板机器格式，而是让爱马仕像普通人一样自然使用 GPT Plus 网页，代替 API 使用。

---

## 2. 每次任务必须加载的启动口令

```text
请先加载并遵守《GPT Plus 网页作为爱马仕超级大脑的使用原则》。

本任务中：
1. GPT Plus 网页是爱马仕的超级大脑，负责分析、判断、编程、设计方案、看报错、改路径。
2. 爱马仕是执行体，负责打开网页、粘贴问题、复制回答、执行本地命令、读写文件、截图、保存证据、把结果反馈给 GPT。
3. 不要要求 GPT 输出 COMMAND/SUCCESS/FAIL 这类机器协议。
4. 像普通人正常使用 ChatGPT 一样自然提问，让 GPT 正常发挥能力。
5. GPT 的回答默认作为后续执行、整理、保存的依据。
6. 如果执行失败，爱马仕要把原始错误、日志、截图、命令输出反馈给 GPT，让 GPT 继续判断和修正。
7. 本任务必须全程按这条规则执行。

请先回报：
GPT_SUPERBRAIN_RULE_LOADED
然后开始执行任务。
```

## 3. 正确工作循环

```text
1. 用户提出自然目标
2. 爱马仕加载 GPT 使用原则
3. 爱马仕把自然问题发给 GPT Plus 网页
4. GPT 正常回答、分析、编程、给方案
5. 爱马仕复制 GPT 最新回答
6. 爱马仕保存回答到本地文件
7. 爱马仕按 GPT 回答执行本地动作
8. 爱马仕收集执行结果、报错、截图、日志
9. 爱马仕把反馈继续发给 GPT
10. GPT 判断下一步、修正方案、换路径
11. 爱马仕继续执行
12. 直到任务完成或明确卡住
```

## 4. 禁止方向

除非用户明确要求，否则不要默认这样使用 GPT：

```text
COMMAND:
SUCCESS:
FAIL:
固定三行格式
复杂机器协议
复杂审查协议
```

原因：

```text
复杂机器协议会破坏 GPT 正常回答质量；
容易触发 Markdown 链接污染、换行污染、命令格式污染；
不符合“用 Plus 网页代替 API”的真实目标。
```

## 5. 编程任务专用规则【待重点测试】

编程任务必须让 GPT 发挥编程、调试、重构、看报错能力，而不是把 GPT 限制成命令生成器。

GPT 负责：

```text
理解需求
设计实现路径
生成代码
解释代码结构
根据报错修改代码
根据测试结果继续修复
决定是否重构或换路径
```

爱马仕负责：

```text
创建/修改本地文件
运行代码
安装依赖
执行测试
收集报错
截图或保存日志
把结果反馈给 GPT
```

## 6. 已验证浏览器接入流程

当前 v0.2 已继承 v0.1 的成功链路：

```text
G01 启动调试版 Chrome，并登录 GPT Plus
G02 打通 Windows Chrome 9333 → Windows 9334 → WSL 访问
G03 安装/定位 agent-browser
G04 agent-browser 接入 ChatGPT 页面并读取 snapshot
G05 自动点击输入框、输入 TEST_OK、按 Enter 发送、截图
G06 使用 UTF-8 文件方式输入中文并发送
G07 点击 GPT 最新回答复制按钮，把答案保存到本地文件
```

链路：

```text
Windows 调试版 Chrome 9333
→ Windows portproxy 9334
→ WSL 网关访问 9334
→ agent-browser 连接 Browser WebSocket
→ ChatGPT Plus 已登录页面
→ 输入问题
→ GPT 回答
→ 点击复制
→ Windows 剪贴板
→ 本地文件保存
```

## 7. 关键接口规则

### Chrome CDP

```text
Windows Chrome 原始调试口：127.0.0.1:9333
WSL / 爱马仕统一入口：WSL_GATEWAY:9334
```

每次动态获取 WSL 网关：

```bash
ip route show default
```

### Browser WebSocket

每次重新启动调试 Chrome 后必须重新读取：

```text
http://127.0.0.1:9333/json/version
http://WSL_GATEWAY:9334/json/version
```

不要永久固定旧 WebSocket。

### PATH

若 agent-browser / hermes 找不到，先加：

```bash
export PATH="$HOME/.npm-global/bin:$HOME/.local/bin:$PATH"
```

### 中文输入

不要直接把中文放进 PowerShell 跨 WSL 传递。  
优先在 WSL 内用 Python 写 UTF-8 文件，再读取文件内容填入页面。

### 复制回答

复制回答时：

```text
snapshot
→ 找最后一个“复制 / Copy”按钮
→ click
→ 从 Windows 剪贴板读取
→ 保存为 UTF-8 txt
```

## 9. 最终验收口径

一个任务真正完成，不是 GPT 回答了就结束，而是：

```text
GPT 给出判断或方案
爱马仕执行
爱马仕收集结果
结果反馈给 GPT
GPT 判断下一步
最终得到成功结果或清晰失败原因
```

关键是：

```text
每次任务必须先加载 GPT 使用原则。
GPT 是超级大脑。
爱马仕是执行体。
二者通过自然语言和执行反馈循环协作。
```
