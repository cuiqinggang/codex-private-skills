# 先整理，再按需深度匹配

主要来源和操作已按用途归类，机器入口见catalog-sources.json与recipes.json；原32个具体公共模板继续保留。目录广度与本机就绪数量分开计算，不把同工具多个操作当作多个已交付业务能力。

接入顺序：已有同合同原程序 → 官方独立脚本/完整工程 → 已部署平台的导出流程 → 需要新运行栈的候选。该顺序减少接入投入，不预先保证某平台最快。优先高频、可复用、有完整原件与明确验收的条目；需要账号、付费或生产写入时沿具体任务授权，不为扩库自动操作外部系统。

每项深度匹配检查：

1. 业务目标和可变参数；原数据字段、金额单位、精度、空值、重复、大小写、日期与标识符语义。
2. 输入格式、数量、尺寸、实际工作目录及输出策略；源不变、覆盖规则、权限和并发共享目标。
3. 本机固定解释器、应用与依赖版本、字体、浏览器、网络、账号和原授权；Windows10兼容性逐项核对，不自动升级。
4. 可复制原件及其来源、版本、许可、SHA256；平台可导出定义不表示可脱离平台本地运行。
5. 原验收器、用户实际入口、产物读回、错误与恢复；按上下文分别验收。
6. 原方式与复用方式同合同的完整有效交付时间、费用与资源；维护与收尾也计入。没有同口径对照则净提速NOT_MEASURED；增加包装无收益就只登记原入口。

状态为CANDIDATE/NOT_CONFIGURED → CONFIGURED → READY，变更需NEEDS_RECHECK；每批NOT_MATCHED只表示该次合同不适用。匹配器现有三类之外的条目仍走原专业入口，未适配不自动可执行。

本轮不为收集目录重装n8n、部署Airflow或替换现有浏览器；后续在实际任务触发或明确安排接入时，沿此清单做最小必要验证。
