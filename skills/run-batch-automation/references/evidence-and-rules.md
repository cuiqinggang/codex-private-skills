证据分层：existing_recipe表示原包有限定历史验收，不等于当前Windows已重新检查；official_native_recipe表示官方存在原生接口，本机安装/调用与本次业务验收均须确认；historical_reference只提供方法和基准证据，默认检索排除。检索命中不等于合同匹配，执行退出0不等于交付通过。

每批确定输入清单、原文件指纹、参数/字段和输出映射；输出隔离、同名碰撞先解决。逐项记录成功、失败、未知和恢复，全部合格才报告整批完成。必要的页面打开、播放、公式外部重算或目标应用操作按用户使用方式验收，不能以API/结构检查替代。

记录首次接入/配置成本及本批从接单到全部验收读回的时间，失败、排队、纠错和等待不删除。复用历史源语义与已完成成果；当前输入的输出验收仍真实执行一次，不重复同一份不变检查。实际账单未知保持未测，不凭token或槽数推定费用。

新成熟流程只在实际需求触发时补入：名称、触发词、输入/版本范围、原入口、输出/验收、恢复条件及来源/回执齐备。无需为了完善目录把所有工具重装或重做性能基准。批处理只覆盖用户授权范围，沿用当前Windows执行桥与各专业包的连接和权限规则；不抄旧文档的过时通道优先级。
