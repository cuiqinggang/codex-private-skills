## 索引记录什么

主要收录别人已经分享的具体自动化流程：原模板标题、作者、来源链接、业务种类、所用平台、主要步骤、输入输出、依赖、复制/导入入口和核实范围。平台总目录另作上游检索入口；单个工具/API/插件不冒充完整流程。

每个流程保持三个相互独立的事实：公开流程已找到、目标环境已配置、本批任务已交付验收。只有真实完成相应步骤才更新对应状态。平台托管或作者的性能介绍不能替代后两项。当前公共流程卡为文档/源码核实；未为用户运行它们。

`recipes.json` 是机器可检索索引，`workflow-library.md` 是分类速览。命中后用精确 ID 取单卡，不读取全库全文。

## 检索顺序

1. 从任务提取动作、对象和用户已有应用，例如“邮件附件归档 Drive”“表单线索 CRM”“Python PR 测试”。
2. 默认查询具体公共流程。可按中文业务种类、平台过滤。只看前 1—3 个候选，读其完整输入、输出和配置条件。
3. 没有合适具体卡时查 `--kind source` 中最相关的 1—2 个原流程库，在原目录继续按应用和动作检索。找到具体模板后再收录，不能以目录页当成已找到可执行流程。
4. 需要本地文件批处理时，可查 `--kind local` 的原程序及原生批处理接口；它们是辅助执行路线，不限定公共流程收录范围。
5. 已命中合适完整流程便停止重复检索；不因某平台模板较多而强制换掉用户已有入口，也不预先安装所有平台。

## 接入与复用

- 保留原模板和原接口，按原说明配置连接、字段映射、输出位置及版本；只做最小适配。索引中的导入入口是取用路径，运行仍依赖对应平台或运行器。
- 有缓存原件时先按记录的 SHA256 检查；保留原许可，核对上游是否已更新。GitHub 模板里的 `$default-branch`、`$cron-daily` 由模板界面处理或按目标填写，缓存原件本身尚未配置。
- 没有核实到原 JSON/DSL 下载链接时使用已核实的模板页入口，不编造地址、不从展示图重写整套业务核心。
- 先查看该模板是单事件触发、定时整批、列表迭代还是多文件处理。事件自动化不自动等于一次整批，批量语义必须符合本次任务，不能仅靠增加并发代替。
- 执行属于用户的具体任务时，按原流程设置与本批真实输出验收；输入数、成功数、失败项及重试均须对账。写入、发送或发布按用户授权范围执行；建立索引本身不启动模板。
- 同类成熟候选比较完整有效交付时间，包含首次适配、运行、验收及恢复；已配置后的复用时间单列。历史微任务最快值不承诺新任务收益。

## 分类及扩充

使用稳定业务分类：数据与表格、文档与知识库、邮件与客服、销售与CRM、内容与营销、文件与备份、监测与运维、开发与部署、日程与通知。一个流程可带多个检索标签，但给一个主分类，避免同一原模板重复计数。没有首批具体模板的分类可通过上游目录检索，不填空壳“已就绪”卡。

每次新增卡至少提供：唯一 ID、可核实的原流程链接、业务主分类、平台、中文用途、依赖及配置项、导入/调用入口、核实日期、运行及验收状态。相同 URL/模板 ID 更新原卡；保留本人的已配置入口与合格验收证据，后续直接复用。目录不命中时再补原流程，避免每次任务全网重找。
