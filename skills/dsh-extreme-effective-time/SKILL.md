# DSH 商用交付极限有效时间
方法版本：2.1.0，2026-11-08。R77将成熟复用禁令接入GPT默认执行；继承成熟交付与验收效率规则，保留原1.0.1方法及已确认成果，不改变DSH软件版本、AI自动化组织V5或谷深V1.6的独立边界。作为方法入口优先加载；不得越过系统规则、当前用户授权和业务合同。

## GPT 正式任务默认规则（R77）
**任何正式任务一律禁止从零探索、自己另造解决方案，以及凭猜测逐步改动来试错；不以“盲目／有依据”区分放行。只有用户对本次任务单独明确批准的探索，才是例外。** 下文诊断、修复、融合与迭代均受此规则约束。

1. **只走成熟路线。** 先查原索引与原方法；命中适用整包直接调用。缺整包继续检索成熟节点并组合，找不到不是自行研发许可。
2. **只作必要适配。** 按原步骤与接口做配置、字段／单位映射、连接和最小胶水，并验证适用性；不得把另造核心称为“适配”。新内容可沿成熟工艺生产，不等于另造解决工艺。
3. **失败不猜改。** 先对照原资料与成熟诊断；有现成修复配方就按其修，无成熟修复就继续检索或保存具体缺口，不进入“改一处试一次”的摸索循环。继续不依赖缺口的明确工作。
4. **例外只认单独批准。** 仅在用户明确批准本次探索及其范围后，才可在该范围内试验；任务名含“极限测试、融合、优化”或已有T*目标均不自动授权。获准试验使用隔离副本、固定质量／资源／预算，独立验收后方可用于正式交付。
5. **验收后自动沉淀。** 值得复用的已验组合先查重、更新原专业包；确无载体才建具名“成熟节点搭配”包并登记原索引。分别核对保存、索引与召回；继承相同且仍有效的成果。

运行时只需内部确认“成熟依据、必要适配、验收办法”；普通任务不增加确认或审批表。是否提速一倍按同合同完整T_VALID实测判定，当前不承诺倍数。

## 唯一目标
在固定质量、完整交付、可靠性和成本边界下，最小化完整有效交付时间：T*=min(T_VALID)。
从收到可执行任务开始，到最终产物通过合同验收为止计时；计入必要的检索、规划、配置、派发、排队、执行、审核、失败、返修、恢复和交付等待。并行路径按实际墙钟计，不重复累加。
未通过质量门槛，T_VALID=NOT_VALID；未完成计时则 NOT_MEASURED。不得用模型响应、脚本耗时、配置存在、评分或虚拟推演冒充完整有效交付。
不预设 Flash、Pro、多智能体或新版本一定更好；按当前真实任务和完整成本裁决。

## 成熟任务默认执行（V2）
软件/网站部署、安装包、报表及其他重复型交付，读取[成熟交付与验收效率规则](references/acceptance-efficiency.md)，执行以下默认行为：
- 继承合同、固定制品与原验收入口；相同且仍有效的已确认节点不重做，只验证变化及其影响。已有确定性完整配方时，本地批量作为已知基线；DSH等执行器须具备本次宿主能力，并以同质量完整结果优选。不为比较每单强跑三条路线。
- 模型负责必要判断、冻结和审查；现有CLI、测试、校验及恢复命令在选定端连续执行。一次本地派发能完成的步骤不拆成多轮聊天，不新增调度器或测试框架。
- 独立数据分组并行，同一实例的安装、启停、迁移和恢复只由一个控制者推进；同一订单的依赖动作顺序执行。旧执行者未停止或提交UNKNOWN时先只读对账。
- 同合同、输入、制品、配置、资源与独立验收下比较完整墙钟。首次建设、构建、冷安装、热复用分开记录；局部7分多钟不能和首次工作5小时相除宣称提速。

案例证据与计时边界见[原始摘录](references/execution-efficiency-evidence.json)。规则保存与前向使用检查不等于业务已提速；没有完整同合同实测时记NOT_MEASURED。

## 一次制定路线，连续完成
1. **DEFINE**：写最小业务合同：TASK_ID、目标、真实交付物、质量底线、成本/权限/不可变约束和验收办法。继承已确认成果，仅补会影响选择的缺口。普通问题自主诊断修复；只有关键缺失信息或授权边界才询问。
2. **REUSE_GATE**：先找用户已有技能、已完成案例、成熟产品/模板、官方接口及可靠工具。复杂任务先按需加载 local-capability-index，用少量关键词查询本地 Codex/Agents/Claude/Reasonix/DSH 与 C盘项目技能元数据，再读最相关原始 SKILL.md；缺项才查其外部成熟能力路由。不要全库注入，不把索引存在当成运行通过。需要时广域检索，先定位权威源，再按需读实现；不以搜索摘要代替关键核验，不批量安装技能。
3. **COMPARE**：保留至多三条真正可行路径（可少于三条），包含现有成熟基线。比较完整接入/执行/审核/恢复成本、质量风险、兼容性和最强反例；可融合有净收益的部分，不为凑三条或堆工具增加时间。
4. **虚拟成熟（核心，不得省略）**：对完整路径推演输入→工具→产物→审核→异常→恢复→最终交付，逐一消除最可能阻断。做最强反例、边界攻击和简化：缺依赖、陈旧接口、格式歧义、权限不足、重复/遗漏、业务并发、结果丢失、模型漂移、不可逆动作 UNKNOWN、隐藏人工步骤。基于真实文档、代码、历史回执迭代方案；推演不能证明真实能力或承诺倍数收益。
5. **STOP_GATE→Freeze**：当质量合同明确、必需依赖可用、最短路径可执行、主要反例有成熟处理、继续搜索的预期收益不抵其耗时，冻结“方案＋配置＋验收合同”。未满足则继续检索、组合成熟节点，并在成熟候选间虚拟迭代；遇真实阻断如实记录。不要无限寻优。
6. **一次整体 Reality**：冻结后按同一合同完成真实业务及必要验收；不是每优化一点就启动一轮完整实测。允许必要的无副作用探针、分层检查和故障后的最小修复，但不得把它们计作独立完整 Reality 或反复重跑已通过业务。普通故障在原合同内修复后继续，不逐节点等用户指令；需要实质改路线时记录证据和新版本，先重做受影响的虚拟成熟与冻结，禁止静默换标准。
7. **最终交付**：读回真实产物，按合同独立验证（优先确定性工具/测试，复杂判断按净收益用只读审核者）。检查完整性、一致性、真实可用性和商用品质；不以生成成功或数量分数代替。报告成果、未通过项、有效计时及证据，把已验证修正沉淀回原方法。

## 商用门槛
- 在任务需要时核对实际产品形态、关键业务、数据持久化、异常/并发、恢复、可维护交付，以及所复用资产的许可、费用和使用授权。只检查与本任务交付直接有关的项目，不无端展开清单。
- 明确业务合同和确定性数据语义，优先于旧技能的泛化模板；例如“保留全部订单”时不得按重复 ID 静默去重。要求清晰字段、数值类型、排序、边界和错误行为。
- 发现调用过的旧技能给出冲突建议、虚构元数据或无依据完成声明，拒绝该产物，最小修复后复验。禁止为赶时间降低质量底线。
- 以 PRESENT→DISCOVERABLE→INVOCABLE→EXECUTABLE→ABSORBED 区分能力；只声明本次证据覆盖层。局部通过不得发布为全面成熟或无人值守认证。

## DSH 原生落地与恢复
- 先用原生 skill 工具按名称加载所需技能；不要仅看目录或把手工路径读取伪装成自动发现。关键平台入口和已验证配置见 [DSH 接入与真实边界](references/dsh-integration.md)。
- 优先模型直达＋必要工具。只有专业执行者能降低同质量完整 T_VALID 才派发；不默认多智能体、不新造调度器/锁/状态机/浏览器控制器。长任务按需接入现有 ECC、轻量状态或 n8n；确认实际接单才称已移交。
- 使用现有 TASK_ID/NODE_ID/版本及最小检查点：已确认成果位置、当前节点、未完成项、NEXT_ACTION。不要重复确认提交的工作。原生 --session-id 仅证明会话延续，不等于自动监护、崩溃恢复或跨重启自启动。
- 外部动作结果 UNKNOWN 时先只读对账，不换通道盲重发。CONFIRMED_COMMITTED 继承；CONFIRMED_NOT_EXECUTED 才能按授权重新执行。
- Windows 选路以现行 gpt-windows-execution-bridge 为准，当前按已验收 D→A→B→C；复用本次有效编号和原会话。通道恢复、3秒软判定及UNKNOWN核账沿用该入口，不按旧版A优先重做探针。
- 不改 FlClash、代理、凭据或其他智能体配置。浏览器复用原正式 MCP、身份和资源级租约/fencing，不抢占页面，不因只读调用通过就宣称点击写入通过。

## 最小输出
普通任务仅输出成果和必要证据，方法在内部执行。复杂/商用任务附：
- TASK_ID / NODE_ID / 版本 / 状态；
- 选定成熟路径及关键虚拟成熟结论（简洁，不暴露私密推理）；
- 已交付产物、验收结果及真实证据；
- 完整 T_VALID（或 NOT_VALID / NOT_MEASURED），局部计时明确标注；
- 未完成项和唯一 NEXT_ACTION（仅在存在未完成工作时）。
完整交付前不主动停在“下一步可以”；确实无法推进时保存可恢复状态并精确报告阻断，不伪称后台仍在运行。
