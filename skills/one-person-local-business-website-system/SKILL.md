# 一人公司·海外本地商家网站系统

把海外本地商家网站业务作为 `one-person-ai-company-success-routes` 总系统中的可执行子模块。覆盖：

`市场选择 → 合规找客 → 评分 → 调研 → 概念演示 → 人工审核外联 → 跟进 → 访谈 → 提案 → 交付 → 三轮验收 → 维护复购`

## 开工门禁

1. 先确认目标国家/城市、行业、预算、每周投入、可用建站技术、英语人工校对、收款和合同能力。
2. 读取 `references/compliance/compliance-and-risk-boundaries.md`，核验当地 B2B 外联、隐私、图片、平台条款和退订规则。高风险或不明确时停止批量外联，只做研究和小样。
3. 读取 `references/sop/end-to-end-sop.md` 和 `references/sop/lead-scoring.md`。
4. 检查 `FAILURE_REVIEW.md`，避免群发、无证据结论、先做完整网站、伪造案例和未经授权素材。
5. 从一个国家、一个行业、1—3 个城市开始；首轮只验证 20—50 条线索，只为 3—5 条高分线索制作概念演示。

## 硬性边界

- 不绕过 Google Maps 或其他平台限制，不未经允许批量抓取。
- 不采集私人联系人数据，只保存最小必要的公开商业信息、来源和日期。
- 不自动发送邮件、私信或电话；每条外联必须人工审核、人工批准并由用户另行执行。
- 不伪造评价、案例、授权、流量、排名、收入或经营结果。
- 公开可见素材不等于可商用；概念演示优先使用授权素材、正规图库或占位视觉。
- 未成交前只做 30—60 分钟可复用概念演示，不为每条线索制作完整网站。
- 演示必须标注“非官方概念演示”、设置 `noindex`、关闭真实支付与消费者数据收集。
- 正式交付必须完成三轮验收并保存设备、时间、截图、缺陷、修复和复测证据。

## 执行流程

1. 用 `references/method/business-model-and-service-packaging.md` 定义“单一行业 + 单一城市 + 单一结果”与三档产品。
2. 复制 `references/data/leads.csv` 建立线索池，保留来源证据与采集日期。
3. 按 100 分制评分：70+ 深度调研，55—69 观察，低于 55 不投入演示成本；一票否决项直接退出。
4. 用 `references/data/merchant-research-card.md` 建卡。所有卖点、问题和评论结论必须能回到来源。
5. 只为高分线索制作首屏/核心服务/评价/CTA 概念演示；餐馆路线可读 `references/cases/restaurant-example.md`。
6. 用 `references/templates/outreach-templates.md` 生成邮件、私信或电话草稿，并执行人工事实核验和批准门。
7. 最多跟进 3—4 次；拒绝后立即停止。读取 `references/templates/follow-up-and-discovery.md`。
8. 用 `references/templates/proposal-and-scope.md` 明确交付范围、不包含项、里程碑、定金、修改轮次、权属和客户责任。
9. 生产模板可复用，但品牌内容必须独立；禁止复制竞争对手网站。
10. 按 `references/quality/three-round-acceptance.md` 做功能、跨设备视觉/内容、真实任务三轮验收。
11. 上线 7—14 天后复盘真实数据，提出维护、评论、本地 SEO/AEO、内容或自动化复购建议。

## 每次运行的最低输出

1. 市场选择与合规预检
2. 线索表、评分和筛选理由
3. 商家研究卡和来源证据
4. 概念演示需求书
5. 待人工审核的外联与跟进草稿
6. 需求访谈、提案和工作说明书
7. 建站交付清单与三轮验收证据
8. 单项目毛利、交付周期和复购建议

## 成功指标

跟踪合格线索率、演示成本、有效送达率、正向回复率、预约率、提案成交率、单项目毛利、交付周期、维护续费率和客户可验证的业务结果。不要把“采集联系人数量”当作核心成绩。
