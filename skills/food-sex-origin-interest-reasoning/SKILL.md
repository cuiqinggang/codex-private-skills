# 食性原点与食续利益推演决策

## 一、技能目的

本技能用于把复杂问题还原到最初目的，再从原点逐层推导出现实利益、约束、方案和第一行动。

它不把人的每一个直接念头都解释成食物或性欲，也不以生物解释替代事实、法律和伦理判断。

它解决的核心问题是：

> 哪个方案最能保护真正利益，符合现实条件，能够以最低成本形成真实结果，并为以后留下可重复能力？

## 二、两个最初支点

### 1. 食：吃饱了，活着

生命首先必须维持当前个体存在。

最简单的表达是：

> 吃饱了，活着。

食物、水、空气、休息、安全和医疗属于直接条件；资源、住所、工具、生产、财富、技术、权力、法律和制度，是为了更稳定地获得这些条件而逐层发展出的工具。

必须区分：

- 原始目的：活着；
- 中间目标：获得资源、安全和行动能力；
- 工具形式：财富、技术、组织、权力和制度。

不得把工具误认为最初目的。

### 2. 性：让自己的基因和后代继续活着

个体最终会死亡。生命要跨越个体死亡继续存在，就必须通过繁衍把遗传信息传递给下一代。

最简单的表达是：

> 繁衍后代，让自己的基因继续活着。

由此逐层产生择偶、繁衍、生育、抚养、亲属保护、家庭合作、教育、继承和代际延续。

### 3. 食与性的顺序

即时顺序是：

> 先活着，后繁衍。

长期关系是：

> 食保住当前生命；性保住生命的下一代。

“续”不是替代“性”的原始概念，而是性、繁衍、抚养和亲属保护进入复杂社会后的扩展形式。

## 三、复杂利益的生成路径

### 路径A：从活着到资源和制度

活着 → 需要食物与安全 → 资源有限 → 寻找、生产与储存 → 竞争与合作 → 分工交换 → 财产、财富、技术 → 权力、法律与制度。

### 路径B：从繁衍到家庭和传承

性与择偶 → 繁衍 → 后代需要保护 → 配偶与亲属合作 → 家庭 → 抚养与教育 → 继承 → 家族、群体与文化延续。

### 路径C：从冲突到攻击和策略

当资源、安全、配偶、后代和群体存续发生冲突时，会产生防卫、攻击、威慑、联盟、谈判、商业竞争、外交、战争和规则。

攻击和策略通常是保护或争夺利益的工具，不是自动正确的最终目的。

## 四、理论边界

1. 不得把所有直接动机都解释为食和性。
2. 不得把推断写成事实。
3. 能够存续不等于合理、公平或正当。
4. 食续利益不能替代法律、安全、隐私、伦理和基本权利判断。
5. 不得用群体长期利益掩盖具体个人正在承担的重大损失。
6. 趋势只能作为判断条件，不能当作绝对预言。

详细理论边界见：`references/theory-and-boundaries.md`。

## 五、标准流程：原、根、界、势、策、验

### 第一步：原——返回最初状态

回答：

- 如果去掉所有复杂形式，最简单的问题是什么？
- 它首先关系到谁继续活着？
- 它是否关系到后代、家庭、关系、成果或群体延续？
- 哪些是原始目的，哪些只是中间工具？
- 从原始状态到当前问题的因果链是什么？

输出：

- 食的原始利益；
- 性或续的原始利益；
- 原点到当前问题的发展链。

### 第二步：根——识别当前真实利益

回答：

- 真正要保护什么？
- 真正要获得什么？
- 不解决会损失什么？
- 谁受益，谁承担成本？
- 当前利益与长期利益分别是什么？
- 表面要求背后的真实需要是什么？

必须区分：

- 已确认事实；
- 当事人明确目标；
- 利益推断；
- 未验证假设；
- 其他可能解释。

### 第三步：界——确认不能突破的边界

检查：

- 法律；
- 安全；
- 隐私；
- 伦理；
- 用户明确意愿；
- 权限和工具能力；
- 不可接受成本；
- 不可逆损失。

突破关键边界的方案直接淘汰。

### 第四步：势——判断现实环境

分析：

- 当前用户和人口结构；
- 使用习惯和传播渠道；
- 技术、市场和社会环境；
- 哪些能力会越来越重要；
- 哪些方案容易过时；
- 是否保留替代路径和退路。

“顺势”不等于盲目追随趋势，还要检查方案能否承受趋势变化。

### 第五步：策——选择最小有效方案

默认只保留：

1. 一个主方案；
2. 一个备用方案；
3. 高风险任务才增加一个应急退出方案。

主方案优先满足：

- 用户容易理解；
- 权限明确；
- 成本低；
- 可快速验证；
- 失败可回退；
- 结果直观；
- 能积累数据、模板、技能、用户或资产。

不得为了显得全面而加入不会改变最终结果的步骤。

### 第六步：验——执行前与执行后验证

#### 执行前验证

先测试决定成败的最小动作：

- 能否访问目标系统；
- 能否读取必要数据；
- 能否完成关键写入、发送、下载或部署；
- 是否需要授权、登录、API、付款或人工接管；
- 关键工具是否真实可用；
- 主执行者失败后由谁接替。

不得在关键权限未验证前投入大规模时间。

#### 执行后验证

检查：

- 是否真正解决问题；
- 用户是否确认结果有用；
- 是否只是表面完成；
- 是否产生新的维护负担；
- 是否留下模板、数据、流程或能力积累；
- 应当保留、修改还是废弃。

## 六、优先级规则

1. 生命、安全和不可逆损失。
2. 解除当前核心阻塞。
3. 建立可重复基础能力。
4. 开展低成本、可验证的真实服务。
5. 核心闭环成立后再优化、美化、扩张和平台化。

一次性紧急任务可以不形成长期资产；重复问题不得每次从零开始。

## 七、强制停止与返工条件

出现以下任一情况时，停止扩展并重新分析：

1. 没有说明最原始目的。
2. 把财富、权力、技术或制度误写成最终原点。
3. 把利益推断伪装成事实。
4. 关键执行者没有权限。
5. 步骤增加但核心结果没有变化。
6. 依赖未经验证的网站、模型或工具。
7. 用户投入持续增加却没有真实收益。
8. 用“大局利益”掩盖具体承担者的重大损失。
9. 只解释失败，没有替代路径。
10. 为完整而加入不影响结果的流程。
11. 最终没有说明现在先做什么。
12. 没有真实验收标准。

## 八、标准输出格式

1. **问题本质**：一句话说明真正要解决的问题。
2. **原始起点**：说明怎样从“活着”和“生命延续”发展到当前问题。
3. **食性与食续利益**：列出资源、安全、家庭、后代、关系和长期积累。
4. **事实与推断**：区分事实、明确目标、推断和假设。
5. **利益主体**：谁受益、谁付出、谁可能受损。
6. **现实边界**：权限、法律、隐私、安全、资金、时间和技术限制。
7. **环境与趋势**：当前环境、传播条件和可能变化。
8. **主方案**：只给一个当前方案并说明选择原因。
9. **备用方案**：关键条件失败时如何切换。
10. **第一执行动作**：现在即可完成的最小动作。
11. **验收标准**：什么结果才算真正完成。

## 九、1.0首个验证案例

本技能1.0以“湖北襄阳老河口微信免费AI服务选择”为首个完整案例。

推导结论：

> 先以家庭影像免费试做建立第一个真实闭环，第一阶段只保留普通照片清晰修复、老照片修复、家庭趣味图片三类入口；默认每人首次一张免费，并通过真实用户、交付结果、反馈、耗时、返修和模板沉淀进行验收。

完整案例见：`references/case-laohekou-wechat-free-service.md`。
