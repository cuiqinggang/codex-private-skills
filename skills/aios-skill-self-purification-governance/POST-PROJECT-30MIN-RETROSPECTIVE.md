# Post-Project 30min Retrospective

Minimum runtime: 30 minutes.

Trigger:

- after a major project reaches PASS or ACCEPTED.

Purpose:

- extract successful methods,
- extract failure and repair lessons,
- identify reusable SOP changes,
- identify whether a skill should be created or updated,
- create candidate patches only,
- write rejected and needs-human-review items.

Forbidden:

- direct formal skill writes,
- automatic merge,
- deletion of failure reviews,
- overwriting hard rules,
- PASS without runtime evidence.
