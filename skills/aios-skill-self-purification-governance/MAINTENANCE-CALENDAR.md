# Maintenance Calendar

## Weekly 30min Light Check

Suggested timing: Sunday night.

Use when the goal is routine hygiene: recent changes, new skills, modified skills, frequently-used skills, duplicate triggers, missing acceptance pages, risky automation language, and rejected-edit buffer updates.

Do not use for big rewrites, merge decisions, deletion, or hard-rule changes.

## Monthly 2h Sample Optimization

Suggested timing: first Sunday night of each month.

Use when 10-15 high-value or high-risk skills need sample scoring, before/after comparison, rejection analysis, and candidate patch buffers.

Do not auto-merge any patch into formal skill files.

## Quarterly 4h Graph Governance

Suggested timing: first Sunday night of January, April, July, and October.

Use when skill relations, duplicate packages, conflicting triggers, stale skills, orphan skills, total-control trigger scope, and do-not-merge lists need a medium-scale review.

Do not run frequently. Do not auto-merge.

## Post-Project 30min Retrospective

Suggested timing: after a major project reaches PASS or ACCEPTED.

Use to extract successful patterns, failures, repair lessons, reusable SOP changes, and candidate skill updates.

Do not directly write formal skill files.
