# The Minimalist Entrepreneur 10 Skills - 中文方法整理

本方法来自 Sahil Lavingia 的《The Minimalist Entrepreneur》及其 `slavingia/skills` Claude Code 技能库。以下按原方法的意思整理为中文步骤，不扩展成其他创业框架。

## 总路线

| 顺序 | 技能 | 用途 |
|---:|---|---|
| 1 | Find Community | 先找到自己已经属于、愿意长期服务的社区 |
| 2 | Validate Idea | 先验证问题和付费意愿，不先做产品 |
| 3 | MVP | 用最小版本交付价值 |
| 4 | Processize | 先把服务手工交付并写成流程，再产品化 |
| 5 | First Customers | 一对一卖到前 100 个客户 |
| 6 | Pricing | 从第一天就收费，并持续调整 |
| 7 | Marketing Plan | 有付费客户后，用内容把销售放大 |
| 8 | Grow Sustainably | 用盈利、现金流和节奏控制增长 |
| 9 | Company Values | 招人前先定义公司价值观和文化 |
| 10 | Minimalist Review | 用极简创业原则复盘每个重要商业决策 |

## 1. Find Community

核心：先从社区开始，而不是先从产品点子开始。好的极简企业来自创始人已经深入的社区，并从社区里反复出现的问题开始。

步骤：

1. 列出自己已经属于的社区：职业圈、兴趣圈、线上论坛、本地组织、身份群体、校友、宗教、家长群等。
2. 列出自己在线上经常待的地方：Reddit、Discord、Slack、X/Twitter、论坛、Facebook 群、Substack、YouTube 社区等。
3. 记录社区里反复抱怨的问题。持续、重复、痛苦的问题更可能成为生意。
4. 判断自己是否愿意多年服务这个社区。
5. 对每个社区做判断：自己是否是真成员、问题是否痛到愿意付费、是否能触达这些人、社区是否足够小到可以占住位置又足够大到能支撑生意。

输出：

- 1 到 3 个可以服务的社区。
- 每个社区的持续问题。
- 自己与社区的真实连接。
- 社区聚集的位置。

## 2. Validate Idea

核心：验证来自销售，不来自先做产品。不要花几个月做没人要的产品；先卖一个手工版本。

步骤：

1. 先定义问题，不先定义解决方案。说明谁有这个问题、他们现在怎么解决、问题有多痛、是否愿意付费消除。
2. 判断能不能先手工解决。自己先做，雇佣自己，把每一步写下来。
3. 判断有没有人愿意付钱。至少找 10 个潜在客户聊，至少 3 个愿意付费或真的付费。
4. 开始做之前问四个问题：能不能一个周末做出第一版；是否让客户生活变好一点；是否有人愿意付钱；是否能快速得到反馈。

不要做的信号：

- 没有人现在试图解决这个问题。
- 说不出 10 个具体有此问题的人。
- 只有朋友说“这想法不错”。
- 需要教育别人他们有这个问题。
- 面向自己不属于的社区。

值得继续的信号：

- 人们已经在为更差的方案付费。
- 已经手工解决过并且对方喜欢。
- 社区在主动抱怨这个问题。
- 能一句话说清客户和痛点。
- 是自己也遇到的问题。

输出：

- 结论：已验证、需要继续验证、或需要转向。
- 下一步要收集的具体证据。

## 3. MVP

核心：尽可能少地构建。目标是尽快给社区交付价值，不是做漂亮、完整或复杂的产品。

三阶段：

1. Manual：自己手工解决问题。自己就是产品、客服、履约和工程。
2. Processized：把手工过程系统化，写到纸上，让别人也能照做。
3. Productized：只自动化已经被手工证明有效的步骤。

四个构建问题：

1. 能不能一个周末发出去。
2. 是否让客户生活好一点。
3. 是否有人愿意付钱。
4. 是否能快速得到反馈。

MVP 应该做：

- 只做一件事。
- 不追求精致。
- 收钱，哪怕很少。
- 优先使用现有工具：Carrd、Gumroad、Stripe、Airtable、Google Forms、Zapier、Notion 等。

MVP 不应该做：

- 不做“以后可能需要”的功能。
- 不为规模而构建。
- 网站能解决就不先做移动 App。
- 表格能解决就不写代码。
- 无代码工具能解决就不先雇工程师。

输出：

- MVP 只做的一件事。
- 最简单的实现方式。
- 这个周末能交付什么。
- 初始价格。
- 反馈收集方式。

## 4. Processize

核心：先流程化，再产品化。伟大的产品通常先是有人手工完成工作。现在的任务不是先写软件，而是证明自己能手工给真人交付价值。

步骤：

1. 说清产品点子，然后削到只剩一件事：客户使用前有什么，使用后得到什么；如果完全不用技术，只用自己、电话和表格，怎么交付。
2. 找到今天就需要它的人：谁正在用替代方案解决；他们在哪里；能否说出 10 个具体的人。
3. 设计手工版本：客户给你什么；你按什么顺序处理；你交付什么；每个客户花多长时间。
4. 写下“魔法纸片”：触发条件、步骤、工具、每步耗时、交付方式。清楚到你休假时别人也能照做。
5. 收费。免费用户不给真实信号，哪怕 1 美元也能证明价值。
6. 只有在手工交付给 10 个以上付费客户、问题稳定、步骤几周不变、交付比找客户更耗时之后，再开始自动化。

输出：

- 手工版本的一句话说明。
- 完整手工流程。
- 本周要服务的 3 个具体对象。
- 初始价格。
- 以后最先自动化的一步。

## 5. First Customers

核心：不要指望发布会，先卖。所谓一夜爆红通常是长期积累。早期要一个一个卖，从每次交流里学习。

销售同心圆：

1. 朋友和家人：先从这里开始，虽然不舒服也要做。目标是让他们成为第一批客户，不是投资人。
2. 自己的社区：列出所有写过、分享过、做过类似事的人；逐个联系，亲自讲解产品；要真实反馈，不要客套宣传。
3. 陌生人冷启动：冷邮件、电话、私信都可以。重点不是复制粘贴，而是在每次拒绝中改进表达。

销售的理解：

- 不是说服别人，而是帮助别人。
- 社区关系已经存在。
- 产品应该给对方生活增加价值。
- 每次没有成交都要变成洞察：是找错人，还是产品需要调整。
- 销售是教育过程，客户了解你，你也了解什么有效。

什么时候发布：

- 不要在有 100 个付费客户前正式发布。
- 到 100 个付费客户后，发布是庆祝社区支持，不是获客策略。

输出：

- 本周要联系的 10 个亲友。
- 要联系的 10 个社区成员。
- 一个可个性化的冷启动模板。
- 初始定价。
- 每周销售目标和追踪方式。

## 6. Pricing

核心：一定要收费。免费和 1 美元之间有巨大差别。不收费就无法活下去，也无法知道客户真正看重什么。

两种定价：

1. 成本定价：计算成本，再加利润。适合实物产品或成本清楚的服务。
2. 价值定价：按客户获得的价值收费，而不是按你的成本收费。适合软件、数字产品和高感知价值服务。

定价原则：

1. 先低后高，产品变好后涨价是正常的。
2. 定价不是永久决定，只是持续迭代的一部分。
3. 目标是逐渐形成分层定价。
4. 不要默认免费。
5. 可以给试用，但必须有清晰的付费路径。
6. 不要把营销误解成免费送产品。

初始定价要问：

- 每个客户的可变成本是多少。
- 替代方案和竞争方案收多少钱。
- 什么价格会让理想客户觉得很容易决定。
- 什么价格能从第一个客户开始盈利。

输出：

- 定价模型。
- 初始价格和理由。
- 未来分层定价设想。
- 达到个人财务独立需要多少客户。
- 什么时候复盘并涨价。

## 7. Marketing Plan

核心：营销是放大的销售，但不要把营销等同于广告。营销是创造粉丝，不是追求新闻标题。先花时间，不先花钱。

前提：

- 已有社区。
- 已有付费产品。
- 大约 100 个客户。
- 有一对一销售经验。

漏斗：

1. 接触内容。
2. 关注你。
3. 研究产品或网站。
4. 考虑价格和功能。
5. 购买。

内容三层：

1. 教育：分享你从业务里学到的东西。
2. 激励：分享旅程、困难和进展。
3. 娱乐：用更有传播性的方式表达观点。

社交媒体：

- 建两个账号：个人账号和业务账号。
- 不发无意义状态更新。
- 保持真实，重点是给出想法，不是自我推销。
- 公开构建，分享正在做什么、改进了什么、学到了什么。
- 选一个适合业务的平台，不要同时做太多。

邮件：

- 社交平台是租来的土地。
- 邮件列表是自己的土地。
- 尽早建立邮件列表。
- 用有价值的东西换邮箱。

付费广告：

- 最后再花钱。
- 只有当有自然增长、知道客户画像后才考虑广告。
- 不要为获客付出超过客户价值的钱。

输出：

- 主要内容平台和发布节奏。
- 教育、激励、娱乐各 5 个内容点子。
- 邮件列表策略。
- 公开构建计划。
- 何时考虑付费广告。

## 8. Grow Sustainably

核心：盈利是一种超能力。少花于所赚，获得无限跑道、清晰和控制权。

公式：

```text
Profit = Revenue - Costs
```

成本类型：

- 可变成本：支付处理、托管、风控等，随每单增长。
- 固定成本：域名、托管、人。最大固定成本通常是人。

成本规则：

1. 创始人起步阶段尽量少给自己发工资。
2. 雇软件，不先雇人。
3. 不先租办公室。
4. 不为了创业搬去高成本地点。
5. 外包一切可以外包的事：先自己和自动化，再自由职业者，再员工。

增长理解：

- 不需要支配市场或颠覆一切。
- 大多数小企业不会被大公司吃掉。
- 公司会按客户决定的速度增长。
- 工作更多小时不等于增长更快。

融资：

- 先自举。
- 盈利会给融资谈判更高主动权。
- 如果必须融资，可以考虑更适合可持续公司的替代路径。

避免耗尽：

- 致命问题有两类：钱用完，精力用完。
- 合伙关系要像婚姻一样提前谈清楚。
- 要讨论成功、退出、增长速度、为什么一起开始。
- 雇人应该发生在“疼”的时候，说明业务已经成熟到能让新人加入。

输出：

- 决策对盈利的影响。
- 是否可逆。
- 是客户驱动还是虚荣驱动。
- 有没有更便宜简单的替代方案。
- 默认活着还是默认死亡。

## 9. Company Values

核心：招人前先定义文化。价值观不是空泛口号，而是把公司相信的、不明显的东西用不明显的方式说出来。

价值观的作用：

- 告诉员工日常和极端情况下怎么行动。
- 比厚手册更有效，因为好的价值观容易记住。
- 吸引合适的人，也劝退不合适的人。
- 让创始人和团队都能被问责。
- 让公司超越创始人本人。

建立价值观的问题：

1. 你相信什么，而大多数人不相信。
2. 没人看着的时候，人应该怎么行动。
3. 即使表现不错，你会因为什么开除一个人。
4. 即使不直接帮助利润，你会庆祝什么。
5. 把价值观写成故事，不要写成口号。

落地方式：

- 在招聘、网站、入职材料中公开表达。
- 在反馈里使用价值观。
- 定期复盘，随着公司成长调整。
- 远程工作时，沟通要深思熟虑、异步、基于可用性而非监控。

输出：

- 3 到 5 条公司价值观。
- 每条价值观的说明和故事。
- 每条价值观在招聘中的体现。
- 每条价值观在日常工作中的体现。
- 每条价值观不代表什么。

## 10. Minimalist Review

核心：用极简创业原则审视任何商业决策。

八个审查原则：

1. 社区优先：是否服务社区和客户，还是来自自我、虚荣指标或模仿大公司。
2. 先手工，再自动化：是否过度构建，是否先手工证明过。
3. 尽量少构建：能否用最小版本让别人生活变好。
4. 先卖，再放大：是否已有真人付钱，是否试图在销售前先营销。
5. 先花时间，再花钱：能不能用内容、社交、个人联系解决，而不是先花钱。
6. 盈利是目标：这个决定让公司更接近还是远离盈利，是否可逆。
7. 按客户速度增长：客户是否真的要求这个。
8. 建造自己想住的房子：是否符合价值观，是否会让公司反过来拥有你。

决策检查表：

| 问题 | 回答 |
|---|---|
| 是否服务我的社区或客户 | |
| 这是不是最简单的方法 | |
| 是否改善盈利 | |
| 如果不奏效是否可逆 | |
| 我是在花时间还是花钱 | |
| 客户是否要求过这个 | |
| 是否符合我的价值观 | |
| 一年后我还会想要它吗 | |

输出：

- 明确建议：做、不做、或简化后再做。
- 极简版本是什么。
- 最大风险是什么。
- 本周可以尝试的一个验证动作。
