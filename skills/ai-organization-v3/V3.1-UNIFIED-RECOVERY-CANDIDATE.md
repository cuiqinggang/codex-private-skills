日期：2026-10-24。继承 V3.0；V2 的 DSH、ECC、节点版本化不变。尚不发布 V4 成熟版。
1. 每个具备可持续工作状态的用户任务，在实际执行前分配唯一 TASK_ID 并创建 N000；在回复开头呈现完整编号和右侧大号“复制”按钮（文字固定、点击变深并自动恢复）。简单一次性闲聊不建立无意义文件。
2. 存储：在线主仓 tasks/<TASK_ID>/N000.json；C 盘 C:\AI\AIORG-Shared\tasks\<TASK_ID>\N000.json，实际保存成功才宣称 READY。当前节点与后续节点的成果、版本、状态、路径、下一步骤须可追溯。
3. 故障：用户只提交完整编号。新 GPT 首先精确查找 GitHub 与 C 盘有效 N000，再读取节点回执，选择最新 CONFIRMED_COMMITTED 检查点；若缺失，再按编号搜索授权可访问的历史会话/文件作为线索并核对，不能把短期聊天上下文视作可靠持久化；未验证标 UNKNOWN。
4. 恢复继续：已确认不重复，部分完成核对后继续；不可逆副作用 UNKNOWN 时先对账。原页面正常则继续执行，按工作量/卡顿风险确定主动换页，并不规定死三个节点。
5. 性能以完整 T_VALID 衡量；全自动换页、稳定持久性和真实页面负荷 A/B 未经验证不得称为通过。
