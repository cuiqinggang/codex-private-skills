# AI 化组织 V3.0 — N000 根节点 / 仅凭 TASK_ID 恢复（增量规则）
不修改 V2 DSH、ECC、节点版本化机制。主任务 TASK_ID 固定，N000 为任务索引/整体合同，N001...Nnn 为业务节点。N000 不计入已完成业务节点，也不是每次重算的工作。
完整定位码：AIORG-YYYYMMDD-NNN/N000/V1；简单恢复口令可仅为 TASK_ID，但须已有访问仓库/索引的授权与工具。
权威恢复路径：仓库 tasks/<TASK_ID>/N000.json（本次示例）。读取其 checkpoint、confirmed_nodes、next_node；逐一读取原始已确认回执（以任务版本和提交证据为准），无法读取时查看已确认 C 盘强备；无权限/找不到时要求粘贴最小恢复包，不能猜测。
新页面恢复步骤：解析 TASK_ID→读取 N000→读取已完成节点回执并核验 version/commit/业务成果→从 next_node 继续；若当前节点部分完成，核对局部检查点，仅重做不能确认的子工作，避免不可逆副作用重放。若 N000 显示 TASK_COMPLETE，则只汇报结果，不再执行任务。原页关闭前不要求其再输出；可用回执必须先已持久化。
一致性：N000 只是轻量索引，节点回执是具体事实依据；N000 可能滞后，须核对更高版本且已确认的回执。任何 UNKNOWN 先核验，不以复制整个页面作为默认方案。
成功边界：人工将 ID 交给新页面+新页面实读仓库并完成待办为人工恢复 PASS；自动打开/填写/提交新页面需另行获授权并实测。完整 T_VALID 含换页、检索、恢复、QA、重试和返工，无可靠计时则 NOT_VERIFIED。

## 统一单编号恢复协议（V3 增量）
- 用户只需复制一个完整定位码：根任务 `AIORG-20261023-001/N000/V1`，或具体节点 `AIORG-20261023-001/N002/V1`。任意原页面失效均不要求复制页面正文。完整码含 TASK_ID、NODE_ID 和版本，避免多个任务编号冲突。
- N000 是任务根索引，负责整体任务合同、节点目录、最近已确认节点、未完成节点与回执指针；N001... 是各自业务节点。根号和子号均须能定位对应任务。
- 收到单一编号的新 GPT：解析并自动检索可访问的主仓 `tasks/<TASK_ID>/N000.json`；核对该任务节点最新已提交的回执、版本、依赖与已确认业务成果。节点号 N002 表示优先查看 N002 的执行合同及进度，并非强制重做 N002；N000 表示恢复整个任务的下一待办。
- 对已 CONFIRMED_COMMITTED 的节点只读取继承；执行 NOT_STARTED 或可确认尚未完成的剩余部分；UNKNOWN 先对账，禁止重放不可逆外部动作；任务已完成则只返回最终成果及回执。
- 前提：每个节点产生可查询的有效保存回执，索引能指向它们，且新 GPT 有仓库/本地强备的读取工具和权限。若新页面无法读取，直接报告 BLOCKED 和缺失权限/材料；编号不是无条件跨页面记忆。
- 固定回执字段：TASK_ID、NODE_ID、NODE_VERSION、STATUS、RESULT_REF、COMMIT_SHA（如有）、NEXT_NODE、T_VALID_EVIDENCE。不要把写入意图当作已成功保存。
