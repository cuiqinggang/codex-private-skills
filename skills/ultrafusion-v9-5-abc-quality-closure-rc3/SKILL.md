# UltraFusion V9.5.1 RC3｜ABC 极限质量闭环与A关能力来源层

## 1. 唯一目标

在可接受的时间和调用成本内，让三个强模型分别达到当前预算内可达高位，选择性吸收互补强点，再以非回退审核降低残留风险；最终用 A_Initial、A、B、C 全链数据证明质量收益是否值得。

## 2. 核心链

```text
原始问题
→ A_Initial零流程基线（封存）
→ 同一个A层统一极限提示词分别交给GPT、Qwen、DeepSeek
→ 三份A_Raw与A_Final
→ GPT执行B层选择性强点收敛
→ B_Final
→ 新GPT会话执行C层非回退强审核
→ C_Final
→ 新GPT会话执行匿名质量与成本评测
→ 最终评测报告
```

## 3. 三条不可破坏的合同

```text
A_Final 不得低于对应 A_Raw。
B_Final 不得低于三份 A_Final 中的最强答案。
C_Final 不得低于 B_Final。
```

这里的“不低于”同时要求：硬闸门不退步、任一核心质量维度不发生材料性下降、总质量分不下降、不得新增决定性错误。无法证明新候选更好时必须回退，不得为了显示流程有作用而强制改写。

## 4. A层：统一极限有效压力

- 只有一份 A 层源提示词；GPT、Qwen、DeepSeek 使用完全相同正文。
- A 层不是普通“再想一遍”，而是：真实初稿、缺陷定位、定向强化、全维复评、历史最佳保留、极限探针和停止条件。
- 每个模型在一次回复中同时输出 A_Raw、A_Final 和简短压力证据；用户只粘贴一次。
- 默认一轮定向强化；仍存在明确材料性缺陷时最多第二轮；禁止第三轮和无方向全文反复重写。
- A_Initial 不得进入 A、B、C，直到 C_Final 锁定后才在最终评测中解封。

## 5. B层：三强选择性收敛

- 固定由新的 GPT 会话执行。
- 最强 A 作为不可丢失的锚点。
- 只吸收另外两稿中经过验证的独有强点；不平均分配篇幅、不机械拼接、不按多数投票。
- 每个纳入强点必须说明：来源、独有性、验证依据、提升维度和是否引入副作用。
- 融合候选无法稳定胜过最强 A 时，B_Final 必须原样回退最强 A。

## 6. C层：非回退强审核

- 固定由新的 GPT 会话执行，只接收原始问题和 B_Final。
- 不重新发散、不重新融合、不读取 A_Initial、A稿或历史评分。
- 冻结 B；一次只处理一个材料性缺陷或一组不可分割缺陷；采用局部补丁。
- 补丁造成任一核心维度下降、信息丢失或新增重大问题时立即撤销。
- 没有材料性问题或无法可靠修复时，C_Final 必须与 B_Final 相同。

## 7. 质量与效率分开

答案质量采用五维：F25、L20、C20、D15、U20。流程效率单独记录人工时间、调用、复制、粘贴、费用、返工和运行错误。速度和低成本不得抵消事实或逻辑退步。

## 8. 什么时候使用完整模式

适用于：高价值决策、多路径方案、专业分析、长因果链、明显不确定性、需要对抗测试或最终发布审核的任务。

不适用于：简单事实问答、日常闲聊、普通改写、无需多路径的低价值任务。

## 9. 证据等级

- E0：只有主观声明；禁止宣布有效。
- E1：单层自评分或单次观察；只作方向性记录。
- E2：单题匿名、顺序平衡比较；可判断该题。
- E3：多题配对统计、错误注入测试、时间和成本记录；可判断候选版本是否保留。
- E4：真实长期使用数据；才能判断稳定价值与产品化。

## 10. 使用顺序

1. 先读 `README_先看这里.md`。
2. 设计或修改时读 `01_V9.5逻辑与量化合同.md`。
3. 实际运行只使用 `运行提示词/`。
4. Codex 部署只复制现成文件、运行自测试和校验；不得自行重写核心提示词。
5. 涉及A关验证时，读取 `05_HTML最小运行页规范与RC3现状.md` 和 `A关能力形成与证据闭环_RC3/`；页面已作为RC3能力验证执行器接入，但真实质量仍为待验证。

## 11. A关能力形成与验证模块（RC3增量）

测试网站、十二道关口、十次模拟、压力计算和证据矩阵不是技能包外部的临时工具，而是 UltraFusion V9.5.1 A关能力的来源、形成、验证、证据和版本演进模块。模块入口：

```text
A关能力形成与证据闭环_RC3/
```

当前成熟度必须显示为：

```text
L3｜模拟验证通过
UF951_A_CAPABILITY_L3_SIMULATION_VALIDATED
```

这只证明测试合同、网站计算和十次模拟逻辑通过；真实模型质量尚未验证。下一关口固定为 `L4｜GPT三题真实烟雾测试`。

### A关能力形成与验证规则

当任务涉及下列内容时，必须调用本模块：

- 测试V15.1-A；
- 判断A关是否有效；
- 比较A_Raw与A_Final；
- 测量极限压力；
- 确定最佳压力；
- 计算固定时间最佳性价比；
- 决定是否冻结A关；
- 为B关或C关提供已验证上游能力。

### 强制执行顺序

1. 读取 `A关能力形成与证据闭环_RC3/01_能力来源与成熟度/03_能力来源账本.json`；
2. 显示当前能力成熟度；
3. 读取冻结版量化测试合同；
4. 执行十二道关口；
5. 记录Q0、QR、Q1、Q2、QF；
6. 计算实际压力、实际最大压力、有效最大压力和最佳性价比压力；
7. 生成图片证据矩阵；
8. 运行独立匿名评审和人工复核；
9. 输出证据完整率；
10. 只根据发布闸门给出冻结、修订、限制、回退或否决。

### 强制禁止

- 模拟测试通过后宣布真实质量有效；
- 用模型自评分替代独立评审；
- 默认最后答案最好；
- 默认100分压力最优；
- A关未冻结就直接扩大B关和C关正式测试；
- 没有数字和证据只写“已完成”；
- 修改正式核心提示词而不建立新候选版本。

### 输出必须包含

- 当前成熟度等级；
- 十二道关口通过数；
- 证据完整率；
- 有效样本数；
- Q0、QR、Q1、Q2、QF；
- 实际最大压力；
- 有效最大压力；
- 最佳性价比压力；
- 固定时间最佳版本；
- 决定性回退数；
- 最终状态与下一关口。

## 12. A关发布状态纪律

最终决策只能使用：`FREEZE｜冻结为正式能力`、`REVISE｜继续修订`、`LIMIT｜限制适用场景`、`ROLLBACK｜回退` 或 `REJECT｜否决能力`。在 L3 阶段不得输出 `FREEZE`；网站和报告必须显示中文解释、证据完整率与下一关口。

## 13. 禁止事项

- 禁止生成英文版技能包或英文版运行提示词。
- 禁止生成三个模型专用的不同 A 提示词。
- 禁止把完整论证、研究论文和公式重复塞入运行提示词。
- 禁止把 A_Initial 提前暴露给 A、B、C。
- 禁止把 B、C 变成自由重写层。
- 禁止以更长、标题更多或语气更自信冒充质量提高。
- 禁止未经真实运行把状态写成“质量已经证明”。
- 禁止 Codex 自动 merge、push、覆盖旧版本或修改用户原始 9.1/9.5 文件。
